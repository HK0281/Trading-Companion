## 1. 本轮解决的问题

此前只能在终端或 Swagger 提交请求。现在用户可以直接在网页输入中文问题，查看事实、关系和证据字段，处理股票澄清，以及查看历史、检查状态、请求取消、重置和结束会话。本轮没有新增研究工具、模型提供方或交易权限。

```text
React 展示组件
  → ResearchController：页面状态、内存凭据、未确认请求
  → createApi：同源 HTTP、DTO 检查、固定错误
  → 原 FastAPI → 原 ResearchApiService → 原 Agent / 工具 / 事实检查
```

页面不会替 Agent 判断股票身份、计算指标或生成投资结论；也不直接连接模型供应商。

## 2. 安装、构建与运行

当前工作区已完成前端构建，可以直接启动 Python 服务。首次克隆、修改前端源码或构建发行包前，需要重新构建。

准备 Node.js 22.12+（建议使用受支持的 LTS 版本）及 pnpm 11.25.0。普通 Windows Node 安装通常自带 npm，可用 `npm.cmd install --global pnpm@11.25.0` 安装 pnpm；不需要激活 Python 虚拟环境。项目根目录运行：

```powershell
pnpm.cmd --dir frontend install --frozen-lockfile
pnpm.cmd --dir frontend test
pnpm.cmd --dir frontend build
```

`pnpm-lock.yaml`锁定解析结果；安装脚本只显式允许 esbuild。没有自动执行的部署、供应商配置或模型调用。不要把密钥写进前端源码或 `VITE_*` 变量；前端构建内容对浏览器公开。

Python API 依赖尚未安装时先执行第一行；日常使用只需后两行：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[api,model,dev]"
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.api_server --demo
```

打开 <http://127.0.0.1:8000/>。同一进程仍提供 <http://127.0.0.1:8000/docs>。Ctrl+C 停止服务。

没有开发服务器或第二个端口；修改 TSX/CSS 后重新 `build` 并刷新页面。刷新会丢失页面内存中的会话令牌，所以应在无在途请求时刷新。

### 固定离线体验

1. 直接在输入框输入问题；页面载入本身只读取 health，不创建会话或请求模型。
2. 点击“个股研究”，检查输入后点击发送箭头或按 Enter。
3. 点击“追问 RSI”并发送；这次读保存结果，不重新取数。
4. 可穿插“理解指标”或“DIF 与 DEA 是什么？”；定义回答不调用模型或行情。
5. 点击“调整指标”并发送；这会产生一次新的分析。
6. 点击“查看上次结果”；页面明确标注历史，不把它当作新研究成功。

首次发送自动建立会话并发送该问题；后续消息沿用同一会话。“新对话”结束并清空当前对话，回到可输入状态，直到下一次发送才创建新会话。当前只有一个内存会话，不支持切回旧聊天。Fake 是有限脚本，不是能回答任意问题的假语言模型；人工数据固定在2026-09-21至09-25。重置不重建脚本，也不返还额度。重跑整套演示点击“新对话”后再发送，不要在同一会话连续重复初始问题。

真实模型需要服务端显式 `--provider deepseek --data synthetic` 或 `--data tencent`，原目录与配置要求不变。网页显示提供方与数据模式；首次发送在输入框旁确认数据发送与可能计费，点击“允许并发送”才创建会话并提交。设置中仍可撤销许可，再次发送或重试时重新确认；新对话不继承旧许可。这不是供应商接入验证，也不授予下单权限；本轮没有进行真实模型或行情请求。

## 4. 网络失败与取消的状态

| 情况 | 页面行为 |
| --- | --- |
| 收到匹配的公共响应 | 展示业务状态和答案；再只读刷新额度。刷新额度失败不抹掉已收到的答案 |
| 断网、120秒浏览器等待超时、成功响应格式/编号错误、未知网关错误 | 保留原问题和编号，标记“响应未确认”，阻止新问题、重置和删除 |
| 点击“重试原请求” | 只由用户触发，使用同一编号和同一问题；可能取回缓存，或执行先前尚未接纳的请求。缓存重放的调用数标为“原请求”，不误记为本次新增调用 |
| 409仍在执行 / 429并行容量满 | 不自动重试；保留原编号，允许手动检查或稍后重试 |
| 已知固定终止错误 | 展示固定说明，结束当前请求；不把服务端失败自动变成第二次模型调用 |
| 401/404会话失效 | 丢弃页面凭据，不重做失败问题；提示下次明确发送会开始新对话，原研究条件不保留 |
| 点击“请求取消” | 单独发送匹配编号的cancel；202不清除在途状态，不声称远程已停止或免费 |

浏览器超时只停止等待，不等于后端取消。状态检查只读取进程内状态；服务端空闲也不证明丢失的原请求没有执行，仍应用原编号取回答案。该机制依赖原API的进程内幂等记录，不是跨重启或分布式exactly-once。

创建会话的响应如果丢失，没有可恢复的令牌；不会自动重建或提交研究，输入框恢复原问题，由用户再次点击发送。原不可访问会话等待30分钟绝对有效期后的惰性清理。创建与首条消息共享同步操作锁，避免快速双击创建多个会话；创建返回后再次检查许可和固定的模型／数据来源。

## 5. 展示与安全边界

- 只有原公共 `answer`进入答案区，不读取调试草稿。React按文本渲染，不解析用户/模型HTML或Markdown，不使用 `dangerouslySetInnerHTML`。
- 仅确实需要澄清时显示候选；旧回答的候选不可再次点击，历史也不展示选择按钮。点击仅填入代码，不自动执行。
- 展示已确认股票/日期、原始口径标签、状态/代码、本轮调用数与证据字段；舍入仅用于显示，不在前端重算关系或预测。
- 历史有独立标记；聊天最多保留40条页面记录，不等于后端保存完整对话，也不会把整个页面记录重发给模型。
- 令牌不放进URL、localStorage、sessionStorage、Cookie或文件；仅保留在当前页内存，开发者工具仍可能检查到它。刷新/关闭不自动撤销服务端会话，原绝对TTL不续期。
- 所有请求同源、无Cookie；保留现有Host/Origin、16KiB、Bearer与no-store保护，不为了UI增加通配CORS。
- HTML设置CSP：脚本、样式和连接只允许self，禁止内联/eval、第三方嵌入和外部base。不从CDN加载React、字体或图标。
- 后端只提供index和有限文件名的JS/CSS；拒绝目录逃逸、source map、TSX、Python和环境文件，不设置“任意路径返回HTML”的兜底。
- 键盘有焦点样式、控件标签和live状态；中文输入法合成期间不会因Ctrl+Enter误发，候选与示例都要再次确认发送。手机证据表内部横向滚动，不撑宽整页。

这不是用户登录系统或公网部署。勾选费用说明、按钮禁用和TypeScript类型不能代替后端权限、额度或事实校验。
