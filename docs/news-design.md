### 当前行为

2026-11-12：第四模块[自选消息收件箱](news-design.md#自选股消息收件箱有限检查与本机未读)按 #629 实现，未提交待审核；它与下述标题调试文件和分类排序分开。页面GET只读本机，手动检查固定新浪/东财公告最多5股10次实际请求；普通当前公司研究只将已取得的两源核验标题旁路保存，零新增来源或模型请求，不依赖 `--capture-news-titles`。旁路本机预算总共200毫秒协作检查（快照50＋合批保存150），不能硬停止磁盘阻塞；只标“研究中发现”，不推进手动成功水位。提交前before_commit/checkpoint可因研究取消回滚，不声称手动gate同锁硬中断。旁路保存状态由API收件箱可选sidecar_status告知（null/已保存固定码/未确认固定码），只存进程内、重启null，不加数据库字段或修改研究响应，UI提示未确认保存；纯store.list_inbox DTO不带它。历史、重放、解释和开发路径不触发；未开个人库时无库访问、额外时钟读取或模型上下文。收件箱不运行Jev，不启用重要提醒、后台定时或推送，也不改变下述排序验收和默认开关。

公司研究默认仍用新浪新闻、东方财富公告，巨潮公告是现有的可选来源。排序默认关闭时，回答收到的资料、顺序、引用编号、提示词和模型调用次数保持原有行为。单独的标题记录功能不运行 Jev 或 DeepSeek，也不读取分类 API 配置。

正常服务可显式打开：

```powershell
.\start.cmd --capture-news-titles
```

默认关闭，不因存在密钥自动开启。仅正常数据、DeepSeek 会话、当前公司研究记录；新版意图入口、旧入口及从筛选名单进入的公司研究共用记录点。历史研究、OpenAI、演示/开发、知识、指数和仅技术研究不产生标题文件。重放相同请求 ID 不重复写入，保存结果的纯解释追问也不重新采集。

记录点在资料采集及校验完成之后、综合回答之前。最多三家公司，每家公司每个来源最多五条，只接受 `content_kind=title` 的原始值。新浪标题、东方财富和巨潮公告保留来源链接及时间精度；东方财富新闻的搜索摘录不拆成标题。原始标题不会因回答显示长度限制而截短。

### 限量采集脚本

三份固定清单位于 [collect_news_titles.py](../scripts/collect_news_titles.py)，每批分别含沪市主板15家、深市主板15家、创业板10家、科创板10家，共150家且互不重叠。默认首批；`--batch second`更多覆盖常用词、地名和集团名，已采集。`--batch third`覆盖本地目录中带ST的名称及能源、化工、有色、光伏、电池材料、航空、地产等有周期特征的行业；只按公司特征选样，未参考已有标题、人工答案或模型错误，也不声称某家公司近期已被立案。第三批真实采集及新增316题定稿已由Claude完成，详见A2文档。它们是研究试点清单，不代表全市场分布。简称仍须通过原适配器的页面/证券身份核验；公司改名、页面变更或来源不可用会保留失败，不猜新名字、不重试、不换源。

默认只输出计划，不读 `.env`、不构造 HTTP 客户端、不建输出目录：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/collect_news_titles.py

# 第三批仅预览；实际执行另需 --live --max-requests 100。
.\.venv\Scripts\python.exe -X utf8 -B scripts/collect_news_titles.py --batch third

# 预览一个子集；同样不联网。
.\.venv\Scripts\python.exe -X utf8 -B scripts/collect_news_titles.py --company 000001.SZ --company 300308.SZ --max-requests 4
```

真实采集由 Claude 执行；Codex 没有执行下面的命令：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/collect_news_titles.py --live --max-requests 100
```

`--live` 必须同时给出 `--max-requests`，允许 1–100；失败尝试也扣除。选择子集时仍只能使用固定清单中的完整证券代码。每家公司新浪一页、东方财富公告一页，每页最多五条，总计至多 100 次公开来源请求、500 条标题。来源窗口统一为运行开始时点之前 30 天，保留原有身份、时间、链接、响应大小及超时校验，不抓正文、PDF 或额外分页。固定 GET 端点以外的请求被拒绝。

整次串行，相邻实际网络尝试开始时点至少间隔一秒；失败后下一来源也遵守间隔。达到预算在下一个来源前停止，不会为补足标题而追加请求。每个来源独立记录，空页或失败不会冒充没有公司事件。源失败、未运行、写入停止均保留在报告中；部分执行退出码为 1，参数无效为 2，计划预览或完整执行为 0。完整执行只说明计划走完，不能说明样本量或质量达标。

### 共用记录格式与边界

[news_triage_shadow.py](../src/trading_companion/news_triage_shadow.py) 提供 `news-title-capture-v1` 格式和有界记录器。在线输出 `.agentbus/tmp/news-triage-shadow/<run>/`，脚本输出 `.agentbus/tmp/news-title-collection/<run>/`。目录均已忽略，每次使用新的运行子目录，不覆盖、删除已有文件。

每份 JSON 包含：

- 版本、来源用途（在线 research 或脚本 collection）、统一截止时点、发表窗口起点；
- 每家公司代码、名称及新闻/公告来源的状态、固定错误码和采集时间；
- 标题原文、原证据 ID、原链接、发表日期/时刻、原时间精度、采集时刻；
- 标准化标题 SHA-256 摘要，即供后续识别完全相同标题的散列值；标题数及恒为零的模型调用数。

只逐字段提取公共资料，不序列化整个研究计划或资料包；因此不写原提问、聊天、回答、密钥、账户资料、来源原始错误正文。来源链接再按既有固定形式检查，防止附带任意查询串。运行 trace 不增加标题正文；普通研究/API 输出也不暴露这些本地记录。

每份至多 30 条、64 KiB；一次运行最多 10 MiB、1,000 份。首次真正写入时才创建目录，先写 `.partial` 再改名为 `.json`；失败留下的 partial 不算完整记录。容量到限、无效资料或写入失败即停止该记录器后续写入，并只发一次固定提示，不丢失已有记录，不改变研究回答。脚本遇写入停止也停止继续取数。取消和整轮截止异常继续向上传递，不当作普通记录失败吞掉。本地磁盘操作有界但不是硬实时保证，尚未测真实额外延迟。

脚本报告列出实际请求数、来源完成/失败/未运行数、保存量、不同“公司—标题—日期”数及距离 400 条的原始缺口。该数量尚未做近似转载聚类或人工标注，不保证已经有 400 条可用评估题。去重和分组封存由 A2 完成。

### 扩样与阶段B同步设计

初次准备仍为每侧130自然加最多70额外真实难例。追加使用完整定稿作为父资料：旧公司的归属、旧题及其标准答案不变；只分配新公司，新共享事件触及相反旧侧时整组排除。每侧从新增候选按标题散列、证券、日期固定顺序新增最多150条自然样本（其中也包含难题），再从剩余候选补原70条难例目标。不能按答案或模型错误挑题；追加后的来源及公司/标题板块比例差仍须不超过15个百分点，失败不写盲标表。新表只含新增题，两人独立标注并合并时承接原定稿。追加后自然数、难例数和比例均按实数报告，不预估标签支持。

扩样后封存集high45、negative31、positive52；一次性组合检验的排序门槛已通过。倾向positive精确率85.2%未达95%，negative预测支持27不足30，倾向门槛未通过。门槛保持high至少30且召回至少95%，正负各至少30条人工和预测支持且精确率各至少95%；未解决仍在分母中。不重新调整封存集、定义或阈值，不因接入排序重跑封存检验。

阶段B已实现、待审核，尚未上线。在线政策版本为`news-triage-sorting-v1`。Jev单独限每轮10条、最多3并发、约2秒，并受整轮剩余时间约束；单独计数、记录用量，不占现有6次模型调用。Jev与DeepSeek都沿用已检验组合的三题，DeepSeek对本轮同公司标题一次批量，占现有6次中的1次，并至少保留2次给回答和必要重写。多公司整轮仍只能一个DeepSeek批次。离线批量成绩不证明线上时间或实际回答质量满足要求。

排序仅在已有公司及新闻/公告同类位置内优先保留明确重要且相关的标题；不挤占财务、技术或其他公司名额，不改原证据和E引用编号，重写复用同一上下文。产品降级比离线组合严格：任一方未配置、超时、失败或预算不足，整轮保持原排序并记录原因，回答照常；真正整轮取消、截止和已触发的token阈值仍按原规则停止。`--news-triage-sorting`默认关闭，仅新版理解路径的DeepSeek公司研究生效。倾向标签不接入，无关过滤不恢复。30组固定资料包须开关各回答一次，由Claude执行真实验收，另列费用和调用上限；完成验收后用户再次同意才开启。

#### 选样、容量和预算

[排序器](../src/trading_companion/news_triage_sorting.py)按研究计划的公司顺序，固定选择第一家有已核验原始标题的公司；该公司的新闻、公告交替取样，每类至多五条。发出请求前，按完整冻结请求体估算token（供应商用来计算用量的单位），确定两方共同处理的最长可容纳前缀；不是先调用再缩批。估算采用UTF-8字节数除以三再加输出预留，不是精确分词或账单硬上限。配置缺失或一条也装不下时零请求。

**2026-11-10 Claude依用户授权作出的预算决定（总线消息#576）**：Jev单轮40,000 token独立记账，不计入DeepSeek整轮24,000或分诊8,000子阈值。DeepSeek分类仍受8,000子阈值和24,000整轮阈值约束，占一次调用，预留至少两次给初稿和必要重写；按当前完整回答输入、输出及修复反馈估算预留token。实际用量未知或达到分类阈值即停止后续可选请求、整轮原序；DeepSeek实际触发整轮阈值时仍停止整轮回答。

Jev全批目标窗口2秒、DeepSeek批次3秒，可选阶段总窗口5秒，资格检查要求至少剩20秒，为原回答保留至少15秒；总窗口同时受整轮剩余时间减去15秒约束。底层网络请求也使用相应的2秒/3秒限制。调整依据为首次配对运行中DeepSeek请求在2.063秒超时；此前三题组合调试批量136次成功请求的p50（中位耗时）为1.328秒、p95（95%的请求不超过的耗时）为1.703秒，封存批量128次为1.391秒/1.766秒；仅重要性分工批量129次为1.234秒/1.547秒，三者不可混为同一实验。原1.5秒限制低于这些p95。历史延迟从既有报告逐请求耗时按最近秩计算，没有新增模型请求。

使用全局最多三条在途请求的有界工作池，抢不到位置直接降级，不积压下一轮。窗口只是本地检查和网络超时约束，不承诺硬实时终止远端请求。迟到响应独立结算用量，已结束的控制对象和下一轮不再变化；普通trace（运行记录）另列Jev和DeepSeek分类流水、发送前预留token及是否收到完整响应，迟到或普通记录装不下时使用`news_triage_settlement`关联原运行编号，不写标题或提问。用户缩小单条记录容量时允许截短调用明细，保留各供应商已知token、未知用量次数和省略数，不使整条研究记录丢失。

先按原选择器固定各公司、各类别的证据位置与条数，再只在目标类别内稳定提升high且相关性为primary/mentioned的记录。若换入长标题超出该类别原序列化长度，改为只重排原成员。补充原始值、修复反馈预留和最终裁剪后再次比较上下文，非目标资料、位置或条数不符即整体恢复原上下文。原始资料包、完整证据和E编号均保留；不向回答注入标签或分类解释。

#### 固定资料配对验收

[重放工具](../src/trading_companion/news_triage_sorting_replay.py)提供固定资料包及散列清单、平衡开关顺序、真实已核验理解执行器接入点和逐次用量记录。资料包保存核验后请求、目录、日期、公司数据响应及每日价格请求/响应，由同一产品流程重新生成证据和交易计划；不调用意图模型或新资料源。JSON只接受封闭类型清单，不执行包中代码。

消息#579方案及#580补充已获批准。固定30组全部来自原三批150家，名单与理由写在[采集脚本](../scripts/freeze_news_triage_sorting.py)：12组单公司（8综合、2仅新闻、2仅公告）、6组含财务/技术的单公司决策、8组多公司（两家、三家各4）、4组容量边界（单、多公司各2）。综合与多公司都带财务和技术；决策明确未来20个交易日的参考计划；容量组要求日线、周线及五类指标，用真实资料逼近边界，未触边必须如实报告。固定15组先开、15组先关，各运行一次，共60轮，不补跑或换包；保留原有受控重试和一次内容修复，所有尝试均计数。

```powershell

.\.venv\Scripts\python.exe -X utf8 -B scripts/freeze_news_triage_sorting.py
# 以下真实采集只由Claude执行，目录必须是可用的本地证券快照。
.\.venv\Scripts\python.exe -X utf8 -B scripts/freeze_news_triage_sorting.py --live --max-source-requests 256 --directory <证券目录.json> --output .agentbus/tmp/sorting-freeze
# 只验证既有30包并输出计划，无模型或资料调用。
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_news_triage_sorting.py --manifest <冻结清单.json>
```

### 定义与身份依据

[news_triage_product.py](../src/trading_companion/news_triage_product.py) 定义独立任务 `news-triage-product-v2` 和规则 `news-triage-product-rules-v5`。本次六条标注规则及三题定义摘要与v3/v4完全相同，版本升级登记三题批量协议、固定组合政策及诊断报告。Jev、DeepSeek、人工表旁的 `task.json` 使用同一份定义或其中负责题目的子集：

| 题目 | 标签 | 约束 |
| --- | --- | --- |
| 相关性 relevance | primary / mentioned / unrelated | 公司主体、顺带提及或行业多主体、明确错配；拿不准不能判无关。 |
| 标题倾向 tone | positive / neutral / negative | 只看归于目标公司的措辞；无关必须中性；目标公司涨跌不到1%中性，其余行情与资金相反时按股价方向。 |
| 重要性 importance | high / ordinary / unknown | 公司自身业绩、重大重组/停复牌、公司本身立案或大额处罚等可重要；下述常规事项一般；其他缺少主体或关键信息的情况用 unknown。 |

另有 `unresolved` 表示明确弃答或外层未解决状态。它与重要性 `unknown` 不同。DeepSeek 可逐题返回 `unresolved`，没有概率字段；Jev 的接口仍返回真实三选一及原始概率，程序不会编造一个“弃答概率”，需要复核又未得到可用结论时由外层标为未解决。标签不证明事实，不预测股价，不计算影响幅度，负面不等于重要，事件类别也不能代替重要性。

用户于2026-11-10确认以下六条规则。共享的 `POLICY_RULES`（按编号列出的统一标注约定）进入每道题的说明，人工和两家模型相同；未增加在模型返回后自动改标签的逻辑。

1. 标题看不出具体议题的董事会、股东会决议公告，重要性为 `ordinary`。
2. 没写金额的担保、投资、增资、项目进展等常规公告，重要性为 `ordinary`；明确写明重大重组、停复牌、立案、重要处罚、公司自身业绩披露等时，仍按重要事项判断。
3. 目标公司行情涨跌幅的绝对值不到1%，倾向为 `neutral`；恰好1%不适用。不要把标题中指数或其他公司的小幅波动套给目标公司。
4. 分行或子公司的小额罚款，重要性为 `ordinary`；公司本身被立案或大额处罚才算重要。不另设未经约定的数值门槛。
5. 以行业对比、排名为主体的标题中提到的业绩，重要性为 `ordinary`；业绩类 `high` 留给公司自身业绩披露。
6. 行情方向与资金流向相反时，倾向按目标公司的股价方向；规则3的小幅波动中性优先。

其余相关性、倾向和重要性判断保持独立。比如只写“关联交易公告”而缺少交易内容，或未具名主体不能可靠确认，并不会因为规则2而自动变成一般事项。人工修改适用题的依据写明“按规则N”；迁移工具不会执行这些重新标注操作。

身份预检只使用受信本地证券目录的简称和别名，不联网刷新，不让模型补全称。输出固定依据：

- `issuer_verified`：来自已核验代码与市场的东方财富公告，或代码与机构编号的巨潮公告。没有公司名也不能因此判无关；此标志不是“公告事实已证实”。
- 名称命中、独立名称依据、证券代码语境、纯数字命中；数字前后必须没有其他数字，带错市场也要复核。
- 同名词处于协会、商会、商行、园区、学校、研究院等更长主体中的怀疑；公司与协会合作时保留公司的独立名称依据。
- 信托/产品/项目等编号碰撞、明确其他证券代码、多家本地证券、行业整体标题。名称与编号提示均不直接充当人工标签。

这套启发式分组可能把不同事件合并，不能保证理解全部语义。代价是可用样本减少。两个标注者必须查看组内原文及组间关系；一般应修正规则并重新准备，不能直接改CSV原始资料或机械填 `grouping_reviewed=yes`。本批用户明确接受现状的例外及局限见下文；不据此免除以后批次的分组复核。

主切分改为[按公司分组分层](../src/trading_companion/news_triage_product_split.py)，不看日期先后或人工/模型答案。同一公司的全部事件只进一边，跨公司同文先把关联公司绑定成一个分配单元。固定种子、64 次初始分配和 512 次局部调整，在来源与板块比例合格的候选中优先平衡公司数和板块，再减少来源偏差；这是有界启发式搜索，不宣称数学最优。如果绑定后搜索仍无法达到平衡，整组排除跨公司同文并明确记录原因和数量，再尝试分配，不拆开同一文章的不同公司变体。若仍失衡，拒绝生成盲标表。

对最终实际选题，新闻/公告比例、具体来源比例、按公司和按标题统计的板块比例，各类别两边差异都不得超过固定的 **15 个百分点**。检查失败返回 `imbalanced`、退出 1，不创建输出目录和盲标表；评估读取数据时再次核对公司、全部事件组分配及比例。日期保留供分析，不决定封存集组成。

每边先按标题散列、证券、日期从**全部**候选抽 130 条自然样本，包括其中的难题；再从剩余真实候选选最多 70 条额外难例。不能先剔除难题让自然样本变容易。难例提示固定为身份不足/碰撞、编号碰撞、多主体/行业、否认传闻、混合或不确定措辞、重要性模糊等，只是选题提示，仍待人工核对。报告每类提示数量，包括零；每类未单独约定配额，不把提示数当人工标签数。

| 题目 | 固定取值方式 |
| --- | --- |
| relevance | 沿用Jev；DeepSeek只作独立诊断，不替代Jev失败。 |
| tone | 两边均有有效标签且相同才输出该标签；不同、失败、未运行或弃答均为unresolved。 |
| importance | 任一边有有效high就为high；否则两边有效且一致取一致值，有效但不同取unknown；没有有效high且任一边缺有效标签则为unresolved。 |

合成的倾向和重要性没有伪造置信度或概率；相关性保留Jev原始值。正常标签分歧引起的倾向弃答属于政策结果，整体报告可为completed；传输失败、协议问题、模型主动弃答、预算耗尽或未运行仍显式记录，报告为partial，不能把两边失败伪装成一致，也不能通过填unknown抬高覆盖率。单侧有效high仍可在另一侧失败时保留，其他有效题也保留。每题的两方来源、状态、原因和调用ID均可追溯。

组合组最坏调用数仍为标题数加批次数。每批共享“标题数+1”次/90秒/24,000已观测token预算；与分工组混选时，两组独立预算、独立真实调用，总最坏次数为两组之和，不复用另一组答案。全局调用上限、用量未知停止、不重试及标题全部保留策略照旧。报告中的 `components` 是同一组实际调用的Jev和DeepSeek各自三题成绩；另列有效分歧数和合成原因，不增加模型请求，费用只在该组唯一调用流水统计一次。合成成绩和两方诊断都保持完整标题分母，原有门槛直接应用于合成成绩。

### 1. 用户能做什么

“消息收件箱”打开时只查看本机已保存标题，默认未读，每页最多20条；可切全部、按完整代码筛选、手动刷新、标为已读及确认清空。点击原链接不会隐式标为已读。标题按普通文本显示，来源链接只接受固定规范形式并安全打开。

只有“检查自选消息”“检查下一批”才发起一批公开来源读取，继续需要再次点击，不自动遍历50只自选。页面固定显示“有限检查，非全量监控”：来源只取最近30天每源最多5条，可能漏掉密集发布、离线期间和列表之外的信息。“本机暂无未读消息”不能解释为没有新闻；“新发现”也不等于刚刚发表。

短时间内连续检查，来源可能限制请求，届时会显示为取不到，请稍后再查。不自动重试、换源或追加请求来补足结果，原有批次期限和请求预算不变。

`start.cmd` 正常模式默认用 `data\personal_memory.sqlite3` 开启；可用 `--personal-memory-db PATH` 改路径、`--no-personal-memory` 仅关个人库，保留聊天及研判回顾，或 `--no-memory` 全关。两个禁用标志优先于路径、不受参数顺序影响；关闭功能不打开或迁移个人库，不删除已有文件。直接运行服务仍需显式个人库路径。启动脚本在 demo、synthetic 模式自动省略隐式个人库默认值，显式个人库路径仍按原规则校验。demo、synthetic、网页 Dev Mode 不读写真实个人库，不构造该功能的真实来源客户端。面板独立于研究会话，不消耗问题、模型、分析或付费额度。重要性判断、重要提醒、后台定时、弹窗和推送均未实现。

### 2. 个人库 v3 与严格升级

个人库格式为 `personal-memory-store-v3`，与聊天库、证据快照库分离。正常模式打开旧v1/v2时，在同一次事务（全部成功才保存的一组操作）中核验完整旧结构、对象和全部旧行，补齐必要偏好表，再建立消息、已见标识和逐股逐源状态，最后设v3并复核。原自选/偏好值、顺序、时间和修改标识保留；陌生版本、额外对象、坏数据拒绝，不覆盖重建。升级后旧程序不能打开此库；关闭和开发路径不触发迁移。

每次加入自选生成一个随机 `generation`，即本次加入的身份标识，放在新的来源状态表中，不改变原自选公开字段。新浪新闻、东财公告独立保存 `revision` 修改标识、是否建立基线、上次成功和尝试时间、固定状态/错误码、跳过数、未读清理累计数与时间。提交结果时在事务内重读自选、generation和来源revision，防止删除重加、清空后迟到写回或旧检查覆盖新水位。

消息只保存核验过的公共字段：完整证券、保存名称、固定来源、规范原链接/文档标识、原发表日期与精度、来源提供的时刻、首次发现时间、来源取数时间、发现途径、基线标签和已读时间。不存问题、回答、持仓、账号或原始响应正文。日期精度保持日期，不补时分，不把发现时间当发表时间。

消息身份由“证券＋来源＋规范文档标识/链接＋发表日期”确定。相同文档改标题不生成第二个未读、不重置阅读状态；相同标题的不同文档或日期分别保留。并发重复导入保留原首次发现和已读状态。

### 3. 基线、水位与有界保留

每股每源分别建立初次基线和推进完整成功水位；水位只是成功检查时间，不代表已经完整覆盖到该时刻。有效空响应可以成功；部分条目核验失败时保存其余有效标题，显示部分失败与跳过数，保留原完整成功水位。请求失败、超时、取消、未执行、容量或存储失败不推进。每次重新看固定30天快照并去重，不仅按上次水位过滤，避免漏掉同日或迟到出现的标题。

新浪个股列表中未提及该公司、不在查询日期窗口内，或链接格式正常但不在原保存白名单内的合格标题属于正常筛选，不计核验失败。仅收件箱窄读取入口先核标题格式、链接和时间戳，再将正常筛选计入 `filtered_count`。格式判断接受HTTP和HTTPS，要求有效新浪域或子域、无用户信息，路径非空且可打印，完整链接及标题各最多600字符；新浪HTTP研报、移动站/快讯站等不支持的形式计为 `news_link_form_unsupported`，仅过滤，不访问、跟随、改写协议或保存。可保存链接仍限原HTTPS白名单，前端链接校验不变。其他协议、非新浪域、坏格式、坏链接和无效时间戳仍计 `skipped_count`，使本次部分失败且不推进完整成功水位。全部条目正常筛除时可返回成功空结果并建立基线，不宣称来源没有新闻。普通研究的原链接白名单、`skipped_count`、覆盖率和返回结构不变。

`filtered_count` 为本批 `results` 每源回执的必填整数0–50，页面显示说明而不作失败；它只保留在当前回执及有界重放缓存，不进入逐源状态表或本机列表DTO，不因刷新或重启继续显示。个人库仍为原v3结构，无本次新增迁移。

- 初次手动成功导入标为“初次建立基线”；后来未见过的标题标为“自上次检查以来新发现”。普通研究旁路另标“研究中发现”，不推进手动检查基线和成功水位。
- 每股消息最多500条、最长90天，先清已读旧项；必须清理未读时保留累计数量及时间，页面可见。清理在本机操作中按需执行，没有后台清理任务。
- 已见文档指纹为独立账本，每股最多2000个，只存标识和日期，至少保留来源30天查询窗口所需标识。无法安全腾出容量时显示容量限制，不静默丢标识或推进水位，避免清理后同文档反复成为新未读。
- 移除/清空自选在同一事务删除对应消息、已见标识和两源状态；重新加入从新基线开始。确认“清空消息收件箱”保留自选、持仓偏好和聊天，删除消息/已见并重置来源状态、轮换generation；请求核对集合修改标识，跨页面变化后先刷新再确认。删除偏好或聊天各自独立。

### 4. 固定来源和实际请求预算

`watchlist_news_sources.py` 负责串行来源读取，固定新浪新闻列表 `sina_company_news` 与东方财富公告 `eastmoney_announcements`。不继承研究的可选来源；巨潮需要目录和查询两次请求，不符合每源一次预算。复用现有证券、页面、发表时间、链接及结构核验，不抓正文、PDF、行情或财务，不调用标题分类或回答模型。

| 限制 | 执行方式 |
| --- | --- |
| 每批最多5股/10次实际HTTP尝试/50条标题 | 服务端自选有序快照；每股每源最多一次，失败也消耗，不重试、不跳转、不换源、不翻页 |
| 最近30天/每源最多5条 | 固定 `ResearchDataRequest` 条件，复用原适配器核验 |
| 实际开始间隔至少1秒 | 读取器实例保留跨相邻批次的上次实际开始时间，等待期间检查取消及期限 |
| 每批20秒/每请求最多6秒 | 使用单调时钟的协作检查，单次超时受批次剩余时间约束；不能保证强制中断底层阻塞调用 |
| 每响应512000字节/全批5120000字节 | 十进制字节；声明长度与实际流读取双重检查，超限停止该源 |
| 与普通研究共用最多3个来源槽位 | `CollectionExecutor.run_inline` 在当前线程借原许可，真实同步调用及客户端清理结束后在 `finally` 释放，不套普通采集Future（可能提前返回的异步结果） |

专用传输在实际发送前重核固定GET端点、证券/来源、严格参数、每对一次及批次额度；等待请求间隔后、真正发送和计数前调用 `before_request(instrument_id, source)`，有界重核自选generation/快照身份，回调前后都检查取消。身份已失效则置取消，不计未发出的尝试或来源位置；不在每个响应块读取数据库。随后重算剩余超时，才扣实际尝试。响应和专用客户端均在真实路径关闭。普通 `collect_many` 仍最多三股，不扩大其额度。

读取方法为 `WatchlistNewsSourceReader.read_watchlist_sources(requests, *, cancel, deadline, on_source, start_source=0, before_request=None)`，同步逐源回调核验证据及状态；`start_source=1` 仅让首股从公告继续。返回实际请求/字节数、已消耗来源对数及停止原因。发出HTTP后才取消/截止仍消耗该来源对，下一批不能隐式重试；等待许可/间隔时尚未发出的来源保留待检查位置。

### 5. 检查、取消、幂等与游标

服务实例最多一个实际检查在途，无后台队列。异步HTTP处理器只等待一个同步工作器；断连、服务关闭或页面停止等待传入线程安全取消信号。槽位直到工作器真实收尾才释放，不能因为浏览器已不等而启动下一批。已提交部分保留，取消不撤销已有保存。

取消与本地提交使用同一个控制锁决定先后：取消先发生则阻止提交；先完成的来源保留。每源发送前、保存前和返回前核对取消与自选身份。同一服务处理移除/清空自选或清空收件箱时立即使在途gate失效，发送前身份回调也能发现其他页面或进程造成的变化，阻止后续来源请求。手动单源本机提交最多200毫秒协作预算并受整批剩余时间约束；SQLite忙等待、进度回调及提交前检查限制本地工作，但操作系统磁盘阻塞无法硬停止，不能声称绝对200毫秒或20秒墙钟上限。

消息列表游标与检查批次游标独立。检查游标只保存自选快照身份及下一“股票—来源”位置；已执行失败来源计入进度，未执行保留。自选集合变化使旧游标失效，提示重新开始。每批返回成功、失败、未检查和剩余进度，不把未执行伪装成功。

列表按首次发现时间倒序；相同发现时间内按发表日期、实际发表时刻、消息标识依次倒序。同一发表日期内有明确时刻的排在仅日期项之前；跨时区时刻统一UTC微秒排序，日期项不补造时分，原字段保持不变。SQL有界取最多21项，列表游标携带同一组排序字段，避免翻页重复或漏项。旧列表游标缺少新排序字段会明确失效，刷新后从首页重新取；检查批次游标不受影响。

每次检查使用独立请求编号；同编号和原游标只返回有界原结果，不重新联网。编号与不同游标组合返回409冲突，忙碌明确拒绝；服务进程保留最近32份回执及最多4096个已接纳编号，回执淘汰后旧编号返回409退役而不重复I/O，到编号上限返回429并明确需重启。这是本机单进程有界账本，重启后重新开始，不是持久任务系统。浏览器等待期限为20秒批次加收尾裕量；响应丢失或写后刷新失败显示“变更未确认，请刷新核对”，保留原编号供用户手动核对，不能换编号自动重试。

### 6. 普通研究的零新增请求旁路

`watchlist_news_sidecar.py` 在正常当前公司研究中读取本轮开始时已在自选的加入标识；资料核验完成、综合回答之前，只复用已经取得的两种固定来源原始公共标题，每股每源最多5条。不借正文、搜索摘录或分类结果补标题，不追加来源、模型或行情请求；不依赖 `--capture-news-titles`，不读临时采集文件。

旁路总共最多200毫秒协作本地预算：开始快照最多50毫秒，合批保存最多150毫秒；不是每股各150毫秒，也不是硬磁盘停止保证。保存失败在API收件箱响应的可选 `sidecar_status` 中告知，只允许 `null`、`inbox_sidecar_saved`、`inbox_sidecar_unavailable`；这是进程内固定状态，重启为null，不新增数据库字段，也不改变研究响应。纯存储 `store.list_inbox` DTO不含该字段，由API附加；页面在保存未确认时提示核对，不据此断言本轮标题已全部写入。原证据、E引用、回答及发布路径保留；旁路在事务提交前调用 `before_commit` 的研究 `checkpoint`，取消使事务回滚，之后仍按原研究取消规则停止。此处是协作检查，不声称旁路具有手动gate同锁边界或能硬中断磁盘阻塞。旁路仍核generation/revision、去重与容量，不推进手动完整成功水位。

历史研究、重放、纯解释、开发/合成路径不触发。未开启个人库时，不增加数据库访问、额外墙钟读取或研究上下文内容。自选、收件箱和持仓不自动进入模型、聊天摘要、标题调试文件或运行记录正文。标题分类排序和重要提醒没有因本模块启用。

### 7. 本机接口与页面隔离

响应版本为 `personal-memory-notifications-v1`；API收件箱DTO可额外附带上述内存 `sidecar_status`，存储层DTO不含此字段。无需研究会话令牌，沿用本机同源/Host保护；不是公网账户体系。请求拒绝任意来源、URL、代码列表、文件路径及额外字段。

| 接口 | 输入和行为 |
| --- | --- |
| `GET /v1/personal/inbox` | `unread_only` 默认true，可选完整 `instrument_id` 与列表 `cursor`；每页20条，只读本机，返回未读总数、最多100条逐源状态和清理告知 |
| `POST /v1/personal/inbox/check` | 仅请求编号 `request_id` 和可选检查 `cursor`，明确执行一批 |
| `PATCH /v1/personal/inbox/{message_id}` | 仅标为已读，严格请求体 `{read:true}`，幂等 |
| `DELETE /v1/personal/inbox` | 网页确认后以 `If-Match` 传64位集合修改标识，保留自选/偏好/聊天 |

前端 `MessageInbox.tsx` 展示、`inboxMessages.ts` 严格解析，controller分别维护列表、检查及写入状态。初始化、打开面板、本机刷新和翻页只有本机GET；切模式、禁用、清空、移除时拒绝迟到响应。跨页面刷新或下次请求核对，不加后台轮询、跨标签页通知或浏览器第二份持久消息。

本模块同时将研判回顾的收益风险比显示为十进制四舍五入后的固定两位，例如 `2.000000 → 2.00 倍`、`1.485714 → 1.49 倍`；原存储、响应、图表数值和一般研究卡保持原口径。窄屏入口可达性单独验证，不能据此宣称修复已有整体侧栏布局限制。

### 8. 规则、验证与提交边界

规则 `personal-memory-notifications-v1` 以完整 `personal-memory-review-v1` 为唯一父版，父摘要为 `8519d1a39c79fdd5657dd2507e5cb8c9d7d01070e7142993d583d93707aff5ca`；不改旧题库、历史预期、封存/付费评估锁，不登记重要提醒规则。代码身份登记不代表模型语言质量或真实来源已经验收。

Codex使用临时库、固定目录、假时钟和HTTP替身验证迁移/回滚、身份竞态、基线/部分失败、水位、日期精度、去重已读、保留/容量、两类游标、请求编号重放、实际来源上限和共享槽位、取消真实收尾、旁路零新增请求、禁用/开发隔离及页面解析。正式门禁为 `verify.py python`、`web`、`bundle`，实际结果在审核请求记录。
