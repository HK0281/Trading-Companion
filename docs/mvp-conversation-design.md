# MVP 会话收口：窗口澄清、相对日期与历史日线刷新

本模块只扩展已有研究条件的有限修改，不是通用聊天记忆，也不授予模型下单权限。

## 1. 模糊窗口修改

已验证研究包含 SMA3、SMA4、RSI2 时，用户说“改成5日”，应用不能自行挑第一条指标：

1. `window_edit_candidates()` 检查整句并生成候选，不调用模型或行情。
2. `ResearchSession` 保存 `PendingIndicatorEdit`：原完整请求、证券身份、目标窗口、候选、创建时间、可信数据配置。
3. 返回 `indicator_edit_ambiguous`，状态为 `awaiting_indicator`，列出用户可复制的原指标标签。
4. 用户只回复“SMA3”时，`resume_indicator_edit()` 重查原基准、当前目录、来源配置及15分钟时效。
5. 校验通过后恢复原来的“改成5日”目标，消费待澄清请求，创建新 request ID 并重新分析一次。

候选唯一时直接执行；MACD 无单独 window，不猜 fast/slow/signal。泛称“均线”只列原组合中的 SMA/EMA。无待澄清请求的短指标不会启动新研究；附加股票、日期等子句不被静默忽略。用户也可重述完整、明确的一项指标修改，替代待澄清修改。

身份澄清和指标澄清互斥。有效回复、取消、清空、新问题、开始新研究、过期或基准失效都会消费或清除待澄清修改。无效短答不延长原请求时效，也不延长原研究基准15分钟的时效。

## 2. 相对日期修改

“改成最近一个月”“把日期改成最近30天”复用 `research_intent._dates()` 的现有算法，而不是让模型换算日期：

- 截止上海前一自然日，包含首尾日期。
- 一周7天、一月30天、一年365天；总区间最多366自然日。
- 股票、指标和数据来源不变，产生新请求重新计算。
- 今天、未来、交易日口径、复合条件不猜，要求用户澄清。

标记 `dates:relative_update`；月/年同时标记 `relative_unit:30_days_per_month_365_per_year`。算法口径和明确日期会进入可见消息。

## 3. 有限整句刷新

“看最新的”“更新到最新”“刷新行情”等完整命令，只把原自然日区间平移到上海前一自然日，保留股票、指标、来源及区间长度。

这不是实时行情，也不保证前一自然日是交易日。合成样例入口使用应用配置的固定参考日期，不查询真实市场。若日期没有变化，明确刷新仍允许新分析，但消息必须说明“区间未变化，重新计算，不代表发现了新行情”。

标记 `dates:refresh_latest_previous_day`；日期不变额外标记 `refresh:same_dates`。不静默换源、不重复使用旧结果。

## 4. 数据流与取消隔离

`用户整句 → 有限路由/解析 → 可信会话基准校验 → 合并一类条件 → 新请求 → 模型工具提议严格比对 → 确定性计算 → 事实检查 → 会话保存`

待澄清状态通过现有 `_fork_for_turn()` / `_publish_turn()` 暂存与发布。真正开始新研究前立即消费父会话旧基准和 pending；取消、超时或迟到模型返回不能重新发布待澄清请求或旧研究基准。

## 5. 主要接口与验证

- `research_edit.py`：整句窗口候选、显式标签和短答解析。
- `research_update.py`：相对日期、刷新命令与条件合并。
- `research_session.py`：待澄清状态、可信基准、时效和身份检查。
- `agent.py`：路由和现有执行链整合，不绕过提议检查或 TurnControl。
- `tests/test_mvp_conversation.py`：离线覆盖窗口恢复、额外子句、身份与配置变化、取消和迟到隔离、日期口径、固定样例刷新及模型/分析调用预算；测试禁止真实 HTTP 和密钥读取。
