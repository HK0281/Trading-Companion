# 自然单股研究：历史数据与未来展望分开

日期：2026-10-25。本文记录本模块的范围与技术契约；离线测试不等于真实模型的语言质量或预测效果验收。

## 1. 要解决的问题

“分析一下中际旭创”已经包含明确的研究动作和股票名称。用户没有写指标或日期，不代表意图不明确；目录唯一匹配时，应采用已有默认条件开始研究，而不是要求用户先学会参数格式。

“预测一下中际旭创下个月的走势”问的是未来展望，不是请求未来日线。过去将两者都塞进日期区间，容易把正常研究误判成非法未来行情查询。

本模块让模型理解研究目标，程序核实身份和取数范围，再沿用已有只读工具循环与自然语言回答。没有新增预测模型、股票模式训练或产品多Agent辩论。

## 2. 两类范围，分别保存

| 概念 | 表达的问题 | 本轮约束 |
| --- | --- | --- |
| 历史数据窗口 `start_date / as_of_date` | 用哪段已发生的行情作为依据？ | 沿用历史请求校验，不放入未来日期 |
| 研究目标 `objective.kind` | 分析当前情况，还是讨论后续情景？ | `analysis` 或 `outlook` |
| 展望期限 `objective.horizon` | 用户关心多久之后？ | 从原文核验并规范化为“下周”“下个月”“未来30天”等受限表达；未指定时为 `null` |

`ResearchConditions` 中的目标示例：

```json
{"kind":"analysis","horizon":null}
```

```json
{"kind":"outlook","horizon":"下个月"}
```

`objective` 不属于行情工具参数，也不赋予额外工具权限。工作流提示词分别传递已确认的历史请求和研究目标；模型要围绕目标作答，但取数仍必须精确匹配已确认请求。

期限只做受限表达规范化，例如“下月”保存为“下个月”、“接下来30日”保存为“未来30天”，不换算成未来实际日期。“下个月”“未来30天”“未来30个交易日”不等价；当前不支持交易日期限，不能用猜测的未来交易日历替代，更不能把未来日期冒充已取得的行情。

量化期限按天/周/月/年的正整数有限表达校验；“未来半年”可规范化为“未来6个月”。以366个自然日的折算量作容量边界（月按30、年按365；这不是未来日期计算）。超界、冲突、交易日、季度或长期等未支持表达需要澄清，不能截掉不支持的后半句。短线/中线是展望标签，不承诺固定天数。

完整时间条件也必须保留：“下下周”不等于“下周”，“下周五”不等于整周，“下个月底”及“未来30天后”不能被截成已有期限。当前不支持这些修饰时明确请求澄清；即使模型只抽出合法子串，原问题中的本地时间边界检查仍会阻止执行。

## 3. 自然输入和默认条件

- “分析一下中际旭创”“看看平安银行”：按当前单股技术研究处理；名称经目录核实，不要求用户先给代码。
- “预测中际旭创下个月的走势”“看看下周可能怎么走”：明确为条件性展望，历史窗口与展望期限独立。
- 未指定历史日期：沿用上海前一自然日为截止日、含首尾365个自然日的默认窗口。实际最新交易日由数据源返回，不能声称前一天必定开市。
- 未指定指标：沿用默认八项配置：SMA(20)、SMA(60)、EMA(20)、MACD(12,26,9)、RSI(14)、BOLL(20,2)、ATR(14)、量能(20)。
- 用户显式给出的合法历史条件优先；未来历史取数、错误参数或不支持的条件不应被默认值悄悄覆盖。
- 名称确有多义、目录无有效匹配或缺少可安全继承的身份时才澄清；模型不能自己猜证券代码。

“分析”目前只覆盖已接通的历史日线与技术指标。模型不能把一个宽泛动词解释成已经读取新闻、财报、公告或完整基本面；用户明确要求未接通的数据时，应如实说明范围，而不是假装查询过。

## 4. “那下个月呢”如何续接

这类问题没有重复股票名称，可以使用会话中经过确认的条件，但不能仅凭聊天文本或模型记忆猜测。

```text
已确认单股研究
  → 用户输入“那下个月呢”
  → 检查15分钟条件有效期、当前目录、同一身份与来源
  → 保留原历史日期和指标，更新独立objective
  → 创建新的研究请求，重新执行行情与指标研究
  → 以新结果回答下个月的条件性情景
```

继承的是**已核实的研究条件**，不是把保存结果改写成新行情。新回合会取得新的研究ID和证据；即使历史日期未变、供应商返回了相同的日线，也不声称发现了新行情或获得实时价格。

条件超过15分钟、时钟异常、目录失效、身份或来源不再一致时，不能继续隐式继承；需要用户重新明确研究对象。重置、结束会话和明确新问题也不能借旧目标偷偷恢复身份。

这与“查看上次结果”“解释刚才的RSI”不同：后两者在既有受限路径中读取保存快照，不重新取数；“那下个月呢”是新的研究目标，不冒用旧快照作当前分析。若用户要更新历史截止日，应走明确的刷新/日期修改路径，而不是把改变展望期限当成刷新命令。

## 5. 回答与界面

沿用现有 `conversation-answer-v1`，不新增必须由前端理解的展望协议：

1. `answer`：直接回答当前判断，说明关键依据和冲突。
2. `outlook`：围绕用户的期限描述有前提的可能方向或情景。
3. `watch_for`：说明哪些表现会支持或使判断失效。

回答不保证涨跌，不编造未来价格、收益率或概率；现有数字正文和引用检查仍适用。精确指标与价格保留在报告数据中，正文依据和图表浮层可查看相应读数。引用核验只能证明请求绑定与被引用的指标关系，不证明文字推理或预测准确率。

前端继续正文优先；2026-10-30按用户要求将附加区精简为默认显示的互动日线图，正文段落依据、研判卡与价位计划保留，其他附加表格和完整报告入口移除，见[图表设计](chart-workspace-design.md)。历史日期前明确标“历史数据”，避免误认成预测区间。正常首页提供无需日期/指标的研究和“下个月”展望示例；点击只填草稿，明确发送后才研究。离线首页保留固定人工日期，不把其少量样例描述成真实市场能力。回答后不新增固定快捷问题或内部诊断面板。

没有取得行情、记录不足或最终答复未通过检查时，仍提供简短的实际原因，不让模型补写缺失行情，不自动换源，也不把指标清单当成答案。

## 6. 没有改变的边界

- 当前是单股票历史日线研究，不支持多股票比较、选股、新闻/财报研究、实时行情或任意联网。
- 行情来源由服务配置固定，模型和用户输入都不能借展望切换来源。
- 继续使用已有工具白名单、次数/时间/上下文预算、取消和幂等机制；“新目标”不会扩大额度。
- 图表与引用的 `trade_date` 仍为历史证据日期；前端不能为支持“下个月”而放松日期、股票或快照绑定。
- 没有券商账户、下单、撤单或资金管理接口。情景解读不是自动交易授权。
- 继承条件不等于长期记忆，历史过滤也不等于严格point-in-time数据。

## 7. 实现与验证位置

- `src/trading_companion/research_intent.py`：自然研究理解、`ResearchConditions` 与独立目标。
- `src/trading_companion/research_objective.py`：`ResearchObjective`、期限核验和有限规范化；不生成未来行情日期。
- `src/trading_companion/research_context.py`：完整短句展望续接识别，以及独立的工作流目标上下文。
- `src/trading_companion/research_session.py`：已确认条件的有效期、目录复核及同股续接。
- `src/trading_companion/agent.py`：自然输入、会话路径与研究调度。
- `src/trading_companion/research_workflow.py`：分别提供可信历史范围与研究目标，复用有界只读循环。
- `src/trading_companion/workflow_response.py`、`research_response.py`：有依据的三段自然语言答复与引用检查。
- `frontend/src/App.tsx`：正常/离线首页示例和“历史数据”标签；没有修改展示协议。
- `frontend/tests/naturalResearchHome.test.tsx`：两个真实提问形式原样发送、草稿不自动研究、日期标签及离线示例兼容。

后端验收应分别覆盖：默认单股分析、名称歧义、未来期限与历史窗口分离、有效/过期同股续接、重新取数和新证据、错误股票提议、预算/取消，以及不支持工具的边界。前端验收只证明输入与展示行为，不能证明模型确实理解或预测正确。完整验证还需单独使用真实模型和真实行情检查切题性与数据接入；本模块的离线测试不读取真实密钥，也不发送外部请求。

2026-10-25本次前端定向验收：`naturalResearchHome`、`App`、`AppMode`、`presentation`、`conversationResponse`五个测试文件共112项通过；`pnpm exec tsc --noEmit`通过。该记录不包含随后整合的后端全量、打包或真实服务验收，也没有修改模式测试与正文证据协议。

## 8. 最终整合验收

2026-10-25，`scripts/verify.py all`通过：1,393项Python测试、473项前端测试、4个Agent固定场景、90次MVP重复与API演练，零跳过；TypeScript、生产构建、ASGI实际编译资源、干净wheel与依赖检查均通过。测试使用人工行情与脚本模型，没有读取真实密钥或请求真实模型、证券目录与行情；未做浏览器或真实回答质量验收。

补充回归覆盖默认八项指标、100根人工日线、知识查询、可用性检查与三项补算的完整展望链路；“下个月”“未来366天”“未来十二个月”均保留primary/supplement两份完整证据，六次模型调用不超过20,000序列化字符上限。目标提示只在展望路径传递，省去重复指令，不通过丢弃证据或放大容量掩盖溢出。

自然入口的开发CSV也遵守截止日早于参考日；MVP中的未来拒绝场景改为明确未来历史取数区间，避免继续把“明天的条件性展望”误当成非法任务。底层纯计算请求的契约不因此新增未来预测能力。
