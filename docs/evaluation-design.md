## 固定场景 Agent 契约评估

日期：2026-10-20

状态：入口与离线测试已有；用户已回传一次 `complete` 真实模型场景通过，其他场景待实测

### 1. 这一步解决什么

上一版 `explanation_demo.py` 使用脚本模型，只能证明程序可以处理一份预先安排的正确输出，不能证明真实 DeepSeek 会遵循 `indicator-explanation-v1`。

本入口复用现有 Agent，将模型选择与行情选择分开：默认假模型＋固定人工 CSV；显式选择 DeepSeek 后，只有模型请求联网，数据和证券目录仍使用固定人工夹具。先隔离模型协议、工具参数和关系检查问题，不把行情端点故障混进来。

它是小型契约检查，不是完整产品入口、实时行情评估、历史策略回放或语言质量评估。原 `tool_smoke.py` 保持兼容，仍只用于旧固定任务的联通检查。

### 2. 四个独立预期场景

固定区间为2026-09-21至2026-09-25，目录检查参考日为2026-09-26。CSV只有5条人工日线；短周期是为了在小样本中覆盖计算和缺项，不是推荐的交易参数。

| `--case` | 问题与指标 | 预期 Agent 状态 | 报告 / 解读 | 模型调用上限 | 分析次数 |
| --- | --- | --- | --- | --- | --- |
| `complete` | 明确代码；SMA3、EMA3、MACD(2,3,2)、RSI2、BOLL(3,2)、ATR2、VOLUME3 | `completed/research_completed` | `complete/accepted` | 2 | 1 |
| `partial` | 明确代码；SMA3、SMA20、VOLUME3 | `limited/partial_research` | `limited/accepted` | 2 | 1 |
| `natural` | 平安银行；SMA3、RSI2 | `completed/research_completed` | `complete/accepted` | 3 | 1 |
| `clarification` | 平安；SMA3 | `needs_clarification/instrument_needs_clarification` | 无报告 / `not_performed` | 1 | 0 |

`partial`必须保留SMA20缺15条记录，不能补值；`clarification`必须保留平安银行和中国平安两个候选及原日期/指标条件，不能猜股票或取行情。按预期受限或澄清，同样是场景通过。

默认只运行 `complete`。`all`顺序运行四项，最多转发8次模型调用、执行3次分析；第一个失败后，后续标为 `skipped`，不重试。当前阶段流程固定，成功场景还要求调用次数恰好符合表中预期；以后若有意修改流程，也要修改版本与场景预期。

### 3. 数据流与职责

```text
固定场景和人工夹具预检
  → 显式选择 Fake 或 DeepSeek
  → 独立计数包装器
  → 现有明确格式 / 自然语言 Agent
  → 原受控工具、计算、事实报告和关系检查
  → 对照场景预期逐项判定
  → 仅向终端输出 JSON 报告
```

- `EvaluationCase`：冻结的场景输入和预期，不按实际返回结果反推答案。
- `_MeteredModel`：在委托调用前消耗额度，独立记录尝试、转发与阻断次数，核对Agent计数。原执行器继续限制每轮最多一次分析。
- `_grade()`：检查状态、入口、请求股票/区间/来源/指标集合、同轮ID、人工数据标记、5条记录、报告与关系检查结果；另核对收盘价10.4和原精度SMA3参考值。部分结果和澄清有额外断言。
- `run_evaluation()`：运行一次所选场景、遇错停止、汇总结果；不修改主Agent算法、模型提供方或交易权限。

检查通过不要求模型选定唯一的一组论断，也不评判其选择的相关性、覆盖率和解释价值。七类指标的计算已有独立测试；本入口不另造一套计算器，也不以两个参考数值覆盖所有数值正确性。

### 4. 夹具与请求边界

仅允许代码中固定的 `data/sample_daily_bars_synthetic.csv` 和 `data/security_directory_fixture.json`。在读取真实模型配置前，先校验两份文件的SHA256；只容许CRLF/LF换行差异。文件变更或缺失则本地停止，不能静默发送未知内容后仍称其为已知人工样本。

不支持自选路径、行情源、输出文件、重复次数或自动刷新目录。固定历史参考日只用于开发夹具，不授权旧目录用于当前真实行情。这不是通用文件沙箱，也不保证抵御运行时外部修改夹具。

真实模式沿用现有适配器：DeepSeek单请求默认45秒超时、512输出token、关闭thinking。底层适配器不重试；2026-10-30起经产品入口运行的请求可由[共享运行控制器](agent-runtime-design.md#整轮运行控制共享预算取消与迟到结果)对超时或连接错误重试一次，每次转发仍计入评估额度与整轮预算。记录的 `elapsed_ms` 是耗时测量，不是全轮硬截止时间；调用次数上限也不等于货币成本上限或完整token预算。

### 5. 如何运行

在项目根目录的PowerShell中：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -X utf8 -B -m evaluation_tools.agent_evaluation
.\.venv\Scripts\python.exe -X utf8 -B -m evaluation_tools.agent_evaluation --case all
```

这两条命令均离线、不读取模型凭据、不写报告文件。只想运行一个场景时，使用表中的名称。

自行确认模型配置后，显式运行真实模型单场景：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m evaluation_tools.agent_evaluation --provider deepseek --case complete
```

此命令最多转发2次可能计费的模型调用；不请求真实行情或目录。无需在报告中提供密钥。建议先检查这一项的JSON，再决定是否显式运行其余场景，而不是因失败反复重试。

### 6. 如何阅读报告

- `version=agent-contract-evaluation-v1`，`evaluation_scope`明确仅检查固定人工场景契约。
- 顶层和每个场景的 `status=passed` 表示符合预期，不等于研究状态必须为 `completed`。例如 `partial`可以通过，同时 `observed.agent_status=limited`。
- `checks`列出布尔断言；`failed_checks`说明哪些不符合。模型HTTP成功或状态碰巧相同，都不足以通过。
- `summary`区分选中、执行、通过、失败和未运行；跳过的场景不能算通过。夹具或配置失败时，全部未运行。
- `provider_calls_forwarded`是交给适配器的次数，不保证HTTP已发出或一定计费。`token_usage`只加总供应商已报告的字段，缺失保持 `null`，并报告完整用量覆盖了多少次请求；不估算费用。
- 不导出模型原文、工具完整结果、原始消息、凭据或底层异常文本。模型名称和响应状态保留为诊断元数据；未知失败代码归为 `unclassified_failure`。

CLI退出码：全部选中场景通过为0，模型配置错误为2，场景失败或夹具错误为1；非法CLI参数由参数解析器退出2。不自动保存报告或创建评估目录。

### 固定题目与判定

配套manifest（记录版本、文件摘要和固定阈值的清单）保存按LF换行计算的 SHA-256。读取时核对摘要、20题数量、各组5题、18题目标和调用上限；不支持临时选题、自动重试整套或按结果删难题。未来修改题目必须显式升级/记录语料版本，不能伪装同一份评估。

`formed_two_reasons` 和 `two_reason_comparison_rate` 另按本次公开结果至少两条理由计数，仍以20为分母。它只是理由数量对照，不是重放旧版全部检查；旧2/20真实报告保留，不按新规则改写。

买入/卖出是用户问题类型，**不是标准答案**。模型可以给出不同评级，只要回答通过既有程序检查。形成率只表示结构化结论可用，不证明结论相关性、推理或投资效果，必须人工复核。

### 上下文题与调用上限

D05、D20标为 `requires_batch_b=true`，先通过正式聊天入口研究中芯国际的SMA3，再分别问“那现在能买吗”和“那止损位怎么设置，给个参考计划”。这两题不从主分母删除；另外分别统计依赖B和不依赖B的形成率。准备步骤必须成功且对象正确，才能计入上下文题的有效结论。

每题新建独立会话，准备步骤和目标问题共享**每题最多6次**的计量器；全套共享**最多120次**的计量器，两者都在转发模型请求前扣减。准备步骤、理解、工具规划、回答和最多一次回答修正全部计费；没有外层再次尝试。主问题通常1次理解＋1次回答＋最多1次修正；加上两道准备题，全套典型的宽松预算估算是66次，绝对上限仍为120。工具不会因为达不到18题而多跑一次。

额度用完后仍输出全部20行，后续题标记not_run；准备题耗尽额度时，目标问题也明确未运行。失败的已转发请求照常计数；局部额度拦截另在逐题accounting中记录。

| 模式 | 模型 | 资料 | 用途 |
| --- | --- | --- | --- |
| offline，默认 | 明确的固定人工脚本 | 人工证券目录、100条人工日线和人工公司传输响应 | 核对正式路由、采集、计算、校验、预算及统计；不代表模型质量 |

`live`预览只读取现有目录，不自动刷新。目录须有效、近期、非人工夹具，题目名称或目录认可别名须唯一解析到预设代码；允许规范名称带交易所后缀，禁止凭模型记忆补身份。运行前重新核对目录摘要，期间变化则停止对应场景。目录文件不提交。

### 输出与指标定义

`metrics.output_truncations` 单独统计 `total`、`first_draft`、`repair_draft`、`affected_questions`，并保存 `known_subtotals` 和 `unknown_questions`。已知 length 不再记为普通 JSON 结构解析失败；小标点修复仍记原始结构失败和本地恢复。旧数据缺少版本/计数时总数与拆分为 null（Markdown 显示“未知”），已知部分单列，不补零。实现指纹覆盖模型配置、传输、回答、数字检查和技术工作流的源文件，而非只散列评估器本身。

JSON报告保留20题、准备步骤状态、当前轮路由和结果码、完整公开回答与证据、quality（程序生成的回答检查状态）、逐题调用用量、价格估算和复核项。仅保存正式发布的内容，不导出拒绝草稿、修正提示、密钥、会话token或原始异常。普通trace仍只有运行元数据；评估报告含这些固定问题和已发布回答，因此是单独的显式产物。

- 形成率、到达回答阶段比率、partial/fallback率、整轮limited率均以20题为分母。到达回答阶段表示目标轮产生v3 quality或已转发回答请求；不能只在有资料的题中计算。各组和B依赖组另列分母。
- 生成段数表示各回答草稿中解析出的narratives个数，包含修正草稿；无法解析时计未知，不当成0段。保留段数、生成/保留/删除句数来自正式quality。各字段缺失另报未知计数，生成与保留数不要求相减等于删除数。
- 删除率为累计删除句数/累计生成句数；`repair_success_rate` 保留原含义，与 `repair_all_passed_rate` 同为修正后quality=complete/实际修正题数。另列 `repair_rating_restored_rate`（至少一股首稿无有效评级、修正后有）和 `repair_content_added_rate`（按证券/字段/位置实际补回模型内容）；三者可以重叠，分母均为实际修正题数，未修正为null。旧quality缺少后两字段时记录unknown，不把未知当失败。评级本来就有效但补了理由，不算评级恢复。
- **结构解析失败率单列**：正式quality中的structure_failures总数/目标轮实际转发的回答请求数；同题两次草稿都可失败。回答请求在传输阶段失败也保留在分母中，传输/整轮结果码另列；没有quality时标记未知。另报受结构问题影响的题数/20，避免被调用数量掩盖。首次失败后修正成功仍计入结构失败次数。
- 本地结构完整/部分恢复另外记录 `local_structure_recoveries`（含部分恢复）和 `partial_structure_recoveries`；`unrecovered_structure_failures` 为未能本地恢复的原始失败数。部分恢复仍可能缺字段，不意味着最终回答全部通过；原始解析失败分子不减去恢复数，本地恢复不额外消耗模型请求。
- 最终原因码与逐草稿拒绝原因分别统计。修正后清除的最终原因不能让首次结构/数值失败从报告中消失。
- A3新增 `numeric_bindings`，使用 `source-bindings-v1` 的程序词元计数：`numeric_tokens`、`bound_numbers`、`bound_matched/bound_rejected`、`unbound_matched/unbound_rejected/unbound_ambiguous`。`coverage=bound_numbers/numeric_tokens`，`bound_pass_rate=bound_matched/bound_numbers`；分母为0时比率为null。计数涵盖实际检查的两稿，同一句可有多词元，不代表最终保留句数或语义正确率。`unknown_questions` 单列缺新版标记的quality数量；旧版缺字段不填成已知0，汇总比率仅描述可得计数，需连同未知数量阅读。没有quality的题继续由原质量未知计数反映。
- 端到端延迟包括每题准备步骤、目标问题、会话及清理；另列目标轮延迟。模型延迟包括所有转发请求与失败请求。中位数按统计中位数，P95用排序后的最近秩，未运行无耗时样本。人工来源含模拟等待，不能用离线延迟声称真实来源性能。
- 总调用、输入/输出/总tokens只累加供应商实际报告值，缺失不填0。费用复用 `evaluation-prices-v1`、价格摘要、核对日期和模型身份要求；只报告可核对的已知小计，不能算全时总费用为null。输入缓存/实际账单差异沿用原价格模块的限制。

`--report-dir`下新建唯一目录，输出 `report.json`、`report.md` 与 `manual-review.jsonl`。人工逐题填写回应问题的相关性、证据支持、措辞和条件可理解性，默认都是null，不能自动当作人工通过。报告保留失败和未运行题的复核行。`--trace-dir`可保留唯一运行目录下的逐题trace；省略则临时trace在汇总后清理。

`--diagnostics-dir` 默认关闭，只允许实际路径在项目 `.agentbus/tmp/`。显式开启后新建唯一 `diagnostics-*` 子目录，写最多4000条、8 MB的 `records.jsonl`。内容包含完整草稿、实际反馈、拒绝句、字段路径、数字词元及至多三个候选、差值/当前误差/拒绝原因、每稿和最终接收状态。A3另存 `model_context` 最终实际供应快照及 `plan_purpose_corrected` 的原/新计划身份；诊断复用实际核对过程。文件包含原文，仅用于本地调查，不进入正式报告、产品或trace。报告只有路径与计数/完整性摘要。越界路径在运行前拒绝；写失败或截断令整套状态为failed、`evaluation_diagnostics_incomplete`，不能声称诊断齐全。目录不覆盖旧产物，预览只校验而不落盘。

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_technical_answers.py --plan-only
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_decision_answers.py --report-dir .agentbus/tmp/decision-regression
```

默认 `offline`：真实聊天服务、路由、取数流程、指标计算、正文核对、会话发布全部照常执行，只替换模型和资料来源。每轮使用独立的有限模型脚本；不允许多余调用或跳过预定阶段。技术资料独立使用固定的 2026-10-29 参考日期和 400 条人工工作日日线，证券目录时间也同步固定；这些日期不是交易所日历。不会修改原 20 题资料，不加载密钥或 `.env`，外网有离线阻断。部分周线指标仍可能受研究区间限制而不可用，缺项保持缺项，不伪造可用读数。

### 判定与范围审计

主分母固定 10，按目标轮计算正文形成；准备轮的对象和成功状态须支持后续会话。准备轮质量另列，所有 14 轮都检查范围。整体机械通过要求执行/记录完整、至少 9/10 形成正文、范围违规为 0 且范围检查无未知、买卖题有有效评级/方向和参考计划状态、所有必需指标及明确日期检查通过。纯程序事实、空正文、整体失败不算形成正文；合法部分正文可以计入。

取数检查在来源服务入口记账：包装 `ResearchDataService.collect_many`，在转发之前逐证券/领域记录请求，失败尝试同样保留；技术来源工厂另记技术请求。另观察真实采集函数返回的确认指标、实际技术请求及领域。检查器依据题库逐轮预期，检查参数、实际计算请求、全部公开证据和最终展示的分析，不依赖模型自评或最终 coverage 推测取数。

- 严格指标要求参数集合完全匹配，证据与正文不能混入未请求指标或 MA20/MA60。兼容 `SMA3`、`SMA(3)`、`sma(window=3)`、MA 和常见中文名称；原始日线 `volume_shares` 不是滚动 VOLUME 指标。“未计算 ATR”是限制说明，不当作实际使用 ATR。
- 领域限制覆盖准备和追问；技术限定时不读取公司资料、财报、新闻、公告。取数失败也不能算没有调用。技术数据推导的参考计划属于计算，不属于公司领域取数。
- 没有可用的同股 ATR14 计划及其证据依赖时，不能在正文或结构化价位中给出止损/目标价格；允许说明计划不可用，支撑压力不能冒充止损和目标。
- T06/T07 必须有现有规则认可的评级和相符方向。可用参考计划须匹配用途和证据；不可用计划须明确状态、原因码、空数值、空 plan_id。报告按现有网页 `ResearchDecision.tsx` 的原因码说明给出中文解释，例如 `risk_atr_not_requested` 对应“本次未计算所需的波动指标。”；不会要求模型凭空补 ATR 或为不可用计划编价格。

反例覆盖未引用 MA20 证据、额外指标、实际计算范围漂移、无计划止损/目标（含中文数值）、失败新闻请求、准备轮违规、错误证券、空正文、评级方向冲突、无原因码的不可用计划，以及伪造可用状态但缺计划证据。缺参数、缺来源台账或缺采集观察为未知，不作通过。

这些检查不证明任意中文改写、指标之间的语义关系或投资结论正确。新出现的别名和不带标签的隐含指标仍需人工复核，因此不能把机械 9/10 称作经过质量验证。

### 质量计数和报告

每题分别输出准备轮、目标轮和整题汇总：正文形成、范围问题、生成/删除句数、删句率、固定失败码次数、截断、调用次数及费用。全套也按准备、目标、全部轮次分别汇总，不用逐题百分比的平均值代替总句数比。

删句率沿用产品现有计量：被实际检查的两稿均计入生成句数，driver 标题也计句；`deleted_sentences / generated_sentences`。正文组装中的去重移除也计入删除数，并另列 `deduplicated_drivers`、`deduplicated_sentences`，不伪装成数字错误。两稿合并会保留首稿通过的内容，生成句数不等于最终正文句数。缺质量计数时汇总比率为未知，同时提供可得小计和未知轮数。

`answer-issues-v1` 记录每稿检查意见的完整错误码次数，不只记录首个错误。`first_draft`、`repair_draft` 分别计数，`all_drafts` 为两者合计，不能把三行再次相加。固定单列：

- `answer_stance_mismatch`：正文或研判立场与评级不符。
- `answer_numeric_unmatched`：数字未匹配到允许证据。
- `answer_binding_invalid`：模型数字来源标注无效。

次数单位为“每稿产生的检查意见条数”，不是受影响题数或数字词元数；同稿可有多个同码错误，修复成功仍保留首稿次数。最终残留原因单列，沿用产品最多 20 条原因的限制，不把它冒充完整逐稿计数。版本缺失、草稿统计缺失或截断统计缺失为未知，不填 0。运行元数据只增加白名单错误码、整数和版本，不加入拒绝原句。

完整错误计数及已知零值存入版本化运行元数据，由评估器读取；普通公开回答不增加零值字段，以保持冻结会话观察的内容指纹。实际发生去重时公开质量记录增加去重计数。指标编辑文件属于规则登记的源码范围，因此同步更新 `intent-rule-baselines-v1.json` 的该文件摘要及源码总摘要；分类/路由规则版本和历史题库不变，旧阈值锁仍因源码总摘要不同而拒绝复用。

成本和 token 用量沿用公共计量与价格模块：准备/目标/失败的实际转发请求都计量；未知价格、用量和供应商模型身份不补成零费用。价格假设只用于预览，不是账单保证。`report-dir` 下新建唯一目录，包含 `report.json`、`report.md`、`manual-review.jsonl`，失败和未运行题仍保留人工复核行，人工评价默认 null。

退出码 0 表示合法预览或完整执行且机械目标通过；1 表示未达目标、执行/记录不完整或运行失败；2 表示参数、题库、目录等配置无效。离线 0 只证明契约。

### 产品小修

v3 提示要求每条 driver 讲不同因素。通过原核对与修复合并后，在同股内按归一正文相同，或非通用标题与非空证据集合相同，保留第一条。仅共用证据的不同因素、相同标题但不同证据、不同股票分别保留。不增加模型调用，不放宽 A3 数字规则，不因重复拒绝整份回答。

归一时保留数值正负号、小数点、百分号及比较符，避免把不同数值的正文误认为相同；按标题和证据集合去重仍是保守近似，不能替代人工语义复核。

指标编辑移除 `indicator_dependency:atr14_for_risk` 时，同时移除尚未被用户明确采用的依赖 ATR14。用户明确指定的 ATR 保留；增加 ATR7 不会把依赖 ATR14 一并变成用户指定。自动移除不增加 ATR 排除标记，后续买卖问题若范围允许可重新加依赖；严格指标范围继续不补 ATR、计划明确不可用。用户明确删除 ATR 的排除约束仍保留。多候选指标选择接续时，证券匹配变化会显示“目录中的证券匹配已变化，请重新明确研究对象。”，不查询。

### 1. 运行与边界

在项目根目录使用已有虚拟环境：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_research_workflows.py
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_research_workflows.py --case C01 --repeat 3
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_research_workflows.py --collection-workers 1 --trace-dir data/traces/evaluation
```

默认执行全部 40 个场景、59 个消息步骤、重复一次。每个场景的新会话保留自己的完整步骤，每次重复重新开始。没有向会话私有字段预先写入名单或待澄清状态。所有消息均通过 `ResearchApiService.message()`，包含准入、目录检查、实际路由、受控执行、结果检查和公开展示。

支持的选项：

| 选项 | 当前含义 |
| --- | --- |
| `--mode offline/live-model/live` | 默认 offline；真实模式必须显式配置，见第 7 节 |
| `--case ID` | 可重复，选择静态语料里的场景；重复 ID、空选择和未知 ID 被拒绝；执行按语料顺序 |
| `--repeat 1/2/3` | 独立重复，不挑选最好一次 |
| `--collection-workers 1/2/3` | 公司和腾讯报价共享同一实际执行器，配置每次采集的宽度 |
| `--model-call-limit N` | offline 默认 `6T`；真实模式必须显式给出且不超过 `6T`；异常仍占额度 |
| `--trace-dir PATH` | 在新运行子目录中保留记录，不覆盖已有运行；不指定则临时收集并删除，结果中路径为 null |
| `--plan-only` | 只校验计划，不读凭据、不构造客户端、不联网 |
| `--report-dir PATH` | 在唯一新子目录导出 report.json、report.md、manual-review.json |

T 是所有选中场景的步骤数乘重复次数，而不是场景数量。完整一次 T=59，默认额度 354；三次 T=177，默认额度 1062。当前完整固定脚本一次实际转发 69 次模型方法，没有真实供应商 HTTP 请求；脚本次数是框架事实，不是模型成本或理解能力。

程序把版本化 JSON 写到标准输出；指定 `--report-dir` 才导出文件，导出文件使用 UTF-8。可重定向输出；PowerShell 5.1 默认重定向编码与 Python 不同，后续程序读取时应明确编码。退出码：全部通过或预览成功 0，场景/框架/写报告失败 1，输入无效 2。真实执行先把计划写到标准错误输出并刷新，再读凭据；标准输出仍只有一份合法 JSON。

计划校验失败时，预览和正式执行返回相同的固定 `code` 与中文 `detail`，说明参数名、合法范围及必要的计算值，不复述路径原文、文件内容、密钥或底层异常。例如：

| 错误码 | 提示内容 |
| --- | --- |
| `evaluation_model_call_limit_out_of_range` | live 默认 44 步时，上限为 `1..264`（6 × 44）；选择子集或重复运行后按实际计划步数重新计算 |
| `evaluation_price_file_invalid` | 说明 prices 文件无法读取或配置无效，提示核查价格结构、单价和核对元数据 |
| `evaluation_live_directory_stale` | 给出目录原始带时区时间戳和当前北京时间日期，说明快照须在当前日期前 0..7 天内，并提示运行 `python -m trading_companion.security_directory_refresh --live` |

模式、重复次数、并发宽度、场景选择、token 假设、提供方、模型和输出目录等也有对应提示；仅最后兜底保留 `evaluation_input_invalid`。过期目录仍被拒绝，预览不会自动刷新；目录刷新命令需显式联网，和计划预览分开执行。

offline 不读取模型环境或 `.env`，不建立真实来源连接。离线模式复用 [verify.py](../scripts/verify.py) 的清洁环境和网络封锁，即使业务捕获了 DNS/连接异常，整次评估仍判失败。模型环境读取另有拦截和计数。仅允许固定数据配置、有限模型脚本和已知参数，不从语料加载任意 URL、文件、类名或代码。

### 2. 语料与独立预期

[research-api-v1.json](../data/evaluation/research-api-v1.json) 是版本化语料。40 个场景覆盖知识、单股、多股比较、筛选、编辑、名单研究、各种澄清、缺数据、拒绝、来源截止及修复/降级；59 个步骤包含全部准备和续接消息。每个场景都有 `tags`，多轮含 `multi_turn`，人工故障含 `fault_injected`，部分覆盖含 `partial_coverage`。

语义语料版本保持 `research-api-v1`，结构扩展为 `research-api-corpus-v2`，运行结果为 `research-workflow-evaluation-v2`；运行器与语料须一起更新。原 offline 的问题、脚本、60 条理由和各层预期不变。每个场景增加 `modes` 及其补集 `mode_exclusions`，不适用的模式必须附具体理由：

| 模式 | 默认兼容场景/步骤 | 因模式不适用排除 |
| --- | --- | --- |
| offline | 40 / 59 | 无 |
| live-model | 39 / 57 | R01 依赖假模型刻意给出坏草稿 |
| live | 30 / 44 | R01；F03 固定 PE 值；L01/L02/C04 固定名单身份；D01/D02/D03/P01/P02 人工缺项、来源故障或截止 |

以上为重复一次。未给 `--case` 时选择所有兼容场景，预览及报告公开列出全部不适用 ID、理由和 `not_applicable_to_mode` 场景数、`not_applicable_steps` 步数（含重复）。这些排除项不算失败或未运行，不进所选任务的分母；显式选择不适用场景会在任何客户端构造前报错。真实模式不消费假模型脚本，`offline_expected_matched=null`；R01 不能要求真实模型照脚本犯错，也不能在 live 注入人工超时冒充来源故障。

预期由 Codex 依据语义要求和现有设计逐项编写，交 Claude 逐场景审核；不把这个过程称为已经完成的人工质量抽查。路由 v1/v2 基线与本语料分开维护。没有从路由结果生成预期、自动更新快照或取当前输出作为答案的功能。修改预期应注明需求依据并再次审核。

每一步的 `expectation` 分开保存三类要求，另有确定的离线基准：

- `required`：安全和正确性的硬性要求，例如拒绝时不取数、不调用模型、证券身份正确、不得输出某些错误码、如实保留缺失领域及筛选数量。`require_codes`/`forbid_codes` 对照公开结果和安全追踪中的结果码。
- `acceptable`：若干可接受的路由、意图、原始终态、语义类别和结果码组合，每项附具体的场景理由和设计依据。不是独立枚举任意拼接成宽松通行证。多数确定性规则只有一种；M03 的超量比较允许“要求缩小名单”或“明确拒绝”，两者都不能截断后取数。60 条理由逐项静态编写，测试检查全部互不重复；这不代表已完成人工回答质量抽查。
- `quality`：回答质量要求，保存 `answer_origin_if_answered`（回答来自模型还是应用）、`answer_status_if_answered`（检查接纳还是降级）和 `answer_contains`（必须展示的文字）。模型回答未通过检查而使用 `application/fallback`，属于安全降级；若本步期望模型回答，则单列质量失败，不计为硬性违反。R01 第二步专门验证降级，其质量目标就是 `application/fallback`。
- `offline_expected`：可接受范围内的一个确定结果。离线严格比较它，并要求上述三类要求全部满足；将来真实模式保留安全、范围和质量的分别判定，不能要求模型与脚本字面一致。

逐步报告分开给出 `hard_requirement_violations`、`outside_acceptable`、`quality_requirement_failures`，另列 `offline_expected_matched`。`required_checks` 和 `quality_checks` 分别保存具体检查结果。摘要里的前三项按“有此问题的步骤数”统计，不是约束条目数；一步有两条质量失败仍只计一步。未运行项的 `quality_checks` 为 null，失败列表为空，不能视为检查通过。带 `_if_answered` 的要求仅在完成类别下检查；没有回答时不生成这些检查，仍由可接受范围和离线基准判断结果。

模型脚本在独立的 `fixture_script`，仅声明有限协议阶段和固定提取参数，不能读取预期。它会核对工具名称和消息结构；意外调用、顺序或未消费脚本使步骤失败。真实执行器仍核对参数是否来自问题、身份、预算和证据。错误路由不会得到一份自动适配的新答案。

### 3. 固定数据与真实采集路径

[workflow_evaluation_fixtures.py](../src/trading_companion/workflow_evaluation_fixtures.py) 提供固定目录、100 条人工日线、人工财务、新闻/公告和腾讯协议响应，参考时刻固定为 2026-09-26。缺日线配置只有 5 条。所有公司数值、名称对应的描述、标题均为人工示例，不能据此评价真实公司。

`synthetic` 产品模式会关闭筛选，因此本运行器在受限作用域内注入来源：

1. 目录和报价源通过实际服务构造参数传入；公司资料使用实际 `ResearchDataService`，报价使用实际 `TencentQuoteSnapshotSource`。
2. 两者注入固定传输工厂，仍经过实际响应解析、身份/时间验证、共享 `CollectionExecutor`、请求和字节预算、确定性合并及发布规则。公司和报价共用最多三个未完成任务，不用不透明假服务绕过多公司并发。
3. 两个日线来源工厂绑定固定实现；仅固定分析/工具模块的日期时钟，以保持准入日期和取数元数据可复现。没有替换计算函数、检查函数、路由或执行器，追踪和延迟使用实际单调时钟。
4. 作用域退出后恢复工厂与日期时钟；每场景释放闸门并等待自己的实际池退出。

内部 `tencent`、`eastmoney_*` 等名称只标识走了哪个解析器，不代表这些人工响应来自网络。顶层、每步及导出的证据真实性明确为 `fixed_synthetic`；不能把内部产品的来源类型标签用于宣称真实数据。输入清单包含固定数据参数、夹具实现摘要和语料 SHA256。运行同时记录 Git 提交、工作区是否有未提交内容以及运行器实现摘要；不能只凭相同 HEAD 推断两次工作区代码相同。

所有人工传输带 2ms 等待，只用于让独立任务存在可观察的重叠机会；这不是来源延迟模型，也不是性能验收门槛。

### 4. 超时、失败和预算

P01 的三家公司各取财务和新闻，只有第三家新闻被闸门挡住；控制线程必须等它实际进入且协调器接纳其余五项后，才推进来源时钟超过共用 20 秒窗口。`CollectionScope.accept` 的只读观察包装先执行原接纳，不改变接纳规则。P02 在任何证据接纳前推进截止，P03 使用同样请求完整获取，便于区分：

- 部分覆盖：五项按时证据保留，第三家新闻为 `research_data_deadline_exceeded`，显示“未取得”，来源摘要 `stopped=1`、`failed=0`。
- 全缺：没有可用证据，原始终态为失败，不能计作部分成功。
- 普通来源错误：D03 返回人工 HTTP 503，统计为失败来源，不能混成来源截止。

API 返回后才释放迟到响应，关闭执行器后再核对追踪文件与返回前完全相同。同步 HTTP 工作退出前仍占用许可，不能把逻辑超时当成线程已经终止。这些场景都带人工故障标签，未来不能混入真实来源超时比例。

[evaluation_common.py](../src/trading_companion/evaluation_common.py) 在委托前原子扣整次额度，调用抛错也保留未知用量位置。它独立于单轮和会话上限；支持跨场景、会话及重复的总限制。达到上限后剩余计划步骤标记 `not_run`，不补问法、不补上下文、不重跑。某步失败后依序执行后续步骤，并继续其他独立场景。原 [agent_evaluation.py](../evaluation_tools/agent_evaluation.py) 和 [mvp_evaluation.py](../evaluation_tools/mvp_evaluation.py) 的首错停止、输出和契约没有改变。

公司评估原 `_SuiteModel`/`_usage` 名称保留为兼容层，继续默认五场景/九次假模型方法调用。用量总计只加已报告字段，缺失保留 null；未知、部分和不一致用量不算完整，报告完整请求数及未知请求数。零模型尝试与真实零 token 也不是同一件事。

### 5. 追踪与原始结果

运行器使用既有 `JsonlTraceSink`，每场景/重复独立子目录，保留原 64 事件、64KB 单条及轮换限制。一次同步 `message()` 后只接受一个新增且合法的 `run_id`；缺失、重复、不合法或多条都记 `trace_incomplete`，不猜测配对。

记录通过 `TraceReader` 和 `parse_record` 的有界验证。解析投影新增固定意图和白名单事件元数据；未知意图/来源不会携带原始字符串进入输出。v1、v2、已有 CLI 文本和 JSON 汇总的统计口径不变。`TraceSummary` 直接计算总/执行耗时、模型调用分布、用量和事件摘要，没有第二套百分位算法：p50/p95 使用排序后的最近秩，即 `ceil(p*n)`，空集合为 null。

每步保存原始终态、意图和路由、语义结果类别、应用检查后展示的回答、证券和覆盖信息、公开事实报告、预期检查结果及安全追踪。公司回答和技术对话的来源也保留，防止受限结果掩盖回答降级；是否达到回答质量目标独立统计。只有需要引用/数字检查的路径才有相应事件，不能把“未执行”补为通过。事件截断时仍保留原摘要，但精细事件数据不可推断为完整。

当前公司入口会把部分 `out_of_scope` 计划投影为公开 `failed`，同时保留 `product_trade_execution_forbidden`、`product_unsafe_request`、`product_request_out_of_scope` 等拒绝码。评估用这三个固定拒绝码判语义类别为拒绝；保留原始终态及 trace 的 `error` 类别，不修改产品行为。其余 completed/limited 映射完成，needs_clarification 映射澄清，invalid_request/out_of_scope 映射拒绝，其他终态映射错误。“完成类别”不等于任务成功，仍须通过静态硬要求、可接受范围和质量要求。

不会导出凭据、模型原文、提示全文、完整工具返回或底层异常文本。公司与技术的已检查显示、公开事实和证据允许用于人工抽查；它们不能证明任意观点被证据支持。运行完整性另列：即使逐步结果符合预期，只要检测到越出离线边界的访问，整次仍失败。

### 6. 指标及分母

[workflow_evaluation_metrics.py](../src/trading_companion/workflow_evaluation_metrics.py) 由逐步结果和已验证追踪计算整体及 `by_tag` 分组。每个比例含分子、分母、未知数，零分母为 null；标签可重叠，不能把分组相加当总数。

- 路由和意图正确率分别核对静态可接受取值，整体以全部所选兼容步骤为分母，另列已执行口径。准入失败、未运行、缺追踪不能消失。
- 逐步任务成功沿用三层要求，offline 再核对精确基准；场景成功要求本次重复的全部步骤通过。四类混淆表以静态主目标为预期行，合法备选另计；不根据观测换行。保留原始终态、受限数量，未运行单列。
- 引用/数字是联合机械检查，按计划要求模型回答的完成步骤列适用分母，未生成回答保留为未执行。按原检查事件和最终来源解释，保留初次拒绝/最终接纳与尝试数，不把同一个码拆成两个语义通过率。截断或缺追踪时细项未知。
- 规则纠正只计 `intent_rule/rule_applied` 的实际进入，跳过不计；模型重写按实际进入 `model_rewrite`。分别列受影响步骤数、进入次数、全部步骤和计划适用步骤的比例。程序降级按最终应用来源或 fallback 状态计，不是安全违规。
- 截止部分覆盖同时要求领域截止码、实际保留证据及显示“未取得”的缺失领域。按计划公司研究及实际进入采集分别列分母，全缺、普通来源错误、整轮停止、人工故障和非人工截止另列。未知不补成“没有超时”，聚合 stopped 不能代替证据。
- p50/p95 和调用/用量直接复用 `TraceSummary`，失败但有记录的耗时也参加，另给延迟覆盖 n/N。细项截断不会抹掉原聚合摘要，但不能据此编造细项。

### 7. 价格、计划与真实模式

[evaluation_pricing.py](../src/trading_companion/evaluation_pricing.py) 校验 [model-prices.json](../data/evaluation/model-prices.json)。Claude于2026-10-28核对并通过消息 #133 提供TypeSafe/Jev和DeepSeek报价，仓库已记录这两项，不改变本工作流的提供方和模型身份检查约定。每项使用以下字段，精确选择提供方和模型，不模糊匹配、不混加币种：

```json
{
  "provider": "deepseek",
  "model": "MODEL_ID",
  "currency": null,
  "verified_at": null,
  "source_url": null,
  "input_per_million": null,
  "output_per_million": null,
  "input_pricing": "uniform"
}
```

这是结构示例，单价单位为每百万 token；token 是供应商的文本用量单位。填价格时还须给币种（支持 USD/CNY/EUR/GBP/JPY/HKD）、不晚于今天的核对日期和不含凭据的 HTTPS 依据链接。拒绝重复键/条目、未知字段、负数、非有限单价和不完整的核对元数据。Decimal 十进制数用于计算，展示时才保留六位小数。

默认核对价：typesafe/jev-latest为USD输入0.042、输出0（[官网](https://typesafe.ai)，输出目前免费）；deepseek/deepseek-flash为CNY输入2、输出8（[官方中文价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)）。DeepSeek实际有峰谷和缓存价：缓存未命中输入谷/峰为1/2元、缓存命中输入为0.02/0.04元、输出为4/8元；峰时为北京时间工作日9–12点及14–18点。现有价格格式不表达这两种分档，因此以uniform记录最高单价；**费用按峰时、缓存未命中计算，是对应已报告token用量的上限，而不是账单**。不猜缓存命中或根据时钟下调，缺用量/请求记录仍未知，预览token假设也不是整次账单硬上限。

`input_pricing=cache_split` 表示输入涉及缓存分档；现有公开用量无法可靠拆分时输入费用未知，已知输出费用可作小计。缺价格、部分或不一致用量、超出有界计量范围、模型身份不匹配也单列未知。`known_subtotal` 不等于完整的 `estimated_total`；请求数和用量完整性均保留，零尝试不是零 token。

### 标签与输入边界

分类器只负责选择语义意图，没有执行工具、修改会话或增加权限的能力。七个业务值直接取现有 `IntentKind`（产品路由类别），另加仅用于实验的 `clarify`（需要反问）：

| 标签 | 判定标准 |
| --- | --- |
| indicator_knowledge | 技术指标定义、公式和一般用法，不分析特定证券当前情况。 |
| general_knowledge | 金融、交易制度或市场风险等一般概念，不针对具体证券研究。 |
| screening | 发起新的股票候选寻找。 |
| screening_edit | 有筛选上下文，修改原条件、排序或数量。 |
| screening_followup | 研究已有名单的成员或序号，不修改筛选条件。 |
| company_research | 公司业务、财务、新闻和综合研究；买卖评级、未来方向、止盈止损等决策与计划统一归此类，最近是技术研究也不改变。名称歧义交身份澄清。 |
| technical_research | 明确的个股指标、历史行情，或接续技术研究本身的解释、修改、重做；不负责买卖评级、未来方向或计划。 |
| clarify | 完全没有对象且没有可接续上下文，或多对象中指代不唯一；名称的身份歧义不属于本标签。 |

定义和中文说明只有[一份来源](../src/trading_companion/intent_router_task.py)，同时生成Jev的固定选项和DeepSeek的JSON提示。DeepSeek只能返回一个 `intent` 字段；不要求它自报概率。Jev复用既有协议，保留供应商置信度和概率；非法标签、重复键、额外决定字段或格式错误记失败，不修正、不重试。

模型仅收到 `{"question": "人工问题原文", "context": {...}}`。上下文字段如下：

| 字段 | 含义 |
| --- | --- |
| has_saved_company / has_saved_technical | 是否保存了公司／技术研究记录。 |
| has_shortlist | 是否有筛选名单，不发送名单内容。 |
| company_enabled / workflow_enabled | 可信配置中对应功能是否开启；关闭时入口先保护。 |
| has_multiple_research_subjects | 最近研究是否涉及多个对象，不发送对象和数量。 |
| latest_valid_research_kind | 最近可接续类别：none/company/technical/screening/unknown；unknown表示无法确认，不猜测。 |

不发送题号、标签、理由、gold（人工标准答案）、划分、规则答案、聊天历史、证券资料或目录。最近类别由人工场景预先指定，用来验证同时保存公司和技术记录时省略主语的归属；本步尚未在产品中实现这个状态派生器。

命令、历史、新问题前缀、公司待澄清、技术待澄清、指标待澄清、多待澄清冲突、执行或注入请求共8组保护题，每组8条。保护记录不进入语义模型或语义准确率分母。入口复用现有命令常量、执行检查等，并接受人工声明的待澄清归属。这里证明的是**独立评估入口**的零调用边界，产品原有边界由现有回归测试保护，不声称本步新增了生产保护层。

### 题库与复核

240条语义题：8类各30条，每类10个家庭、每家庭3条输入案例；每类开发18条、留出12条，总计开发144、留出96。家庭指同一个语义场景的说法和上下文对照，整组进入一个划分，避免近义句同时出现在开发与留出中。稳定性对照会使用同句、不同最近类别，不能把这些案例称为彼此独立的自然表达。

按审核#159修正决策标签后，公司／技术共享家庭只保留“解释原研究”和“重做原研究”两个，因此共78个语义家庭。18条最近类别为technical的决策／方向题统一改为公司研究，理由记录对象可以经可信交接沿用；跨执行器交接尚属2b，不在产品中实施。

24个配对、48条消融题在重新验证之前写定于manifest的 `ablation_design`，开发和留出各12对／24条。其中6对的标签随最近类别变化（开发解释3对、留出重做3对），18对标签应保持不变（开发9对概念题、留出8对概念题及1对纯历史行情）。稳定性题检查元信息不应干扰明确请求，不能当成“最近类别有用”的证据；报告按两组分别给出完整／去字段准确率和双端正确率。旧24对选择已废弃，不按任何模型结果挑配对，也不在消融里重新选策略。

为维持各类18／12的配额，原公司研究槽位补入明确的日线、EMA、成交量、布林带、MACD、周线等技术题和无对象的财报反问题；I229–I231“平安”三题改为公司研究并整家庭移至开发，I058–I060历史行情家庭整组移至留出。clarify另补无对象的比较家庭，移除旧题中直接说明“最近类别未知”的元语言。每条变化均按人工语义与配额确定，未参考规则或模型输出。

所有语义题均带 `paraphrase`（换说法）标签，因此本版本换说法子集等于语义全集；它不是另一个独立证据集。另有60条近似反例，留出24条，逐题列出禁止误触发的类别。覆盖口语、换词、省略对象、长句和少量错别字。

先写题再运行规则，不按得分挑题或修改冻结规则。#159要求的全量自然表达自查去掉了题目中主动描述隐藏状态、排除其他标签、提示标准答案的说法；状态只放context，理由只放标注字段。但人工作者和规则实现者相同，仍可能有偏差。题库为合成数据，不代表真实请求分布。Claude逐条检查问题、输入是否足够、标准答案、理由和禁止类别；歧义须交用户确认，不能照模型答案改标签。

复核时在manifest每条 `reviews` 中填写 `status=approved`、`reviewer=claude` 和说明，保留与题目匹配的 `row_sha256`；全部通过后再设置顶层 `annotation_status=reviewed`、`reviewer=claude`、`reviewed_at=YYYY-MM-DD`。修改题目必须重新计算摘要并重新审核。仅翻转顶层标记不能通过检查。数据、定义、家庭划分和冻结生产文件均校验摘要。

### 冻结规则与公平口径

A2（#175/#176）因统一原文对象识别修改了 `product_agent.py` 和 `product_plan.py`。原304题及manifest不改写；仅登记这两份源码的精确历史/当前摘要对，仍拒绝未知变更。新计划公开实际源码摘要，参考报告兼容检查也核对它；历史摘要继续标明题库编写时的来源。117轮零差异与独立名称测试见A2记录。这不是2a标签或阈值调整，也未接入模型路由。

[基线适配器](../src/trading_companion/intent_router_baseline.py)调用真实的知识提前分支和 `route_research_request`，固定人工证券目录、合法筛选状态和时钟，不另写简化关键词分类器，不读行情、不调用模型、不修改生产源文件。

模型输入包含本步拟评估的最近类别，冻结的生产路由尚不支持该字段，因此不把它强塞进既有路由状态。规则只接收目前支持的状态；消融去掉最近类别时，规则预测不变。

**语义路由不等于最终执行结果。** 例如无上下文“能买吗”，真实路由可能选择公司研究，执行器随后安全询问对象。规则没有通用clarify，所以按真实返回值计分，不替规则编造反问，也不把标签不符说成最终回答一定错误。

总表同时展示全部8类与 `gold != clarify` 的7类子集准确率和macro-F1，避免只利用规则缺少clarify取得优势。gold=clarify单列正确反问、缺信息强行路由，以及规则执行器能否继续澄清（本实验未运行执行器，写“未判定”）。“追踪一下消息”可属于公司研究，“上市以来走势”是纯技术历史分析；本实验不能证明company内部decision/analysis目标判断的改进。

“平安怎么样”已明确是在研究公司，究竟是平安银行还是中国平安交现有执行器的身份澄清，不要求拿不到证券目录的语义模型消歧。clarify仅处理对象完全缺失或多对象指代不明。未来方向、买卖评级和止盈止损计划始终交公司研究；最近技术上下文只可提供可信对象，不把决策变成技术研究的解释。

### 开发、锁定、留出与消融

先跑开发集选择Jev采用阈值；候选为0.50、0.55…0.95和0.99。采用条件为合法非clarify且置信度不低于阈值。开发候选要求：准确率至少95%、采用至少40条、覆盖至少40%、Wilson 95%区间下界至少85%。在符合条件者中取覆盖最大者，同覆盖取较高阈值；没有合格候选则锁定null，含义为不直接采用。

只能从完整144题、每题一次、包含Jev且模型结果合法的开发报告导出锁。锁包含开发报告路径与摘要、选择规则、阈值和请求／返回模型身份，初始为draft。Claude审查开发结果后把锁设为 `review_status=approved`、`reviewer=claude`。正式留出运行必须提供该锁，且题库、实现、定义、价格和所选模型组合与开发一致。开发报告不能移动后不更新引用；任何修改都会使锁失效。offline来源的锁不能用于live。

留出仅输出锁定阈值的选择性指标，不扫描留出最优阈值。离线允许无锁诊断，采用阈值为null且永远不能满足切换门槛。预算截断保留全部题目和not_run，报告partial，不能导出有效开发锁。

消融必须引用同划分、同条件、完整且每题一次的主报告；只运行预选24条，删除最近类别字段，其他输入不变。不自动补主实验，不额外选择配对，不再调阈值。报告完整／去字段准确率、差值、反问率和一对两端都答对的比例；返回模型身份不一致时不计算改善差值。live留出消融同样需要已复核锁。

### 指标与费用

[指标实现](../evaluation_tools/intent_router_metrics.py)保留每个比率的分子、分母和值，空分母为null：

- 准确率＝正确条数／全部计划题数；每类准确率实际为该类召回率，另给precision、recall、F1。F1＝2TP/(2TP+FP+FN)，macro-F1固定8类等权平均；非clarify子集固定7类。混淆矩阵另设failed和not_run列。
- 误路由率＝业务题被判成其他业务类别的数／N；反问率＝合法clarify输出／N。正确反问、过度反问及gold=clarify时强行选业务分列，失败或未运行不伪装为反问。
- ECE为置信度校准误差：固定10个等宽桶，按桶内有效样本数加权平均“平均把握与实际正确率之差”。给有效覆盖M/N，另给非clarify输出口径。DeepSeek不虚构置信度。
- 选择性准确率＝阈值以上非clarify采用中正确数／采用数，附覆盖、样本数和Wilson 95%区间。家庭内说法及稳定性对照有关联，区间仅为案例比例参考，不代表独立真实请求的置信范围，也不能据此宣称统计显著。
- 近似反例误触发率只检查该题预先列出的禁止类别，另给反例总体错误率。
- 延迟用最近秩p50/p95，分成功、失败、超时、全部已尝试口径，列出样本数。未尝试不补零毫秒。
- 级联是用保存结果模拟：Jev达到锁定阈值则采用，否则反问或使用DeepSeek已有结果。不给模拟追加请求，未运行的必需结果保留缺失；分别统计准确率、误路由、反问、强行路由、反例误触发、后续需求和费用。串行耗时是已需请求耗时之和，不能当作部署链路延迟或实际节省费用。

仅把新闻指标中的 `ratio` 和 `percentiles` 两个纯函数抽入 [共用模块](../src/trading_companion/classification_metrics.py)，新闻仍使用相同函数、同一统计口径。传输、DeepSeek解析、费用、网络限制均复用既有实现。

请求用量乘显式价格，保留请求和返回模型身份。失败、未知用量、价格不适用或模型版本无法匹配时，费用仍未知，不补零；不同币种不相加。预览可给输入／输出token（供应商的文本计量单位）假设，产生费用情景估算，不是实际账单或硬费用上限。运行调用上限是请求次数的硬约束。

## 工具调用联通验证入口

日期：2026-10-19（America/Los_Angeles）

### 这一步解决什么问题

工具适配器的离线测试已通过，但还没有一个供开发者显式运行的真实工具往返入口。[tool_smoke.py](../src/trading_companion/tool_smoke.py) 补上固定任务的验证流程，不接管自然语言对话或实现完整Agent。

默认Fake完全离线，不读取模型凭据。只有 `--provider deepseek` 才读取已有环境配置，并可能向DeepSeek发送最多两次付费请求。此入口实现时仅做离线验证；开发者随后提供一次真实工具往返记录，见文末更新，不把两类验证混为一谈。

### 固定任务与数据流

测试任务固定为 `000001.SZ`、2026-09-21至2026-09-25、SMA3/SMA20/量能3。数据由程序注入仓库内的人工CSV，短周期仅用于展示可用与历史不足，不是产品默认或交易参数建议。

1. 模型接收固定指令和工具声明，提出一次调用。
2. 程序检查恰好一个提议，名称和参数与测试任务一致；指标顺序可以变化，参数不能遗漏、增加或改写。
3. 同一个 `ResearchToolExecutor` 实际计算人工CSV，保留原调用ID、精确数值和不可用字段。
4. 原助手提议及工具结果一起交回模型；第二次必须返回完整文本，否则停止。

没有循环、自动重试或提供方回退。不会补造工具提议、纠正参数、扩大日期、访问真实行情，或新建执行器重置额度。工具声明仍复用已有白名单；固定任务检查进一步收紧本入口的范围，不替代执行器自身的业务与权限校验。

首次直接回答、拒绝、截断、多提议或参数不符，都不能算工具验证通过。执行失败/无可用数据后不发送第二次请求；第二次再提工具也不会发送第三次。

### 在PowerShell运行

在项目根目录，先运行离线版本，无需密钥和虚拟环境激活：

```powershell

```

如需真实验证，先在同一个终端按[模型配置说明](../README.md#setup)设置 `DEEPSEEK_MODEL` 和 `DEEPSEEK_API_KEY`；使用账号实际支持的型号，密钥只输入本机的掩码提示，不粘贴到聊天或保存进代码。若尚未安装HTTP依赖，使用已有可选依赖 `pip install -e ".[model]"`，本步没有新增依赖。

只有你愿意把固定测试指令、工具声明和人工计算结果发送给DeepSeek并承担API费用时，才运行：


这条命令不是免费预览或dry run。默认配置每次最多512个输出token、30秒HTTP等待；不自动重试。两次模型调用加本地计算仍没有实现产品Agent的全轮截止时间。测试后可用 `Remove-Item Env:DEEPSEEK_API_KEY` 清理当前终端密钥。

### 怎么读输出

| 字段 | 含义 |
| --- | --- |
| `status / code / stage` | 是否完成、本次原因，以及停在配置/提议/执行/最终回答哪一阶段 |
| `provider / live_provider_selected` | 选择Fake还是DeepSeek；选择真实路径本身不证明联网成功 |
| `model_calls_attempted / analyses_used` | 调用了几次模型接口、消费了几次分析额度；不是成功数或实际HTTP次数保证 |
| `model_responses` | 每次返回的状态、请求/实际型号、模拟标志和可用token用量；不伪造未知用量 |
| `tool_round_trip_completed` | 工具提议、计算、结果回填和完整文本往返是否完成 |
| `tool_result` | 人工CSV的结构化结果及原调用ID；SMA20缺15条仍保留不可用状态 |
| `answer / answer_validation` | 最终模型原文；本入口恒标记 `not_performed`，不宣称金融事实已检查 |

成功时 `status=ok`、`tool_round_trip_completed=true`、模型调用2次、分析1次。默认运行仍是Fake，不能作为真实接通记录；DeepSeek路径也可在自动化测试中被模拟HTTP替换。真实兼容性需由开发者的显式实际运行记录确认，不能只看 `is_mock=false`。

退出码：0表示固定往返完成；1表示未验证成功或运行失败；2表示配置/命令参数需修改。失败输出固定原因或适配器的脱敏错误码，不打印密钥、原始异常或提供方错误正文。模型原文和工具结果不是生产脱敏日志，不应任意上传。
