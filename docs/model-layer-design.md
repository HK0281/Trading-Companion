# 模型接入层：第一步

日期：2026-10-07

## 本轮目标

先完成一个独立的后端子模块：输入消息，返回统一格式的模型文本或明确的错误。暂不调用行情工具、不生成交易分析、不维护对话记忆。

根据当时讨论，先把模型接入作为独立学习步骤；该步骤开始时多指标计算尚未完成。2026-10-16已补齐七类纯计算与独立多指标服务/证据契约，并新增独立工具消息协议、受控日线执行器与脚本Fake往返；后续仍需真实提供方工具适配、单轮编排及解释检查，才连接Agent主流程。这个顺序调整不表示放弃PRD中的多指标需求。

## 三个部分

| 部分 | 职责 |
| --- | --- |
| `model.py` | 定义消息、结果、错误与统一接口；提供不联网的假模型 |
| `deepseek_model.py` | 读取显式配置，发送兼容Chat Completions的HTTP请求，转换响应与错误 |
| `model_cli.py` | 独立演示入口；默认假模型，只有显式选择DeepSeek才可能联网 |

接口统一是为了让未来agent不依赖某个供应商的响应细节。当前只有假模型和DeepSeek适配器，不宣称所有OpenAI模型都可以直接换地址使用。

## 本轮边界

- 使用已有的requests发送HTTP请求，不引入agent框架或OpenAI SDK；参考OpenAI Docs核对兼容消息格式、结束原因及用量字段。
- DeepSeek请求地址固定，密钥不能随模型输出发送到任意URL；禁用重定向，不自动重试。
- 模型名称由`DEEPSEEK_MODEL`显式配置，不猜测用户账号可用的型号；密钥使用`DEEPSEEK_API_KEY`。不自动读取`.env`。
- 本轮只支持非流式文本，返回工具调用、拒绝、截断或损坏响应均不冒充完整文本成功。
- 保留实际返回的模型名称与可用token用量；缺少用量时标记未知，不填0，不估算账单。
- 请求错误使用固定、可理解的分类，不输出服务端原始错误体、请求头或密钥。
- 超时是连接/读取等待限制；整个agent回合的总截止时间留给后续调度层，不能声称本轮已实现。
- 假模型不等于真实模型效果验证。单元测试使用模拟HTTP响应，不发送用户数据或产生推理费用。

## 完成条件

离线演示可运行；合法响应能解析；配置缺失在联网前报错；超时、鉴权、限流、错误数据与截断分别测试；敏感配置不出现在repr/CLI错误中；已有行情测试不回退。

真实DeepSeek接口、所选模型的字段兼容性和可用性，必须由用户配置服务后单独联通验证。本轮不把模拟测试写成真实接入已验证。

## 联通准备更新：2026-10-13

- 核对[DeepSeek官方接入说明](https://api-docs.deepseek.com/zh-cn/)，当前示例模型名为`deepseek-flash`；应用仍要求显式配置型号，不把文档示例写成账号权限保证。
- 核对[思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，当前默认开启思考。纯文本适配器显式发送`thinking: {type: "disabled"}`，避免依赖供应商默认行为；保留512-token限制与截断检查，不保证任意请求都能在预算内完成。
- README补充PowerShell隐藏输入密钥的步骤。密钥不进入命令历史，但传给Python的环境变量仍是明文进程配置，不是加密存储；不持久化、不写入代码、不自动读取`.env`。
- 此更新只有离线回归测试和公开文档核对；真实联通仍需用户在本机配置密钥后执行。

### 后续联通反馈：2026-10-13

开发者随后提供了本机运行的成功输出：`status=ok`、`provider=deepseek`、请求/返回型号均为`deepseek-flash`、回答`OK`、用量29个输入token和1个输出token、`is_mock=false`。据此记录一次真实纯文本请求已验证；主Agent没有读取其密钥或另外发送付费请求。该结果不代表其他型号、工具调用或行情分析已验收。

参考：[Chat Completions接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。这是兼容协议参考，不是DeepSeek账户或型号可用性的保证。
