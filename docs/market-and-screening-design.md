## 证券主数据与交易日历背景

日期：2026-10-22。状态：本地快照契约、API附加投影、会话内冻结与Web卡片已实现；真实主数据／日历适配器和历史版本库未实现。

### 1. 解决的问题与边界

指标能算出来，并不代表我们知道股票当时属于什么板块、是否ST、是否全天停牌。缺少某天K线也不能直接推断停牌。此模块先把这些背景的信息来源、业务有效期、发布时间和未知状态明确表达出来。

它是附在原研究答案旁边的只读背景，不是新工具或交易规则引擎：

- 不改变Agent提示词、指标计算、研究答案或模型调用次数，也不把背景发送给模型。
- 不按ST、科创板或新上市类别排除股票；不判断涨跌停、委托资格、成交可能性或止盈止损。
- 不从代码前缀猜板块、不从名称猜ST、不从缺失K线猜停牌、不按工作日猜开市。
- 来源字段只是本地文件的标注；严格解析不等于认证其官方来源或事实正确。
- 始终声明 `historical_availability=not_established`，不称为point-in-time系统。

名称目录 `SecurityDirectory` 仍只负责身份核实。今天的名称→代码匹配不能成为过去某天ST或停牌的证据，因此两份契约分开。

### 2. 数据流与文件职责

```text
追问／历史：原已保存研究ID → 原背景缓存（不读当前文件）
```

### 3. 本地快照契约

实际完整样例见 [人工夹具](../data/market_context_fixture.json)。根对象只允许以下字段：

```json
{
  "version": "market-context-snapshot-v1",
  "snapshot_id": "example-local-v1",
  "retrieved_at": "2026-09-20T02:00:00+08:00",
  "is_fixture": false,
  "security_states": [],
  "calendars": []
}
```

空数组是合法的“未提供”，不是正常状态。不要把人工夹具简单改成 `is_fixture=false` 来冒充真实数据。

#### 证券状态记录

`security_states` 每项必须完整给出：

| 字段 | 约束 |
| --- | --- |
| `instrument_id` | 完整6位代码加 `.SH` / `.SZ` / `.BJ`；不扩大原行情源支持范围 |
| `effective_from` / `effective_to` | 闭区间ISO日期，同股票记录不得重叠；区间空档是未知 |
| `board` | `sse_main`、`star`、`szse_main`、`chinext`、`bse`、`unknown`，必须与交易所一致 |
| `listing_date` | ISO日期或null；允许未来上市日，不据此定义“新股”阈值 |
| `st_status` | `not_st`、`st`、`star_st`、`unknown` |
| `suspension_status` | `full_day_suspended`、`not_full_day_suspended`、`unknown` |
| `published_at` | 带时区ISO时间或null；若给出，不得晚于采集时间 |
| `source` / `reference` | 来源枚举与安全引用标签；标签不是URL、任意描述或认证凭证 |

“非全天停牌”不保证没有盘中临停或能够成交。上市年龄为 `as_of_date - listing_date` 的自然日差，上市当日为0、尚未上市为null；它不是交易日数，也不代表适用任何交易规则。

来源枚举是 `synthetic_fixture`、`sse`、`szse`、`bse`、`curated_local`。交易所来源必须匹配记录的交易所；人工快照只能标synthetic_fixture，非人工快照不能标该值。ID/reference首位字母或数字，总长1–100，只允许字母数字及 `_.:-`；原研究ID继续遵守其已有契约。

#### 交易所日历

`calendars` 每项必须给出 `exchange`、`coverage_start`、`coverage_end`、`published_at`、`source`、`reference`、`days`。每个交易所至多一块，总数不超过SH/SZ/BJ三块。

`days` 是按日期递增的 `{ "date": "YYYY-MM-DD", "status": "open|closed|unknown" }` 列表，覆盖期内每个自然日都必须显式存在。少一天、重复一天或乱序均拒绝；覆盖外日期保持unknown。没有BSE日历时不能借用沪深日历。

### 4. 时间语义

| 时间 | 含义与使用 |
| --- | --- |
| 状态有效区间 | 业务上这条状态适用哪些日期；只选择覆盖分析日的证券状态 |
| `published_at` | 文件声称的发布时间；未知或晚于上海分析日结束时，状态值隐藏／日历按未知处理 |
| `retrieved_at` | 应用获得快照的时间；晚于本轮参考时间则拒绝这份未来快照 |

采集晚于分析日，但不晚于本轮参考时间时，可以显示回溯业务背景，同时提示采集较晚。即使声称的发布时间较早，也没有证明保存过当时版本、没有后来修订或遗漏，因此仍明确“不是PIT”。本模块按日线分析日截止，不支持日内时点。

ST、上市或停牌状态不是从今天反推过去。查不到有效记录、未公开或部分字段未知时，就保留unknown；不能把“没查到ST记录”写成“非ST”。

### 5. 日历对照与失败行为

返回查询范围内的 `open_dates`、`closed_dates`、`unknown_dates`，三者有序互斥且完整覆盖所有自然日；再与同一研究结果的实际bars对照：

- 开市但无日线：列入 `missing_bar_dates`，提示未匹配，不推断停牌。
- 休市却有日线：列入 `unexpected_bar_dates` 并标来源冲突。
- 所报上市前有日线、已公开全天停牌区间有日线：只标冲突，不删改原行情，也不擅自裁定哪个来源正确。

背景 `available` 只表示分析日状态完整、查询日历已覆盖且无冲突，不表示内容已独立核实、全区间证券状态已知或可交易。未知或冲突时为 `limited`。未配置、文件不合法、未来快照、真实性混用、结果错配或体积超限时，返回固定unavailable，不暴露路径或原始异常。

`data_authenticity` 为 `synthetic` 或 `unverified_local_snapshot`。人工背景只允许配人工行情；真实行情不能显示测试属性。前端独立校验这个可选字段；失败只降级卡片，正文、图表和请求确认不受影响，不触发任何自动重试。

### 6. 冻结、边界与生命周期

缓存按内部研究ID，而不是外层HTTP幂等ID绑定。只有重新核实已提交的 `SavedResearch` 后才加载背景。停止轮即使保留安全指标事实，若未提交保存结果，也不会加载或缓存背景。

首次背景失败同样冻结；幂等重放、追问和历史查看不能因文件后来修复而偷偷补读。缓存缺失返回 `context_cache_miss`。新的成功研究才读新快照。返回值和缓存深复制，防止调用者修改原记录；同锁发布背景和幂等响应。HTTP重置、自然语言重置、删除、会话过期和关闭服务均清理背景。

| 边界 | 限制 |
| --- | --- |
| 原始快照文件 | 最多5MiB，只读MAX+1字节检查边界 |
| 证券状态 | 最多10,000条 |
| 日历 | 每交易所最多3,660自然日；最多3个交易所 |
| 研究范围 | 最多366自然日，沿用原请求边界 |
| 公共背景DTO | 最多64KiB紧凑UTF-8 JSON，不含原始记录全集 |
| 背景缓存 | 每会话最多20项（可随问题额度收紧），不跨会话共享 |

JSON序列化大小不是Python对象总内存或整个HTTP响应的上限。可选文件准备在Agent结束后进行，不宣称受Agent的90秒协作截止强制中断；本地文件不自动刷新，也不支持网络流式源。

## 真实证券背景与A股规则解释

更新：2026-10-26。实现范围为真实公开接口适配器、可保存的来源快照和纯规则解释函数；会话、模型证据和前端由产品层组合。

### 数据流

```text
已核实的股票ID（最多3只）
```

### 来源与覆盖

| 字段 | 来源与处理 |
| --- | --- |
| 沪市板块 | 官方主板A股、科创板两个已校验列表片段的STOCK_TYPE；不从代码前缀推断业务板块 |

固定公开入口：

- [上交所股票与存托凭证列表](https://www.sse.com.cn/assortment/stock/list/share/)，查询ID `COMMON_SSE_CP_GPJCTPZ_GPLB_GP_L`。
- [上交所风险警示板](https://www.sse.com.cn/disclosure/listedinfo/riskplate/)，查询ID `PL_SSGSXX_FXJSBGPLB`；科创板风险名单查询ID `SSE_PL_SSGSXX_KCBFXTS_L`，`type=0`。
- [深交所股票列表](https://www.szse.cn/market/product/stock/list/index.html)，报表 `CATALOGID=1110 / TABKEY=tab1`；按股票路径固定访问 `https://www.szse.cn/api/report/ShowReport/data`。

按股票获取最多3只：深市每只一次已过滤的官方JSON请求；沪市使用两个完整列表片段和两个可降级的风险名单请求。JSON分页声明、股票代码和报表业务日期必须匹配。没有自动抓取全市场146页，没有把分页第一屏当完整市场。

不提供instrument_ids时保留整表刷新路径：两个沪市列表加深市XLSX导出。三块上市元数据必须全部成功才保存；可选沪市风险名单失败时保留上市字段并明确风险状态未知。2026-10-26的真实探测中，深市XLSX下载失败，而按股票JSON查询可用；两条模式是显式选择，不是悄悄切换提供方。

### 时间与真实性

v1人工夹具和现有本地快照继续原样解析。v2增加：

- `SecurityState.observed_at`：抓取时间；`st_reference`：另一个风险名单来源引用，可为null。
- 根级 `source_records`：`reference / source / source_url / as_of_date / retrieved_at / published_at / publication_precision / field_scope / coverage`。
- 接口没有可靠发布时间时，`published_at=null`、`publication_precision=unknown`，不会用抓取时间冒充发布时间。
- `as_of_date`是来源标注的业务日期。深交所清晨仍可能展示上一交易日的报表；来源日期和抓取上海日期分开保存。来源业务日期只接受距采集0–7天。

在线状态只覆盖来源业务日期这一天，不能创建跨月历史区间。`build_market_context`仍按原分析日和可用时间过滤。独立的`current_security_background`可以展示“当前取得的背景”，但其`analysis_date_st_status`只有分析日、来源日期、抓取上海日一致时才可能给出已核实ST；否则为unknown。来源较晚取得不能证明过去当时就拥有这条记录。

例如：10月27日抓取、报表日期10月26日，可以显示“来源报表截至10月26日，10月27日取得；板块和上市日为当前报表所示”，不能说“已验证10月26日历史ST”。当前观察接口还有7天新鲜度上限，超期或未来快照返回unknown。

来源链接限制到固定交易所HTTPS域名；解析检查不能证明本地文件未经人为篡改，因此公共背景仍沿用`unverified_local_snapshot`，并保留`historical_availability=not_established`。本模块不是PIT版本数据库。

规则结果区分：

- `ordinary_daily_limit_percent`：在普通竞价日、给定板块和风险分类下的条件性基准。
- `applied_daily_limit_percent`：只有上市交易日序号、普通/特殊事件等输入齐全时才给出；默认null。
- `price_limit_status`：普通、条件性普通、IPO无涨跌幅限制、特殊事件无涨跌幅限制或unknown。
- `listing_trading_day`：必须由独立可信的交易日历等依据提供，不能由自然日或K线数量替代。适配器日历缺失时不自动计算。
- `same_day_resale`：解释普通A股T+1卖出限制；不判定账户可卖余额，也不推导资金取用规则。

没有涨跌幅限制不代表没有临停、有效申报价格范围或其他交易约束。规则函数不判断涨停价、委托是否有效、个人账户权限、保证成交或实际可交易性；返回`tradability=not_assessed / execution_allowed=false`。缺日线也不能用于推断停牌。

### 独立数据、计算和单位

`index_contracts.py` 定义独立请求、日线和结果，股票 `Security`、`DailyBar`、`MultiIndicatorRequest` 的校验保持严格。指数只有可信白名单身份和真实OHLC（开、高、低、收），价格单位 `index_point`；成交量、成交额未经核实，数值始终为空，不乘100、不填0。默认去掉量能指标，显式请求 volume、OBV、VWMA 时说明不可用。

正式来源只接腾讯固定日线地址，按年分片；单片最多640条、512 KiB，禁止跳转及自动换源。截止必须早于上海当天，忽略合法起日前记录，拒绝超截止、重复/倒序、错误对象、供应商失败码、非有限值及非法OHLC。任一必要分片失败，整次取数失败。读取遵守现有轮次截止与取消。AKShare、普通CSV不自动替代；开发模式用独立人工指数生成器，禁止读取股票CSV或联网冒充指数。

`ohlc_weeks.py` 共用周分组及OHLC聚合，股票技术周线和股票周图也调用它。周一分组、丢弃截断首周；文字研究只用周日边界不晚于截止的完整周，不假设五条记录等于完整周、不补节假日。图表可显示未完末周并标注。指数价格指标复用 `_indicator_values.py` 和 `chart_intervals.chart_series` 的既有公式，不构造带假零量的股票对象。均线、MACD、BOLL、ATR用指数点；RSI、ADX保留原 `index_points` 指标读数量纲。

证据从同一个不可变日线结果计算，包括最新完整日收盘、窗口最近至多120条日线的历史极值候选及日/完整周指标。送给模型和公共卡片的 `raw_value`、`display_value` 均按股票既有的十进制两位小数显示规则取整；数字按同一显示精度核对，模型应照抄显示值。原始OHLC、指标计算和图表序列保持原精度。极值是窗口事实，不能保证将来支撑、压力有效或当作未来目标。每条记录绑定指数、来源、日期、字段、周期和指标参数；公共结果绑定研究编号、窗口、真实性、获取时间。保存/重建时重算证据和图表，不信任客户端提供的价格或序列。

### 模型回答和会话

初次研究：一次日期理解、一次JSON结构回答，校验失败最多修复一次，总计最多三次模型调用；指标修改复用既有整句解析器，不再调用日期理解。解释或“那周线呢”使用保存的同轮证据，仅写回答、不重取数、不续期。所有调用均经过原轮次控制器，计入额度、截止、取消和追踪。

日期输入与股票B2共用 `historical_date_inputs`：不带数量的最近、近期、近来、近日、目前、现在不指定历史区间，使用默认窗口；“最近一个月”“近20日”等数量条件完整保留，不能因模型省略而丢失。日期工具的固定空值拼写按已有共用规则归一化，清除首尾空白；具体日期仍须来自原文。无对象的数量区间追问也不能被旧窗口覆盖，未来观察期限与历史窗口继续分开。

指数回答有独立 `index-answer-v1` 结构，方向固定为偏多/震荡/偏空/暂不判断，把握为高/中/低并注明“模型自评，未经历史校准”。复用股票正文的数字绑定和技术关系校验，逐段、逐句保留合格内容；至少有一段有效“结论”明确包含与卡片一致的方向，其他段可以省略。提示词要求首句独立写方向与把握，再写数字理由，短窗口不引用不足的指标。复合标题按最先出现的类别词归类，如“情景与反向条件”归情景、“限制与情景”归局限；合法未知标题照原文保留，不能代替结论，原标题也要核对。跨指数/股票、错单位、错数、把历史读数当作计划、没有证据的量能/资金流/财报等句子删除；不输出公司买卖评级。局限段可说明“本轮不含成交量、资金流、板块或宏观信息”，不能借否定说明夹带其他肯定事实。指数复用缺失成分检测，并要求“处于低位读数区间”“仅作区间参照”等无主语残句不能独立发布；股票原规则保持默认行为。

`index-answer-quality-v1` 记录生成、保留、删除句数、保留和拒绝段数、部分保留句数及修复次数。删除内容时仍显示有效方向与把握，状态为 limited，并在纯文字和卡片提示“部分内容未通过核对已移除”；历史查看保留原计数。有效结论成立即返回，不为补齐其他段落再调用模型。结论或顶层结构不成立时最多修复一次；两稿均失败才保留程序核实的收盘读数，方向暂不判断。纯文字、状态和卡片使用同一个复核后的回答。

`index_pending` 和 `index_saved` 独立保存，15分钟有效；来源或开发模式变化失效。无对象追问只认最近成功发布且仍有效的研究主体。股票→指数→追问续接指数，指数→股票→追问续接股票。新研究开始即令旧主体失效；失败和取消不自动借用旧对象，显式历史可查看未过期快照。完整新任务按原成功替换待办规则发布；多个待办的短回复拒绝猜所有者。重置、取消、并发锁和迟到发布继续使用共用协议。

### 已实现的能力

本模块从明确的报价样本中执行数值条件筛选，再按用户指定的一个字段排序。它没有跨指标综合得分，不预测“潜力”或未来收益，也不拥有下单能力。

- 支持多个 AND 条件：`gt`、`gte`、`eq`、`lte`、`lt`；最多12项。
- 支持单字段升序或降序；相同原始值按证券代码升序稳定排列，最多展示50项。
- 缺失值保持 `null`。条件所需字段缺失时，该条件为 `unknown`，不会填0或当成已验证的条件失败。符合条件但缺少排序字段的记录单独计数，不排名。
- 返回逐项条件、实际数值、单位、报价更新时间、样本覆盖和来源。过旧报价单独计数，不与条件失败混在一起。
- 科创板、ST、新股、停牌股票没有被默认排除。不过，本模块没有独立的历史证券状态、上市日期或实时可交易性证明；没有出现在样本里的股票不能被说成“未通过筛选”。
- 提供完全离线的人工样例，也提供两个显式可选的公开报价适配器。真实来源失败不会变成人工样例、空结果或另一个供应商。

本模块不负责解析自然语言、选择模型或定义 HTTP 路由。Agent/API可调用下述公共接口；它们必须继续说明筛选范围是实际覆盖样本。

### 公共接口

#### 请求

```python
from trading_companion.screening import ScreeningRequest

request = ScreeningRequest.from_dict({
    "conditions": [
        {"field": "pe_dynamic", "operator": "gt", "value": 0},
        {"field": "pe_dynamic", "operator": "lte", "value": 20},
        {"field": "amount_cny", "operator": "gte", "value": 100_000_000},
    ],
    "sort_by": "amount_cny",
    "sort_direction": "desc",
    "limit": 10,
    "max_quote_age_days": 7,
})
```

| 字段 | 含义 | 规范单位 |
| --- | --- | --- |
| `price` | 最新价；没有报价或来源返回0时不可用 | 元/股 |
| `change_percent` | 供应商涨跌幅 | 百分数；`2.5`表示2.5% |
| `amount_cny` | 供应商当日报价中的成交额 | 元 |
| `turnover_percent` | 供应商换手率 | 百分数 |
| `pe_dynamic` | 供应商动态市盈率 | 倍 |
| `pb` | 供应商市净率 | 倍 |
| `market_cap_cny` | 供应商总市值 | 元 |
| `float_market_cap_cny` | 供应商流通市值 | 元 |

阈值必须是有限数字，不接受字符串、布尔值或模型添加的未知字段。PE/PB负数作为来源实际观察值保留。如果用户要求“盈利且PE不超过20”，应显式使用 `pe_dynamic > 0 AND pe_dynamic <= 20`，不能把负PE自动解释为便宜。

`max_quote_age_days`按上海日历日计算，允许0至14天。它限制供应商报价更新时间，不等于验证实际交易发生时间。采集快照本身只允许复用24小时，身份目录必须满足现有的7日新鲜度规则。

#### 返回内容

`result.to_dict()`的版本为 `quote-screening-result-v1`，主要字段如下：

- `status/code`：有结果为 `completed`；已核验、日期合格的样本确实没有符合条件项为 `empty`；没有日期合格的已核验报价为 `unavailable`。网络或无效响应由异常明确报告。
- `rows`：证券ID、目录名称、分层、报价时间、8个数值字段、逐条件 `passed/failed/unknown`、排序原始值及样本内展示位置。
- `conditions`：每个条件在日期合格的实际样本中的通过/不通过/未知数量。
- `coverage`：扫描数量、身份已核验数量、身份未知数量、没有报价数量、日期过旧数量、符合条件数量、缺少排序值数量、截断情况和逐字段覆盖。
- `coverage.strata`：每个分层的总量依据、实际选取或扫描数量、返回的核验报价数量、缺报价数量及请求次数。
- `coverage.directory_audit`：独立按可信目录ID统计五类目录量、已观察/尚未观察量、选中/未选中量（仅腾讯）、供应商未读量（仅东财）、抽样方法及名额。不会改变原有字段含义；尤其东财分层的`directory_records`仍为`null`，独立目录量放在新审计对象中。
- `source`：供应商、采集时间、身份目录元数据、采样方法和同一组分层覆盖。
- `overall_score/forecast`：始终为 `null`；`trading_enabled`始终为 `false`。

腾讯按可信目录选择样本，因此 `directory_universe_records`有值、`vendor_declared_records`为 `null`。东财有供应商列表总量，因此后者有值；这个数字仍不是独立证明的全市场总量。两种来源的 `independent_full_market_completeness_proven`始终为 `false`。

`quote_date`是供应商报价更新时间在上海时区的日期。它没有被包装成已经交易所核验的实际成交日期。跨请求的报价不是原子快照。

### 请求与错误边界

两种来源都只执行固定域名的GET请求。连接等待最多3秒，单次读取等待默认6秒、最多10秒；本次采集的合作式总截止默认25秒、最多30秒。超时不会强制终止已经发生的远端工作。

每个响应最多200000字节，总响应最多2000000字节。关闭响应对象，禁重定向，检查流式大小，不重试、不自动换源。原有取消和回合截止检查同样生效。

异常遵循现有项目契约：

- `InvalidRequestError`：不支持的字段、条件、排序、上限或可信配置。
- `DataValidationError`：身份目录不合格、重复或错配身份、协议改变、数值/时间无效、响应超限等。
- `DataSourceError`：来源连接、HTTP或采集截止失败。返回固定安全错误描述，不透出底层连接异常中的任意文本。

### 条件续改与双边区间（2026-10-27，B 部分，已提交）

首次筛选可以使用下列双边表达，结果将显示两个原子条件（每个原子条件只含一个比较符和阈值）：

- `筛选PE在10到20之间的股票`、`筛选PE介于10和20之间`：按`PE ≥ 10 AND PE ≤ 20`执行，包含两端。
- `筛选10 < PE <= 20`、`筛选20 >= PE > 10`：按原比较符保留开闭边界，不把`<`改为`≤`。
- `筛选PE不低于10且不高于20`：原文只写一次PE，仍可派生两个有原文依据的边界。模型必须为两个条件复制完整原区间片段，不编造第二个PE短语；漏一个边界、改阈值或方向均不取数。

正负数、百分数和人民币单位继续逐项核对。`成交额在1亿到2亿元之间`可执行；`成交额在1到2亿之间`不会猜省略的倍数，要求两端都写清。`换手率在2到5%之间`的两个数值均为百分数点。上下界写反、`10到20以上`、严格开区间空集、冲突相等条件、单位不符或未知尾句先澄清。相同端点只有两端包含时可表示该单点；负PE保留负值含义，不自动增加盈利条件。

同一会话保存的筛选条件可在原15分钟内续改，包括空结果的条件：

- `再加换手率大于2%`：追加条件，其他字段、排序、数量与报价日期限制保持原值。
- `把PE改为低于15`、`把PE改为在10到20之间`：仅替换已有PE字段的全部旧约束，其他字段保留。目标字段不存在时明确说明缺少哪个字段，并给出“再加动态市盈率低于15”等对应新增写法；不读取报价。
- `按市净率升序选3只`：仅改排序和数量；省略数量时继承原数量。省略方向时须用“排序/排列”或明确数量表明排序意图，例如`按市净率排序选3只`，沿用首次筛选的降序默认并在结果里显示。单独“按市盈率”不再据此判断为改条件。

每轮只修改一类：追加数值条件、替换一个字段，或修改排序与数量。最终仍限八字段、最多12个不同的AND原子条件、单字段排序、聊天展示1–20只；重复、无变化、冲突、中文数量、不完整句和任何未消费要求均不执行。有限续改完全由程序解析，不额外调用模型；无法解释时不会转交模型猜测。

有效续改会重新读取整个配置样本，不只筛上轮展示的几只；因此原先未展示的证券可以成为新名单成员。先消费旧名单和旧研究对象，再取报价；失败、取消或超时不恢复旧对象，不发布迟到结果，也不自动换源。成功后显示完整新条件、来源、样本覆盖和新序号，重新起算15分钟；无效修改不消费或延长原条件。新名单内仍最多选择三只继续研究。

路由在一般知识之后、完整新筛选及名单选择之前识别明确的条件续改；待回答的公司/技术身份与指标澄清仍优先，历史查看不触发修改。识别必须从句首锚定“再加＋字段＋数值比较/区间”“把＋字段＋改为数值条件”“按＋字段＋排序写法”，或显式“在原筛选条件上”前缀；是否保存名单不放宽语法，未知尾句仍交完整核对并拒绝。普通“按市盈率分析浦发银行的估值”“把浦发银行和平安银行的市盈率比较一下”回原公司研究；“把第一只和第二只比较一下”“按基本面分析第一只”回名单选择，无名单时说明名单不可用，不当成条件修改。“再加RSI”等回原技术入口，参数是否足够明确仍由原流程决定。当前公司研究对象存在时，结构明确的“再加换手率…”等仍修改保存的筛选条件。没有基准、过期、时间倒退、目录/身份、来源或Dev模式不符时，在模型和取数前拒绝；正常模式的条件不能借到Dev模式。知识问题与历史查看不消费也不延长原条件，幂等重放不重复取报价。没有新增HTTP路径、客户端可写可信上下文或前端协议。
