## 公开回答与展示

2026-10-29 A4（方案 #199、批准 #200）：DeepSeek 无工具声明的结构化回答使用 4096 输出 tokens，上界配置允许到 8192；有工具声明的请求仍最多 1500。token 是模型计量文本长度的单位。无工具回答启用 JSON 对象模式，纯文本 CLI 仍用独立文本适配器。提示要求最多四条 drivers、每条一至两句，numbers 优先标注关键价位，负百分比显式写负号；数字容差、评级和价位公式不变。

供应商返回 `finish_reason=length` 时，记录 `answer_output_truncated`，不解析或恢复任何前缀；有预算时仅使用原有一次精简重写机会。两稿均截断时回到程序事实；第二稿截断时保留首稿已核验的内容。发生截断的公开 `quality` 增加 `output_truncation_version=answer-output-v1`、`output_truncations`、`initial_output_truncations`、`repair_output_truncations`；无截断的正常回答保持原有形状。诊断和 trace 始终记录带版本的计数（含零），评估从 trace 取得零计数，不以旧答案缺字段推断为零；诊断保留结束原因，普通 trace 不保存正文。

仅完整返回的草稿允许一次有界标点恢复：最多四处插入缺失的 `}`/`]` 或删除容器末尾逗号，包括内层右括号缺在外层结束符之前的情况。扫描识别字符串与转义，不补键、值、引号或词句；修复后仍严格拒绝重复键、NaN、多对象、不安全包装，并走完整结构和同股数字检查。`punctuation_structure_recoveries` 单独计数，也计入本地结构恢复；原有完整字段前缀恢复仅用于完整返回但结构受损的草稿，不能用于已知截断。

公司研究与参考研判统一返回 `product-research-answer-v3`。每股一组 `narratives`：`summary` 直接结论、`current` 带日期的当前情况、`drivers` 主要依据、`levels` 关键价位、`scenarios` 基准/变好/变坏条件、`stance` 操作倾向。评级 `decisions` 与原 ATR 条件计划独立保留，普通基本面回答不强加评级。

文字块是 `{text, evidence_ids}`；引用可省略，程序仍按本股实际发送给模型的资料核对数字。公开引用转换回完整证据 ID。价位输入只能选程序生成的 `price_levels` ID，不能让模型填入上下界；公开表格由程序填 `lower/upper/lower_label/upper_label`。计划端点也有独立引用，模型无法改公式。

前端用 React 文本节点显示，有限解析 `**粗体**`，列表与表格由组件构造。没有通用 HTML/Markdown 执行器，文本中的图片、链接和标签不会成为元素。来源链接仍由应用原有域名白名单控制。v3 的公开来源上限为480条，以容纳三股各5期财务与新增窗口事实；单条和其他结构限制继续核对。历史 v1/v2 仍保持240条来源上限，读取与展示继续支持；旧协议专项测试使用明确命名的 legacy 入口，当前业务统一走 v3 的测试。

`quality` 由程序生成：`complete/partial/fallback`、固定 `code`、最多20个原因位置、句子计数、修正次数、结构失败次数及下述数字词元计数。`narratives[].origin=application` 的价位表列名为“程序事实”；模型解释才叫“我的判断”。资料超时说明同步进入结构化显示。

整轮 `status=limited` 与回答 `quality.state=complete` 可以同时成立：前者表示请求的资料有缺项，后者表示已生成的内容通过本轮校验。此时回答顶部按 `coverage` 列出实际未取得的领域；可用、明确排除和未请求的领域不列为缺项。

## 新增证据口径

`research_price_context.py` 使用本轮已检查的同一份 `technical.bars`，不再获取行情：

| 事实 | 算法与缺失条件 |
| --- | --- |
| 最新收盘 | 最后已完成日线，不是盘中实时报价 |
| 近5/20/60日涨跌幅 | `(C_t/C_(t-N)-1)*100`，分别要求 N+1 条有效记录 |
| 20/60日高低点与日期 | 最近 N 条 high/low；并列取最近日期，样本不足不输出 |
| MA20/MA60 | 最近 N 条收盘算术平均，样本不足不补值 |

证据的 `calculation_basis` 保留版本、复权口径、样本数、日线截止、并列规则与依赖命名空间。`request|raw_daily_bar|日期|字段` 是归档中 `technical.bars` 的行/列引用，并非原指标 `facts` 的 ID；每个引用都能定位同请求的冻结原始行。高低点依赖完整窗口，收益依赖首尾收盘，均线依赖窗口收盘。

财务接口原本一次请求最多5个报告期，现在保留这次响应中合格的5期、每期5字段（上限25），不增加请求或翻页。原披露截止、更新日期和人民币口径检查继续生效。`financial_periods.py` 只对同公司、来源、币种及指标的累计数据差分：Q1直接采用，其他季度减本年上一期；同比另需去年同季所需的累计记录，分母为0则缺失。记录全部依赖和最晚披露日。依赖缺失或同一报告期有歧义修订时不推导，缺失不写0。

模型上下文按公司与领域分配额度，优先价格、计划和财务，最终再按现有模型消息预算裁剪；删掉的证据也从可用价位中删除，引用不得悬空。A2 为修正消息预留800字符；最多4项、合计700字符的反馈，原句每项最多80字，按评级、结构、其他问题排序并去重，包含证券、字段路径、失败条件及至多两个候选值。超限时先省候选细节。预算仍不足时保留完整计划证据，优先保留当前日线价格资料，再从末尾裁剪其他证据；三股场景同时受原有调用与超时控制。

## 校验与一次修正

`answer_validation.py` 按句检查，不能证明任意自然语言推理属实。硬拒绝限于收益/涨跌保证、自编概率或胜率、HTML/链接/指令注入、声称执行、跨股错配。定位到一句就删该句，硬风险文本不反馈给模型。普通数字、日期、期限、引用和结构问题为软错误，最多修正一次。

数字由模型声明来源，程序使用 Decimal（精确十进制）核对本股、本轮实际供应的来源、值与单位。普通数字的指标、窗口、日期关联及财务报告期由模型负责选择，程序不再用邻近关键词推断它们。**核对通过只能说明数值与所选来源相容，不能证明文字中的指标、时期或解释正确**；未标注数字的语义保障更弱。提示仍要求区分累计/单季、日线/周线及标题/正式财报，人工复核要检查这些含义。

价格容差仍为 `max(0.01元,0.5%)`，微小价格另受2%上限约束；粗舍入需落在显示精度的半单位内、至少2位有效数字且相对误差不超过2%。金额先换算人民币元，再按显示末位半单位舍入，无金额百分比容差。百分比和百分点、价格和金额分别有类型；`元/股`只匹配价格。无显式符号的“下降5%”可对应-5%，显式正负号与方向冲突时拒绝，“涨跌幅”保持中性。区间两端均核对，并检查顺序，没有统一放宽容差。

有效日期须在请求历史范围或本股供应记录的日期/报告期中，但不再推断它属于旁边哪个数字。`1-9月`等期间、20日均线的参数、止盈1的序号和合法证券代码不作为裸数值。`一个月/未来1个月/下个月` 期限归一及评级期限检查保留，明确两个月不改成一个月。当前不支持的中文金额数字、外币换算等表述软删除，可在修正时改成可核对形式。

### A3 数字标注协议

每个文字块可附可选 `numbers` 数组，包括 summary、current、drivers、levels、scenarios、stance、评级理由与失效条件；标题中的数字也检查，但不另设标题标注字段。例子中的编号须替换为本轮实际编号：

```json
{"text":"若收盘跌破25.99元，应重新评估。","numbers":[{"text":"25.99元","ref":"L5","field":"reference_stop"}]}
```

`text` 必须在所属文字块中逐字且唯一出现；重复片段、重叠和格式错误拒绝。能够定位时只影响相应句子，定位不到时影响该文字块。坏标注不会退回未标注搜索。原因码区分 `answer_binding_invalid`（来源或标注无效）与 `answer_binding_value_mismatch`（来源有效但值不符）。跨股仍按原安全规则拒绝。

| 字段或编号 | 含义与限制 |
| --- | --- |
| `ref=E…` | 实际供应的一条证据，公开引用还原完整证据 ID |
| `ref=L…` | 实际供应的一条价位，展开为背后的 E 和确定字段 |
| `field`，可省略 | 仅选择该记录公开的字段，如 `latest_close`、`close_20d_ago`、`revenue_yoy`、`reference_stop`、`target_1`；不接受任意对象路径或自报值 |
| `derive=distance` | 唯一开放的派生计算，必须配恰好两个有序 `refs` |

同股所有实际供应证据均参与未标注数字的兜底，不受段落 `evidence_ids` 缩小；裁掉的证据、其他股票和其他轮资料不可用。精确值优先，否则多个不同值同时落入容差就拒绝；相同值、相同类型的重复来源可合并。整句所有数值都检查，成功匹配的来源补回公开引用。新闻/公告只使用实际供应的标题文本，诊断标记 `source=title`，不能当作完整正文或正式财务字段。

距离示例：

```json
{"text":"止损11.20元距收盘11.54元约2.9%。","numbers":[{"text":"11.20元","ref":"L2","field":"reference_stop"},{"text":"11.54元","ref":"E8"},{"text":"约2.9%","derive":"distance","refs":["E8","L2"]}]}
```

`refs[0]`是基准及分母，`refs[1]`是比较价，计算 `abs(second-first)/abs(first)*100%`。两端须为同股、人民币每股单位、实际供应且各自唯一的正价格；多价计划应用 L 选择单价。分母为零、端点歧义、跨股及其他派生类型均拒绝；原稿未标注的距离不猜计算关系。

明确“止损、止盈1、止盈2、入场参考、退出观察位、上下方观察位”后紧邻数字仍须对应计划字段，标成另一字段也不能绕过。计划数值取已核对的结构化 `values`，不再从“止盈112.05元”等展示串反推。levels 端点应选 L；误写 E 时只在其能唯一映射到已有同股价位时兼容，不造新价位。上下文裁剪同步移除依赖该证据的价位。

`quality.numeric_validation_version=source-bindings-v1`；`numeric_tokens` 是实际核对的数字词元数，`bound_numbers` 是其中已绑定数量；另列 `bound_matched/bound_rejected`、`unbound_matched/unbound_rejected` 和失败子集 `unbound_ambiguous`。同一句可有多个词元，计数不能当删句数；格式/安全检查提前拒绝的内容可能未进入词元核对。标注及完整资料不进入公开回答。固定版本和有界计数可入普通 trace，原文只进显式本地诊断。

正文和评级分别接收。评级仍核对身份、期限、评级/方向、理由及计划用途。坏数字句不抹掉有效评级，坏评级不抹掉有效正文。首版有效字段与列表位置保留，修正只补缺失位置；部分通过的文字块可追加修正后的干净句子。最终合并后再核对结论与评级方向。整体 JSON 无法解析也允许一次结构修正；取消、调用预算和超时仍直接服从控制器。

计数定义：`generated_sentences` 累计两次草稿实际检查的句子（含小标题）；`deleted_sentences` 累计被拒绝的句子；`retained_sentences` 是最终保留的模型句子，两次草稿的相同句子不会在最终回答里重复。因为修正草稿可能重复首版，三个计数不要求相加相等。`retained_paragraphs` 为最终有模型内容的段落数。结构无法解析不虚构句子数，由 `structure_failures` 单独计数。

## 事实兜底与诊断

模型完全失败时展示程序事实、最新可用行情/财务及观察价位；已有 ATR 计划继续显示。缺资料明确说明，不补造“持有”或任何已形成评级。计划/上下文完整性检查失败不向模型或表格泄漏无效价位。没有证据不调用模型。

追踪保持 `trace-v2`，增加 `answer_validation` 事件，内含固定 `version=1` 的白名单元数据；不存问题、答案、错误原句或反馈。`product_answer` 逐次记录草稿检查，评估可区分先拒绝、修正通过与最终兜底。CLI 可按运行号查询：

```powershell
.\.venv\Scripts\python.exe -m trading_companion.trace_cli --trace-dir data\traces --run-id <32位运行号>
```

`start.cmd` 默认开启 `data\traces`，`--trace-dir PATH` 可覆盖，`--no-trace` 优先关闭；直接启动 Python 服务仍默认关闭。容量、故障隔离和旧 trace 读取维持原约定。

## A2：局部接收、格式恢复与本地诊断

方案 #175 经 #176 批准。v3 研判保留至少一条通过核对的理由即可形成；尽量提供2～4条。无效理由逐条删去，`reason_review` 只公开保留/删除数和原因码。模型失效说明不合格时，只有同股、同用途、可用程序计划及相应证据都存在才补充条件，标记 `invalidation_origin=application`；不计作模型保留句。缺少合法计划不编造条件。历史 v1/v2 的读取契约不变。

操作倾向识别有限同义表达，并处理否定和跨逗号条件范围；条件性退出不等于当前卖出建议。明确反向时仅删除对应结论/倾向，已核对的评级独立保留。一次修正保留原有效评级、方向、期限、把握及计划身份；这些身份全部一致时，才按理由原位置补缺及替换程序补位的失效说明。

`narrative_answer_parser.py` 将表示格式与内容分开：先严格 JSON 解码，再尝试单层围栏/说明中的唯一完整对象，或截断外层中的完整前缀字段、完整数组条目。只接收实际解码出的值，不补半截对象，不改内容。重复键、非有限数、多个对象、危险前后文或中间语法坏片段不救援。narratives/decisions 独立检查；恢复部分仍必须逐项通过身份、引用、安全和数字规则。原始解析失败仍计入 `structure_failures`；本地完整/部分恢复另计，不能冒充模型修正。

`answer_diagnostics.py` 仅在评估显式指定 `--diagnostics-dir` 时绑定收集器，默认不创建文件。实际路径必须在 `.agentbus/tmp/`，解析后越界的符号链接/目录联接拒绝；每次唯一子目录写 `records.jsonl`，最多4000条、8 MB。记录题号、草稿/修正阶段、字段及句位置、被拒原句、实际数字匹配候选/误差/拒绝原因、反馈、各稿和最终接收结果。候选最多三个，匹配候选优先，其余按差值排序；未检查的原因保留未知，不另造一套核对规则。A3新增 `model_context` 保存最终实际供应快照，及 `plan_purpose_corrected` 保存用途纠正的原/新计划 ID。写入失败或限额截断将诊断标为不完整，并使显式诊断评估失败。传输在草稿返回前失败只记无草稿状态，不强取原文。

原句、反馈和完整供应快照不进入公开原因、普通 trace 或正式报告。A2当时保持数字规则不变，诊断重跑形成16/20；A3按用户选择C调整普通数字语义责任，保留上述单位、容差及明确计划字段约束。完整B上下文交接仍未实施。[117轮A2差异记录](request-routing-a2-deltas.md)和[A3独立差异](request-routing-a3-deltas.md)保留旧观察器和历史文件。

## A3：确定的计划用途纠正

仅当模型原 `plan_id` 是本轮实际供应、同股、真实可用的计划，且按已接受评级可选出唯一合法用途计划时，程序纠正用途；保留评级、方向及原程序价格。未知 ID、跨股、未供应及不唯一均拒绝。纠正后重新检查失效说明是否对应新计划；不能核对时沿用A2程序条件补位并标明 `invalidation_origin=application`。这不为模型补选评级，也不修改ATR计划公式。
