# 对话式研究界面

初版：2026-10-24。最新界面修订：2026-10-25。

2026-10-25 UI 清理：发送问题直接触发请求，首次发送自动创建会话；移除 DeepSeek 发送确认卡、侧栏许可勾选和前端许可状态门。移除回答后的固定 RSI / DIF、DEA / 调整指标追问按钮，以及整个“本轮详情 / 参数与执行记录”区块。聊天不再展示内部状态码、调用计数、默认参数清单、工作流和引用诊断；来源、人工行情标记、图表、证据与完整报告仍保留。该次清理未改变后端执行器、校验、额度与取消；后续模式改动另见下文，历史验收分开记录。

同日后续修订：研究主回复已改为 `conversation` 自然语言正文，先回答问题，再给条件性方向和观察条件；人工/不足数据返回简短说明。下文的“标题→读数→观察”仅是旧展示协议和知识/保存结果追问的兼容路径，不再是新研究主答复。见[自然语言答复设计](natural-research-response-design.md)。

## 本轮解决的问题

旧页面直接展示 `display_answer`：事实报告、关系解释、四维综合和多轮限制说明被拼在一起。仅调整字体不能解决信息重复，因此本轮同时调整展示协议和交互布局，不修改研究计算或新增模型调用。

当前默认阅读顺序是自然语言回答 → 按需展开图表、证据、证券背景和完整报告。旧的简短标题、读数和观察仍用于兼容视图，不再把执行记录或内部诊断作为聊天附件。重复的通用免责声明不占据主界面；人工行情、历史结果、缺失读数、模型解读失败等影响理解的信息仍直接可见。

## 数据与组件如何协作

```text
Agent 的核验结果 / 已保存的结果
  → public_turn：保留原 answer、report、chart 和状态
  → conversation：自然语言主答复；answer_presentation：兼容紧凑视图
  → 前端：正文、可选视图与股票/日期绑定检查
  → ResponseContent：优先正文；兼容读数卡片、观察与定义
  → App：消息列表、输入框、折叠附件和会话控制
```

- `src/trading_companion/answer_presentation.py` 只使用应用已核对的对象。简短句子来自已知关系枚举与固定模板，不用字符串替换删除任意模型文本，不把参考位置包装成收益预测。
- `research_followup.py` 保留已接受的定义主题和核对关系。追问视图只展示相关指标，标明“基于已保存结果 · 未重新取数”；历史概览必须匹配原快照。
- `frontend/src/presentation.ts` 把新视图当作可选数据。坏结构或错请求编号只让卡片降级，不丢掉已确认的答案，也不触发模型重试。研究读数仍来自原始 `report.fields`，显示舍入不改变计算精度。
- `frontend/src/ResponseContent.tsx` 分开渲染关键读数、观察、知识解释和证据表。超过六项读数可以本地展开；缺失值保留为“—”，不补零。
- `frontend/src/App.tsx` / `styles.css` 提供固定页头与输入区、独立滚动的消息区、会话目录和手机导航。自动滚动只作用于消息区，从最新回答顶部开始；用户上翻时不强制拉回。
- `frontend/src/controller.ts` 沿用原请求、取消、幂等重放和会话状态机；新增明确的通知级别，让实际错误始终可见，不通过错误文案关键词猜测是否显示。

新视图有异常时返回 `null`；旧客户端仍可读取原答案，新客户端也能展示没有新视图的旧服务响应。界面始终用 React 文本节点渲染外部内容，不执行 HTML。

## 使用变化

- 桌面左侧为当前会话目录，不是假装支持持久化的多会话列表。
- 打开页面即可输入，首次发送自动建立会话；不再要求点击“开始会话”。左侧“新对话”结束当前会话并清空页面，下一条发送时再创建。手机点击左上角展开导航，发送不依赖侧栏。
- Enter 发送，Shift + Enter 换行；继续支持 Ctrl/Cmd + Enter。中文输入法组合输入和 keyCode 229 不触发发送。
- 点击示例或澄清候选只填入输入框，不自动提交。
- 本机服务设置中查看配额规则、连接诊断、接口文档，检查状态或结束会话。
- DeepSeek 与其他模式使用相同发送方式，不再要求确认卡或许可勾选；只有用户明确发送时才创建会话并提交问题。页面载入、写草稿、选择示例或候选不会请求模型。真实提供方仍可能计费，每个后端的来源由服务端启动配置固定；Dev Mode 只切到独立预配离线服务，不允许自由配置模型或行情，未增加存储或下单权限。
- 回答后不再固定显示 RSI、DIF/DEA 和调整指标按钮；需要追问或修改条件时，直接在输入框发送自然语言。
- 不再提供“本轮详情 / 参数与执行记录”，也不在正文尾部显示内部状态码、模型/分析计数、默认参数、工作流或引用诊断。后端仍返回和校验原有结构化字段，图表、证据与完整报告仍可按需查看。

首次创建失败会显示错误并恢复原草稿，不自动重试；创建过程显示进度并阻止重复发送。初次检查连接期间仍可写草稿，断连时输入框旁提供重新连接。点击“新对话”不预先创建空会话；删除旧会话失败时保留原聊天和草稿，旧会话已过期则可直接回到空白对话。存在响应未确认的原请求时，仍禁止另开会话或换编号重发；这里的“未确认”是网络结果未知，不是已经移除的发送许可。

### 正常模式与 Dev Mode

网页默认正常模式，服务默认使用 DeepSeek + 腾讯历史日线。Dev Mode 按钮切换到同源 `/dev-api` 下的独立 `fake + synthetic` 后端，不用为切换重启 Python；两个后端不共享会话令牌、模型实例或预算，也不会迁移旧结果。

仅空闲且没有未确认请求时能切换。原会话清理失败不丢弃原聊天；清理成功后立即选择目标并清空聊天、草稿和凭据，再检查目标 health。目标 health 失败会留在已选目标的断连空白状态，不恢复已删除聊天、不自动回退或重发；可手动重连或重新切模式。连接成功后，下一条发送才创建目标会话。页面刷新回正常模式，不通过浏览器存储记住开发选择；`--demo` 离线启动没有可切回的正常后端。

人工模式明确标记来源，只包含四条证券目录和五根平安银行人工日线，不能用来研究任意股票。按钮只是界面能力入口，不替代服务端鉴权和数据边界；完整路径和失败状态见[模式设计](dev-mode-design.md)。

## 构建与查看

升级到正常/开发双模式需要重新构建前端并重启 Python 服务，旧进程不会因源文件变化自动增加 `/dev-api` 路由。此后页面内模式切换不用重启；刷新前先确认没有在途或响应不确定的请求。

从 GitHub 拉取后，在项目根目录运行：

```powershell
pnpm.cmd --dir frontend install --frozen-lockfile
pnpm.cmd --dir frontend build
.\.venv\Scripts\python.exe -m trading_companion.api_server
```

打开 `http://127.0.0.1:8765/`。正常模式需先按[本地配置与启动](local-environment.md)准备根目录 `.env` 和有效真实目录，启动只做本地检查，实际提交问题才调用所需模型/行情，密钥不进入前端。需要离线脚本时点 Dev Mode，或使用显式 `--demo` 启动：可依次手动发送“分析平安银行，2026-09-21 至 2026-09-25，只看SMA3和RSI2”“这里的RSI为什么偏高”“把SMA3改成5日，其他不变”；指标知识可穿插。它们不是回答后必须点击的快捷按钮，Fake 模型也不是任意对话模型。
