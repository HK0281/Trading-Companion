# 有界 A 股报价样本筛选

## 腾讯批次并发（2026-10-28，3c 工作区待审核）

腾讯来源默认同时获取最多3个固定ID批次，和公司资料共用全进程3个未完成任务名额；东方财富所有配置下仍逐页读取。standard默认每板块50个ID、五板块共5批，expanded每板块最多200个、默认80个一批共15批；可信batch_size=50时最多20批。原代码前缀/均匀间隔选样、板块及批次边界、名单排序和覆盖说明不变，不跨板块混批、不补样本。

服务端和独立命令均可用`--collection-workers 1`做同来源串行对照，或收紧到2；默认3。独立命令示例：

```powershell
.\.venv\Scripts\python.exe -m trading_companion.screening_cli --live --directory data/security-directory.json --condition price gt 0 --screening-coverage expanded --collection-workers 1
```

目录路径应替换为实际新鲜的非人工证券目录。参数非法在取目录和联网前拒绝；独立`--demo`不接受显式在线并发配置。聊天和HTTP没有修改该可信配置的字段。腾讯注入客户端工厂每批使用独立客户端；旧借用`session=`默认串行且跨调用互斥，不由采集器关闭，不能与并发2/3或工厂同时使用。

来源窗口仍默认25秒、最多30秒，整次只起算一次，排队也计入；请求仍最多20、每响应200,000字节、实际总响应2,000,000字节。每个块在保留前原子扣共享预算，失败不退款。任何批次传输、协议、预算或截止失败，整次不发布快照/部分名单；合法遗漏和no-match仍按`missing_quote_records`计数。整轮取消直接传播，迟到任务持续占槽直至结束，不能修改新轮的名单或追踪。并发失败时已经发出的请求可能多于原串行首错即停，但不超原计划且观察到错误后不再提交，不重试、不换源。

追踪仍是一条`screening_snapshot`逻辑读取。离线固定100ms等待下，5/15/20批的串行与并发3理论等待分别为5→2、15→5、20→7；人工样本的快照、条件结果、覆盖、请求批次和字节均逐字段相同。原始计时、测试范围和限制见[并发设计](collection-concurrency-design.md)。这些数据不能证明真实来源速度、当前限流或全市场完整性。

## 已实现的能力

本模块从明确的报价样本中执行数值条件筛选，再按用户指定的一个字段排序。它没有跨指标综合得分，不预测“潜力”或未来收益，也不拥有下单能力。

- 支持多个 AND 条件：`gt`、`gte`、`eq`、`lte`、`lt`；最多12项。
- 支持单字段升序或降序；相同原始值按证券代码升序稳定排列，最多展示50项。
- 缺失值保持 `null`。条件所需字段缺失时，该条件为 `unknown`，不会填0或当成已验证的条件失败。符合条件但缺少排序字段的记录单独计数，不排名。
- 返回逐项条件、实际数值、单位、报价更新时间、样本覆盖和来源。过旧报价单独计数，不与条件失败混在一起。
- 科创板、ST、新股、停牌股票没有被默认排除。不过，本模块没有独立的历史证券状态、上市日期或实时可交易性证明；没有出现在样本里的股票不能被说成“未通过筛选”。
- 提供完全离线的人工样例，也提供两个显式可选的公开报价适配器。真实来源失败不会变成人工样例、空结果或另一个供应商。

本模块不负责解析自然语言、选择模型或定义 HTTP 路由。Agent/API可调用下述公共接口；它们必须继续说明筛选范围是实际覆盖样本。

## 公共接口

### 请求

```python
from trading_companion.screening import ScreeningRequest

request = ScreeningRequest.from_dict({
    "conditions": [
        {"field": "pe_dynamic", "operator": "gt", "value": 0},
        {"field": "pe_dynamic", "operator": "lte", "value": 20},
        {"field": "amount_cny", "operator": "gte", "value": 100_000_000},
    ],
    "sort_by": "amount_cny",
    "sort_direction": "desc",
    "limit": 10,
    "max_quote_age_days": 7,
})
```

| 字段 | 含义 | 规范单位 |
| --- | --- | --- |
| `price` | 最新价；没有报价或来源返回0时不可用 | 元/股 |
| `change_percent` | 供应商涨跌幅 | 百分数；`2.5`表示2.5% |
| `amount_cny` | 供应商当日报价中的成交额 | 元 |
| `turnover_percent` | 供应商换手率 | 百分数 |
| `pe_dynamic` | 供应商动态市盈率 | 倍 |
| `pb` | 供应商市净率 | 倍 |
| `market_cap_cny` | 供应商总市值 | 元 |
| `float_market_cap_cny` | 供应商流通市值 | 元 |

阈值必须是有限数字，不接受字符串、布尔值或模型添加的未知字段。PE/PB负数作为来源实际观察值保留。如果用户要求“盈利且PE不超过20”，应显式使用 `pe_dynamic > 0 AND pe_dynamic <= 20`，不能把负PE自动解释为便宜。

`max_quote_age_days`按上海日历日计算，允许0至14天。它限制供应商报价更新时间，不等于验证实际交易发生时间。采集快照本身只允许复用24小时，身份目录必须满足现有的7日新鲜度规则。

```python
from trading_companion.screening import (

snapshot = demo_screening_snapshot()

```

### 真实报价采集

```python
from trading_companion.security_directory import load_security_directory
from trading_companion.screening import ScreeningService
from trading_companion.screening_source import TencentQuoteSnapshotSource

directory = load_security_directory("data/security_directory_live.json")
snapshot = TencentQuoteSnapshotSource().read_snapshot(directory)
result = ScreeningService().screen(snapshot, request)
```

也可显式选择 `EastmoneyQuoteSnapshotSource()`，调用方式相同。两者是启动配置选项，没有“腾讯失败后自动用东财”或反向切换。

`ScreeningService(clock=...)`、`demo_screening_snapshot(clock=...)`以及两种来源的`session`和`clock`均可注入，便于固定时间及离线测试。底层身份、快照、分层覆盖等对象都为不可变dataclass，并在构造时检查契约。

### 返回内容

`result.to_dict()`的版本为 `quote-screening-result-v1`，主要字段如下：

- `status/code`：有结果为 `completed`；已核验、日期合格的样本确实没有符合条件项为 `empty`；没有日期合格的已核验报价为 `unavailable`。网络或无效响应由异常明确报告。
- `rows`：证券ID、目录名称、分层、报价时间、8个数值字段、逐条件 `passed/failed/unknown`、排序原始值及样本内展示位置。
- `conditions`：每个条件在日期合格的实际样本中的通过/不通过/未知数量。
- `coverage`：扫描数量、身份已核验数量、身份未知数量、没有报价数量、日期过旧数量、符合条件数量、缺少排序值数量、截断情况和逐字段覆盖。
- `coverage.strata`：每个分层的总量依据、实际选取或扫描数量、返回的核验报价数量、缺报价数量及请求次数。
- `coverage.directory_audit`：独立按可信目录ID统计五类目录量、已观察/尚未观察量、选中/未选中量（仅腾讯）、供应商未读量（仅东财）、抽样方法及名额。不会改变原有字段含义；尤其东财分层的`directory_records`仍为`null`，独立目录量放在新审计对象中。
- `source`：供应商、采集时间、身份目录元数据、采样方法和同一组分层覆盖。
- `overall_score/forecast`：始终为 `null`；`trading_enabled`始终为 `false`。

腾讯按可信目录选择样本，因此 `directory_universe_records`有值、`vendor_declared_records`为 `null`。东财有供应商列表总量，因此后者有值；这个数字仍不是独立证明的全市场总量。两种来源的 `independent_full_market_completeness_proven`始终为 `false`。

`quote_date`是供应商报价更新时间在上海时区的日期。它没有被包装成已经交易所核验的实际成交日期。跨请求的报价不是原子快照。

## 腾讯来源：默认可选方案

固定公开端点：`https://qt.gtimg.cn/q=`。请求中的证券只能来自调用方预先配置、已验证且新鲜的非人工目录，不能由模型提供任意URL或任意身份映射。

1. 按沪市主板、深市主板、科创、创业和北交5层划分当前目录。
2. 默认标准档每层按代码升序选择前50个，可信配置可调到每层最多100个，总数最多500个。扩大档每层最多200个，按完整目录代码排序后，令`q=min(目录数量,名额)`，选择下标`floor(i × 目录数量/q)`，`i`为0至`q-1`。目录为空则不选择任何ID；其余恰好抽满`q`个互不重复、递增的均匀位置，例如401条、名额200会取200条；小目录取全部。无随机数，同一目录可复现；覆盖更靠后的代码不等于证明上市年代或统计代表性。标准档选择保持不变。
3. 每批最多80个代码；允许的可信批次配置为50至80。标准档每层最多2次、全程最多10次；扩大档最多1000个ID，默认80只/批时每层最多3次、全程15次，批量为50时最多4次/层、全程20次。没有逐股HTTP请求，原响应字节和25秒默认截止不因扩大而放宽。
4. 对返回的变量名、代码、名称、币种和完整上海时间逐项核对。来源未返回某个已选ID时，计为 `missing_quote_records`，不当作条件失败或身份未知。
5. 正常名称只做Unicode和空格规范化；科创来源额外的 `-U`尾缀允许与目录中的同代码完整基础名称匹配。其他改名、ST变化等不自动放宽。最终输出保留可信目录名称，不根据这个后缀宣称已核验盈利状态。
6. 响应只按固定赋值语法解析；没有执行JavaScript、`eval`或动态导入。

逐字段映射已经通过实际原始响应检查，不能将相近字段混用：

| 返回索引 | 规范字段 | 转换 |
| --- | --- | --- |
| 3 | `price` | 元/股 |
| 30 | `quoted_at` | `YYYYMMDDHHMMSS`，上海时区 |
| 32 | `change_percent` | 原始百分数 |
| 38 | `turnover_percent` | 原始百分数 |
| 46 | `pb` | 原始比率 |
| 52 | `pe_dynamic` | 原始动态PE；不用索引39或53替代 |
| 57 | `amount_cny` | 万元×10000；与索引35内人民币成交额交叉核对，允许1元显示精度差 |
| 45 | `market_cap_cny` | 亿元×100000000 |
| 44 | `float_market_cap_cny` | 亿元×100000000 |

例如2026-10-26实测平安银行，动态PE索引52为4.20；索引39为5.04，不能替代。成交额索引57为148599.9504万元，与索引35中的1485999504元一致。此记录用于验证协议映射，不保证未来接口不变。

当前的交易所目录刷新来源覆盖沪深，未提供独立北交目录。腾讯本身实测能返回`bj920000`报价，但正式服务只有在可信目录包含北交身份时才采集它。目录未覆盖北交时，该层的目录数和采样数都为0；不能说北交股票没有通过条件。

## 东方财富来源：显式备选

固定公开端点：`https://82.push2.eastmoney.com/api/qt/clist/get`。它是供应商公开接口，不是本项目拥有的有SLA的官方交易所API。

5层`fs`筛选器固定为：

| 分层 | 固定筛选器 |
| --- | --- |
| 沪主板 | `m:1 t:2` |
| 深主板 | `m:0 t:6` |
| 科创 | `m:1 t:23` |
| 创业 | `m:0 t:80` |
| 北交 | `m:0 t:81 s:2048` |

每层默认1页，每页最多100条；最多每层2页、合计10请求/1000条。使用代码升序，不按返回的候选数冒充全市场完整性。检查逐页长度、总量一致性、重复ID、代码顺序和分层身份，任何页失败则本次采集失败。

字段映射：`f2`最新价、`f3`涨跌幅、`f6`人民币成交额、`f8`换手率、`f9`动态PE、`f23`PB、`f20/f21`人民币总/流通市值、`f12/f13/f14`身份、`f124`带日期的Unix报价更新时间。未被当前可信目录核验的合法来源证券计入 `unverified_records`，不进入筛选，也不计为条件失败。

实现参考了[AKShare的公开报价列表适配器](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_hist_em.py)使用的接口类别，但本模块直接进行有界请求、验证和单位转换，不导入AKShare进行整市场扫描。具体公开端点参数以本模块固定配置和实际响应核验为准。

## 请求与错误边界

两种来源都只执行固定域名的GET请求。连接等待最多3秒，单次读取等待默认6秒、最多10秒；本次采集的合作式总截止默认25秒、最多30秒。超时不会强制终止已经发生的远端工作。

每个响应最多200000字节，总响应最多2000000字节。关闭响应对象，禁重定向，检查流式大小，不重试、不自动换源。原有取消和回合截止检查同样生效。

异常遵循现有项目契约：

- `InvalidRequestError`：不支持的字段、条件、排序、上限或可信配置。
- `DataValidationError`：身份目录不合格、重复或错配身份、协议改变、数值/时间无效、响应超限等。
- `DataSourceError`：来源连接、HTTP或采集截止失败。返回固定安全错误描述，不透出底层连接异常中的任意文本。

### 扩大样本档与目录对账（2026-10-27，待审核）

服务端启动与独立CLI均可显式启用：

```powershell
.\.venv\Scripts\python.exe -m trading_companion.api_server --screening-data tencent --screening-coverage expanded --port 8765
.\.venv\Scripts\python.exe -m trading_companion.screening_cli --live --source tencent --directory data/security_directory_live.json --screening-coverage expanded --condition pe_dynamic gt 0 --condition pe_dynamic lte 20 --sort-by amount_cny --limit 5
```

`--screening-coverage`默认为`standard`，扩大档只由可信启动参数授权。CLI的`--per-stratum`和`--pages-per-stratum`只用于标准档，不可与扩大档混用，也不可用错供应商；冲突在读目录/联网前拒绝。人工演示不接受在线采样配置。`configured_quote_source()`统一两种入口的档位，扩大档腾讯用均匀间隔200名额、东财复用每层两页。扩大档会增加请求、延迟及限流风险；目前只完成离线验证，真实速度、稳定性和独立市场完整性仍待联网核验。默认样本不变。

新增的`screening-directory-audit-v1`审计对象以五类目录ID与已核对报价集合对账，计数关系如下：

- `directory_records = directory_observed_records + directory_unobserved_records`，分层合计与目录及已核对报价总量一致。
- 腾讯的`directory_selected_records`为实际选中的目录ID数，`directory_not_selected_records`为目录未选中数；选中但没有返回报价的证券仍计入原`missing_quote_records`。
- 东财的`vendor_not_scanned_records`为供应商声明数量减实际读取数；目录中尚未观察到的证券不全部叫作缺报价，因为可能尚未读到其分页。返回但不在目录的合法ID仍单独计`unverified_records`。
- `selection_method`区分`directory_code_prefix`、`directory_code_uniform_interval`、`vendor_page_order`、`synthetic_fixture`；扩大腾讯每层还提供`selection_limit`（本类名额，1–200），校验`directory_selected_records=min(selection_limit,directory_records)`，网页显示“按代码均匀间隔抽取 实际数量/目录数量”。不把非整数间隔伪装为固定整数步长。
- `request_count`是实际批次/分页总量，最多20。原`pages_read`继续表示该类实际请求数：腾讯至多4，东财至多2。

“配置目录扫描完”“供应商声明列表读完”“所选报价齐全”“所需字段完整”“报价日期合格”是不同条件。即使前两者为真，`independent_full_market_completeness_proven`也始终为`false`。目录为0时，原`0==0`的耗尽布尔值只说明没有配置对象，网页明确显示“目录未覆盖”，不能解释为该市场没有股票。北交所独立目录仍未接入。

网页的折叠覆盖区显示审计信息，旧响应缺少新增对象时保留原表格；审计对象存在但版本、方法、名额或计数矛盾时回退确认后的原文字。扩大采样不增加聊天显示上限、不改变最多三只研究、不把全部报价存入模型上下文；条件续改重读同一档位的全部配置样本。

## 正常聊天接线

`screening_agent.py`用一次受预算约束的模型调用提取首次筛选条件，`ResearchApiService.message`再调用服务端固定的报价源。`screening_intent.py`负责原文核对和有限语法解析：完整消费字段、比较方向、数值、单位、排序、数量和原文片段，不能修改阈值、漏掉边界或跳过未知附加条件。单边条件仍采用“字段→比较符→数字”；新增双边语法见下节。单个反向比较、复杂或歧义表达会请用户重述，不扩大样本范围后继续。

只支持AND与单字段排序。OR、行业/板块过滤、指定股票名单、财报/技术信号条件和非动态PE口径等尚未接入；应用会在取数前说明缺口。泛泛选股没有阈值时，明确默认正价格样本、成交额降序、5只，通过`applied_defaults`传递活跃候选标记，网页不会隐藏该默认解释或把它当作潜力评分。

对于完整匹配的简单无过滤问句，如“帮我选几个潜力股”或“选出10只股票”，这些默认值与数量由程序决定，不让模型的clarify提示或自行添加的阈值覆盖它们；其他请求继续核对模型提取与原问题。数量仍限定1–20，带行业、风险、板块等限定的句子不能借此获得默认筛选。

筛选开始前消费旧研究基准，后续“它”不会误指上一次公司。成功名单可以继续研究，具体规则见下节。授权、幂等重放、同编号冲突、取消和超时共用原会话服务；取消/超时后不发布迟到名单。Dev服务强制隔离正常来源，不只依赖启动器恰好没传在线对象。

## 条件续改与双边区间（2026-10-27，B 部分，已提交）

首次筛选可以使用下列双边表达，结果将显示两个原子条件（每个原子条件只含一个比较符和阈值）：

- `筛选PE在10到20之间的股票`、`筛选PE介于10和20之间`：按`PE ≥ 10 AND PE ≤ 20`执行，包含两端。
- `筛选10 < PE <= 20`、`筛选20 >= PE > 10`：按原比较符保留开闭边界，不把`<`改为`≤`。
- `筛选PE不低于10且不高于20`：原文只写一次PE，仍可派生两个有原文依据的边界。模型必须为两个条件复制完整原区间片段，不编造第二个PE短语；漏一个边界、改阈值或方向均不取数。

正负数、百分数和人民币单位继续逐项核对。`成交额在1亿到2亿元之间`可执行；`成交额在1到2亿之间`不会猜省略的倍数，要求两端都写清。`换手率在2到5%之间`的两个数值均为百分数点。上下界写反、`10到20以上`、严格开区间空集、冲突相等条件、单位不符或未知尾句先澄清。相同端点只有两端包含时可表示该单点；负PE保留负值含义，不自动增加盈利条件。

同一会话保存的筛选条件可在原15分钟内续改，包括空结果的条件：

- `再加换手率大于2%`：追加条件，其他字段、排序、数量与报价日期限制保持原值。
- `把PE改为低于15`、`把PE改为在10到20之间`：仅替换已有PE字段的全部旧约束，其他字段保留。目标字段不存在时明确说明缺少哪个字段，并给出“再加动态市盈率低于15”等对应新增写法；不读取报价。
- `按市净率升序选3只`：仅改排序和数量；省略数量时继承原数量。省略方向时须用“排序/排列”或明确数量表明排序意图，例如`按市净率排序选3只`，沿用首次筛选的降序默认并在结果里显示。单独“按市盈率”不再据此判断为改条件。

每轮只修改一类：追加数值条件、替换一个字段，或修改排序与数量。最终仍限八字段、最多12个不同的AND原子条件、单字段排序、聊天展示1–20只；重复、无变化、冲突、中文数量、不完整句和任何未消费要求均不执行。有限续改完全由程序解析，不额外调用模型；无法解释时不会转交模型猜测。

有效续改会重新读取整个配置样本，不只筛上轮展示的几只；因此原先未展示的证券可以成为新名单成员。先消费旧名单和旧研究对象，再取报价；失败、取消或超时不恢复旧对象，不发布迟到结果，也不自动换源。成功后显示完整新条件、来源、样本覆盖和新序号，重新起算15分钟；无效修改不消费或延长原条件。新名单内仍最多选择三只继续研究。

路由在一般知识之后、完整新筛选及名单选择之前识别明确的条件续改；待回答的公司/技术身份与指标澄清仍优先，历史查看不触发修改。识别必须从句首锚定“再加＋字段＋数值比较/区间”“把＋字段＋改为数值条件”“按＋字段＋排序写法”，或显式“在原筛选条件上”前缀；是否保存名单不放宽语法，未知尾句仍交完整核对并拒绝。普通“按市盈率分析浦发银行的估值”“把浦发银行和平安银行的市盈率比较一下”回原公司研究；“把第一只和第二只比较一下”“按基本面分析第一只”回名单选择，无名单时说明名单不可用，不当成条件修改。“再加RSI”等回原技术入口，参数是否足够明确仍由原流程决定。当前公司研究对象存在时，结构明确的“再加换手率…”等仍修改保存的筛选条件。没有基准、过期、时间倒退、目录/身份、来源或Dev模式不符时，在模型和取数前拒绝；正常模式的条件不能借到Dev模式。知识问题与历史查看不消费也不延长原条件，幂等重放不重复取报价。没有新增HTTP路径、客户端可写可信上下文或前端协议。
