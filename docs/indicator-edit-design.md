# 指标修改与条件继承：小范围、可检查的多轮状态

日期：2026-10-21（America/Los_Angeles）

状态：已实现并通过离线验证；本步未调用真实模型、行情或目录网络。

后续2026-10-22已增加[明确条件修改](condition-update-design.md)：股票、ISO日期及单个指标增删走独立分支，与本模块共享基准检查及实例解析。本文722项记录为指标替换子步骤的历史验证，最新全量813项离线通过。

## 1. 本步解决什么

在同一 `ResearchSession` 内完成一轮有可信事实的研究后，可以输入：

> 把SMA3改成5日，其他不变。

程序只替换那一个指标实例，保留股票、原起止日期、其他指标及来源，生成新请求并重新取数计算。原日期即使来自“最近一个月”或默认区间，也不因跨午夜而重新计算。

指标修改本身不从聊天记录或旧模型草稿恢复条件，也不支持股票/日期/来源修改、添加删除指标或“看最新的”。后续同日已增加独立[成功结果快照、追问与历史查看](result-followup-design.md)，不会改变新查询必须重算的规则。本步完成M3的一小部分，不把M3整体标为完成。

## 2. 为什么先采用明确表达

初始研究问题仍由模型提取意图、程序核对目录和条件。本步的修改分支采用有限整句语法，不新增意图模型调用：这是把确定的状态修改交给程序，不是让模型自由重建旧参数。

支持“把/将 X 改成/改为/换成/换为/调整为 Y”，允许有限礼貌前缀、全角写法和“其他不变”后缀；必须完整消费整句话。它不是任意中文改写器。带修改/继承线索但不能按本步规则理解时先澄清，避免落回新查询默认值；完整独立问题可用“新问题：”明确重置。

| 示例 | 行为 |
| --- | --- |
| `把SMA3改成5日，其他不变` | 仅改变原SMA3的窗口 |
| `把20日均线改成5日均线` | 在此明确写法中，均线指SMA |
| `把RSI改成3日` | 只有原组合中恰有一个RSI实例才可继续，不使用默认RSI14寻找目标 |
| `把均线改成5日` | 在SMA/EMA中查找；不唯一则要求重述完整修改句并写出原参数 |
| `把BOLL(3,2.5)改成5日` | 保留倍率2.5，只改窗口 |
| `把MACD(2,3,2)改成MACD(3,5,2)` | 使用完整参数；只说“MACD改5日”不猜具体周期 |
| `把SMA3改成5日，另外换成中国平安` | 整句拒绝，不先做前半句 |

七类指标均支持同类实例的明确替换。参数复用现有 `IndicatorSpec` 校验；目标不存在、跨指标种类修改、无变化、重复实例或多项修改不执行，不静默添加、合并或删除。遇到歧义目前要求用户重述完整修改句，不另存一个指标待选任务。

## 3. 状态与数据流

```text
初始完整问题 / 股票身份续接
  → 原研究执行器
  → 有可解释事实 + 事实报告完整性检查通过
  → 保存不可变 ConfirmedResearch（只含条件和身份）

明确指标修改
  → 检查基准有效期、当前目录、来源、日期和契约
  → 整句检查 + 解析原指标 + 唯一匹配 + 参数校验
  → 构造新的 MultiIndicatorRequest（新request_id）
  → 执行前消费旧基准
  → 原提议绑定、执行器、计算、事实报告及关系检查
  → 本轮有可信事实才保存新基准，否则保持无基准
```

本步增加两个职责独立的条件槽；后续另有结果槽，三者不混用：

- `pending`：尚未确认股票的条件和候选。
- `confirmed`：最近一轮具有可解释、通过完整性检查的事实所对应的请求、条件、证券及确认时间，不包含结果本身。

待确认候选不覆盖原已确认条件，处理顺序仍优先股票待选；待选时不能用修改句绕过股票确认。“取消”只清待选请求；`/reset`、“新对话”、“重新开始”、“清空会话”及“新问题：”清除条件与后续结果槽。退出、EOF、Ctrl+C同样清除全部状态，不补调用额度。

`session_state.state=idle`表示没有待选股票，不保证`confirmed`为空；可编辑基准由单独的`confirmed`字段表示。导出是脱离内部对象的元数据快照，没有CSV路径、原始问题或模型响应。它仍不是用户认证或生产脱敏日志方案。

## 4. 保存、失效和失败规则

| 情况 | 是否可成为/保留修改基准 |
| --- | --- |
| 完整研究，事实报告通过 | 保存本轮条件 |
| 部分指标不足，但仍有可解释且通过检查的事实 | 保存；不把缺项称为成功计算 |
| 模型解读失败/超时，但本轮事实有效 | 保存事实对应条件；不保存错误解读 |
| 无数据、全部不可解释、取数失败或事实完整性失败 | 不保存 |
| 修改有歧义、参数无效、包含额外要求 | 不执行，保留原基准且不延长有效期 |
| 明确修改已进入执行，随后提议不符、取数失败或中断 | 执行前旧基准已消费；无本轮可信事实则不恢复 |
| 待选股票尚未确定 | 单独保存pending，原confirmed不被覆盖 |

基准15分钟有效，以该研究轮传入的可信起始时刻计时；不是行情新鲜度或整轮执行截止时间。无效回复不续期，真实终端时钟与人工数据参考日分开。时间倒退、来源/开发CSV配置变化、证券消失/更名、目录不可用或原日期不再符合在线限制时清除基准，要求完整新问题。

修改前重查当前目录和原条件的当前可执行性；原日期锚点仍保留用于说明最初相对日期的解释。构造新请求自动生成新 `request_id`，不继承旧证据命名空间；旧模型JSON即使论断看似相近，也不能通过本轮请求绑定。

一轮有效修改最多2次模型调用、1次分析；本地无效修改为0/0，不自动重试、不换源。终端仍最多5条问题和15次模型转发，失败调用不退款，超长/非空修改问题也计入输入次数。完整token、费用和总截止时间预算仍待做。

## 6. 如何尝试

沿用终端入口，在已配置模型的同一PowerShell中：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.agent_cli --provider deepseek --data synthetic
```

依次输入完整问题 `分析平安银行，2026-09-21 至 2026-09-25，只看SMA3和RSI2`，获得可信事实后，再输入 `把SMA3改成5日，其他不变`。此命令会显式使用真实DeepSeek，可能计费；行情仍为人工数据。本步没有代用户运行这条付费路径。

只检查离线实现：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -X utf8 -B -m unittest discover -s tests -p test_research_edit.py -v
```

后续同日已完成[可信结果追问](result-followup-design.md)，使用独立深复制结果槽而不是把本步条件槽当缓存。新研究开始将旧成功结果标为非当前；执行失败后只能显式历史查看，不能恢复旧修改基准或用于隐式当前追问。新增47项后，全量769项离线通过；本节722项仍是指标修改子步骤的历史记录。
