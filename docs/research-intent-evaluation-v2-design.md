## 数据与划分

## 标注口径

| 字段 | 含义 |
| --- | --- |
| task / operation | 个股统一stock_research；指数为index_research，其余知识/选股/本地等独立。operation表示新研究、解释、修改、刷新或本地操作 |
| objective_kind | analysis=普通或历史分析；decision=个股买卖研判及未来走势的评级与方向（#144），不自动授权价位；outlook保留指数等无个股评级的纯展望 |
| wants_plan | 是否索要具体参考价位或风险计划；方向问题不自动加价位 |
| subject_source / bound_subjects | 本句/最近可信对象/无对象，以及允许程序实际绑定的对象；为空表示本轮不能直接绑定，不是证券目录为空 |
| horizon / date_expression | 未来期限与历史窗口分开；短/中/长线按现有规范化为10/40/120交易日，历史表达保留本句文本 |
| indicator_mentions / research_kinds | 用户要求的指标及明确研究领域，不把所有默认领域写成用户明确要求 |
| exclusions / strict_scope | 计划、指标或领域排除，以及“只看/仅看”等范围约束 |
| outcome / zero_intent_calls | 期望直接研究、哪种澄清、本地答复或拒绝；是否应无独立理解调用（回答调用另计） |

`evidence` 单独保存对象、期限、日期、指标和排除项的本句片段，读取器检查所有片段确实来自本句。省略对象或继承条件时不造本句片段。“近期”等模糊期限单列 `vague_horizon`，不放进已明确的 `horizon` 证据，两者不能重叠；gold期限仍可为空。“未来两三个月”有明确中线含义，V2203按既有中线代表值40交易日标注并在证据保留原文，不能奖励当前解析器漏认。

个股只有一个task，技术属性由research_kinds、strict_scope和指标字段表达；不再给“研究技术面”和“只看技术面”使用互相竞争的task标签。A层保留生产原始company/technical路由值，仅在v2观测字段统一映射为stock_research，旧v1标签不改。

**身份和缓存分开：** 当前股票身份不随15分钟缓存期限失效。D11距发布901秒仍绑定000001.SZ并重新取数，但不能继承原来的中线期限；没有新期限且要价位则询问期限，自带短线则研究，普通刷新也直接研究。有效标记失效、未来发布时间、来源/模式变化或会话归属不合法另行处理，不等同单纯缓存超时。明确新对象不借用旧期限、指标或证据；多对象的“它”先选择；知识插问不替换最近对象；不能从无效记录回找旧缓存。否决价位优先；同轮明确矛盾要求先澄清。

## 两层观测及复用范围

只新增4个小模块，不改旧评估器的固定304题契约：题库/复核、规则适配、固定执行、运行/评分/报告。复用旧评估的严格JSON解码、重复键拒绝、内容指纹、Markdown单元格转义、比例表示，以及现有工作流的固定证券目录、时钟、合成资料、有限模型响应序列、v3人工回答和Git版本记录。单独加载v2是因为旧读取器硬性限定304题、旧8标签和旧上下文/配额；强行扩充会改变冻结实验含义。没有新写一套行情模拟或模型分类框架。

**A层**直接调用现有知识提前分支、业务分流、交易判断/价位/否决判断与期限提取。保存原始intent、route、rule_id和规则布尔结果，以及可直接观测的task、objective_kind、wants_plan、horizon；个股未来走势的decision与评级要求一致，不能据此声称要求具体价位。主体身份、操作、最终澄清等没有被这些函数直接输出的字段保留 `not_determined`，不按人工标准答案补齐。A层不证明执行器会绑定哪只股票或会否给计划。

**B层**通过 `ResearchApiService.message`（正式会话入口）复用现有固定数据与有限旧协议脚本。只替换模型/资料传输，不替换路由、身份校验、期限确认、计划公式或发布。模型的旧协议响应由独立 `probe.steps` 保存，预测函数不读取标准答案；脚本不含v2任务、wants_plan或直接指定最终结果。每个场景新建临时内存会话，不接用户数据库。目标轮前检查实际最近发布、缓存与待办确与声明状态一致；不一致即“未测”，不强塞状态。

首批开发集预排47个B层目标轮、58个含前置步骤的调用轮次，优先建仓故障、回顾、期限确认、计划否决、严格范围及本地保护；预排不保证每题都能被既有模拟协议覆盖。其他题逐题写明未测原因。需要额外复杂响应时不扩建，脚本不匹配或入口异常如实保留失败/未测、原因和已有步骤，不算正确。留出B层尚未编排，不执行。

B层从程序保存的计划与公开结果取实际对象、目标、规范化期限、指标参数、领域、已发布计划和调用次数。待办只允许使用其程序保存的证券，不从回答文字推断。观察到的不可用计划记录不等于给出了具体价位；计划否决检查针对 `status=available` 的具体计划。完整价格文字审核、跨对象证据/条件来源审计尚未实现，不能凭对象相同判定这些检查通过。

每次B层运行另复用现有验收脚本的干净环境与离线网络边界，并拒绝本地模型凭据文件读取。即使意外分流尝试联网且执行器吞掉异常，也会在退出边界时记为失败，不能冒称成功；模拟计划的资料真实性统一标为 `fixed_synthetic`。

## 计分、版本和复核

字段准确率、全部字段全对率均保留完整子集分母，缺失/未测/失败计不对；另列测到多少字段。两层分别报告，不拼凑成完整意图单。旧规则不能输出全部14字段，联合全对率会受此限制，不能拿这个值声称新模型已经改善用户结果。模型对照须使用同一层、题目、状态和输出口径。分别列语义、本地、真实故障、多轮、反例；B层的协议故障使用独立处理表，不混进正常语义分母。正确澄清、过度澄清和直接正确处理分开统计。本地简单题不抬高语义成绩。

五类零容忍项均列“违例/已测/未测”：否决后出计划、错误对象、跨对象借用、严格范围、本地路径新增理解。当前对计划否决、实际非空绑定、ATR排除/明确指标与领域严格范围、本地理解次数可做有限检查；一般跨对象来源审计保留未测。零违例而未测多不能视为通过，报告始终 `eligible_for_switch=false`。之后的95%门槛、同条件不差于规则、零容忍及真实端到端会话验收仍按 #332 执行。

生产基准是 `bb6bc34cd5ad2b5f8cd0f02ed851c5e8bb369297`，规则 `index-scenario-ui-v1`，50份语义依赖源码聚合指纹为 `9a38e39bb66e9d3648dea4a688a566b85c189a5f5543386ac26162e2f66c6fb3`。读取时复用现有规则登记校验；题库另外固定内容/划分/逐题指纹。运行计划分别记录生产基准、评估器和复用实现的源码指纹、实际Git版本及工作区是否有改动，避免把评估器的新提交误称生产规则改版。历史成绩不覆盖，新报告使用独立随机目录。

Claude按家庭逐题复核，将manifest每行设置为 `status=approved`、`reviewer=claude`，保留匹配的 `row_sha256` 并写意见；全量通过后再设顶层 `annotation_status=reviewed`、`reviewer=claude` 和日期。只翻转顶层不能评分；改题后行指纹不符也拒绝。**本次初始送审为全量pending，不生成正式基线；后续状态以manifest为准，回填后同步生成复核清单。** 首批提交后另跑开发基线并交审核。第1步命令不接受holdout或live；留出待第2步锁定模型/工具/提示词/数据后同条件测量，见过失败再改需登记新一轮。
