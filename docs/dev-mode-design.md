# 正常模式与 Dev Mode

日期：2026-10-25。

## 1. 要解决的问题

真实模型连接成功不代表使用了真实行情。此前 `--provider deepseek --data synthetic` 可以连到 DeepSeek，但仍只有四条人工证券目录、平安银行五条人工日线；正常输入“分析一下中际旭创”因此找不到证券。让用户改输代码无法补齐不存在的目录记录。

现在 Web 产品默认正常运行，把人工开发环境放到明确的 Dev Mode。二者复用同一套 Agent 代码，但不混用模型、目录、行情、会话或预算。

## 2. 启动契约

```powershell
.\.venv\Scripts\python.exe -m trading_companion.api_server
```

默认监听 `127.0.0.1:8765`，正常后端使用 DeepSeek、腾讯不复权历史日线和本地真实证券目录。源码项目自动按原规则加载根目录 `.env`，进程环境变量优先。显式 `--provider` / `--data` / `--port` 仍可覆盖正常后端；它们不是浏览器请求参数。

启动检查依赖、密钥格式和现有目录是否可用，不调用模型、不获取行情、不自动联网刷新目录。真实目录缺失或过期、密钥或依赖无效时明确失败，不静默降级为人工数据。目录由用户通过已有 `security_directory_refresh --live` 命令手动更新，详见[本地配置](local-environment.md)。

`--demo` 是单独的完全离线入口：固定假模型和人工夹具、不读 `.env`，网页不能借此启用正常模式。`agent_cli` 和固定评估入口的默认行为不变。

## 3. 两个固定服务，而非任意切源

```text
同一网页 / 同一 loopback 进程
  ├─ normal：/health、/v1/sessions...
  │    └─ 正常服务：启动时固定模型、真实目录、行情来源
  └─ Dev Mode：/dev-api/health、/dev-api/v1/sessions...
       └─ 独立离线服务：fake + synthetic + 固定人工目录
```

两个 `ResearchApiService` 各自拥有会话、令牌、幂等记录、模型实例及额度；一个服务的令牌不能访问另一个服务。模型建议、聊天内容和 HTTP body 仍不能设置提供方、来源、目录、CSV 路径或预算。切模式只是选定一个服务端预配入口，不能在原会话里换源。

根 health 可返回可选 `development_mode_available` 布尔值，供界面显示或禁用按钮；它是展示能力提示，不是权限或隔离边界。健康检查成功只说明本地服务能响应，不证明供应商网络、数据质量或研究结论正确。两个后端仍分别执行原有令牌、来源绑定、配额与事实校验。

## 4. 页面切换状态

页面初始为正常模式，不持久化模式选择。首次发送在当前模式懒创建会话；模式切换本身只做 health / 会话清理，不提交研究问题。

1. 只允许空闲时切换；创建中、发送中、取消尚未确认或原请求响应不确定时禁用切换。
2. 存在旧会话时，先按原后端成功结束它；清理失败保留原模式、聊天和草稿，不创建目标会话。
3. 旧会话清理成功后，立即选择目标入口、清空原聊天、草稿、health 与页面凭据。此时旧会话已结束，不能把它当作可恢复的备份；尚未创建目标会话。
4. 再检查目标 health 并核对预期提供方与数据模式。成功后允许下一次明确发送时创建目标会话；失败则保留已选目标的断连空白状态，显示错误，不恢复已删除聊天、不自动回退、更换来源或继续发问题。用户可手动重连，或空闲时明确切回另一模式，但这仍是新对话。
5. 刷新页面回正常模式，不保留开发模式令牌或聊天。刷新仍应在无在途/不确定请求时进行，避免丢失原请求的恢复凭据。

这是丢弃旧聊天后切换环境，不是保存两个可随时来回恢复的聊天窗口。原响应重试仍使用原服务、原会话与原请求编号，不能把不确定请求带到另一个后端重发。取消请求获 202 也不表示供应商已停止或不再计费。

## 5. Dev Mode 的能力边界

- 不请求真实模型或行情，页面清楚显示假模型和人工数据。
- 目录仅含平安银行、中国平安、贵州茅台、中芯国际四条人工记录；行情样例只有平安银行在 2026-09-21 至 2026-09-25 的五条人工日线。目录中有名字不等于该股票有可用行情。
- Fake 是固定演示脚本，不是可理解任意问题的通用模型。默认长周期指标在五条样例上可能不足；不会补零、伪造历史或把结果当真实走势。
- 正常模式的新闻、基本面、选股、实时行情与下单能力没有因此增加；项目仍无自主交易权限。

## 6. 验证要求

自动检查应覆盖默认启动及显式覆盖、`--demo` 不读 `.env`、启动无真实模型/行情请求、正常配置失败不降级、双服务令牌/会话/额度隔离，以及模式切换的空闲门、清理失败、目标失败、重复点击和响应不确定保护。构建检查不能代替浏览器验收；离线检查不能代替真实供应商连通和研究质量测试。

2026-10-25 本轮离线验收：`scripts/verify.py all`通过1,341项Python测试、468项前端测试、4个Agent场景、90次MVP固定场景及API演练，零跳过；TypeScript检查、生产构建、ASGI编译资源与干净wheel检查通过。补充覆盖了正常后端重启为离线服务时，既有页面切回正常或重连均不得静默接受人工模式。本轮未进行浏览器手动验收、真实模型或行情请求，未读取真实`.env`或重启现有服务。
