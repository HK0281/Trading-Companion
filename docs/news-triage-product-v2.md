# 真实标题的新三题：准备、盲标与对照

2026-11-10，A2。入口和研究回答仍只使用原有资料，分诊不会排序、标记或过滤线上资料。本批只处理 Claude 已采集的公共标题、生成空表并使用测试模型验证协议；未新采集、未请求真实分类模型、未填写真实人工答案。旧 [v1 合成题及历史结果](news-triage-design.md)保持原义。

## 定义与身份依据

[news_triage_product.py](../src/trading_companion/news_triage_product.py) 定义独立任务 `news-triage-product-v2` 和规则 `news-triage-product-rules-v2`。Jev、DeepSeek、人工表旁的 `task.json` 使用同一份定义：

| 题目 | 标签 | 约束 |
| --- | --- | --- |
| 相关性 relevance | primary / mentioned / unrelated | 公司主体、顺带提及或行业多主体、明确错配；拿不准不能判无关。 |
| 标题倾向 tone | positive / neutral / negative | 只看归于目标公司的措辞；无关必须中性；否认传闻、例行、正负平衡通常中性。 |
| 重要性 importance | high / ordinary / unknown | 明确的目标公司业绩、重大重组/停复牌、正式立案处罚可重要；一般例行事务普通；规模或主体不足用 unknown。 |

另有 `unresolved` 表示明确弃答或外层未解决状态。它与重要性 `unknown` 不同。DeepSeek 可逐题返回 `unresolved`，没有概率字段；Jev 的接口仍返回真实三选一及原始概率，程序不会编造一个“弃答概率”，需要复核又未得到可用结论时由外层标为未解决。标签不证明事实，不预测股价，不计算影响幅度，负面不等于重要，事件类别也不能代替重要性。

身份预检只使用受信本地证券目录的简称和别名，不联网刷新，不让模型补全称。输出固定依据：

- `issuer_verified`：来自已核验代码与市场的东方财富公告，或代码与机构编号的巨潮公告。没有公司名也不能因此判无关；此标志不是“公告事实已证实”。
- 名称命中、独立名称依据、证券代码语境、纯数字命中；数字前后必须没有其他数字，带错市场也要复核。
- 同名词处于协会、商会、商行、园区、学校、研究院等更长主体中的怀疑；公司与协会合作时保留公司的独立名称依据。
- 信托/产品/项目等编号碰撞、明确其他证券代码、多家本地证券、行业整体标题。名称与编号提示均不直接充当人工标签。

即使 Jev 高置信，同名/编号怀疑、多主体、行业、身份不足或输出无关仍转交 DeepSeek。过滤候选必须同时有程序错配依据、DeepSeek 明确判无关、没有可信目标身份冲突；Jev 单独不授权过滤，已核验公告永不被这一规则过滤。级联中身份冲突或复核没预算保留原材料并记未解决；原始模型结果保留在调用流水中供分析。

规则登记 [news-triage-product-v2.rules.json](../data/evaluation/news-triage-product-v2.rules.json) 记录定义摘要与七个独立模块的源码指纹（统一换行后的散列）。`news-triage-product-dataset-v2` 和 `news-triage-company-split-v1` 登记本次公司切分结构；旧的时间切分空表和数据版本失效，须重新准备。三道题定义摘要未变，生产意图规则版本、历史题库、报告或封存锁未改。

## 真实输入和分组切分

输入为 A1 的 `news-title-capture-v1`，只读编号 JSON 文件；可重复 `--captures` 合并一至四个不同采集目录。单文件仍限 64 KiB，每目录至多 1,000 份，合计至多 2,000 份/20 MiB/2,000 条原始标题。每份记录带批次标识，两个目录同名的 `000001.json` 不会覆盖；跨批次标题仍合并去重，目录顺序不改变结果，重复目录拒绝。校验来源状态、证券、日期和标题摘要。准备脚本默认只输出计划，不读密钥、不联网、不建目录：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/prepare_news_triage_product.py --captures <采集目录>

# 明确本地写入；默认写到已忽略的 .agentbus/tmp/news-triage-product/<新运行>/
.\.venv\Scripts\python.exe -X utf8 -B scripts/prepare_news_triage_product.py --captures <采集目录> --write

# 第二批实际采集后再执行；本批尚未取得第二批数据。
.\.venv\Scripts\python.exe -X utf8 -B scripts/prepare_news_triage_product.py --captures <首批目录> --captures <第二批目录> --write
```

先按标准化标题、来源、日期和证券去完全重复。再跨来源、跨证券联结相同标题/文章；七天内同公司事件族或共享证券且近似的标题保守归组，用于把改写和转载放在同一边。相同标题跨日期也归组。每组每证券只保留一条代表题，难例提示只按该代表标题本身判断，不能从同组其他难题继承。完整原始变体与联结依据保留在 `dataset.json`。多公司同文仍可保留不同目标公司的题目，但必须在同组、同一集合。

这套启发式分组可能把不同事件合并，不能保证理解全部语义。代价是可用样本减少。两个标注者必须查看组内原文及组间关系；发现漏归或误归须修正规则、重新准备，不能直接改 CSV 原始资料或把 `grouping_reviewed` 机械填 yes。

主切分改为[按公司分组分层](../src/trading_companion/news_triage_product_split.py)，不看日期先后或人工/模型答案。同一公司的全部事件只进一边，跨公司同文先把关联公司绑定成一个分配单元。固定种子、64 次初始分配和 512 次局部调整，在来源与板块比例合格的候选中优先平衡公司数和板块，再减少来源偏差；这是有界启发式搜索，不宣称数学最优。如果绑定后搜索仍无法达到平衡，整组排除跨公司同文并明确记录原因和数量，再尝试分配，不拆开同一文章的不同公司变体。若仍失衡，拒绝生成盲标表。

对最终实际选题，新闻/公告比例、具体来源比例、按公司和按标题统计的板块比例，各类别两边差异都不得超过固定的 **15 个百分点**。检查失败返回 `imbalanced`、退出 1，不创建输出目录和盲标表；评估读取数据时再次核对公司、全部事件组分配及比例。日期保留供分析，不决定封存集组成。

每边先按标题散列、证券、日期从**全部**候选抽 130 条自然样本，包括其中的难题；再从剩余真实候选选最多 70 条额外难例。不能先剔除难题让自然样本变容易。难例提示固定为身份不足/碰撞、编号碰撞、多主体/行业、否认传闻、混合或不确定措辞、重要性模糊等，只是选题提示，仍待人工核对。报告每类提示数量，包括零；每类未单独约定配额，不把提示数当人工标签数。

首批实际结果（50 家、465 原始标题；未人工确认分组）：

| 项目 | 实算 |
| --- | ---: |
| 标题—来源—日期—证券去完全重复后 | 464 |
| 保守事件组 | 373 |
| 每组每证券的可用代表标题 | 375 |
| 带程序难例提示的代表标题 | 75 |
| 公司分配 | 调试 25 家；封存 25 家 |
| 跨公司冲突排除 | 0 组 |
| 调试集 | 130 自然 + 14 额外难例 = 144 |
| 封存集 | 130 自然 + 12 额外难例 = 142 |
| 合计 | 286；距 400 缺 114 |
| 额外难例缺口 | 调试 56；封存 58 |

自然样本已经含部分难题；75 不等于还能额外补入 75 条。没有用普通标题或合成题补齐。它是固定 50 家、有限日期的试点，不代表全市场。重要、正面、负面和拟过滤标签的人工支持数尚未知，不能把 286 条称作已审核评估集。报告明确已复核支持为零、距 high/正面/负面各 30 和拟过滤 50 尚差多少，实际可用支持仍待标注，不根据关键词猜答案。

## 双人盲标与裁定

输出 `codex.csv`、`claude.csv` 两份完全相同的 UTF-8 表；含目标公司、标题、来源、日期、链接、身份依据和同组变体。三题及各题依据、`reviewed`、`grouping_reviewed` 全空，不含模型输出、标准答案。标注时分别查看共用 `task.json`，独立填写标签和理由，完成逐题复核及分组核对后填两个 yes。本批不填写这些真实表。

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/merge_news_triage_annotations.py --dataset <运行>/dataset.json --codex <运行>/codex.csv --claude <运行>/claude.csv
```

合并工具检查所有 ID、不可变原文和字段，重复、漏题、改原文、无效标签直接拒绝。空答案、空理由或未确认分组是 incomplete；两人完整但标签不同是 disagreement。输出新的 `annotations.json`、`pending.json`（逐项两份答案与分歧）和空白 `adjudication.csv`。两人一致才能自动合并；有争议交用户，显式填写 `adjudicator=user`、三题及理由、裁定理由和两个 yes 后，通过 `--adjudications <裁定表>` 重新合并。裁定不能代替一方未完成的工作。

仍有未完成/分歧时退出 1，不是工具故障；全部合并退出 0；无效输入退出 2。可以逐集合完成；真实评估只放行所选集合全部已复核的题。散列用于绑定本地内容，不认证真人身份；“已复核”仍是两人的明确声明，不能由模型或脚本自动批量盖章。

## 独立对照和实际级联

```powershell
# 默认只有计划；不建模型客户端、不读凭据、不建报告目录。
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_news_triage_product.py --dataset <运行>/dataset.json --annotations <合并运行>/annotations.json

# 只预览封存集；不会自动跟随调试集运行。
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_news_triage_product.py --dataset <运行>/dataset.json --split sealed
```

四个实验组分别为 `jev`、`deepseek`、`cascade_0.65`、`cascade_0.90`，可重复 `--arm` 选择子集。每组真实单独执行、单独统计费用；级联只在真实触发路由时发 DeepSeek 请求，不把两家独立结果拼成“已经省下费用”的实测。全部组最多每题六次请求，标题用固定种子打乱、逐标题轮流执行各组。小预算下报告保留所有未运行题，不能据偏向前序实验组的部分结果比较质量。

真实执行由 Claude 在费用授权范围内做；本批没有运行。须 `--live --max-calls <明确上限> --prices data/evaluation/model-prices.json`，需要 DeepSeek 时还须 `--deepseek-model <明确模型>`。未复核空表、未裁定分歧或人工夹具证券目录均不能放行；预检完成后才加载所选提供方的密钥。只允许固定分类 POST 端点，不抓新闻、正文或证券目录；不重试、不跟随重定向。

调用上限覆盖所有实验组及失败尝试。单题同时限制六次、90 秒、24,000 已观测 token（模型计费用量单位）；完整响应后才知道 token，不能当精确费用硬上限。请求默认六秒，可调至 1–60 秒，是协作式超时，不保证 DNS/远端停止或绝对墙钟上限。缺少或不一致用量立即停止后续可选付费请求；原失败仍计次数。费用按实际请求、请求模型、实际模型及可验证用量计算，Jev 别名不一致、价格或用量未知均明确 unknown；美元和人民币不相加，不把未知记零。

JSON 报告逐题保留原始流水、模型身份、用量、耗时、转交原因、最终状态和拟过滤策略；独立分类器显示原始分类，级联显示可采用结论，身份冲突的原始分类仍在流水中。按实验组、来源、自然/额外难例分别报告混淆矩阵（正确/错误及弃答的计数）、每标签精确率/召回率、整体覆盖、费用和拟过滤指标。失败、未运行、未解决全部留在总分母；人工 unresolved 单列，不当正确答案贡献。报告只说明标题分类能力，不自动启用产品功能。

门槛保持：high 至少 30 条、召回至少 95%；正负各至少 30 条人工支持和预测支持、各精确率至少 95%；拟过滤至少 50 条、精确率至少 98%、95% Wilson 区间下界至少 90%；相关材料保留至少 99%，重要相关误删零。Wilson 是小样本下比点估计更保守的比例区间。支持不足就报告不足，不降门槛；后续仍需配对回答验收和用户同意。

正常线上 B/C 的预算和开关仍按[接入方案](news-triage-integration-design.md)另做；本批没有接入模型调用、并发、排序或过滤。验证使用合成输入与假传输，运行 `scripts/verify.py python`；无前端改动。
