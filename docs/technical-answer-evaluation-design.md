## 运行与预算

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_technical_answers.py --report-dir .agentbus/tmp/technical-offline
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_technical_answers.py --plan-only
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_decision_answers.py --report-dir .agentbus/tmp/decision-regression
```

默认 `offline`：真实聊天服务、路由、取数流程、指标计算、正文核对、会话发布全部照常执行，只替换模型和资料来源。每轮使用独立的有限模型脚本；不允许多余调用或跳过预定阶段。技术资料独立使用固定的 2026-10-29 参考日期和 400 条人工工作日日线，证券目录时间也同步固定；这些日期不是交易所日历。不会修改原 20 题资料，不加载密钥或 `.env`，外网有离线阻断。部分周线指标仍可能受研究区间限制而不可用，缺项保持缺项，不伪造可用读数。

`live-model` 使用真实模型加人工来源；`live` 使用真实模型与真实来源。真实配置预览：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/evaluate_technical_answers.py --mode live --provider deepseek --model deepseek-flash --prices data/evaluation/model-prices.json --model-call-limit 90 --directory data/security_directory_live.json --plan-only
```

预览校验题库、目录、价格与输出位置，不创建模型、不加载密钥、不联网、不创建报告/诊断目录。实际运行由 Claude 在合入后去掉 `--plan-only`，可增加 `--report-dir`、`--trace-dir` 及显式的本地 `--diagnostics-dir .agentbus/tmp/...`。诊断默认关闭，沿用既有目录范围、限量和完整性检查；正式报告不含被拒草稿和密钥。

每轮最多 6 次模型调用，与产品上限相同；每题最多 `6 × 轮数`，单轮 6 次、多轮 12 次；准备和修复均计入，14 轮总上限 84 次。`--model-call-limit 90` 合法，但有效预算取 `min(90, 84)`；报告同时显示请求额度 90、有效额度 84，不会实际调用 90 次。额度小于 84 时照实运行，耗尽后保留全部 10 题和 14 轮，单独标记 `budget_exhausted`，并与非预算导致的正文失败分开统计。不增加外层重试，结构化回答和工具输出上限仍分别为 4096、1500 tokens。

## 判定与范围审计

主分母固定 10，按目标轮计算正文形成；准备轮的对象和成功状态须支持后续会话。准备轮质量另列，所有 14 轮都检查范围。整体机械通过要求执行/记录完整、至少 9/10 形成正文、范围违规为 0 且范围检查无未知、买卖题有有效评级/方向和参考计划状态、所有必需指标及明确日期检查通过。纯程序事实、空正文、整体失败不算形成正文；合法部分正文可以计入。

取数检查在来源服务入口记账：包装 `ResearchDataService.collect_many`，在转发之前逐证券/领域记录请求，失败尝试同样保留；技术来源工厂另记技术请求。另观察真实采集函数返回的确认指标、实际技术请求及领域。检查器依据题库逐轮预期，检查参数、实际计算请求、全部公开证据和最终展示的分析，不依赖模型自评或最终 coverage 推测取数。

- 严格指标要求参数集合完全匹配，证据与正文不能混入未请求指标或 MA20/MA60。兼容 `SMA3`、`SMA(3)`、`sma(window=3)`、MA 和常见中文名称；原始日线 `volume_shares` 不是滚动 VOLUME 指标。“未计算 ATR”是限制说明，不当作实际使用 ATR。
- 领域限制覆盖准备和追问；技术限定时不读取公司资料、财报、新闻、公告。取数失败也不能算没有调用。技术数据推导的参考计划属于计算，不属于公司领域取数。
- 没有可用的同股 ATR14 计划及其证据依赖时，不能在正文或结构化价位中给出止损/目标价格；允许说明计划不可用，支撑压力不能冒充止损和目标。
- T06/T07 必须有现有规则认可的评级和相符方向。可用参考计划须匹配用途和证据；不可用计划须明确状态、原因码、空数值、空 plan_id。报告按现有网页 `ResearchDecision.tsx` 的原因码说明给出中文解释，例如 `risk_atr_not_requested` 对应“本次未计算所需的波动指标。”；不会要求模型凭空补 ATR 或为不可用计划编价格。

反例覆盖未引用 MA20 证据、额外指标、实际计算范围漂移、无计划止损/目标（含中文数值）、失败新闻请求、准备轮违规、错误证券、空正文、评级方向冲突、无原因码的不可用计划，以及伪造可用状态但缺计划证据。缺参数、缺来源台账或缺采集观察为未知，不作通过。

这些检查不证明任意中文改写、指标之间的语义关系或投资结论正确。新出现的别名和不带标签的隐含指标仍需人工复核，因此不能把机械 9/10 称作经过质量验证。

## 质量计数和报告

每题分别输出准备轮、目标轮和整题汇总：正文形成、范围问题、生成/删除句数、删句率、固定失败码次数、截断、调用次数及费用。全套也按准备、目标、全部轮次分别汇总，不用逐题百分比的平均值代替总句数比。

删句率沿用产品现有计量：被实际检查的两稿均计入生成句数，driver 标题也计句；`deleted_sentences / generated_sentences`。正文组装中的去重移除也计入删除数，并另列 `deduplicated_drivers`、`deduplicated_sentences`，不伪装成数字错误。两稿合并会保留首稿通过的内容，生成句数不等于最终正文句数。缺质量计数时汇总比率为未知，同时提供可得小计和未知轮数。

`answer-issues-v1` 记录每稿检查意见的完整错误码次数，不只记录首个错误。`first_draft`、`repair_draft` 分别计数，`all_drafts` 为两者合计，不能把三行再次相加。固定单列：

- `answer_stance_mismatch`：正文或研判立场与评级不符。
- `answer_numeric_unmatched`：数字未匹配到允许证据。
- `answer_binding_invalid`：模型数字来源标注无效。

次数单位为“每稿产生的检查意见条数”，不是受影响题数或数字词元数；同稿可有多个同码错误，修复成功仍保留首稿次数。最终残留原因单列，沿用产品最多 20 条原因的限制，不把它冒充完整逐稿计数。版本缺失、草稿统计缺失或截断统计缺失为未知，不填 0。运行元数据只增加白名单错误码、整数和版本，不加入拒绝原句。

完整错误计数及已知零值存入版本化运行元数据，由评估器读取；普通公开回答不增加零值字段，以保持冻结会话观察的内容指纹。实际发生去重时公开质量记录增加去重计数。指标编辑文件属于规则登记的源码范围，因此同步更新 `intent-rule-baselines-v1.json` 的该文件摘要及源码总摘要；分类/路由规则版本和历史题库不变，旧阈值锁仍因源码总摘要不同而拒绝复用。

成本和 token 用量沿用公共计量与价格模块：准备/目标/失败的实际转发请求都计量；未知价格、用量和供应商模型身份不补成零费用。价格假设只用于预览，不是账单保证。`report-dir` 下新建唯一目录，包含 `report.json`、`report.md`、`manual-review.jsonl`，失败和未运行题仍保留人工复核行，人工评价默认 null。

退出码 0 表示合法预览或完整执行且机械目标通过；1 表示未达目标、执行/记录不完整或运行失败；2 表示参数、题库、目录等配置无效。离线 0 只证明契约。

## 产品小修

v3 提示要求每条 driver 讲不同因素。通过原核对与修复合并后，在同股内按归一正文相同，或非通用标题与非空证据集合相同，保留第一条。仅共用证据的不同因素、相同标题但不同证据、不同股票分别保留。不增加模型调用，不放宽 A3 数字规则，不因重复拒绝整份回答。

归一时保留数值正负号、小数点、百分号及比较符，避免把不同数值的正文误认为相同；按标题和证据集合去重仍是保守近似，不能替代人工语义复核。

指标编辑移除 `indicator_dependency:atr14_for_risk` 时，同时移除尚未被用户明确采用的依赖 ATR14。用户明确指定的 ATR 保留；增加 ATR7 不会把依赖 ATR14 一并变成用户指定。自动移除不增加 ATR 排除标记，后续买卖问题若范围允许可重新加依赖；严格指标范围继续不补 ATR、计划明确不可用。用户明确删除 ATR 的排除约束仍保留。多候选指标选择接续时，证券匹配变化会显示“目录中的证券匹配已变化，请重新明确研究对象。”，不查询。
