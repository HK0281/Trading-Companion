### 1. 本轮解决的问题

此前只能在终端或 Swagger 提交请求。现在用户可以直接在网页输入中文问题，查看事实、关系和证据字段，处理股票澄清，以及查看历史、检查状态、请求取消、重置和结束会话。本轮没有新增研究工具、模型提供方或交易权限。

```text
React 展示组件
  → ResearchController：页面状态、内存凭据、未确认请求
  → createApi：固定 normal / dev 同源前缀、DTO 检查、固定错误
  → FastAPI → 两个隔离的 ResearchApiService → 原 Agent / 工具 / 事实检查
```

页面不会替 Agent 判断股票身份、计算指标或生成投资结论；也不直接连接模型供应商。

### 2. 安装、构建与运行

Web 运行使用前端编译产物。首次克隆、修改前端源码或构建发行包前，需要重新构建；升级双模式后也要重启 Python，使新路由与界面匹配。

准备 Node.js 22.12+（建议使用受支持的 LTS 版本）及 pnpm 11.25.0。普通 Windows Node 安装通常自带 npm，可用 `npm.cmd install --global pnpm@11.25.0` 安装 pnpm；不需要激活 Python 虚拟环境。项目根目录运行：

```powershell
pnpm.cmd --dir frontend install --frozen-lockfile
pnpm.cmd --dir frontend test
pnpm.cmd --dir frontend build
```

`pnpm-lock.yaml`锁定解析结果；安装脚本只显式允许 esbuild。没有自动执行的部署、供应商配置或模型调用。不要把密钥写进前端源码或 `VITE_*` 变量；前端构建内容对浏览器公开。

Python API/模型依赖尚未安装时先执行第一行；按[本地配置](operations.md#本地模型配置与启动)填写根目录 `.env`、准备有效真实目录后，日常只需启动命令：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[api,model,dev]"
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.api_server
```

打开 <http://127.0.0.1:8765/>。同一进程仍提供 <http://127.0.0.1:8765/docs>。默认正常后端为 DeepSeek + 腾讯历史日线；启动只做本地检查，缺配置或目录不自动降级。Ctrl+C 停止服务。

没有开发服务器或第二个端口；修改 TSX/CSS 后重新 `build` 并刷新页面。刷新会丢失页面内存中的会话令牌，所以应在无在途请求时刷新。

#### 正常与开发模式

页面默认正常模式，首次明确发送才创建会话并提交问题；页面载入、草稿和 health 检查不调用模型或行情。正常问题可能发送给 DeepSeek 并计费，密钥始终只在服务端读取。

Dev Mode 按钮把当前页切到服务端预配的 `fake + synthetic` 独立服务：`/dev-api/health` 与 `/dev-api/v1/sessions...`。正常服务仍用 `/health` 与 `/v1/sessions...`。切换不是让客户端自由配置来源，也不改变已存在会话的提供方。两个服务的令牌、研究状态、幂等记录、模型实例和预算相互隔离。

只允许空闲、无在途或响应不确定的请求时切换。旧会话清理失败保留原模式和内容；清理成功后即选择目标并清空聊天/草稿，再检查目标 health。目标失败仍留在目标断连状态，不恢复已删除聊天、不自动回退或重发；可手动重连或重新切模式。切换不会预先创建新会话，下一句明确发送才创建。页面刷新回正常模式，不能借刷新绕过不确定请求的恢复要求。`--demo` 则完全离线、不读 `.env`，没有可切回的正常后端。详见[模式设计](agent-runtime-design.md#正常模式与-dev-mode)。

#### 固定离线体验

正常启动后先点击 Dev Mode；没有真实配置、只想离线演示时也可用 `api_server --demo` 单独启动。

1. 直接在输入框输入问题；页面载入本身只读取 health，不创建会话或请求模型。
2. 输入“分析平安银行，2026-09-21 至 2026-09-25，只看SMA3和RSI2”，点击发送箭头或按 Enter。
3. 输入“这里的RSI为什么偏高”并发送；这次读保存结果，不重新取数。
4. 可穿插“解释一下MACD里的DIF和DEA”；定义回答不调用模型或行情。
5. 输入“把SMA3改成5日，其他不变”并发送；这会产生一次新的分析。
6. 输入“查看上次结果”；页面明确标注历史，不把它当作新研究成功。

首次发送自动建立会话并发送该问题；后续消息沿用同一会话。“新对话”结束并清空当前对话，回到可输入状态，直到下一次发送才创建新会话。当前只有一个内存会话，不支持切回旧聊天。Fake 是有限脚本，不是能回答任意问题的假语言模型；人工数据固定在2026-09-21至09-25。重置不重建脚本，也不返还额度。重跑整套演示点击“新对话”后再发送，不要在同一会话连续重复初始问题。

人工目录只有平安银行、中国平安、贵州茅台、中芯国际四条记录，人工日线仅包含平安银行五天；Dev Mode 不能分析任意股票。显式 `--provider deepseek --data synthetic` 仍是可能计费的真实模型配人工数据，不等于离线 Dev Mode。`--data` 可显式覆盖正常后端的启动来源，但不通过网页消息、URL参数或请求体配置。重试仍须用户明确触发并使用原服务的原请求编号；去掉前端许可门不等于供应商接入验收或授予下单权限。

### 4. 网络失败与取消的状态

| 情况 | 页面行为 |
| --- | --- |
| 收到匹配的公共响应 | 展示可读状态和答案，不附加内部诊断面板；再只读刷新额度。刷新额度失败不抹掉已收到的答案 |
| 断网、120秒浏览器等待超时、成功响应格式/编号错误、未知网关错误 | 保留原问题和编号，标记“响应未确认”，阻止新问题、重置、删除及模式切换 |
| 点击“重试原请求” | 只由用户触发，使用同一编号和同一问题；可能取回缓存，或执行先前尚未接纳的请求。重放不被当成新的问题，聊天不额外展示调用计数 |
| 409仍在执行 / 429并行容量满 | 不自动重试；保留原编号，允许手动检查或稍后重试 |
| 已知固定终止错误 | 展示固定说明，结束当前请求；不把服务端失败自动变成第二次模型调用 |
| 401/404会话失效 | 丢弃页面凭据，不重做失败问题；提示下次明确发送会开始新对话，原研究条件不保留 |
| 点击“请求取消” | 单独发送匹配编号的cancel；202不清除在途状态，不声称远程已停止或免费 |

浏览器超时只停止等待，不等于后端取消。状态检查只读取进程内状态；服务端空闲也不证明丢失的原请求没有执行，仍应用原编号取回答案。该机制依赖原API的进程内幂等记录，不是跨重启或分布式exactly-once。

创建会话的响应如果丢失，没有可恢复的令牌；不会自动重建或提交研究，输入框恢复原问题，由用户再次点击发送。原不可访问会话等待24小时绝对有效期后的惰性清理。创建、首条消息和模式切换受同步操作门保护，避免快速双击创建多个会话或把旧模式结果写入新聊天；创建返回后仍检查会话生命周期和所选服务固定的模型／数据来源，不再检查已移除的前端发送许可。

### 5. 展示与安全边界

- 优先展示已校验的公共 `conversation` 自然语言正文，兼容旧紧凑视图；不读取调试草稿。React按文本渲染，不执行用户/模型HTML，不使用 `dangerouslySetInnerHTML`。
- 仅确实需要澄清时显示候选；旧回答的候选不可再次点击，历史也不展示选择按钮。点击仅填入代码，不自动执行。
- 展示已确认股票/日期、来源/人工标签和可读状态；附加区仅直接显示互动日线图，正文内依据仍可展开。聊天不展示内部代码、本轮调用数、默认参数清单、工作流或引用诊断；舍入仅用于显示，不在前端重算关系或预测。
- 没有“本轮详情 / 参数与执行记录”或其他附加表格，也没有回答后固定的 RSI、DIF/DEA 和调整指标追问按钮。追问直接在输入框输入。
- 历史有独立标记；聊天最多保留40条页面记录，不等于后端保存完整对话，也不会把整个页面记录重发给模型。
- 令牌不放进URL、localStorage、sessionStorage、Cookie或文件；仅保留在当前页内存，开发者工具仍可能检查到它。刷新/关闭不自动撤销服务端会话，原绝对TTL不续期。
- 所有请求同源、无Cookie；保留现有Host/Origin、16KiB、Bearer与no-store保护，不为了UI增加通配CORS。
- 根 health 的可选 `development_mode_available` 仅用于决定按钮可用性，不是服务端权限边界。开发路径仍校验自己的令牌、来源和额度，不能复用正常服务会话。
- HTML设置CSP：脚本、样式和连接只允许self，禁止内联/eval、第三方嵌入和外部base。不从CDN加载React、字体或图标。
- 后端只提供index和有限文件名的JS/CSS；拒绝目录逃逸、source map、TSX、Python和环境文件，不设置“任意路径返回HTML”的兜底。
- 键盘有焦点样式、控件标签和live状态；中文输入法合成期间不会因Ctrl+Enter误发，候选与示例都要再次确认发送。手机证据表内部横向滚动，不撑宽整页。

这不是用户登录系统或公网部署。前端按钮与TypeScript类型不能代替后端权限、额度或事实校验；移除发送许可卡不会移除这些后端保护。

## K 线与指标可视化

2026-11-12：[研判回顾](memory-design.md#研判回顾原记录与按需后续走势)新增独立的后来收盘价图，已由 Claude 审核、提交并推送 `f2484cf`。它只在点击后加载腾讯不复权日线，先核对原价格口径，再叠旧程序参考水平线；来源标为供应商报告、未经独立核实。新记录以程序完成时间为边界，旧记录按源对话最近保存日期保守截断，并显示 #625 原句提示。此图不属于下文绑定原研究区间的 `research-chart-v1`，不会把未来日线加入旧指标序列，不计算命中率、准确率或收益。

### 1. 数据从哪里来

```text
原日线分析 → MultiIndicatorResult
  ├─ 事实报告与受限关系 → 公共 answer / report
  └─ build_chart_projection → result.chart → 浏览器校验 → 原生 SVG
```

日线图和文字使用同一次分析，不另外查询“最新行情”，也不在浏览器重算指标。周线与小时线的独立取数和重算规则见第7节，仍绑定原研究日期与来源。图表不是模型生成的图片，坐标由已校验数字计算。

已有接口返回可选 `chart` 日线快照及 `chart_capabilities` 来源能力声明；新增周期走下文独立接口。公共 `parameters` 明确携带来源，包括开发 CSV；工具提议协议不变。图表内部 `request_id` 与报告研究编号一致，不是 HTTP 请求的幂等编号。

### 2. DTO 与检查

`research-chart-v1` 成功响应包括：请求编号、股票、请求区间、来源、复权、真实性、获取时间、current/saved上下文、保存时间、`bars`和`series`。

- `bars` 按日期递增，包含date/open/high/low/close/volume，只导出本次返回的记录。
- `series` 包含指标实例、参数、算法版本、字段、单位、起点敏感提示，以及与bars逐项对齐的values/statuses。
- 先复用事实报告的请求与最新证据检查，再检查每个历史行的日期、字段、状态、所需/实际条数和空值。不重新计算指标，也不声称任意历史数字已独立核实。
- `available` 必须有有限数值；其余状态保持null。成交量单位是股，量比与指数点不得混入价格轴。图表数字绝对值最多1e15，此限制不改变研究计算契约。
- 最多366条日线、12个指标实例、48个字段序列。完整紧凑UTF-8 JSON最多256KiB；超限整张图不可用，不静默截断、抽样或删指标。
- 固定失败码：`chart_context_invalid`、`chart_data_unavailable`、`chart_integrity_mismatch`、`chart_payload_limit`。失败仅导出版本、状态和代码，不回显异常、路径或未核实编号。

前端仍做运行时检查：绑定报告编号、股票/区间/来源/指标参数，检查日期、算法、单位、数值及数组长度。TypeScript不替代这项检查。可选图表非法时只显示固定降级提示，不把已确认研究答案改成“网络响应未确认”，不触发模型重试。

### 3. 当前、追问与历史

初始研究从本轮 `research_result` 导图，标记current。已接受的结果追问和显式历史查看，再通过原 `saved_result()` 校验保存结果的有效期、身份及配置；只附与回答研究编号一致的快照，标记saved。数据保留原保存时间，界面简短标明“已保存快照，非新分析”。

该重查是本地验证与深复制，不取行情、不调模型。历史不是新的编辑基准；新研究失败后不能自动附旧图，只有明确查看历史才可取得旧快照。知识、歧义、取消、过期和无保存结果不借机展示旧图。附加快照或图表投影出错，不抹掉已经确认的文字回答。

图表和其余公共结果一起进入原幂等缓存；重复同编号取回原快照，不更新获取时间或重做分析。返回对象深复制，调用者不能修改缓存中的图表。

### 4. 展示与交互

回答附加区只保留图表，默认直接显示；正文、段落依据、研判卡与价位计划保留。移除附加技术证据表、全局研究依据、证券状态与交易日历、完整报告入口；相应后端数据契约和校验不变。图表支持：

- 日K线、独立成交量区；红/绿/灰表示当日收盘相对开盘，不是相对昨收。
- SMA/EMA/BOLL价格叠加，可按实例开关。
- RSI、MACD各字段、ATR及量能各字段单独选择，独立坐标轴；MACD柱值以零为基线。
- 最近30/60/120条或全部，默认60条；缩小窗口时将所选记录限制在新窗口内。
- 鼠标悬停、触屏横向拖动选择最近蜡烛，操作时才显示纵横十字线和浮层；默认不遮挡图表。指针离开或触摸结束/取消后隐藏，键盘聚焦时可以继续查看，失焦后隐藏。鼠标点击产生的焦点不会让浮层在离开后常驻。
- 浮层使用紧凑的名称/数值两列，日期下按“开、高、低、收、量”逐行显示，缺项为“—”及原因，不补零、不换行、不提供内部滚动条。始终保留已开启价格线中的桌面前3条、窄屏前2条，以及所选副图；其余显示“另有 N 条线”。可关闭部分叠加线查看其余读数。浮层根据选中位置切边，指针可穿透，不妨碍继续选蜡烛。极大或极小的读数用科学计数法保持紧凑，仍保留最多7位有效数字。
- 叠加线开关、图例、浮层和副图选项使用短名称，如SMA20、BOLL 上轨、MACD DIF、RSI14、成交量均量(20)；内部指标编号只用于绑定。相同指标有多套参数时以BOLL(20,2)、MACD(12,26,9)等常用写法区分；单位放在坐标标题与读数中，不拖长下拉选项。
- 图表可用 Tab 聚焦，左右键逐条移动，Home/End 选择区间两端。读屏播报仅包含日期与收盘；指针移动不持续播报。触屏捕获在抬起、取消或失去捕获时结束，保留页面纵向滚动。窄屏条数/副图紧凑同排；周期按钮旁的价格叠加标签局部横向滚动，不使页面横向溢出。
- 一行来源、复权与“历史日线，非实时”；人工样例和未核验CSV醒目标注。移除日期滑块、独立行情数字框、指标读数表、颜色/区间长说明和采集详情折叠区。

只对实际记录等距排列，不补周末或缺失日期，也不凭缺日推断停牌。指标null断线；只有一个可用点时画点，不填0或跨缺项连线。价格线的显示舍入不改变研究数值。历史点没有新增fact ID，最新证据仍保留在原报告数据中。

选择原生SVG，是因为当前数据量有明确上限、交互有限，不需要引入完整交易图表库、CDN或额外服务。目前没有实时订阅、任意区间加载、拖拽缩放、复权切换或图形形态预测。容器宽度变化时调整SVG坐标，指针按实际显示尺寸换算，索引与十字线均限制边界；375px窄屏控件换行、浮层内收。使用样式表定位浮层，兼容禁止内联样式的内容安全策略。图表读数显示7位有效数字，不改变原结果精度。

### 6. 仍然存在的边界

256KiB限制是单张图紧凑JSON大小，不是Python对象或整个API响应的内存上限。图表随每会话至多20条幂等记录保存，最多32会话；新增内存负担仍只适合本机开发，不是生产容量设计。页面至多40条记录，当前每张合法图直接渲染；没有为旧图引入虚拟列表，也不等于有持久化或账户配额。

真实源当前不复权，CSV复权未知；除权、拆分等可能造成价格跳变。图表模块不识别公司行动，不补证券状态/交易日历，不证明真实行情或投资表现。初版之后的公司研究、筛选等功能另见[模块进展](architecture.md#当前模块交付与使用示例)，不属于本图表批次。

### 7. B步：周线和按需小时线

`GET /v1/sessions/{session_id}/chart?research_id=<报告研究编号>&interval=1w|60m|120m`

复用 Bearer 令牌、同源和会话到期检查。查询只接受研究编号和周期，拒绝额外股票、日期、条数或来源参数。服务端在当前会话未退休的完成记录中解析已验证单股日线快照；不能使用聊天请求编号、别的会话编号、多股结果或已重置记录。`chart_capabilities` 绑定同一研究编号，前端据此禁用不支持的周期，服务端独立检查能力。

能力声明仅在HTTP返回的深复制对象上附加，不写回服务层聊天记录；原聊天重放与历史路由观察保持原样。图表代次单独记录，聊天内“新对话”等重置也会使旧图表失效，不改变原聊天重放规则。

| 来源 | 日线 | 周线 | 小时线 |
| --- | --- | --- | --- |
| 腾讯支持的沪深 A 股 | 原报告快照 | 同轮日线聚合 | 点击时取腾讯 m60，重算60m/120m |
| AKShare / 东方财富 | 原报告快照 | 同轮日线聚合 | 暂不可用，不自动改用腾讯 |
| CSV / 开发 | 原报告快照，保留真实性标记 | 同轮聚合，保留真实性标记 | 禁用，零分钟网络请求 |

AKShare 当前 SDK 固定15秒等待并完整读取 JSON，不能下传8秒截止及512KiB限制；因此按 #267/#268 暂禁该源小时线，不用线程等待包装来声称底层请求已经停止。

新增周期使用独立 `research-chart-interval-v1` 数据传输对象，携带周期、上海时区、真实 `start_at`/`end_at`、实际覆盖、来源、复权、真实性、获取时间及研究绑定。柱包含 `complete` 标记；日线仍为 `research-chart-v1`，没有放松旧契约。浏览器校验版本、绑定、时间端点、单位、参数、字段、数组及256KiB大小，失败只降级图表。

周线复用 `technical_insights.group_daily_weeks` 的周一分组，首周周一起点早于原请求开始则省略。开取首、收取末、高低取极值、量求和；不补节假日，不按五条记录猜完整周。周日边界晚于原快照截止日的末周保留，标明“本周未完（截至快照日期）”；原研究仍只使用已完成周线。

腾讯小时线只访问固定 HTTPS `ifzq.gtimg.cn/appstock/app/kline/mkline?param=<symbol>,m60,,320`，无翻页、重试、重定向或换源。按 #248 实测契约读取 `data.<symbol>.m60`：时间、开、收、高、低、量及两个忽略字段。10:30/11:30/14:00/15:00 为结束标签，分别对应09:30–10:30、10:30–11:30、13:00–14:00、14:00–15:00。科创板 `sh688` 原量为股，其他支持沪深板块为手并乘100；输出整数股。原始全批先校验，乱序、重复、错误端点、周末、未来、非法价格/量整批拒绝，再截取原研究日期窗口；空交集明确不足，不拿最新行情代替旧窗口。2小时只合并同日上午或下午的完整配对，缺配对整批不可用，不影响60m。

原始响应最多512KiB/320柱；连接、响应头和每次读取前传入剩余时间，读取后复核总8秒协作截止。不是用后台线程超时冒充请求停止。成功缓存60秒、失败10秒；60m基础柱可复用给120m。同会话至多1个、进程至多2个图表任务，取数/计算在全局锁外；缓存随研究记录有界，不持久化、不占模型额度。完成前重新鉴权和核对重置代次、记录退休状态；重置、删除、到期和关闭清理缓存，迟到结果不回写。前端切周期/回日线/卸载会取消等待并丢弃过时响应；取数失败回到原日线，不重试研究。加载中的周期按钮显示省略号及可访问的忙状态；快照更新时立即刷新真实性警示，并取消旧周期取数。前端允许连续小时柱首尾相接，仍拒绝重叠、重复和倒序。

指标从 `indicators.py` 抽到只处理有序数值的 `_indicator_values.py` 内核，日线入口保留真实 DailyBar 类型、同股和日期递增校验，分钟柱不伪造日期。图表按原参数在所选周期重算全部10类指标；SMA20 周线代表20根周线，缺历史为空。抽取前的十类数值保存在固定黄金夹具中逐项回归。小时线醒目标明“分钟数据有延迟、非实时”，历史研究窗口取数不冒充原保存分钟快照。

分钟适配器与缓存仅由图表接口引用，不进入保存研究、证据、研判、价位或模型消息，也不改聊天重放快照。离线隔离测试比较调用前后的这些实际对象与模型消息，并改变分钟夹具确认研究不变。源码登记仅更新服务层指纹、保留历史，不改变路由规则、题库或标注。

### 本轮解决的问题

旧页面直接展示 `display_answer`：事实报告、关系解释、四维综合和多轮限制说明被拼在一起。仅调整字体不能解决信息重复，因此本轮同时调整展示协议和交互布局，不修改研究计算或新增模型调用。

当前默认阅读顺序是自然语言回答（含段落依据、研判与价位计划）→ 互动日线图。旧的简短标题、读数和观察仍用于兼容视图，不再把执行记录或内部诊断作为聊天附件。重复的通用免责声明不占据主界面；人工行情、历史结果、缺失读数、模型解读失败等影响理解的信息仍直接可见。

### 数据与组件如何协作

```text
Agent 的核验结果 / 已保存的结果
  → public_turn：保留原 answer、report、chart 和状态
  → conversation：自然语言主答复；answer_presentation：兼容紧凑视图
  → 前端：正文、可选视图与股票/日期绑定检查
  → ResponseContent：优先正文；兼容读数卡片、观察与定义
  → App：消息列表、输入框、默认显示的图表和会话控制
```

- `src/trading_companion/answer_presentation.py` 只使用应用已核对的对象。简短句子来自已知关系枚举与固定模板，不用字符串替换删除任意模型文本，不把参考位置包装成收益预测。
- `research_followup.py` 保留已接受的定义主题和核对关系。追问视图只展示相关指标，标明“基于已保存结果 · 未重新取数”；历史概览必须匹配原快照。
- `frontend/src/presentation.ts` 把新视图当作可选数据。坏结构或错请求编号只让卡片降级，不丢掉已确认的答案，也不触发模型重试。研究读数仍来自原始 `report.fields`，显示舍入不改变计算精度。
- `frontend/src/ResponseContent.tsx` 渲染正文及其段落依据，兼容关键读数、观察与知识解释；附加证据表已移除。兼容视图超过六项读数可以本地展开；缺失值保留为“—”，不补零。
- `frontend/src/App.tsx` / `styles.css` 提供固定页头与输入区、独立滚动的消息区、会话目录和手机导航。自动滚动只作用于消息区，从最新回答顶部开始；用户上翻时不强制拉回。
- `frontend/src/controller.ts` 沿用原请求、取消、幂等重放和会话状态机；新增明确的通知级别，让实际错误始终可见，不通过错误文案关键词猜测是否显示。

新视图有异常时返回 `null`；旧客户端仍可读取原答案，新客户端也能展示没有新视图的旧服务响应。界面始终用 React 文本节点渲染外部内容，不执行 HTML。

### 使用变化

- 桌面左侧为当前会话目录，不是假装支持持久化的多会话列表。
- 打开页面即可输入，首次发送自动建立会话；不再要求点击“开始会话”。左侧“新对话”结束当前会话并清空页面，下一条发送时再创建。手机点击左上角展开导航，发送不依赖侧栏。
- Enter 发送，Shift + Enter 换行；继续支持 Ctrl/Cmd + Enter。中文输入法组合输入和 keyCode 229 不触发发送。
- 点击示例或澄清候选只填入输入框，不自动提交。
- 本机服务设置中查看配额规则、连接诊断、接口文档，检查状态或结束会话。
- DeepSeek 与其他模式使用相同发送方式，不再要求确认卡或许可勾选；只有用户明确发送时才创建会话并提交问题。页面载入、写草稿、选择示例或候选不会请求模型。真实提供方仍可能计费，每个后端的来源由服务端启动配置固定；Dev Mode 只切到独立预配离线服务，不允许自由配置模型或行情，未增加存储或下单权限。
- 回答后不再固定显示 RSI、DIF/DEA 和调整指标按钮；需要追问或修改条件时，直接在输入框发送自然语言。
- 不再提供“本轮详情 / 参数与执行记录”，也不在正文尾部显示内部状态码、模型/分析计数、默认参数、工作流或引用诊断。后端仍返回和校验原有结构化字段；图表直接显示，正文内依据按需查看，不再提供其他附加表格或完整报告入口。

首次创建失败会显示错误并恢复原草稿，不自动重试；创建过程显示进度并阻止重复发送。初次检查连接期间仍可写草稿，断连时输入框旁提供重新连接。点击“新对话”不预先创建空会话；删除旧会话失败时保留原聊天和草稿，旧会话已过期则可直接回到空白对话。存在响应未确认的原请求时，仍禁止另开会话或换编号重发；这里的“未确认”是网络结果未知，不是已经移除的发送许可。

#### 正常模式与 Dev Mode

网页默认正常模式，服务默认使用 DeepSeek + 腾讯历史日线。Dev Mode 按钮切换到同源 `/dev-api` 下的独立 `fake + synthetic` 后端，不用为切换重启 Python；两个后端不共享会话令牌、模型实例或预算，也不会迁移旧结果。

仅空闲且没有未确认请求时能切换。原会话清理失败不丢弃原聊天；清理成功后立即选择目标并清空聊天、草稿和凭据，再检查目标 health。目标 health 失败会留在已选目标的断连空白状态，不恢复已删除聊天、不自动回退或重发；可手动重连或重新切模式。连接成功后，下一条发送才创建目标会话。页面刷新回正常模式，不通过浏览器存储记住开发选择；`--demo` 离线启动没有可切回的正常后端。

人工模式明确标记来源，只包含四条证券目录和五根平安银行人工日线，不能用来研究任意股票。按钮只是界面能力入口，不替代服务端鉴权和数据边界；完整路径和失败状态见[模式设计](agent-runtime-design.md#正常模式与-dev-mode)。

### 1. 这个模块做什么

让终端以外的客户端也能调用已有Agent，不把指标计算、模型编排或事实检查搬进HTTP路由。

```text
HTTP请求 → FastAPI / Pydantic校验
         → ResearchApiService：令牌、会话、额度、幂等及取消
         → request_routing：只读判断语义意图、澄清所有权与执行入口
         → 原执行器 / TurnControl
         → 原目录、工具、指标与证据检查
         → 白名单公共响应，不使用Agent调试导出
```

代码分工：

- [api.py](../src/trading_companion/api.py)：HTTP输入/响应模型、正常/开发固定路由、请求体限制、同源与Host保护、统一错误。
- [api_service.py](../src/trading_companion/api_service.py)：独立于FastAPI的服务层，拥有进程内会话和模型实例，协调配额及幂等记录。
- [request_routing.py](../src/trading_companion/request_routing.py)：语义意图、固定原因码和执行入口分开；六条原研究/知识路径与受控本地答复按静态优先级选择，知识插问保留待澄清，身份/指标回复交原所有者。两阶段目录策略与名单惰性时钟保留，授权和状态变化仍在执行器。v1保留35场景/105轮旧事实，v2逐轮核对目标与完整差异，详见[请求路由设计](request-understanding-design.md#请求路由明确意图优先级与澄清所有权)及六项修正。
- [api_server.py](../src/trading_companion/api_server.py)：正常默认及显式离线启动、服务端模型/数据配置，固定127.0.0.1及一个worker。
- [api_demo.py](../src/trading_companion/api_demo.py)：TestClient进程内HTTP演示，不开监听端口、不请求真实模型或行情。

FastAPI/Pydantic只在HTTP边界使用，内部仍复用dataclass。初版未引入数据库；后续聊天历史、自选和证据归档各有独立可选本机 SQLite 存储，不能共用文件。仍未引入任务队列、SSE、WebSocket或新Agent框架。

按[本地配置](operations.md#本地模型配置与启动)准备根目录 `.env` 与有效真实目录后，启动正常产品：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.api_server
```

无参数默认 DeepSeek + 腾讯不复权历史日线、端口8765，自动按原规则读取根目录 `.env`；`--provider` / `--data` / `--port` 可显式覆盖正常后端。上面的直接 Python 启动默认仅检查本地配置、依赖和现有目录，不请求模型或行情、不自动刷新目录；缺配置明确失败，不切人工数据。运行后打开 <http://127.0.0.1:8765/docs> 查看Swagger接口；Ctrl+C停止服务。

Windows 可直接运行 `.\start.cmd`，它额外启用 `--open-browser --refresh-stale-directory`。只有正常真实数据模式、未显式传入 `--directory` 时，缺失、过期或未来日期的默认名单才在启动阶段从交易所刷新一次。名单有效时不联网；格式错误、人工名单、读取失败直接报错。刷新前不读取 `.env`，新名单校验后才原子替换旧文件，再重新加载检查；失败返回非零并保留旧文件。运行期间不自动刷新，名单失效继续由既有研究检查拒绝。直接 Python 入口也可显式传入这个参数，默认关闭；`--demo` / `--data synthetic` / 自选目录不生效。原因码与排错见[本地启动文档](operations.md#启动错误原因)。

扩大筛选样本须显式从PowerShell启动，不由模型、网页参数或聊天文本修改可信采集规模：

```powershell
.\.venv\Scripts\python.exe -m trading_companion.api_server --screening-data tencent --screening-coverage expanded --port 8765
```

默认`standard`仍为腾讯各类代码前50只；`expanded`在各类完整目录上取`q=min(200,总数)`个均匀位置，下标为`floor(i × 总数/q)`，每类抽满名额，小目录取全部，总量最多1000、请求最多20次。东财显式选择`--screening-data eastmoney`时扩大档使用每类两页的供应商分页顺序，不能称为间隔抽样。扩大档会增加延迟和限流风险，仍保持默认25秒/最多30秒采集截止、不自动换源；扩大档的真实速度与来源稳定性尚未联网验证。`--demo`/`--data synthetic`拒绝扩大档，正常启动的独立Dev Mode也不会继承在线样本配置。公共结果保持原版本，`coverage.directory_audit`新增目录对账；旧结果没有该对象时仍可显示，畸形审计对象回退原文字。详见[筛选设计](market-and-screening-design.md#有界-a-股报价样本筛选)。

完全离线服务显式加 `--demo`，不读 `.env`、不能从网页启用正常模式。它使用原 `ConversationDemoModel`，不是通用Fake语言模型：先研究固定问题，再问固定追问，可选原SMA替换脚本；重新创建会话才得到新的脚本实例。重置不重建模型或返还额度。正常启动另外预配独立的同类 Dev Mode 服务，详见下一节。

另开一个PowerShell终端，可实际调用：

```powershell
$apiBase = 'http://127.0.0.1:8765/dev-api'
$apiSession = Invoke-RestMethod -Method Post -Uri "$apiBase/v1/sessions" -ContentType 'application/json' -Body '{}'
$apiHeaders = @{ Authorization = "Bearer $($apiSession.access_token)" }
$apiMessage = @{
    request_id = [guid]::NewGuid().ToString('N')
    question = '分析平安银行，2026-09-21 至 2026-09-25，只看SMA3和RSI2'
} | ConvertTo-Json
$apiReply = Invoke-RestMethod -Method Post -Uri "$apiBase/v1/sessions/$($apiSession.session_id)/messages" -Headers $apiHeaders -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($apiMessage))
$apiReply.result.answer
```

上例使用正常进程中的独立 Dev Mode API，不发送真实模型或行情请求。若以 `--demo` 启动，离线服务位于根路径，应把 `$apiBase` 改为 `http://127.0.0.1:8765`。不要把固定人工示例误发到正常路径来声称真实市场验收。随后用新的 `request_id`发送“这里的RSI为什么偏高”；也可GET `.../result`查看历史。重复发送完全相同的 `$apiMessage`只重放响应，不再调用模型。Swagger正常接口仍先POST `/v1/sessions`，将其 `access_token`粘贴到Authorize的Bearer输入框；正常路径可能触发计费请求，不要分享令牌。

需要真实 DeepSeek 配人工数据的专项检查时，仍可显式启动：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.api_server --provider deepseek --data synthetic
```

该命令可能计费，并不等于离线 Dev Mode。真实腾讯模式现为默认，也可显式 `--data tencent`；需当前有效本地目录，可用 `--directory` 指定服务端路径。除上述显式开启的启动刷新外，不会自动刷新目录、静默换源或让HTTP客户端提交模型密钥/路径。用户明确提交的研究问题、确认参数与紧凑证据会发给配置好的 DeepSeek，可能计费；启动及 health 检查不发送这些内容。终端 `agent_cli` 仍保留原显式模式规则，没有改变其默认行为。

### 3. 接口契约

自选接口与历史浏览一样采用本机单用户语义，无需研究会话令牌；沿用同源/Host、请求体上限及固定错误保护，不是公网账户鉴权。`GET /v1/personal/watchlist` 返回版本、启用状态、50只上限和有界清单；关闭与读取失败分开。`POST` 同路径仅接收完整 `instrument_id`，`DELETE /v1/personal/watchlist/{instrument_id}` 移除一项，`DELETE /v1/personal/watchlist` 清空（网页先确认）。`GET /v1/personal/watchlist/search?q=...` 只查询现有本地目录，1–80字符、最多20候选并标明截断；没有联网刷新。具体数据约束见[自选设计](memory-design.md#本机个人记忆自选股持仓与偏好)。未开启提示给出启动参数名 `--personal-memory-db`，不显示路径。

明确聊天自选命令仍通过下列 messages 接口，占一条会话消息，沿用忙碌和编号重放；面板不消耗研究额度。管理命令在意图模型前本地处理，结果通过可选 `personal_memory` 字段返回，不调用模型/行情、不写聊天历史或摘要、不改变研究待澄清状态。“平安银行值得加入自选吗”“分析自选股里的平安银行”继续研究明确对象，不自动读取清单；“清空自选”只引导面板确认。

持仓偏好响应版本为 `personal-memory-preferences-v1`：`GET /v1/personal/preferences` 返回 `version/enabled/limit/items/collection_revision`，最多50份，与自选独立计数。`PATCH /v1/personal/preferences/{instrument_id}` 仅接受 `{expected_revision, changes:{holding_status?,horizon?,risk?}}`；新建 `expected_revision:null`，省略类别保持原值，显式 `null` 清除此项，禁止全空记录。类别为持有状态 `null/unknown/held/not_held`、期限 `null/short/medium/long`、风险 `null/low/medium/high`，不接受成本/比例/自由文本。`DELETE` 单股通过 `If-Match` 传裸32位十六进制记录标识，清空同路径传裸64位清单标识，网页分别确认；该请求头只传固定修改标识，不实现ETag协议。过期返回409/`preference_revision_conflict`，不静默覆盖或自动重试，写后刷新失败仍提示变更未确认。完整字段和升级边界见[个人记忆设计](memory-design.md#本机个人记忆自选股持仓与偏好)。

研判回顾使用独立 `research-review-v1`，无需研究会话令牌，沿用本机同源保护：

| 接口 | 输入与边界 |
| --- | --- |
| `GET /v1/research-reviews` | `instrument_id`，可选上海提问日期 `from_date/to_date` 和 `cursor`；最多扫描20个原结果，返回扫描/异常数和下一页状态 |
| `GET /v1/research-reviews/{conversation_id}/{sequence}` | 查询参数 `request_id/instrument_id`，只读返回这一条原问答与投影，不切研究会话 |
| `POST /v1/research-reviews/{conversation_id}/{sequence}/prices` | 请求体仅 `request_id/instrument_id`；服务端从原记录计算资格和日期，客户端不能指定来源、地址、复权或价位 |

回顾依赖聊天库，与个人库开关独立；原结果不复制到第二个库。列表/详情零模型、零行情，价格请求也零模型且不占研究额度。新结果可选 `review_context` 记录程序完成时刻；旧结果按 #625 取源对话最近保存上海日期之后，清楚标明可能遗漏较早走势。复权及真实性在联网前核验；单实例最多一个实际取数，取消等待后仍由工作器真实清理释放槽位。源删除最终拒绝发布。完整DTO、错误降级和366日/两请求/8秒协作预算见[研判回顾设计](memory-design.md#研判回顾原记录与按需后续走势)，已随 `f2484cf` 提交推送。

消息收件箱使用独立 `personal-memory-notifications-v1`，无需研究会话令牌，仍受本机同源/Host保护；关闭时只返回未启用状态，不打开个人库或来源客户端：

| 接口 | 输入与边界 |
| --- | --- |
| `GET /v1/personal/inbox` | `unread_only` 默认true、可选完整 `instrument_id` 和列表 `cursor`；每页20条，只读本机，含未读数/逐源状态/清理告知 |
| `POST /v1/personal/inbox/check` | 仅 `request_id` 和可选检查 `cursor`；服务端当前自选最多5股，新浪新闻/东财公告各一次，最多10次实际HTTP尝试、每源5条/最近30天 |
| `PATCH /v1/personal/inbox/{message_id}` | 严格请求体 `{read:true}`，64位消息标识，仅标为已读、幂等；打开原链接不隐式写入 |
| `DELETE /v1/personal/inbox` | 确认后 `If-Match` 传64位集合修改标识；清消息/已见并重置基线、轮换加入标识，保留自选/偏好/聊天 |

列表游标与检查游标不能互用；自选变化使检查游标失效，继续下一批必须再点。检查编号重放不联网，冲突、忙碌及退役编号均固定报错。一个实例仅一个实际检查，20秒协作批次/6秒单次请求/跨批1秒实际发起间隔，与普通研究共享原3槽；异步HTTP只等待同步工作器，断连置取消标志，真实响应与客户端收尾后才放槽。手动检查取消和本地提交同锁决定先后，已保存部分保留；单源本机提交最多200毫秒协作预算并受批次剩余约束，不承诺硬磁盘停止。请求间隔结束后、真实发送计数前的 `before_request(instrument_id, source)` 回调有界重核自选身份，前后检查取消；本服务移除/清空自选、清空收件箱时立即使在途gate失效，未发出来源不消耗进度。页面等待含收尾裕量，响应未知保留原编号供手动核对，不自动换编号重试。API收件箱DTO还可附 `sidecar_status:null|inbox_sidecar_saved|inbox_sidecar_unavailable`，仅进程内固定码、重启null；纯 `store.list_inbox` DTO不含此字段，不新增数据库或改变研究响应。界面提示旁路保存未确认；研究旁路提交前checkpoint取消使事务回滚，属于协作边界，不声称手动gate同锁硬中断。完整字段、v3迁移及有限覆盖告知见[收件箱设计](news-design.md#自选股消息收件箱有限检查与本机未读)。

检查回执 `results` 的各来源另有必填 `filtered_count`（整数0–50），表示新浪合格但未提及该公司、落在查询日期窗口外，或HTTP/HTTPS新浪域/子域链接格式正常但不在原保存白名单的正常筛选，不阻止建立基线或推进水位；不支持的HTTP研报、移动/快讯链接只过滤、不访问、跟随、改写协议或保存，可保存及前端可打开链接仍限原HTTPS白名单。其他协议、非新浪域及真正格式、链接、时间戳错误仍为 `skipped_count`，按部分失败处理。过滤计数仅在本批回执及有界重放中，不新增v3库字段或列表 `source_states` 字段，普通研究统计和链接白名单原样。消息列表同一首次发现时间内按发表日期/实际时刻倒序，日期精度不补时分；列表游标同步包含发表日期和可空时刻，旧列表游标需刷新，检查游标不变。

明确“记住我持有平安银行”等个人管理指令在本机执行、跳过模型和历史摘要；成本/仓位管理整条固定拒绝，不部分写入。普通“我持有平安银行，分析走势”“如何设置仓位”继续研究/知识。当前研究页的主动草稿只填完整代码和研究问题类型，`held`提供退出、`not_held`提供买入观察条件，`unknown`/未填写无该按钮；不复制类别、时间或资料对象，不自动发送。删除资料保留自选和历史，普通研究接口不附带个人资料。

| 接口 | 功能 | 正常HTTP状态 |
| --- | --- | --- |
| GET `/health` | 服务模式及只读边界，不检查供应商连通 | 200 |
| POST `/v1/sessions`，body `{}` | 创建会话，返回ID和一次可见的访问令牌 | 201 |
| GET `/v1/sessions/{id}` | 当前状态、已用额度；忙时不读正在修改的研究槽 | 200 |
| POST `.../{id}/messages` | body仅 `request_id`、`question` | 200 |
| GET `.../{id}/result` | 显式历史查看；0模型/0分析，不消耗问题额度 | 200 |
| GET `.../{id}/chart?research_id=...&interval=1w\|60m\|120m` | 当前会话单股研究绑定的独立图表；不消耗模型或研究额度 | 200 |
| POST `.../{id}/cancel` | body仅 `request_id`，对准当前轮发取消信号 | 202 |
| POST `.../{id}/reset`，body `{}` | 清研究状态，旧请求编号退役，额度不退 | 200 |
| DELETE `.../{id}` | 删除空闲会话及其状态 | 204 |

正常启动另提供 `/dev-api/health` 和 `/dev-api/v1/sessions...`，对应独立的 `fake + synthetic` 服务。它与正常服务不共享会话、令牌、模型实例、幂等记录或预算；令牌必须属于所访问服务。开发目录只有四条人工证券记录、平安银行五条人工日线，不能用于任意股票研究。根 health 可包含可选 `development_mode_available`，只是页面能力提示，不是鉴权机制。

网页切换只在空闲且无响应不确定请求时进行：旧会话清理失败保留原内容；清理成功即选择目标并清空聊天/草稿，再核验目标 health，下一句明确发送才创建目标会话。目标失败会留在目标断连状态，不恢复已删除聊天、不自动回退或重发。每个后端的模型和行情仍由启动固定，客户端没有任意来源参数。`--demo` 只提供离线根服务，不能切回正常后端。完整状态约束见[模式设计](agent-runtime-design.md#正常模式与-dev-mode)。

除health、文档和创建会话外，必须有 `Authorization: Bearer <access_token>`。这是一份会话能力凭据，不是DeepSeek密钥，也不是用户账户登录。ID不是授权依据；另一会话令牌不能访问该会话。

ID与 `request_id`均为32位小写十六进制字符串。问题为严格字符串、1–2000字符，不接受空白句；首尾空白规范化后参与幂等比较。所有请求禁止额外字段，不能用body配置模型、来源、目录、文件、预算或会话对象。POST需要JSON，总请求体最多16KiB；即使流式上传或伪报Content-Length，也检查实际累计字节。

HTTP 200表示服务处理了这条合法消息，`result.status/code`才表示研究成功、澄清、范围拒绝或模型失败。不能把200当作投资判断正确。结构错误422，缺令牌401，不匹配/未知/过期会话统一404，编号冲突或会话忙409，容量/额度满429，目录不可用503，未预期内部失败500。错误只含固定 `error.code/message`，不回显输入、底层异常或Pydantic错误详情。

公共响应只选取程序安全答案、事实报告、已确认参数、候选、默认口径、运行统计及有界chart。chart来自本轮分析或接受追问所绑定的已验证快照，最多366条/48字段/256KiB紧凑UTF-8 JSON，不额外取数。图表不可用不会抹掉文字；历史/追问附原参数与报告，失败新研究不附旧图。该大小界限不是整个响应或内存上限。禁止直接返回 `AgentTurnResult.to_dict()`：它包含调试草稿和完整研究结果，不适合作为HTTP协议。

可选 `market_context` 独立返回板块、上市／ST／全天停牌、逐日交易所日历及来源冲突；最多64KiB紧凑UTF-8 JSON，不发送模型、不参与计算或筛选、不声称PIT。仅已提交且内部研究ID相同的保存结果可附背景；新研究读取可选本地loader，历史和追问只深复制原缓存，首次失败也冻结，cache miss不补读当前文件。缓存每会话最多20项，与幂等响应同锁发布，reset／自然重置／delete／TTL／close清理。停止轮保留的指标事实不能据此升级为已保存背景。未配置或读取失败只让背景unavailable，正文仍有效。

启动器 `--market-context` 仅接受应用选定的可信本地JSON，原始≤5MiB；禁止在消息body或模型工具里配置。demo固定人工夹具，Tencent默认未配置，不自动联网或刷新。默认夹具的真实股票代码配有故意虚构的上市/ST/停牌和日历属性，仅用于程序验证，不能作为市场事实。`source=sse/szse/bse` 也是快照自报标签，不代表应用已认证官方内容。详见[背景契约](market-and-screening-design.md#证券主数据与交易日历背景)。

### 4. 幂等、并发与取消

每会话维护一个有限 `request_id → 问题摘要/响应或错误`记录。摘要使用SHA-256，不保存原始问题；记录上限由20条问题额度限制。相同编号/问题已结束时，返回原响应并标 `replayed=true`；仍在执行时409，不发第二次请求；同编号换问题409。缓存包括已接纳请求的目录/内部失败，不能通过网络重试偷偷再调用。

重放是“原消息的原结果”，不是重新查询最新状态。重置清报告缓存，但保留编号退役标记，重用返回409。达到服务并行上限而尚未接纳的请求不消耗问题编号，可用同一编号稍后重试。

同会话同时只能一个操作；默认整个服务最多2轮在执行，忙时立即拒绝，不建立无界队列。同步路由 `def`由框架放在线程池运行，不能把同步模型HTTP直接塞入 `async def`阻塞ASGI事件循环。取消路由仍能响应：只发送 `TurnControl.cancel()`，不从另一个线程直接清研究状态。

取消必须匹配当前API `request_id`，不是内部研究事实的request ID。202只表示已发信号；正在执行的远程请求未必已经中断，也可能计费。原消息连接会在协作检查后返回 `turn_cancelled`。取消不提前释放运行槽，否则旧工作尚未结束就可能启动更多工作。重置/删除忙会话先返回409，应等待原请求结束再操作。

一般研究客户端断开或取消HTTP等待，不等于Agent收到取消信号；需要显式调用取消接口。回顾价格和收件箱检查的独立异步处理器另将断连转为各自的协作取消信号，仍不提前释放真实工作槽。当前没有持久任务ID、后台任务、流式进度或断线续传。

### 5. 配额、安全和生命周期

- 默认最多32个会话，每会话20条新问题、60次模型方法转发，创建后30分钟绝对失效；访问和重置不续期。
- 失效按请求惰性清理；发现正在运行的失效会话时发取消，返回后清理。没有独立定时清理线程。
- 原Agent的15分钟结果/条件有效期和每轮90秒协作限制仍独立生效。上传及本地目录准备发生在Agent入口之前，不宣称整个HTTP请求90秒硬结束。
- 创建新会话/重启会重获本机额度，因此这不是跨会话的账户限流、付费花费上限或抗滥用系统。
- 访问令牌来自随机生成并以常量时间比较；服务内存保存，重启后失效。不使用浏览器Cookie，不开启跨域通配CORS。
- 启动器固定loopback、一个worker。Host仅接受localhost/127.0.0.1/IPv6 loopback；拒绝跨Origin及cross-site浏览器请求，防止网页诱发本地付费操作。未来不同端口前端需要另行明确配置可信Origin。
- 所有HTTP响应no-store；启动器关闭访问日志。服务不写聊天、报告或凭据文件，不将会话令牌作为模型请求配置。
- 关闭服务时撤销空闲会话并向在途轮发取消；不能声称强制杀死供应商请求。

会话隔离不等于生产用户鉴权。不能把此服务绑定0.0.0.0、启用多个worker或放进公网反向代理就称部署完成；还需用户身份/资源归属、TLS、账户配额、共享状态、真正任务生命周期、可观察性与上线验证。离线HTTP测试工厂与 `--demo` 不读取真实配置；Web启动器默认正常模式。两者不能混为一谈，正常默认也不意味着真实提供方已经通过连通或质量验收。
