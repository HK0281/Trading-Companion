# 本机个人记忆：自选股、持仓与偏好

更新：2026-11-12。自选股和第二模块“持仓与偏好”已由 Claude 审核、提交并推送，分别为 `9aa98af`、`4faea64`。第三模块[研判回顾](research-review-design.md)按 #622/#625 实现，当前为未提交工作区改动、待 Claude 审核。各模块沿用线程 #589 的 #592 方案和 #594 选择，只保存在本机，不自动发送个人背景。消息收件箱、重要提醒、后台定时和推送均未实现。

## 1. 开启和数据范围

代码默认关闭。正常公开数据模式下显式指定本机文件，例如：

```powershell
.\start.cmd --personal-memory-db data\personal_memory.sqlite3
```

`start.cmd` 本身不默认启用个人库。`--no-memory` 优先禁用聊天历史、轮次摘要和个人库，忽略两个记忆库参数；关闭不会删除已有文件。demo、synthetic 和网页 Dev Mode 不创建、不读取或返回真实个人库；前两种模式不支持显式开启个人库。未开启的界面提示使用 `--personal-memory-db`，不显示文件路径。

SQLite 是单个本机文件数据库。独立个人库不向原 `data/conversations.sqlite3` 加表，也不与证据快照库共用文件。首版 `personal-memory-store-v1` 只存自选；本轮升级为 `personal-memory-store-v2`，保留原自选表，新增逐股持仓与偏好表。两者均使用本机用户 `local`、完整证券代码、经目录核验的名称、创建和更新时间。保存名称不声称自动跟随更名。

- 每用户最多 50 只，按完整代码去重。事务（一次全部成功或全部撤销的数据库操作）内检查重复和容量，再写入；满额重复加入仍返回已在自选，不改原时间和顺序。
- 新对话、重置、模型切换、服务重启和删除聊天都保留自选及持仓偏好。“清空自选”“清空持仓与偏好”“清空聊天历史”分别确认：每项只删除自身，不连带删除其他资料。
- 文件未加密、不自动同步，不存账户、成本价、仓位比例、资金或凭据。关闭和删除当前记录都不能撤回用户另存的文件备份。
- 错误格式、陌生版本、损坏字段和容量异常拒绝读取，不覆盖或悄悄重建原库；同一文件不能配置为个人库与聊天/快照库。启动时显式配置失败则报错，运行中失败明确显示“读取失败/变更未确认”，不回显路径、SQL 或数据库正文，不阻断普通研究。写入后刷新失败或响应丢失时不能断言没有保存，需刷新核对，不自动重试。

## 2. 用户入口

侧栏“自选股 · 保存在本机”提供本地目录搜索、候选选择、加入、逐项移除、确认清空及手动刷新。公司研究结果卡对已核验证券提供加入/移除按钮；从按钮提交的旧代码也必须重新核验，不能从回答正文猜代码。页面按钮独立于研究会话，研究额度耗尽仍可管理自选；打开页面仅读本机清单，不自动请求行情或新闻。

聊天支持“把平安银行加入自选”“从自选移除平安银行”“查看自选”。每条管理消息仍占用一条会话消息，沿用会话忙碌、问题数上限与请求编号重放规则，但不调用模型、不取行情、不做分析。重复请求只重放当时结果，不重复写入；页面另外读取最新清单，不把旧响应当成当前状态。聊天“清空自选”仅引导到面板确认，不直接删除。

身份只来自服务端现有证券目录：唯一精确代码、名称或核验别名可直接解析；部分匹配即使只有一项也要用户确认。歧义候选保留管理动作，选择后发送“把 000001.SZ 加入自选”等完整命令，不发送可能被研究澄清误解的裸代码或“第一个”。新增要求目录新鲜、身份可用；移除按已保存代码/名称解析，目录过期、股票退市或更名后仍可删除。查看和清空不读目录。目录搜索不联网、不自动刷新。

## 3. 与研究分流的边界

确定性程序在意图模型之前识别明确管理动作。否定句不写入；多对象、多动作或“加入并研究”等混合管理请求只给本地说明，不部分写入或调用模型。以下研究问法仍走原研究流程，不被“加入自选”几个字截获：

- “分析自选股里的平安银行”：研究明确说出的平安银行，不自动加载整个清单。
- “平安银行值得加入自选吗”：询问研究判断，不是保存清单的命令。
- “什么是自选股”：沿用知识/问答分流，不写清单。

管理结果使用独立 `personal_memory` 公共字段。管理原话和结果不写聊天历史或轮次摘要，不进入回答模型、意图模型、Jev（新闻标题分类辅助模型）、标题采集或运行记录正文。运行记录只允许固定类型/状态码。管理操作保留原待澄清问题、研究主体、旧图和已保存结果，不把管理候选放进研究状态。

明确要求“记住我的成本价/仓位”等个人资料管理语句优先整条本地拒绝，固定说明“目前只记录是否持有、期限和风险偏好，不记录成本和仓位”；混合支持字段时也不部分写入、不引导到不存在的成本表单。普通研究问题仍按原规则发送；用户主动在研究问题里输入个人数据时，不能承诺该原话不会送模型。没有个人背景授权开关和自动注入路径，将来增加这类功能须另行审核。

## 4. 本地接口与界面隔离

所有接口沿用本机同源、Host、请求体大小和固定错误保护，与历史浏览相同使用本机单用户语义，不增加账号认证。浏览器和模型不能指定文件路径。

| 接口 | 用途 |
| --- | --- |
| `GET /v1/personal/watchlist` | 读取启用状态及最多 50 条清单 |
| `POST /v1/personal/watchlist` | 仅接受一个完整 `instrument_id`；名称由服务端核验 |
| `DELETE /v1/personal/watchlist/{instrument_id}` | 移除指定代码，可重复执行 |
| `DELETE /v1/personal/watchlist` | 清空自选，可重复执行；网页先确认 |
| `GET /v1/personal/watchlist/search?q=...` | 查询已有本地目录，1–80 字符，最多 20 个候选，标明截断 |

清单结果版本为 `personal-memory-watchlist-v1`，包含 `enabled`、`limit:50` 和 `items`；关闭、已启用但为空、读取失败是三个不同状态。搜索返回有界候选和截断标志，写接口拒绝额外字段。前端严格核验版本、证券字段、时间、去重和上限，收到成功响应后才更新；不在浏览器持久存储中另存清单。

切到 Dev Mode 立即清除页面个人清单和搜索候选，返回正常模式重新读取。请求代次阻止旧模式或旧搜索的迟到响应覆盖新状态。跨标签页通过手动刷新或下次操作读取最新值，不做后台轮询，不承诺已显示静态内容能被远程擦除。

## 5. 实现和验收边界

`personal_memory.py` 管字段和公开版本，`personal_memory_store.py` 管独立库和事务，`personal_memory_commands.py` 只解析明确动作；`api_service.py` 处理本地管理并跳过聊天记忆保存；`api.py` 提供 `/v1/personal/` 接口；前端 `Watchlist.tsx`、`controller.ts` 和 `api.ts` 管理展示与状态。

自选规则基线为 `personal-memory-watchlist-v1`，父版为 `intent-research-documents-v3`；持仓偏好另登记 `personal-memory-preferences-v1`，将完整自选父版保留一次。当前研判回顾登记 `personal-memory-review-v1`，父版为 `personal-memory-preferences-v1`。旧题库、规则历史和付费评估锁不改写；新版本只证明代码身份，不代表语言质量或真实模型验收通过。

离线验收使用临时库、固定目录、假时钟和禁止真实模型/HTTP 的替身，覆盖容量与并发、重启保留、坏库和同文件误配、目录过期仍可删、管理命令不进入历史/模型、原研究状态不变、研究反例与现有意图题库、禁用/开发隔离、界面确认和迟到响应。工程门禁为 `verify.py python`、`web`、`bundle`；本模块真实页面流程由 Claude 用临时库检查，不需要调用付费模型或行情。此处不预写测试通过数或页面验收结论。

## 6. 持仓与偏好 A 档

资料按股票独立保存，不增加全局画像，不从自选、研究问题或历史聊天推断持仓，也不跨股票继承。每股只接受以下三类固定值，不接受金额、比例、自由文本或额外字段：

| 字段 | 值与含义 |
| --- | --- |
| `holding_status` | `null` 未填写；`unknown` 不确定；`held` 持有；`not_held` 未持有 |
| `horizon` | `null` 未填写；`short` 短线；`medium` 中线；`long` 长线 |
| `risk` | `null` 未填写；`low` 谨慎；`medium` 均衡；`high` 积极 |

至少填写一项才保存，清除最后一项应明确删除整份资料。未填写、不确定和未持有分开；页面标“本机自报，可能已变化”，显示整份记录的最后修改时间，不把它说成持有状态刚核实的时间，也不以固定过期天数推断买卖状态。同值重复保存不更新日期或修改标识。

最多 50 份资料，与 50 只自选分开计数；无需先加入自选，保存也不会自动加入。移除/清空自选保留资料；删除/清空资料保留自选和聊天。新建资料须经新鲜目录核验，已有资料按保存代码与名称维护，不因目录过期、更名或退市而无法修改、删除。

## 7. 个人库 v1 到 v2 的严格升级

空库直接建立 v2；正常公开数据模式打开精确匹配的 v1 时，在一次事务内核验原格式、完整对象清单和全部旧数据，再创建 `preferences` 表、最后设 `user_version=2` 并复核完整 v2。原 `application_id`、自选建表语句、数据、顺序和时间全部保留。已有 v2 严格校验后使用。

陌生版本、额外表/索引/触发器、结构不符或坏记录均拒绝升级；中途失败整体回滚，不覆盖重建、不降级，也不自动复制含个人资料的备份。升级后旧版程序会拒绝打开此文件；需要回退版本时，应事先自行妥善保存原文件。`--no-memory`、demo、synthetic 和 Dev Mode 的隔离在打开库前生效，关闭路径不读取、不创建、不迁移。

## 8. 持仓偏好接口和修改冲突

资料使用独立 `personal-memory-preferences-v1` 响应，不改变自选接口版本，也不往自选记录中追加个人类别。列表响应包含 `version`、`enabled`、`limit:50`、`items` 和 `collection_revision`（识别清单是否变化的不透明标识）；每份资料带自身 `revision`。

| 接口 | 行为 |
| --- | --- |
| `GET /v1/personal/preferences` | 读取启用状态、至多 50 份资料和清单修改标识 |
| `PATCH /v1/personal/preferences/{instrument_id}` | 请求体为 `expected_revision` 与 `changes`；后者仅含本次修改的 1–3 个 `holding_status`、`horizon`、`risk` 字段 |
| `DELETE /v1/personal/preferences/{instrument_id}` | `If-Match` 请求头携带上次读取的裸 32 位十六进制记录标识，确认后删除；已不存在则成功 |
| `DELETE /v1/personal/preferences` | `If-Match` 携带确认时的裸 64 位十六进制清单标识，确认后清空资料 |

`changes` 省略的字段不改，显式 `null` 清除该项；新建传 `expected_revision:null`，仅在记录不存在时成功。更新、删除在事务内核对读取时的修改标识，每次实际变更生成新标识，删除重建也不复用。清单标识从有界记录集合及其标识派生，不另存一份资料副本。`If-Match` 这里只承载上述固定标识，不实现 HTTP ETag 协议。标识过期返回 HTTP 409、固定码 `preference_revision_conflict`，页面保留编辑内容并提示刷新核对，不静默覆盖、不自动重试；清空时集合发生变化也要重新确认。

关闭、空资料和读取失败分开显示。响应丢失或写后刷新失败显示“变更未确认，请刷新核对”，不能宣称没有保存。面板沿用本机同源保护、无研究会话依赖和原研究额度隔离；不开公网身份体系。

## 9. 个人资料管理命令

少量完整固定形式由程序在意图模型前处理：

- “记住我持有平安银行”“记住我未持有平安银行”；
- “把平安银行的持有状态设为不确定”；
- “把平安银行的期限偏好设为中线”“把平安银行的风险偏好设为谨慎”；
- “查看持仓与偏好”“查看平安银行的持仓与偏好”。

每次明确点名一股、修改一个字段，在事务内合并最新其他字段，不因只修改持有状态清空期限或风险。缺对象不继承最近研究；歧义候选回复携带完整代码、字段和值，保留原研究待澄清。删除和清空只引导面板确认。否定、多对象、多动作、管理加研究只给本地说明，不部分写入、不调用模型。

“我持有平安银行，分析走势”“如何设置仓位”“如何记录我的成本价”仍沿普通研究/知识流程，不因出现个人词语就截获或保存。明确成本/仓位管理才整条本地拒绝。所有纯管理继续计一条会话消息，沿用忙碌、重放、取消和写入提交边界；不请求模型、行情或新闻，不写聊天历史/摘要，不改变研究状态。

## 10. 页面资料与主动研究草稿

“持仓与偏好 · 仅本机”提供固定类别表单、查看、保存和确认删除，可从自选项、本地资料搜索或已核验公司研究对象打开。当前同股研究旁可显示自报类别与记录修改时间，历史结果只读展示不挂今天的持仓提示。

只有 `held` 提供退出条件研究草稿，`not_held` 提供买入条件研究草稿；`unknown` 和未填写不提供该按钮。生成的草稿只含完整代码与研究问题类型，例如“请分析 000001.SZ 的退出观察条件”，不复制持有状态、期限、风险、修改时间或整个资料对象，不自动回答原期限澄清，也不改变程序价位。

点击按钮只放入可编辑草稿，不发送、不调用 `send`；已有草稿先让用户选择保留或替换。页面说明草稿尚未发送，按发送后会交给当前模型，并按普通聊天规则保存。用户自行追加背景仍按普通问题规则发送；资料修改或删除不擦除用户自行编辑的普通草稿。切 Dev Mode 清除个人清单、表单、提示及管理候选，遵循既有问题草稿切换规则，迟到响应不得恢复资料；返回正常模式重新读取。浏览器不另存资料副本。

研究执行不读取个人库组装问题，不给资料生成 E 证据编号、不加入数值白名单，不改研究对象、领域、日期、ATR 或价位算法。意图模型、回答模型、Jev、运行记录正文、标题采集、聊天历史与摘要都不自动增加存储的个人字段。删除本机资料不删除已有聊天原话或摘要；需要另删对应历史并重置当前会话，且无法撤回已经发出的请求。

自选搜索会区分“已在自选”和“清单尚未确认”，首读慢/失败或刷新失败时不把未知状态显示成未加入，并同步按钮可访问名称。≤534px 侧栏与历史入口的可达性是既有已知限制，本模块不调整整体响应式布局，不将它写成已修复。

## 11. 与研判回顾的关系

回顾直接从聊天库原结果有界扫描，不在个人库保存判断副本，不要求股票在自选或持仓中；关闭个人库不关闭已开启的聊天历史回顾，`--no-memory` 则统一禁用。删除源聊天会使对应回顾失效；移除自选、删除持仓资料仍保留聊天原记录。

本轮回顾同时补充草稿禁用原因和可访问说明：资料变更未确认时显示“资料待刷新核对”；版本冲突提示去除重复首句，编辑内容仍保留。原草稿不复制个人字段、不自动发送的规则不变。回顾的分页、原问答、旧记录保守时间和点击后取数规则见[研判回顾设计](research-review-design.md)，本轮待审核，不预写验收结论。
