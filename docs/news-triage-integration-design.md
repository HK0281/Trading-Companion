## 当前行为

公司研究默认仍用新浪新闻、东方财富公告，巨潮公告是现有的可选来源。排序默认关闭时，回答收到的资料、顺序、引用编号、提示词和模型调用次数保持原有行为。单独的标题记录功能不运行 Jev 或 DeepSeek，也不读取分类 API 配置。

正常服务可显式打开：

```powershell
.\start.cmd --capture-news-titles
```

默认关闭，不因存在密钥自动开启。仅正常数据、DeepSeek 会话、当前公司研究记录；新版意图入口、旧入口及从筛选名单进入的公司研究共用记录点。历史研究、OpenAI、演示/开发、知识、指数和仅技术研究不产生标题文件。重放相同请求 ID 不重复写入，保存结果的纯解释追问也不重新采集。

记录点在资料采集及校验完成之后、综合回答之前。最多三家公司，每家公司每个来源最多五条，只接受 `content_kind=title` 的原始值。新浪标题、东方财富和巨潮公告保留来源链接及时间精度；东方财富新闻的搜索摘录不拆成标题。原始标题不会因回答显示长度限制而截短。

三份固定清单位于 [collect_news_titles.py](../scripts/collect_news_titles.py)，每批分别含沪市主板15家、深市主板15家、创业板10家、科创板10家，共150家且互不重叠。默认首批；`--batch second`更多覆盖常用词、地名和集团名，已采集。`--batch third`覆盖本地目录中带ST的名称及能源、化工、有色、光伏、电池材料、航空、地产等有周期特征的行业；只按公司特征选样，未参考已有标题、人工答案或模型错误，也不声称某家公司近期已被立案。第三批真实采集及新增316题定稿已由Claude完成，详见A2文档。它们是研究试点清单，不代表全市场分布。简称仍须通过原适配器的页面/证券身份核验；公司改名、页面变更或来源不可用会保留失败，不猜新名字、不重试、不换源。

默认只输出计划，不读 `.env`、不构造 HTTP 客户端、不建输出目录：

```powershell

# 第三批仅预览；实际执行另需 --live --max-requests 100。
.\.venv\Scripts\python.exe -X utf8 -B scripts/collect_news_titles.py --batch third

# 预览一个子集；同样不联网。
.\.venv\Scripts\python.exe -X utf8 -B scripts/collect_news_titles.py --company 000001.SZ --company 300308.SZ --max-requests 4
```

真实采集由 Claude 执行；Codex 没有执行下面的命令：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/collect_news_titles.py --live --max-requests 100
```

`--live` 必须同时给出 `--max-requests`，允许 1–100；失败尝试也扣除。选择子集时仍只能使用固定清单中的完整证券代码。每家公司新浪一页、东方财富公告一页，每页最多五条，总计至多 100 次公开来源请求、500 条标题。来源窗口统一为运行开始时点之前 30 天，保留原有身份、时间、链接、响应大小及超时校验，不抓正文、PDF 或额外分页。固定 GET 端点以外的请求被拒绝。

整次串行，相邻实际网络尝试开始时点至少间隔一秒；失败后下一来源也遵守间隔。达到预算在下一个来源前停止，不会为补足标题而追加请求。每个来源独立记录，空页或失败不会冒充没有公司事件。源失败、未运行、写入停止均保留在报告中；部分执行退出码为 1，参数无效为 2，计划预览或完整执行为 0。完整执行只说明计划走完，不能说明样本量或质量达标。

## 共用记录格式与边界

[news_triage_shadow.py](../src/trading_companion/news_triage_shadow.py) 提供 `news-title-capture-v1` 格式和有界记录器。在线输出 `.agentbus/tmp/news-triage-shadow/<run>/`，脚本输出 `.agentbus/tmp/news-title-collection/<run>/`。目录均已忽略，每次使用新的运行子目录，不覆盖、删除已有文件。

每份 JSON 包含：

- 版本、来源用途（在线 research 或脚本 collection）、统一截止时点、发表窗口起点；
- 每家公司代码、名称及新闻/公告来源的状态、固定错误码和采集时间；
- 标题原文、原证据 ID、原链接、发表日期/时刻、原时间精度、采集时刻；
- 标准化标题 SHA-256 摘要，即供后续识别完全相同标题的散列值；标题数及恒为零的模型调用数。

只逐字段提取公共资料，不序列化整个研究计划或资料包；因此不写原提问、聊天、回答、密钥、账户资料、来源原始错误正文。来源链接再按既有固定形式检查，防止附带任意查询串。运行 trace 不增加标题正文；普通研究/API 输出也不暴露这些本地记录。

每份至多 30 条、64 KiB；一次运行最多 10 MiB、1,000 份。首次真正写入时才创建目录，先写 `.partial` 再改名为 `.json`；失败留下的 partial 不算完整记录。容量到限、无效资料或写入失败即停止该记录器后续写入，并只发一次固定提示，不丢失已有记录，不改变研究回答。脚本遇写入停止也停止继续取数。取消和整轮截止异常继续向上传递，不当作普通记录失败吞掉。本地磁盘操作有界但不是硬实时保证，尚未测真实额外延迟。

脚本报告列出实际请求数、来源完成/失败/未运行数、保存量、不同“公司—标题—日期”数及距离 400 条的原始缺口。该数量尚未做近似转载聚类或人工标注，不保证已经有 400 条可用评估题。去重和分组封存由 A2 完成。

### 选样、容量和预算

[排序器](../src/trading_companion/news_triage_sorting.py)按研究计划的公司顺序，固定选择第一家有已核验原始标题的公司；该公司的新闻、公告交替取样，每类至多五条。发出请求前，按完整冻结请求体估算token（供应商用来计算用量的单位），确定两方共同处理的最长可容纳前缀；不是先调用再缩批。估算采用UTF-8字节数除以三再加输出预留，不是精确分词或账单硬上限。配置缺失或一条也装不下时零请求。

**2026-11-10 Claude依用户授权作出的预算决定（总线消息#576）**：Jev单轮40,000 token独立记账，不计入DeepSeek整轮24,000或分诊8,000子阈值。DeepSeek分类仍受8,000子阈值和24,000整轮阈值约束，占一次调用，预留至少两次给初稿和必要重写；按当前完整回答输入、输出及修复反馈估算预留token。实际用量未知或达到分类阈值即停止后续可选请求、整轮原序；DeepSeek实际触发整轮阈值时仍停止整轮回答。

Jev全批目标窗口2秒、DeepSeek批次1.5秒，可选阶段总窗口4秒，资格检查要求至少剩19秒，为原回答保留约15秒。使用全局最多三条在途请求的有界工作池，抢不到位置直接降级，不积压下一轮。窗口只是本地检查和网络超时约束，不承诺硬实时终止远端请求。迟到响应独立结算用量，已结束的控制对象和下一轮不再变化；普通trace（运行记录）另列Jev和DeepSeek分类流水，迟到或普通记录装不下时使用`news_triage_settlement`关联原运行编号，不写标题或提问。用户缩小单条记录容量时允许截短调用明细，保留各供应商已知token、未知用量次数和省略数，不使整条研究记录丢失。

先按原选择器固定各公司、各类别的证据位置与条数，再只在目标类别内稳定提升high且相关性为primary/mentioned的记录。若换入长标题超出该类别原序列化长度，改为只重排原成员。补充原始值、修复反馈预留和最终裁剪后再次比较上下文，非目标资料、位置或条数不符即整体恢复原上下文。原始资料包、完整证据和E编号均保留；不向回答注入标签或分类解释。
