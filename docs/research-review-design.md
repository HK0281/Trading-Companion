# 研判回顾：原记录与按需后续走势

更新：2026-11-12。第三模块按线程 #589 的 #592/#594、实施方案 #622 及 #625 最终时间口径实现；已由 Claude 审核、提交并推送 `f2484cf`（#627），工程门禁和临时库页面验收由 Claude 完成。前两模块自选和持仓偏好已分别提交推送 `9aa98af`、`4faea64`。

## 1. 范围和开启条件

用户在独立“研判回顾”面板输入一只完整证券代码，可按上海时区的提问起止日期筛选，查看原评级、方向、把握、期限和程序参考价位，打开单条原问答。仅点击“加载之后走势”才请求后来日线。列表和原问答零模型、零行情请求；后续价格也不调用模型，不占研究会话的问题或模型额度。

查询按原记录保存的完整代码进行，不依赖当前证券目录新鲜度；旧名称或退市后的历史仍可按代码查找，名称只展示原记录所载内容。

回顾依赖现有聊天历史 `--memory-db PATH`，不要求开启个人库，也不要求加入自选或保存持仓。`--no-memory` 在读取前禁用；demo、synthetic 和网页 Dev Mode 不访问真实聊天库。回顾只读取可识别的公司研究事件；指数、筛选及纯解释追问不会变成新的个股判断。未形成判断和旧版未记录字段仍可展示，不从正文猜测缺项。

本模块不计算命中率、评级准确率、止盈止损触达率、收益、最大回撤或其他校准统计，不根据未来价格修改旧判断。新闻收件箱、重要提醒、后台行情轮询和推送均未实现。

## 2. 唯一来源和有界扫描

聊天库原 `turns.result` 是判断唯一来源，不建立回顾表，不向个人库或浏览器持久存储复制一份判断。聊天库仍为原两表格式；本模块不迁移格式或新增索引，也不加载全部对话交给模型搜索。

- 每次最多读取、解析20个原始结果，每个结果最多1 MiB（1,048,576字节）。查询通过正文的实际字节长度在数据库侧排除超限内容，再解码；判断下一页只查键，不读取第21个大正文。
- 按 `asked_at DESC, conversation_id DESC, sequence DESC` 稳定排序。游标记录最后扫描的原项，包含不匹配或异常项；绑定用户、数据模式、证券和日期条件，筛选变化后重新查询。游标不代替源记录归属校验。
- 20个原项不保证有20个匹配。响应返回本次 `scanned`、`skipped_invalid`、`has_more`、`next_cursor`，页面同时显示匹配数；空匹配且有下一页时仍可“继续查找”，不声称全部历史没有。一次操作不自动循环扫描全库。
- 多公司结果只投影所选证券；纯解释追问和查看保存结果不重复记为新事件。旧字段缺失标“未记录”；损坏、超限或无法可靠关联证券的结果不脑补，异常项给可见跳过状态。库不可用与空列表分开。
- 每次扫描和单条读取关联原对话核对本机用户与数据模式；单条还精确核对 `conversation_id/sequence/request_id`。删除游标锚点后可按排序值继续，但不能恢复已删内容。

20项约束的是正文读取、解码和投影量；排序仍可能访问更多数据库键，不承诺整个查询只访问20行。若后续实测需要索引或格式升级，应单独设计和审核。

## 3. 原判断、原价位和数据结构

DTO（接口传输的数据结构）版本为 `research-review-v1`。列表是有界展示字段，单条详情才返回该轮完整原问答和公开结果，不读取整段对话或摘要。

| 返回内容 | 主要字段和含义 |
| --- | --- |
| 列表 | `version/enabled/items/scanned/skipped_invalid/has_more/next_cursor` |
| 原项身份 | `conversation_id/sequence/request_id/instrument_id/name/question`；问题仅为短摘要 |
| 原判断 | `status/code/rating/direction/conviction/horizon`；缺项保持 `null` 或 `unrecorded` |
| 原研究日期 | `asked_at/daily_cutoff/completed_at/historical_type`；回溯、普通及未知类型分开标记 |
| 原程序计划 | 可选 `trade_plan`，保留原价位字符串、方法、行情日、来源、复权及真实性 |
| 走势资格 | `prices.enabled/code/message/start_date/end_date/basis/basis_at/notice`，附原价格口径字段 |
| 单条详情 | `version/item/question/result`，其中 `result` 是该轮原公开结果 |
| 价格结果 | `version/status/item/source/price_adjustment/data_authenticity/retrieved_at/points`；不可用时有固定 `code/message` 且 `points=[]` |

有效公开判断使用 `decisions.status=available`、`code=decision_ready`，不是模型原始输出的 `formed`。兼容结构化v2/v3；整体回答降级时，已通过校验的逐股判断仍可独立展示。`unavailable` 保留当时未形成判断的状态。

价位只按同股、唯一 `plan_id` 关联原 `available`、`origin=application`、`execution_allowed=false` 的程序计划，并检查用途、版本、方法、日期、字段及内部请求身份。原计划不重算，模型正文不作为数字来源。技术分析内部请求编号与聊天请求编号不同，不能强行相等。`explicit_historical=true` 标“回溯研究”；缺失时标时点类型未知，不默认称当时实时判断。

## 4. 后续日期起点：#625 最终口径

提问时间 `asked_at`、资料截止 `daily_cutoff`、计划行情日期 `source_date`、回答完成时间分别展示，不能相互替代。

正常公开行情模式、开启聊天记忆的新公司研究在公开结果投影完成后、写入聊天库前，由程序加入 `review_context={version:"research-review-context-v1",event:"company_research",completed_at:带时区时间}`。仅新的公司研究事件且运行未停止时记录一次；未开启回顾的研究不增加元数据或完成时间读取，重放、查看保存结果及解释追问不刷新它。此元数据不进入模型或轮次摘要。有效 `completed_at` 优先使用。

没有该上下文的旧结果，用当前源对话 `conversations.updated_at` 作为保守保存边界。原结果插入和对话保存时间更新在同一事务中，保存时间位于内容形成之后；它属于整段对话，不是本条回答的精确完成时间。列表、详情和图表固定显示：

> 旧记录未保存完成时间，起点取所在对话最近保存日期之后，可能遗漏较早走势；继续该对话会使起点后移。

每次请求重新读取这个边界。时间缺失、无时区、早于 `asked_at`、晚于当前时刻或无法校验时，保留原判断并禁用走势；已有但无效的新上下文也不伪装成可靠完成时间。

不使用“提问时间+10分钟”，也不以90秒推出回答或保存的硬上界。90秒是研究检查点的协作预算，开始前的目录读取、结束后的投影和写库没有这样的总时限；跨午夜的慢目录读取会使固定十分钟推算落到回答形成之前。

将有效边界转成上海日期后，从后一天开始；终点为 `min(上海今天前一天, 起点+365天)`，最多366自然日。仅接受范围内实际返回的已完成日线，不取当日，不用周末推断交易日，不补停牌、非交易日或缺失价格。尚无可查询日期时本地说明，不发空范围请求。回溯研究同样从实际回答形成或保守保存边界之后开始，不能从较早的资料截止日开始。

## 5. 价格可比性在联网前检查

后来日线固定来自腾讯，口径是 `source=tencent`、`price_adjustment=unadjusted`、`data_authenticity=provider_reported`。最后一项表示供应商报告，未经独立核实。仅支持现有腾讯转换器认可的沪深A股；其他证券可回看原判断，走势显示不支持。

原价格基准须有明确的不复权口径和可接受真实性。优先使用经核验的原程序计划；没有计划时，可使用同股 `price_context:latest_close` 原程序证据，其单位须为 `CNY/share`，`calculation_basis.version=daily_price_context_v1`，内部请求编号、依赖、样本数与日期依据一致。证据日期等于自身 `cutoff` 且不晚于研究资料截止；假日截止不要求等于最后成交日。有计划和价格证据时，进一步核对来源、复权、真实性、行情日和内部请求编号。

无可核验基准、复权未知或不同、人工/合成或真实性未知、计划和证据冲突时，均不联网画图，只保留原判断、原价位及原因。不能退回不复权备用曲线，也不能靠回答文字或多股顶层图表猜口径。不复权曲线可能因除权跳变，不能将其解释成投资收益。

## 6. 三个本机接口

| 接口 | 输入和行为 |
| --- | --- |
| `GET /v1/research-reviews` | 必填 `instrument_id`；可选 `from_date/to_date/cursor`。日期为上海提问日期，首尾日期均包含；返回单页扫描结果 |
| `GET /v1/research-reviews/{conversation_id}/{sequence}` | 查询参数仅 `request_id/instrument_id`；读取这一条原问答及其投影 |
| `POST /v1/research-reviews/{conversation_id}/{sequence}/prices` | 请求体仅 `request_id/instrument_id`；点击后服务端重新核对源记录、资格和日期，再加载价格 |

沿用现有同源、Host、仅本机地址、请求大小和固定错误保护，不增加账号体系，不借研究会话令牌。`conversation_id/request_id` 为原32位十六进制编号，顺序号为1–500。客户端不能指定数据源、地址、日期边界、价格、复权或算法。

“查看原问答”不切换当前研究会话、待补充事项或编辑基准；保留“打开原对话”入口，只有用户明确操作才走原历史打开流程。单条读取不受原界面只展示末40轮的限制。

## 7. 有界取数、取消与释放

`research_review_prices.py` 使用固定腾讯HTTPS主机和日线路径，复用证券转换、`day` 响应解析和原日线行校验，不改变普通研究适配器。禁止跳转、自动重试、换源及 `qfqday` 等复权回退。

- 一次加载最多两个按年切片，失败也消耗尝试，不追加请求补量；最多366点。只输出实际日期与收盘价，完整价格响应最多256 KiB。
- 单个响应最多512 KiB，声明 `Content-Length` 和实际逐块读取分别检查；仅状态200及identity编码可用。供应商忽略下限时，先验证整片行的身份、日期递增、重复和OHLC（开高低收）约束，再过滤早于下限的记录；超出上限的记录拒绝。
- 总期限8秒，连接、请求、读响应和读正文前按剩余时间设置超时，在分片、读取和解析检查点查看取消信号。所有取得的响应和连接都在最终清理中关闭。
- 服务实例最多一个实际在途取数。异步断连探测、处理器取消、源删除和服务关闭通过请求专属标志通知同步工作器；浏览器停止等待不提前释放槽位。只有工作器实际返回并完成连接清理后，服务的 `finally` 才释放它。
- 取消和期限属于协作检查，不能保证立刻中断已经阻塞的底层网络调用；不以后台线程先返回来声称网络已停止。服务在调用取数器前及最终发布前重读源记录，并再次检查取消、期限和输出大小。

## 8. 页面、删除和验收边界

独立收盘价图使用 `research-review-v1`，可复用绘图尺度，不把后续日线塞进绑定原分析区间的 `research-chart-v1`。仅口径一致时画旧价位水平线，显示原行情日、后续范围、来源、不复权、真实性、取数时间及上述旧记录提示。鼠标和键盘可查看单日值，不计算隐藏统计。

换证券、筛选、页、原记录、模式或关闭面板时取消等待，以请求代次拒绝迟到响应；取数失败保留原判断。删除源聊天成功后，本页立即清除相关原项、详情和曲线并重查游标；清空历史则清空回顾。其他已打开页面在刷新或下次请求时失效，不额外建设跨标签通知，不承诺擦除浏览器已经显示的静态内容。个人库没有判断副本，删除自选或持仓不会删除聊天回顾。

同模块修正持仓草稿禁用原因的就近说明和可访问关联，资料待确认时显示“资料待刷新核对”；冲突提示去掉重复首句，保留编辑内容。≤534px侧栏与历史入口可达性仍为既有已知限制，未顺带修复整体小屏布局。

规则版本为 `personal-memory-review-v1`，以 `personal-memory-preferences-v1` 为父版并完整保留一次；不改写旧题库、历史规则或封存评估锁。登记只证明代码身份，不代表质量或真实来源验收通过。

实现验证使用临时聊天库、固定原结果、假时钟和网络/模型替身，覆盖20项扫描与空页继续、异常跳过、旧版本、多股与跨股计划、跨午夜旧边界、继续对话使边界后移、新记录优先、复权资格、网络预算/取消/关闭及删除竞态。工程门禁为 `verify.py python`、`web`、`bundle`。按 #623/#625，Claude 页面验收使用临时库和合成原记录，不读取用户真实聊天库；可小量真实请求腾讯日线验证取数。最终结果由模块审核另行记录，本文不预写通过数字。
