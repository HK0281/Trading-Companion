## 模型接入层：第一步

日期：2026-10-07

### 本轮目标

先完成一个独立的后端子模块：输入消息，返回统一格式的模型文本或明确的错误。暂不调用行情工具、不生成交易分析、不维护对话记忆。

根据当时讨论，先把模型接入作为独立学习步骤；该步骤开始时多指标计算尚未完成。2026-10-16已补齐七类纯计算与独立多指标服务/证据契约，随后补上工具协议、受控执行及DeepSeek工具适配。2026-10-20记录开发者一次真实工具/人工CSV反馈，并新增[初版单轮编排](agent-runtime-design.md#单轮研究-agent受控编排的第一个版本)。它只支持明确格式输入与未校验草稿；通用请求理解、解释检查和对话仍待完成。这个顺序调整不表示放弃PRD中的多指标需求。

### 三个部分

| 部分 | 职责 |
| --- | --- |
| `model.py` | 定义消息、结果、错误与统一接口；提供不联网的假模型 |
| `deepseek_model.py` | 读取显式配置，发送兼容Chat Completions的HTTP请求，转换响应与错误 |
| `model_cli.py` | 独立演示入口；默认假模型，只有显式选择DeepSeek才可能联网 |

接口统一是为了让未来agent不依赖某个供应商的响应细节。当前只有假模型和DeepSeek适配器，不宣称所有OpenAI模型都可以直接换地址使用。

### 本轮边界

- 使用已有的requests发送HTTP请求，不引入agent框架或OpenAI SDK；参考OpenAI Docs核对兼容消息格式、结束原因及用量字段。
- DeepSeek请求地址固定，密钥不能随模型输出发送到任意URL；禁用重定向，底层适配器不自动重试。2026-10-30起默认连接/读取等待为45秒；产品入口的[共享运行控制器](agent-runtime-design.md#整轮运行控制共享预算取消与迟到结果)对超时或连接错误最多重试一次，仍消耗同一轮调用额度和剩余时间，独立文本CLI保持单次请求。
- 模型名称由`DEEPSEEK_MODEL`显式配置，不猜测用户账号可用的型号；密钥使用`DEEPSEEK_API_KEY`。`DeepSeekConfig.from_env()`只负责环境映射读取与校验；2026-10-24起真实入口增加本地`.env`合并，见[配置说明](operations.md#本地模型配置与启动)。
- 本轮只支持非流式文本，返回工具调用、拒绝、截断或损坏响应均不冒充完整文本成功。
- 保留实际返回的模型名称与可用token用量；缺少用量时标记未知，不填0，不估算账单。
- 请求错误使用固定、可理解的分类，不输出服务端原始错误体、请求头或密钥。
- 超时是连接/读取等待限制；整个agent回合的总截止时间留给后续调度层，不能声称本轮已实现。
- 假模型不等于真实模型效果验证。单元测试使用模拟HTTP响应，不发送用户数据或产生推理费用。

### 完成条件

离线演示可运行；合法响应能解析；配置缺失在联网前报错；超时、鉴权、限流、错误数据与截断分别测试；敏感配置不出现在repr/CLI错误中；已有行情测试不回退。

真实DeepSeek接口、所选模型的字段兼容性和可用性，必须由用户配置服务后单独联通验证。本轮不把模拟测试写成真实接入已验证。

## 工具模型协议与离线 Fake 往返

日期：2026-10-16（America/Los_Angeles）

### 本次交付与边界

这是M2的第一个切口：让统一模型契约能够表达工具定义、模型提出的调用、调用方返回的结果和完整文本。通过脚本Fake验证协议往返，尚未完成自然语言Agent、正式工具注册/执行器或模型解释检查。

后续实施更新：受控执行器已在独立 `research_tool.py` 中接入多指标服务，见[受控工具设计](agent-runtime-design.md#受控日线指标工具执行器)；2026-10-19补上[DeepSeek适配](agent-runtime-design.md#deepseek-工具调用适配器)与模拟HTTP/人工CSV计算。2026-10-20记录开发者一次真实固定任务工具反馈，新增[明确格式单轮runner](agent-runtime-design.md#单轮研究-agent受控编排的第一个版本)，全量371项离线测试通过。本文以下仍描述第一切口的固定结果演示；旧演示保持不执行工具。通用请求理解、解释检查与完整对话仍待做。

旧 `ChatMessage`、`TextModel.complete()`、`FakeTextModel`、`DeepSeekTextModel` 与 `model_cli` 保留纯文本语义。新协议在独立 `tool_model.py` 中实现，演示入口是 `tool_model_demo.py`。不增加依赖，不读取真实密钥，不发送模型或行情请求。

开发继续使用ProductManager明确范围、Engineer实现与测试、CodeReviewer复审、UserProxy独立运行验收；产品运行时的单Agent架构不因此改变。

### 公开契约

| 类型 | 表达的内容 |
| --- | --- |
| `ToolDefinition(name, description, parameters)` | 工具名称、用途及参数结构描述；不是Python函数或执行权限 |
| `ToolCall(call_id, name, arguments)` | 模型提出的调用标识、工具名称与JSON对象参数 |
| `ToolMessage` | `system/user/assistant/tool`消息，以及所属角色允许的文本、调用或结果字段 |
| `ToolModelResponse` | 完整文本、工具调用、拒绝或截断等互斥状态 |
| `ToolCapableModel.complete(messages, *, tools)` | 接收合法历史和本次声明工具，返回一个经过校验的响应 |
| `FakeToolModel(responses)` | 按固定脚本返回响应，用于离线验证，不执行工具或推理 |

`ToolMessage`通过 `tool_calls` 表达assistant调用，通过 `call_id/name/result` 表达tool结果。`ToolModelResponse.as_message()`只允许完整文本或工具调用转换成可继续使用的assistant消息；拒绝和截断不能伪装为完整回答。

状态含义：

- `complete`：完整非空文本，没有待执行工具调用。
- `tool_calls`：一个或多个工具调用提议，尚未执行。
- `refused`：未提供正常答案，保持拒绝状态。
- `incomplete`：输出不完整，不能作为完成文本展示。

2026-10-29 A4：`ToolModelResponse.finish_reason` 是可选的固定枚举，保留供应商的 stop/tool_calls/length/content_filter/insufficient_system_resource/aborted；旧 Fake 脚本可省略。长度或资源中断不能伪装成完成响应；供应商的拒绝优先于其他状态。`to_dict()` 与 Fake 透传该元数据。`complete(messages, tools=...)` 签名不变；没有工具声明的现有业务调用方均约定 JSON，对纯文本的需求使用独立文本模型接口。

这些是内部协议状态，不宣称供应商HTTP字段或行为已验证。后续适配器需显式转换提供方消息、结束原因和错误。

### 一次往返

```text
调用方构造用户消息与工具定义
    ↓
Fake返回assistant工具调用提议
    ↓
调用方保留该assistant消息
    ↓
调用方显式加入固定人工tool结果，带原call_id与工具名
    ↓
Fake接收合法的完整消息组
    ↓
Fake返回完整文本
```

这个旧演示中的工具结果来自程序写明的固定人工数据。Fake没有查行情、没有调用 `analyze_indicators()`，也没有根据用户问题决定执行动作。现有独立受控执行器在业务校验后调用M1b研究服务，运行入口见[受控工具设计](agent-runtime-design.md#受控日线指标工具执行器)。

### 调用标识与消息顺序

- assistant提出的每个调用都有可定位的call ID。tool结果必须精确匹配已提出的调用ID和工具名称。
- 不能先出现tool结果，也不能重复、伪造或遗漏结果。一个assistant批次中的多个结果可以按不同顺序返回，但必须全部回齐。
- pending调用未解决时，不接受用户消息或新的assistant消息插入，也不能提前再次请求模型。
- 传入模型的历史必须停在合法的新用户消息或已完成的tool结果组边界。
- 工具名只能来自本次传入的声明集合，重复工具定义和未知名称明确拒绝。

本模块检查协议完整性，不负责证明工具结果内容真实。调用方仍须使用程序实际执行得到的结果；不能仅凭消息能解析就把它当行情证据。

### JSON、边界与隐私

参数和结果采用严格JSON对象：只接受合法类型、字符串键和有限数值；拒绝非对象参数、重复JSON键、非有限数、循环或超出资源上限的结构。数据进入契约后保存为经过校验的规范JSON，属性与序列化返回独立内容，避免外部修改嵌套字典后绕过验证。

本轮声明schema只承担参数结构描述和实现中明确检查的局部结构约束，不实现完整JSON Schema校验器。缺少业务参数、非法股票/日期、未知指标、数据源范围与权限，由独立工具执行层和已有 `MultiIndicatorRequest` 等业务契约验证，不能依赖本协议容器。

工具名称和调用ID有明确格式与长度限制。以下是本轮选择的本地协议上限，超限报错，不静默截断：

| 项目 | 上限 |
| --- | --- |
| 输入历史 | 20条消息 |
| 单条用户文本 | 2,000字符 |
| 完整请求 | 20,000字符，累计工具声明和消息各自ASCII转义JSON的序列化长度 |
| 单个JSON对象 | 10,000字符的规范JSON |
| JSON嵌套与节点 | 最大深度12、结构节点最多2,000 |
| 工具名称与调用ID | 最多64字符，限定各自标识字符范围 |
| 提供方和模型元数据 | 最多128字符，无空白或不可打印字符 |
| 工具声明 / 单响应调用 | 最多12个声明 / 8个调用 |
| Fake脚本 | 最多100项响应 |
| 单响应内容 | 文本、参数和标识等按实现计数，最多20,000字符 |

完整JSON内容也参与请求预算；模型/提供方名称是不透明元数据，不复用工具名和call ID的窄字符规则。这些是通用协议容器上限，不能扩大产品权限：首版执行器仍按PRD只注册一个日线分析工具、限制每轮行情执行次数。协议允许多调用配对，不意味着产品允许多次取数。这些限制不等于M3的token预算、整轮截止时间或会话管理。

`repr()`隐藏消息、参数、schema、工具结果和脚本响应中的敏感文本；错误使用固定脱敏描述。显式 `to_dict()` 是调用方主动访问协议内容，不是日志脱敏器；不能直接把其完整输出作为生产日志。

### Fake脚本行为

Fake先验证输入历史和工具声明，再验证下一条脚本响应。无效输入抛 `ModelRequestError`，无效脚本/模型输出抛分类 `ModelCallError`；错误不复制用户或脚本原文。校验失败不推进脚本，耗尽时明确失败，不自动重启或重试。`refused/incomplete`属于合法返回状态，返回时同样消费一项脚本；“已消费响应”和“完成了用户回答”是不同含义。

Fake返回结果明确标记模拟来源，token用量保留未知。即使离线往返通过，也只证明协议及覆盖到的行为成立，不代表DeepSeek真实工具调用可用、模型理解质量达标或完整Agent已完成。

## DeepSeek 工具调用适配器

日期：2026-10-19（America/Los_Angeles）

### 本步范围

M2已经有工具消息契约和受控执行器，但原 `DeepSeekTextModel` 只接受文本。这一步新增独立 `DeepSeekToolModel`，把内部工具消息转换成DeepSeek请求，再把响应转换回 `ToolModelResponse`。原文本接口和CLI保持兼容。

适配器只负责通信和协议转换，不执行工具、不维护会话、不检查回答中的金融结论。适配器实现阶段只做模拟HTTP验证；文末后续更新记录开发者的真实工具反馈及初版单轮编排。通用自然语言理解、回答检查和整体运行预算仍待实现。

`DeepSeekToolModel.complete(messages, tools=...)` 满足已有 `ToolCapableModel` 接口。业务调用方不必了解DeepSeek字段，也不能把工具执行权限交给适配器。

### 消息如何转换

| 内部对象 | DeepSeek格式 | 保留的约束 |
| --- | --- | --- |
| `ToolDefinition` | `tools[].type="function"`，定义放入 `function` | 发送前检查工具声明及名称唯一性 |
| 助手的 `ToolCall` | `tool_calls[].id/type/function` | 名称与原调用ID不变；`function.arguments` 是JSON字符串，不是对象 |
| `ToolMessage(role="tool")` | `role="tool"`、`tool_call_id`、`content` | 结果JSON编码成字符串；通过原ID匹配提议，不把内部 `name/result` 字段直接发送 |
| 普通文本消息 | `role/content` | 保留系统、用户和助手文本 |

例如内部 `arguments={"window":3}` 在HTTP请求中表示为 `"arguments":"{\"window\":3}"`。这是编码格式转换，不是重新生成参数或修改数值。返回参数用已有 `ToolCall` 解析，拒绝重复JSON键、非有限数、非对象及超限结构。

调用前必须通过 `validate_tool_messages()`：历史中的每个提议都有且仅有一个匹配结果，不能把缺失或孤立的结果交给模型。响应提议还要检查声明白名单和历史ID复用。协议最多表达8个调用，不意味着本产品允许执行8次；A4 有界研究工作流按顺序执行预算内的提议，工具尝试总数仍为6、主分析与补算合计最多2次。旧明确格式单轮执行器仍保持原契约，见[有界研究工作流](agent-runtime-design.md#有界研究工作流设计)。

### HTTP成功不等于可以继续执行

| 提供方输出 | 内部处理 |
| --- | --- |
| `stop` | `complete`；必须有非空文本，不能同时含调用 |
| `tool_calls` | `tool_calls`；必须有合法、非空且有界的调用提议 |
| `length / insufficient_system_resource / aborted` | `incomplete`；丢弃所有调用，不解析或执行半截提议 |
| `content_filter` 或非空 `refusal` | `refused`；丢弃调用，返回固定说明，不暴露原始拒绝详情 |
| 未知结束原因或旧 `function_call` | `unsupported_response` 错误，不猜测如何兼容 |
| 非法结构、参数或元数据 | `invalid_response`；未声明工具单独归类为 `unknown_tool` |

即使HTTP是200，也可能只有半截输出；不能仅凭 `tool_calls` 字段存在就执行。`as_message()` 也禁止将拒绝或不完整响应转成正常助手历史。

返回值记录请求/实际模型名、提供方和可用token用量。未知用量保留 `None`，不是0。`is_mock=False` 表示走这个提供方适配器，而不是Fake；单靠该字段不能证明联网成功，测试可以模拟HTTP。

A4 保留有界的 `finish_reason`，区分长度耗尽和其他中断。产品工厂的结构化回答额度为4096 tokens；带工具声明的请求取配置值与1500中的较小值。没有工具声明的业务路径全部要求 JSON 对象，适配器发送 `response_format={"type":"json_object"}`；它不保证语义正确，也不替代本地检查。调用方清单由离线测试审计：通用知识、旧公司回答、旧决策回答、当前自然语言回答。纯文本调用继续使用 `DeepSeekTextModel`，不启用 JSON 模式。

### 为什么这样实现

- **文本与工具接口分开，共享传输。** `_post_chat()` 统一固定地址、鉴权、超时、错误分类和响应关闭；各适配器自行处理各自的消息语义，避免修改旧CLI的输入契约。
- **底层单次传输、不接受模型指定URL。** 地址固定为DeepSeek官方Chat Completions端点，禁用重定向。默认连接/读取等待45秒，HTTP超时不等于整个Agent回合的截止时间。2026-10-30起产品入口的[共享运行控制器](agent-runtime-design.md#整轮运行控制共享预算取消与迟到结果)可在剩余整轮时间和原调用额度内，对超时或连接错误重试一次，每次尝试单独计量；直接调用适配器仍只发一次。
- **显式关闭thinking，采用非流式。** 当前内部协议没有推理历史字段；官方说明工具调用的思考模式需要回传相应推理历史。因此本步使用 `thinking={"type":"disabled"}`，不能只改开关就宣称支持思考模式。提供方额外的推理字段不暴露或回放。
- **复用配置，不扩大功能。** 使用已有 `DeepSeekConfig`、显式型号和输出token限制。有工具时发送 `tool_choice="auto"`，没有则省略工具字段；不新增依赖、CLI或自动付费请求。

## 单轮研究 Agent：受控编排的第一个版本

日期：2026-10-20（America/Los_Angeles）

### 本步范围

把固定工具联通测试之外的业务流程封装为可复用的 `run_research_turn()`：接收明确格式的中文研究问题，检查参数，接收模型工具提议，执行一次分析，保留事实和模型解释草稿。

这不是任意自然语言理解，也不是完整对话 Agent。没有名称解析、隐式日期或指标默认值、跨轮记忆、自动重试、回答检查或全轮截止时间。产品目标与默认值提案仍以 [PRD](prd-agent-v0.1.md) 为准，不把本步的收窄实现写成整个 M2 已完成。

| [agent.py](../src/trading_companion/agent.py) | 管理单轮阶段、模型与分析次数、退出状态，以及可信事实与草稿的分离 |

### 输入先明确，执行才有依据

当前支持的输入示例：

```text
分析 000001.SZ，2026-09-21 至 2026-09-25，指标：SMA3、SMA20、VOLUME3
```

必须提供一只股票的完整代码、起止日期及明确指标参数。简称、裸代码、“最近”、省略指标或额外不明指令都会返回澄清提示。代码语法合法不代表股票确实存在，也不代表具备 ST 或上市状态识别能力。在线来源仅允许上海当日之前的截止日。

| 指标族 | 示例 |
| --- | --- |
| SMA / EMA | `SMA3`、`SMA(20)`、`EMA20` |
| MACD | `MACD(12,26,9)` |
| RSI / ATR | `RSI14`、`ATR14` |
| BOLL | `BOLL(20,2)` |
| 量能 | `VOLUME20`、`量能20`、`成交量20` |

多个实例用顿号、顶层逗号或分号分隔；不会把 MACD/BOLL 参数中的逗号拆成多个指标。周期、区间、最多 12 个不同实例等业务限制复用 `IndicatorSpec` 和 `MultiIndicatorRequest`，不另建一套互相冲突的范围规则。没有自动补预热历史。

### 谁负责澄清，谁有执行权

模型可以负责生成“你指哪只股票？”这样的澄清问题；但一句自然语言追问不等于执行屏障。程序必须同时保存“尚未明确”的状态，在补充信息通过校验前禁止查询。

本步先使用固定澄清消息，信息不足时不调用模型也不读行情。原因是当前缺少名称解析和跨轮状态，固定提示足够解释缺项，并能稳定验证零执行。以后可以替换提问措辞，但不能把执行权转交给模型。

适配器只负责消息和 HTTP 转换，执行器只负责白名单及业务执行；是否澄清、何时停止、是否保留部分结果由单轮编排层决定。

### 单轮数据流

```text
明确格式输入 → 研究契约校验 → 规范参数
  不明确：needs_clarification，零模型/行情调用
规范参数 → 模型提议 → 与已识别请求逐项比对
  不一致：阻断，零分析
一致的单次提议 → 同一个执行器 → 完整本地研究 + 紧凑工具结果
  无可解释字段：保留实际结果，不请求综合解释
可解释事实 → 第二次模型请求 → 未校验草稿 + 本轮状态
```

模型收到程序生成的规范参数，而不是原始自由文本指令。提议必须与已识别请求的股票、日期、指标及可信来源一致。仅仅符合通用 JSON/业务范围还不够：换成另一只合法股票仍然是本轮范围错误。

每轮最多两次模型接口调用、一个执行器、一次实际分析。第二次再提工具、拒绝、截断或失败都结束；不换源、不重建执行器、不重置额度。次数记录的是接口尝试，不能当作成功次数或严格 HTTP 次数。全轮 token/时间预算仍待实现。

模型实例和在线来源由可信调用方注入。开发 CSV 只能通过 `development_source` 注入，不暴露路径或 CSV 开关给模型。本步不读取环境凭据、不增加付费命令入口。

### 状态与部分结果

数据、计算和产品状态是三个层次，不能都用一个 `ok` 判断：

| 层次 | 例子及含义 |
| --- | --- |
| 数据 | `data_status=ok` 表示数据读取及校验正常，不代表所有指标可算 |
| 计算 | `calculation_status=complete/limited/unavailable` 表示字段就绪程度；完整状态是 `complete`，不是 `ok` |
| 本轮 | `needs_clarification/out_of_scope/failed/limited/completed` 表示本轮流程结果 |

五条样例数据上 SMA3 和量能3可用，SMA20缺15条：保留全部有效事实和缺项，返回 `limited / partial_research`。不会为了算出 SMA20 静默改变用户给定区间。

没有日线、全部请求字段不可解释或取数失败时，不请求模型编出综合分析；已有实际结果仍尽量保留。若事实已取得而第二次模型失败，返回 `limited / explanation_unavailable`，不丢掉已计算结果，也不重新取数。

### 事实不是模型草稿

`AgentTurnResult` 分开保存 `confirmed_request`、`research_result`、`model_draft` 和调用元数据。原始用户问题不由 runner 留存；首次直接生成的模型文字不能冒充研究结果。

初版 `completed` 仅代表字段就绪与模型往返完成。后续受限解读升级后，它还要求本轮所选结构化关系通过检查；检查失败为 `limited/explanation_rejected`，有字段缺项仍为 `limited/partial_research`。`explanation_validation`单独报告关系检查；`answer_validation=not_performed`保留并明确范围为任意自由文本语义，不能夸大为所有回答均正确。提示词要求“依据事实”不能替代程序检查。

`to_dict()` 是显式结果导出，不是生产脱敏日志：包含研究证据和模型草稿，不应随意上传。导出的模型响应仅含状态、型号、用量等元数据，不包含初次提议中的任意文字。

### 1. 这次改变了什么

过去的自然研究流程是固定的：理解问题，要求模型提出一次指标分析，计算完成后要求模型回答。模型如果再次请求工具，会被当成异常。

现在保留股票身份和参数核验，但把后续研究改成有限循环：模型看到已有结果后，可以选择继续使用只读工具，也可以结束研究、回答原问题。工具顺序不是写死的，也不要求每轮用完所有工具。

这仍然是一个单股票研究 Agent，不是多个角色辩论，也不是可以自由联网和执行代码的通用 Agent。

```text
用户原问题
  → 理解意图，核对证券目录、日期、来源与指标
  → 歧义需要澄清；范围明确才进入研究
  → 模型选择一个或多个工具，程序按提议顺序逐个处理
      → 程序核验权限、参数、消息容量和预算
      → 执行只读工具，将结果返回模型
      → 模型选择继续研究，或者提交最终回答
  → 核验请求绑定、指标关系、引用和回答格式
  → 聊天正文（含段落依据、研判与价位计划）+ 默认显示的互动日线图
```

模型负责“接下来需要了解什么”；程序负责“这个动作是否允许执行、结果是否能支持所引用的事实”。模型提出工具调用，不等于获得执行权限。

### 2. 当前可用的四个工具

| 工具 | 作用 | 重要限制 |
| --- | --- | --- |
| `analyze_daily_indicators` | 获取已确认股票区间的日线，确定性计算原请求指标 | 参数必须与确认请求完全一致；行情读取最多尝试一次 |
| `get_indicator_knowledge` | 查询项目维护的指标定义与计算口径 | 每次选择 1–3 个不同主题；不是搜索互联网或生成新的行情证据 |
| `inspect_research_snapshot` | 查看主快照的来源、范围，或指标可用性 | 必须先有主快照；只读现有结果，不重新取行情 |
| `analyze_additional_indicators` | 在同一批内存日线上补算 1–3 个新指标实例 | 最多一次；不换股票、日期或来源，不重新读取行情 |

例如，模型可以先查询 RSI 的定义，再执行主分析；也可以取得主结果后查看缺项，再补充一个 EMA，最后综合回答。一次主分析已经足够时，应直接结束。

2026-10-29 A4 起，一次响应可提出多个工具，程序按原顺序逐个核对和执行，每个参数/范围不合法的调用只拒绝自身，仍消耗工具尝试额度；主分析后的同批快照或补算可读取刚取得的主结果。未知工具、重复调用 ID 或坏协议 JSON 仍在任何执行前整体拒绝。相同的已执行工具请求不能通过换一个调用 ID 来重复取数。失败的行情读取不会自动重试或静默切换供应商。

补充计算不能与原请求重复。对于原请求中已有的指标种类，不能缩短其周期来把“历史不足”变成一个看似可用的信号；当前程序按该种类的已有参数组合核验。

### 3. 为什么分 primary 和 supplement

主分析结果称为 `primary`。它固定绑定原先核验的请求，负责主报告、图表和保存结果。补充计算称为 `supplement`，只补充本轮回答的证据，不能悄悄覆盖主结果。

补充分析不是第二次查询市场。程序从主结果中取出已校验的日线，构建只读内存数据源，再运行同一套确定性指标算法。补充结果沿用主快照的采集时间、真实性标记和复权口径，并使用新的请求 ID。

最终检查要求两个结果的股票、起止日期、来源、复权口径、真实性、采集时间及日线记录完全一致。指标集合可以不同，否则就失去了补算的意义。

每份工具结果的 `f0`、`f1` 等证据别名只在自身结果内有效。因此回答使用：

```text
primary:f7     → 主结果中的 f7 → 对应完整 fact ID
supplement:f7  → 补充结果中的 f7 → 另一个完整 fact ID
```

即使两个别名都叫 `f7`，也不能互相替换。最终正文的引用会转换成完整事实 ID，而不是把两份别名字典混在一起。

补充指标全部历史不足时，仍可保留有效的 primary 回答，但不能引用不存在的补充关系。primary 本身没有可解释指标时，流程不会靠缩短周期或忽略原请求来凑结论。工具视图超过容量时也不会静默删掉部分证据，让模型误认为看到了完整结果。

### 4. 运行预算与容量

研究工作流的单轮上限如下；应用可以传入更紧的限制，模型不能扩大它们。

| 限制 | 当前值 | 含义 |
| --- | --- | --- |
| 模型调用 | 6 次 | 包括前置的意图理解，不是额外再给循环 6 次 |
| 工具调用 | 6 次 | 按提议逐次计数，包含参数/范围拒绝；一个模型响应可有多个提议 |
| 分析尝试 | 2 次 | 主分析与一次内存补算；不是允许两次行情读取 |
| 整轮时间 | 90 秒 | 在协作检查点停止后续调度，不是远端请求硬中断 |
| 已观察 tokens | 24,000 | 根据供应商返回 usage 触发停止，不是提前核算的费用上限 |

这些是同时存在的上限，不是都能用满的配额。例如一个新请求花一次模型调用理解意图，再执行四次“模型选工具→工具返回”，最后一次模型调用回答，就已达到六次模型上限。最后一次模型机会不能再执行工具。

一个批次仍只算一次模型调用，每个提议独立消耗工具额度。超出剩余额度的部分不执行，按原调用 ID 回填 `tool_call_budget_exhausted`；最后一次模型机会的提议全部标为未执行。主数据失败、取消和截止时间到达会停止后续实际执行，并记录各剩余项的未执行原因。

消息协议也有独立容量限制：最多 20 条消息，工具声明加完整消息历史合计最多 20,000 个 ASCII 序列化字符，单个 JSON 对象最多 10,000 个序列化字符。中文经过 JSON 转义后会占用多个 ASCII 字符，不能只按屏幕上看到的字数估算。

每次模型请求前和工具执行边界都会检查消息配对与容量。容量不足时，优先返回有分类的受限结果或停止；不把尚未完成的工具调用留在历史中，也不无限增长上下文。

A4 批次调度预先为全部提议预留有界的“未执行/受限”结果空间，并在每次执行前用原批次声明、已完成结果和剩余预留结果检查闭合历史。结果总量过大时保留此前完整结果，当前结果使用受限信封且完整研究对象仍留在程序内，其余项明确未执行，停止后续模型请求；不压缩主证据。模型历史保留原始一个 assistant 批次和每个 ID 的唯一结果，内部预留内容不会作为实际观察送给模型。

为让默认八项指标也能完成多步补查，可信请求只在系统消息中传一次，用户原问题单独保留。模型已读取的知识结果随后转换成项目维护的简短定义（保留计算口径与限制），快照检查摘要则指向仍在上下文里的主证据；最新工具结果必须先完整提供给模型。主分析和补充分析的完整证据、别名、工具调用参数及配对始终不删不改。这里不能假设模型记得上一轮的隐藏状态，所以知识摘要不能只写“之前已经告诉过你”。预算结束提示也预先占位，避免最后一轮额外文字把证据挤出容量。更大的组合或长问题仍可能触发上限，最大工具次数不保证所有最大参数组合都能容纳。

还有会话级上限：本地 API 默认每会话最多转发 60 次模型调用、接收 20 条消息；实时 CLI 每次启动保留 15 次模型转发总额、最多 5 条非空问题，分析总上界为 10 次。单轮上限与整次启动上限谁先达到，谁先停止；CLI 不保证五个问题都能使用完整的六次模型预算。

供应商没有返回完整 usage 时，程序不会把未知 token 用量冒充为零费用。取消和截止时间也不能撤回已经发送的远端请求；迟到内容会被丢弃，但可能已经产生供应商费用。

### 5. 最终回答如何生成和检查

模型完成研究后，提交 `research-workflow-response-v1`，不是直接把工具 JSON 显示给用户。协议包括：

- 绑定 primary 的请求 ID、股票代码和实际最新交易日。
- 1–8 条指标关系论断，每条指定 `snapshot`、本地证据别名、关系字段和值。
- 恰好三段正文：`answer` 直接回答问题，`outlook` 给出有条件的方向判断，`watch_for` 说明成立或失效的观察条件。

每段正文 1–600 个字符，必须引用 1–8 个不重复且已经核验的论断；完整最终 JSON 最多 8,000 个字符。提示模型整体用简洁自然的中文，不列出所有指标。除实际指标的标准标签外，正文暂不支持额外阿拉伯数字；精确价格和指标读数保留在数据视图。

程序先按 primary / supplement 分组，复用原有关系验证器：检查完整事实、相邻交易日、单位、依赖、参数和原始精度，并重新计算关系，而不只是判断引用 ID 是否存在。股票、日期、别名空间或关系值不符，整份模型正文都会被拒绝。多余字段、重复 JSON 键、控制字符、NaN、坏引用和不完整结构也不会自动修补成一个成功回答。

兼容的 `research-response-v1` 和 `indicator-explanation-v1` 仍可使用，但只能引用 primary。旧关系协议不会被冒充成新自然语言回答。

**这些检查不能证明自然语言推理正确。** 引用真实关系，仍可能错误解释趋势、忽视冲突或夸大预测。当前验证范围是“请求绑定与指标关系、引用核验”，不是自由文字语义、投资价值、收益预测或胜率验证。禁止额外数字也不能证明中文写出的数量或推论正确。

人工或未经核验的开发 CSV 不用于真实股票方向判断；即使指标算得出来，应用仍会明确说明它是开发数据。没有可用行情或历史不足时，给出简短解释，不把指标清单冒充答案。

### 6. 展示、会话与兼容边界

API 的 `conversation` 负责正文与引用，`research_workflow` 负责有界执行记录。被接受的补充论断会投影为 `supporting_evidence`，包含完整事实 ID、所属请求和程序生成的关系说明；`evidence_snapshots` 用于说明证据来自哪份结果。主图表和原有报告仍绑定 primary，不会因为补算而突然更换指标。

2026-10-25 界面不再把 `research_workflow`、参数、默认值、内部代码和模型/分析计数渲染成回答后的诊断区块，也不逐段展开内部引用诊断；这些结构化字段仍由后端计算并保留在 API 中，用于核验、兼容和测试。2026-10-30进一步将附加区精简为默认显示的日线图；正文的段落依据保留，移除附加入口不删除证据校验。追问直接输入，不要求固定的 RSI 或 DIF/DEA 快捷按钮。

页面载入和编辑草稿不调用模型；只有用户明确发送，才在需要时创建会话并提交问题。没有额外 DeepSeek 许可卡或勾选步骤，真实模型请求仍可能产生供应商费用。显式重试沿用原编号与幂等保护，不因移除许可门而自动重发或扩展工具权限。

当前会话保存的仍然只有 primary，而不是整轮循环、完整聊天历史或全部辅助证据。后续“查看上次结果”和保存结果追问使用主快照；不能宣称这些追问会记住 supplement。知识解释、证券澄清、条件修改和保存结果追问继续使用各自已有路径，并不强制每个问题都进入研究循环。

取消会清除本轮可展示的新结果；超时或预算停止可以保留停止前已核验的事实，但不会把停止轮次发布为新的会话研究结果。新研究开始时，旧结果不能自动冒充当前结果。API 幂等重放复用已保存的同一请求响应，不重新调用模型或查询行情。

开启方式：

- `ResearchApiService` 默认 `workflow_enabled=True`，网页由这一服务进入新流程。
- 正常的实时 CLI 启动路径传入 `workflow=True`；低层 `run_conversation` 保留旧默认值以兼容原有脚本与测试。
- 低层 `run_natural_research_turn` 保留 `workflow=False` 默认；显式传 `True` 才进入新循环。
- `run_research_turn` 继续是旧显式格式入口，保持两次模型、一次分析的上限。

这不是把全局所有入口悄悄换成新协议，也没有改变数据源必须由可信应用配置的约束。

### 7. 尚未实现的能力

当前没有新闻、公告、财报、基本面、实时行情、网页搜索或选股工具。模型不能因为用户问到这些内容，就假装已经查询过。当前补算也不会自动扩大历史区间、重新取更早行情，或比较第二只股票。

无券商凭据、下单、撤单、交易执行或资金管理接口；所有真实交易仍由人自己操作。日线日期过滤也不等于严格 point-in-time：历史发布时间、修订版本、完整当时可得性仍需未来的数据工程支持。

后续可以在相同边界内增加真正的数据工具，但必须分别实现数据适配、权限、证据与测试，不能只在提示词里列一个不存在的能力。

### 这一步解决什么问题

M2第一切口让模型协议能够表达工具调用和结果。这一步把白名单调用接到已有多指标研究服务：程序校验参数、控制实际执行次数、读取指定数据源并计算，再按原调用ID返回结构化结果。

### 为什么需要紧凑结果

研究服务保留完整历史、逐字段状态、初始化信息、关系和事实。工具协议的单JSON对象上限为10,000个ASCII转义字符、2,000个结构节点；完整请求累计工具声明与消息不能超过20,000字符。直接发送完整 `MultiIndicatorResult.to_dict()` 容易超过这些限制，也会重复发送大量历史。

因此完整结果留在可信本地，模型接收带版本与列定义的紧凑视图。查询条件集中存一次；保留请求指标的最新字段、不可用原因、初始化限制及关系依赖的事实。证据可使用请求内短别名，可信本地维护其与原始事实的对应。别名以 `request_id` 为作用域：不同请求都可以出现 `f0`，但不能用另一请求的映射解析它。数值保持计算精度，不为缩小结果而舍入。

容量仍需经过实际工具消息及完整历史校验。超限必须明确失败，禁止默默删除指标、依赖、警告或截断JSON；已执行的计算不能因此自动再取数。

`research-view-v1`集中记录请求区间、实际最新/前一日、读取时间、源、复权、真实性、记录数和数据/计算状态。表格的 `columns` 描述各行含义：

| 表 | 内容 |
| --- | --- |
| `indicators` | 请求实例短编号、类型、完整参数和算法版本；源失败时仍保留请求组合 |
| `states` | 状态与原因共享表，区分历史不足、零基准未定义及计算错误 |
| `latest_fields` | 最新字段、状态引用、所需/缺少记录数和事实别名 |
| `components` | 组件周期、最少记录、种子、首个可用日、递推次数和起点提示 |
| `numeric_facts` | 当前/紧邻前一点的数值事实及日期索引；数值不舍入 |
| `relations` | 关系值、状态、缺少数量及完整依赖别名 |

单位集中在 `units`。关系规则 `research-rules-v1` 和种子字典 `research-seeds-v1` 在唯一工具声明中发送一次，结果显式引用其版本；组件种子使用 `c0` 等字典键。模型必须结合声明和结果解释这些键，不能将包单独当作无须版本信息的通用数据格式。警告采用含义明确的固定英文标识压缩，未知警告保留原文，完整中文警告仍在本地结果中。

### 调用接口

`RESEARCH_TOOL_DEFINITION`是唯一工具声明，名称为 `analyze_daily_indicators`。参数为 `instrument_id`、`start_date`、`as_of_date`，可选 `indicators` 和 `source`；日期使用严格 `YYYY-MM-DD`。指标数组的每项是 `kind` 与该指标允许的参数，例如 `{"kind":"sma","window":3}`；省略数组使用现有默认8实例，不能传空数组。

`ResearchToolExecutor(development_source=...)`可由可信程序固定注入 `CsvDailyBarSource`。开发模式中模型必须省略 `source`，实际结果明确记为CSV；模型显式选择任何源时拒绝，避免将在线请求静默改成本地数据。非开发模式只接受 `tencent` 或 `akshare_eastmoney`，省略时选腾讯；模型选择 `csv` 始终拒绝。

`execute(response, *, messages)`接收状态为 `tool_calls` 的 `ToolModelResponse`。`messages`必须是**模型产生该提议之前**的合法历史，不含这次assistant提议。执行器预检原调用ID、名称、可回填空间，再尝试执行；调用方继续模型时按下面的顺序拼接：

```python
executor = ResearchToolExecutor(development_source=trusted_csv)
proposal = model.complete(history, tools=(RESEARCH_TOOL_DEFINITION,))
execution = executor.execute(proposal, messages=history)
next_history = [*history, proposal.as_message(), *execution.messages]
```

这只是结构化调用用法，`trusted_csv`、`model`与 `history`由调用方装配；完整可运行示例是 `research_tool_demo.py`。

返回的 `ToolExecution` 包含：

| 字段 | 用途 |
| --- | --- |
| `status` | 执行层状态；不能代替结果内 `data_status` 与 `calculation_status` |
| `messages` | 只有本次tool结果消息；ID与原提议配对，多调用拒绝也回齐整个批次 |
| `full_result` | 本地完整研究结果；没有开始分析或执行未产生结果时为空 |
| `fact_aliases` | 请求内别名到原始 `Fact` 的独立副本，包含原始ID和依赖；未产生事实时为空 |
| `projection_metrics` | 完整紧凑视图的ASCII字符及节点计数；极端整数无法序列化时仅含节点及 `serialization_failed=1`，不能当成成功状态 |

同一执行器的 `analyses_used`最多为1，检查与消费使用锁。业务参数被拒绝不消费分析额度；正常数据失败、投影超限及已开始的异常会消费。下轮由可信应用创建新执行器；模型不能自行重置。

`status=executed`仅表示拿到了可回填的分析结果，源失败仍可能得到 `data_status=source_error`，不能据此生成走势解释。`rejected`表示参数、多调用或额度拒绝；`failed`表示受控执行未产生分析结果；`limited`表示结果/剩余历史容量不足，回填 `result_too_large` 且保留本地完整结果。所有拒绝/容量失败均设置 `synthesis_allowed=false`。

未知工具、复用历史调用ID或非工具提议抛分类 `ToolExecutionError`。数据源构造/研究服务执行段的未知异常分类为 `internal_error`，固定错误不泄露该原始异常，不能冒充正常数据状态；投影等其余未知编程错误仍可传播，并非全部代码都被脱敏包装。非法历史或回填空间不足可在执行前抛 `ModelRequestError`。调用方必须结束或处理这些状态，不能假装已有可用tool结果继续请求模型。

## 整轮运行控制：共享预算、取消与迟到结果

日期：2026-10-22。状态：已接入两个产品Agent入口及终端，离线验证；没有新增真实模型、行情或目录请求。

### 1. 解决的问题

此前不同路径有自己的次数边界，但没有贯穿“理解 → 提议 → 行情分析 → 解释 → 保存结果”的统一停止机制。单个HTTP请求有timeout，也不代表整轮研究一定在该时间内结束。

本模块把这些阶段接到同一个 `TurnControl`。预算由可信应用代码创建，模型工具参数和用户文字不能修改预算、时钟或取消信号。没有引入Agent框架、线程池或新第三方依赖。

### 2. 默认限制及适用范围

| 维度 | 实际默认行为 |
| --- | --- |
| 整轮时长 | 从进入受控执行到会话发布前，使用单调时钟检查90秒期限 |
| 模型调用 | 自然入口共享最多3次；明确格式入口默认2次，原流程本身也不增加调用 |
| 分析 | 全轮共享最多1次，在构造数据源/读取前消费，失败不退还 |
| token | 累计观察值达到24,000立即停止，不重试；不是预付费或严格花费上限 |
| 模型输出 | 沿用DeepSeek现有每次默认512、配置最多1,500 tokens |
| 网络timeout | DeepSeek默认45秒、OpenAI默认30秒、行情默认15秒；实际传入值进一步取剩余整轮时间的较小值 |
| 模型传输重试 | 每次逻辑请求仅在超时或连接错误后、且剩余时间和调用额度允许时重试一次；每次尝试独立扣额度 |

`TurnLimits`允许应用收紧限制，不能扩大所选预算配置的上限。原逻辑流程的单次指标修改、身份续接最多2次模型请求，结果追问最多1次；传输重试也消耗同一控制器的模型尝试额度，实际次数以 `runtime.model_calls_attempted` 为准。明确知识和历史查看0次。每条新消息创建新的控制器，不能重用已开始/完成的控制器。

适用范围是 `run_research_turn()`、`run_natural_research_turn()`及经它们运行的CLI/契约评估场景。独立文本模型CLI、底层工具smoke、目录刷新等没有因此变成整轮受控任务。终端在Agent入口之前读取本地目录的时间也不计入这一轮90秒。

终端原有每启动5条普通问题、15次模型转发上限仍独立生效。若外层会话额度拒绝转发，整轮控制器记录一次模型方法尝试，不伪称已发生一次付费供应商请求；没有返回usage则用量不完整。

### 3. 数据流与代码职责

```text
产品Agent入口
  → 创建/认领单次TurnControl；占用原会话锁
  → 暂存会话状态 + ControlledToolModel包装原模型
  → 理解 / 提议：调用前扣次数，响应后记usage并检查停止
  → 工具：验证参数后扣分析额度，计算完成并返回时再次检查
  → 解释：共用同一控制器，迟到的解释不参与展示
  → finish()：在取消锁下最后检查，再发布新会话状态
```

- [turn_control.py](../src/trading_companion/turn_control.py)：不可变限制、单次生命周期、线程安全取消、预算计数、脱敏运行元数据。
- [agent.py](../src/trading_companion/agent.py)：包装两个入口，处理停止结果，协调会话暂存及提交；不改变股票/日期/指标绑定。
- [research_session.py](../src/trading_companion/research_session.py)：`_fork_for_turn()`暂存，`_publish_turn()`发布；新研究开始仍立即消费旧基准。
- [research_tool.py](../src/trading_companion/research_tool.py)：在实际分析前消费共享额度，不让通用工具异常处理吞掉停止信号。
- [deepseek_model.py](../src/trading_companion/deepseek_model.py)、[tencent_adapter.py](../src/trading_companion/tencent_adapter.py)、[akshare_adapter.py](../src/trading_companion/akshare_adapter.py)：传入剩余时间约束；腾讯每个跨年分片后检查，防止继续发下一片。
- [agent_cli.py](../src/trading_companion/agent_cli.py)：每消息新建控制器，只显示安全答案、时间和用量完整性。

使用 `ContextVar`把控制器传到嵌套的同步I/O边界，避免把预算加入模型可提议的业务参数，也不需要让会话额度包装层识别DeepSeek的具体类型。绑定在 `finally`恢复；它不是进程全局可变单例，也不承诺自动传播到新线程。本项目当前执行链不在后台线程继续研究。

`TurnStopped`独立于模型/数据源异常，不能被内部失败回退误吞。计数在调用/分析尝试前消费；实际返回的次数以控制器为准，而不是入口预先递增的旧局部计数。

2026-10-30增量：`ControlledToolModel`（在所有模型阶段共用的计量包装层）仅对 `timeout` / `connection_error` 重试一次，不重跑行情或分析。每次实际尝试各自记录追踪事件并消耗原有调用额度；超时那次用量未知，后一次成功也不能把整轮用量标为完整。期限到或已取消时立即停止；额度不足时保留原模型失败，不为重试另开预算。已返回但内容、JSON或格式不合格，以及拒绝、限流、鉴权和其他HTTP失败均不重试。独立文本CLI及直接调用底层适配器仍为单次请求。

DeepSeek统一采用45秒连接/读取等待，为较长回答留出余量，同时保留整轮90秒上限及前端现有120秒等待边界。重试等待仍取剩余整轮时间与45秒中的较小值，前置阶段耗时后不保证能完成两次完整等待；协作式截止的限制仍适用。原有较窄路径的调用额度可能已经用尽，此时不会重试。

### 4. 超时与取消：实际边界

这是**协作式截止控制，不是90秒必定返回的硬中断**。Python同步函数、正在等待的requests和远程模型不能被这个对象强行终止。requests的timeout主要限制连接/读取等待，不是整个HTTP下载的硬期限。

控制器在阶段之间、每次模型前后、腾讯每片请求前后及最终发布前检查；如果进行中的操作超过期限，返回后的内容被丢弃，不再启动下一阶段。未在90秒内返回的远程请求仍可能计费。AKShare只约束其公开方法传入的timeout和返回后的行为，不能控制其依赖内部不可见的请求或重试。未来真正需要即时返回时，要单独设计异步任务/进程隔离和供应商取消能力，不能把超时线程称为请求已取消。

`control.cancel()`可以由可信上层UI的另一执行上下文发出，只设停止信号、不创建线程。终端仍同步运行，没有后台 `/cancel`；等待时按Ctrl+C会退出、清理会话并返回130。中文“取消”仍是空闲时清待选请求的命令，不等同于终止正在执行的模型请求。

`finish()`最后检查与发布共用取消锁：若取消先被接收，不发布新状态；若已成功发布并完成，后来的 `cancel()`返回False，不把已完成轮重新改成取消。发布回调只做有界本地引用替换，不做网络、模型调用或再次取消。

### 5. 会话与展示政策

| 停止时机 | 默认展示 | 会话影响 |
| --- | --- | --- |
| 理解/提议停止，尚无事实 | 说明未完成 | 不增加候选或成功结果 |
| 分析迟到，或投影直到超时才返回 | 不展示迟到事实 | 不存结果，不调用解释模型 |
| 解释停止，已有及时核验事实 | 只展示本轮事实与未完成说明 | 不存本轮新结果/编辑基准 |
| 明确发出取消信号 | 不展示本轮分析 | 不存本轮新状态 |
| 合法新研究已开始，之后停止 | 不恢复旧编辑基准 | 旧成功结果只可显式历史查看 |
| 已有结果的追问停止 | 不展示迟到追问答案 | 原可信结果仍保留，TTL不续期 |

旧基准消费和显式“新问题：”重置属于立即失效操作；新候选、新条件、新快照属于暂存后发布操作。这不是数据库事务，也不将所有错误回滚到旧研究。暂存的不可变条件可共享引用；快照读取仍走原来的深复制隔离。

普通模型失败与预算停止不同：前者仍可按原规则保存可信事实；后者不提交新的会话结果。已消费的有效选股回复即使中断也不能再次续跑。原会话锁在停止/异常/中断后释放，进行中第二条消息返回 `session_busy`。

### 6. Token统计不能伪装成成本控制

每个响应将可用的prompt/completion/total分别累计；缺失字段保持未知，不凭空补0。停止计数取 `max(可用total, 可用prompt+completion)`再累加，保守使用已有数据；只在三个字段完整且相加一致时标记该响应usage完整。

没有完整usage时，累计观察值只代表已知部分或不一致报告下的保守停止值，不能视为真实总消耗。`usage_complete_for_attempts`还要求每次模型尝试都有完整一致usage；失败但未返回usage的调用不会被忽略。晚返回的有效模型响应仍统计usage，但它的工具调用和文本被丢弃；若传输/解析失败而无可用响应，则无法追补账单。

阈值在响应后检查，允许本次已经越过阈值，但不再后续调度；没有使用分词器估算输入、预留下一次最大费用、账户余额或人民币预算。默认继续允许缺usage的响应，仍受次数/时长/现有输出上限约束，不把这个策略称为严格token上限。

`AgentTurnResult.to_dict()`新增 `runtime`，包含限制、停止码、耗时、尝试数、收到响应数和usage完整性。被丢弃的响应不会加入原 `model_responses`，但可出现在 `runtime.responses_received`统计中。runtime不包含密钥、问题、模型草稿、文件路径或底层异常；整个Agent调试导出仍不是脱敏生产日志。

停止码：`turn_deadline_exceeded`、`turn_cancelled`、`model_call_budget_exhausted`、`analysis_budget_exhausted`、`token_budget_exhausted`。本层自动重试仅限上述模型传输错误，不修改参数或答案、不换模型或行情源；业务层已有的有界回答修复继续按原规则执行，并共用本轮预算。

### 边界与职责

- [消息入口](../src/trading_companion/api_service.py)在 `message()` 进入时创建随机运行号，先于 `_admit()` 的会话核验、额度和幂等检查。知识、研究、筛选、澄清、命令、历史以及目录失败、准入拒绝均经过此边界。
- [追踪模块](../src/trading_companion/turn_trace.py)提供 `TurnTrace` 收集器、`TraceLimits` 容量配置和 `JsonlTraceSink` 写入器。它不解释问题、不重算路由、不控制预算、不发布会话。只在消息全部原收尾完成后写一条记录。
- [整轮控制器](../src/trading_companion/turn_control.py)仍拥有执行期限、取消、预算和迟到结果处理；追踪复用其 `to_dict()` 的白名单快照，不另建控制器，不改变执行起点或增加业务时钟读取。
- `ControlledToolModel` 在成功预留原预算后开始模型事件，在原用量/取消检查之前记录有效响应；DeepSeek 的[共享传输](../src/trading_companion/deepseek_model.py)与[OpenAI 适配器](../src/trading_companion/openai_tool_model.py)在实际 HTTP 客户端调用前标记发送。
- [启动入口](../src/trading_companion/api_server.py)仅把同一个可信写入器注入正常服务与独立 demo/Dev 服务，不改变公共响应结构。运行号仅存于内存请求缓存和追踪文件，不加入 HTTP 返回。

消息服务之前的 HTTP 来源、格式、请求体和缺失凭据校验，以及创建/删除会话、健康检查等非消息操作不记录为研究轮次。`agent_cli`、独立文本 CLI、目录刷新与独立评估脚本本次没有持久化开关。`trace-v2` 增加工具、来源、检查和修复事件；`workflow` 仍只复用已有结束原因和工具总次数，不能整份复制其中的股票或业务请求号。只读查看命令见下文。

### 三种模型计数

| 字段 | 实际含义 | 不代表什么 |
| --- | --- | --- |
| `attempted` | 原 `reserve_model()` 成功后调用模型包装层的次数 | 供应商请求数；会话额度或本地协议仍可能拒绝 |
| `provider_requests_started` | 已知供应商适配器算好剩余超时后，开始调用 `requests.post()` 的次数 | 供应商已收到、计费或完成；连接失败也算开始发送 |
| `responses_received` | `ControlledToolModel` 收到有效、已校验的 `ToolModelResponse` 的次数 | HTTP 200 的次数；无效 JSON/协议不算有效模型响应 |

本地消息无效、会话调用额度耗尽、发送前截止：有预留成功的尝试，没有发送或有效响应。单轮模型预算已经耗尽：预留失败，不增加尝试，终态保留预算停止码。假模型：有尝试/返回，没有供应商 HTTP 请求。

`transport` 为 `http`、`mock` 或 `unknown`。供应商和请求模型标识仅从已知适配器的可信配置读取；模型标识限 128 个 ASCII 字母、数字及 `_.-`，不符合者为 `null`。不照抄供应商返回的模型名，不遍历未知包装器。未知适配器没有发送钩子时，发送数只是已观测值；`attempts_with_unknown_transport` 明确提示不完整，不能把零解释成没有计费。

迟到有效响应先计入响应和 usage（供应商报告的 token 用量），再按原规则拒绝内容，取消后也不会发布会话。usage 缺失为 `null`；部分字段累加已知部分，不能把缺失补成零。完整性要求三个字段齐全且总量等于输入加输出。值超出追踪可表达的 10¹² 计数上界时记未知；这是记录边界，不是放宽预算或估算费用。

### 时间与结束方式

`total_elapsed_ms` 从进入消息服务到原结果投影、缓存、额度释放及异常收尾结束，包含本地目录工作，排除本条记录最终写盘。它不是浏览器渲染或 HTTP 网络往返延迟。`execution_elapsed_ms` 来自原 `TurnControl`，只计算受控执行阶段；执行未开始时为 `null`，`execution_started=false`。追踪另用独立单调时钟，不消耗原注入的业务时钟。

`phase` 是最后进入的阶段：`admission`、`directory`、`routing`、`execution` 或 `projection`。路由尚未作出时 `route=null`，不伪造技术后备。终态分别记录完成、澄清、受限、拒绝、错误、停止、中断或重放。非预期内部错误仍按原公共错误返回；中断仍传播，不被记录逻辑吞掉。可捕获的异常/中断尽力留下终态，不保证强杀进程或掉电时落盘。

成功与失败缓存的幂等重放都会生成新的访问记录，`original_run_id` 指向原随机运行号；本次模型次数为零，没有复制旧模型事件或执行时间。冲突/进行中/会话忙等拒绝不冒充重放。鉴权成功后才关联缓存和提供方；无效令牌既不获取原运行号，也不显示会话提供方。运行号关联仅在当前内存缓存存续时可用，不恢复聊天。

固定代码使用明确词表；未知业务/异常代码仍记 `other`，不能仅凭字符串格式看起来安全就写入。源码完整性测试通过 AST（把源码解析为结构的抽象语法树）检查所有 Python 模块的代码字段、位置参数构造、辅助函数、默认值、赋值、字典字段和固定 `(code, message)` 返回，以及已审核的模型状态派生码。每个发现的码必须进入固定词表，或列在附逐项理由的 `NON_TURN_CODES` 排除清单；没有按目录或前缀整批豁免。过时、无理由或同时出现在两份清单中的排除项也会失败。

排除项只用于代码完整性审核，例如图表/证据附件、归档或独立评估状态；新增公开结束码应明确加入词表，不能借排除清单跳过。一般知识的模型不可用、输出无效、本地检索失败、拒绝和未完成已通过真实消息入口回归，确认公开结果与追踪原因一致。生产记录仍只查固定词表，不在运行时扫描源码、自动注册新值或记录原始异常。扫描器是受约定约束的静态检查，不是通用数据流证明；新增计算码形式或辅助函数签名需同步审核测试。

### 隐私、容量和故障隔离

只按白名单组装记录。问题、提示词、答案、草稿、工具参数/响应、证据、证券身份/业务日期、用户请求编号、会话编号、问题指纹、请求头、URL、文件路径、密钥、令牌及异常文本均不写入。UTC 起始时间是运行元数据。没有自动脱敏原文开关；`AgentTurnResult.to_dict()`、模型 `to_dict()` 以及完整 `workflow_trace` 都不能直接用作追踪记录。

| 限制 | 默认硬上限与行为 |
| --- | --- |
| 全部详细事件 | 模型与工具/来源/检查/修复合计每轮 64 条；超限只保留总计并增加 `dropped_events` |
| 单条 JSONL | 包含换行最多 64 KiB；再丢弃详细事件，保留总计、控制器与终态，设置 `truncated` |
| 单个文件 | 最多 5 MiB；写入新行前按字节大小轮换 |
| 文件数 | `turns.jsonl` 加 `turns.1.jsonl` 至 `turns.3.jsonl`，总共最多 4 个，即 20 MiB |

可信程序代码可以收紧限制，不能扩大；单条最低 2 KiB。只操作这些固定名字，不递归删除目录，不清理其他文件。已有同名文件异常超大或为符号链接时拒绝写入，保留原文件；容量承诺针对正常由本写入器生成的文件，不会修复外部篡改/损坏的数据。发生短写时尽力退回原完整行边界，磁盘持续故障时不承诺最后一行可恢复；查看器会跳过末尾未换行的残行并报告。

单进程共用独立写入锁防止混行，写盘在 API 会话锁、控制器取消/发布锁、会话发布回调及收集器锁之外。打开、写入、序列化或轮换失败不会改研究回复、缓存、额度释放或状态发布；本地同步磁盘 I/O 不承诺硬超时。不同服务进程应选择不同目录，不支持多进程共享一个目录的写入。

收集器用 `ContextVar`（按执行上下文保存值）传递。新建线程不会自动继承；第 3 阶段加入并发时，每个任务必须分别调用 `contextvars.copy_context()`，再以该副本的 `run()` 执行，不能让多个线程同时进入同一份上下文。单元测试锁定：线程池未复制上下文时没有该轮事件，逐任务复制后能归入原轮；独立消息和嵌套关闭范围不会串记。本次没有新增并发取数。

```json
}
```

| 字段 | 解释 |
| --- | --- |
| `schema_version` | 此历史样本为 `trace-v1`；现在生成 `trace-v2`，按版本解释，旧记录不原地重写 |
| `run_id` / `original_run_id` | 随机运行号 / 仅重放时关联的原运行号，均非用户请求编号 |
| `started_at` | UTC 起始时间，和业务研究日期无关 |
| `entry` / `mode` | 当前入口固定为 `api_message`；模式为正常、开发服务或离线 demo |
| `provider` / `history` | 经鉴权的会话提供方，无法确认时为 `null`；是否通过可信历史查看入口 |
| `phase` | 最后进入的处理阶段，失败时帮助定位发生在执行之前还是之后 |
| `route.kind` / `intent` / `rule_id` | 实际执行入口、语义意图及静态路由原因，不记录匹配原文或额外扫描候选 |
| `outcome.category` / `code` | 终态类别及固定结果/停止码；重放引用原轮而不重复研究 |
| `total_elapsed_ms` | 消息服务的完整处理耗时，不含最终记录写盘 |
| `execution_started` / `execution_elapsed_ms` | 是否开始受控执行及原控制器的执行耗时；未开始时耗时为 `null` |
| `control.state` / `stop_code` | 原控制器状态及固定停止原因；执行前失败则整个 `control=null` |
| `control.analyses_used` / `model_calls_attempted` / `responses_received` | 原控制器的预算与返回计数，保持原口径 |
| `control.observed_tokens` | 已观察到的停止阈值计数。示例为 0 因为假模型无 usage，不代表真实成本为零 |
| `control.reported_usage` / `responses_with_complete_consistent_usage` / `usage_complete_for_attempts` | 原控制器报告的已知输入/输出/总 token、完整一致响应数及完整性标志 |
| `control.limits` | 原轮次时限、模型次数、分析次数及已观察 token 停止阈值，不是账单硬上限 |
| `workflow.stop_reason` / `tool_calls_used` | 现有工作流的固定结束原因和工具次数；不含详细工具事件 |
| `models.attempted` / `provider_requests_started` / `responses_received` | 三种明确分开的计数，见上表 |
| `models.reported_usage` / `responses_with_complete_usage` / `usage_complete_for_attempts` | 从有效模型响应得到的已知用量和一致性，截断详细事件后仍保留总计 |
| `models.attempts_with_unknown_transport` | 发送边界未能确定的尝试数，防止用零发送数推断零费用 |
| `models.events[].sequence` / `start_ms` / `elapsed_ms` | 轮内顺序、相对轮次起点的开始偏移和该次尝试耗时 |
| `models.events[].provider` / `requested_model` / `transport` | 已知提供方、可信请求模型标识及 `http/mock/unknown` 传输类别 |
| `models.events[].provider_requests_started` / `response_received` / `response_status` | 该次尝试的发送次数、是否有效返回及 `complete/tool_calls/refused/incomplete` 状态 |

示例生成方式由[启动器测试](../tests/test_turn_trace_api.py)中的离线 demo 测试覆盖；启动上述 `--demo` 命令后，在网页发送固定演示问法也会生成相同结构，运行号、时间和毫秒值自然不同。假模型调用证明流程可执行，不是模型理解能力或在线延迟的证据。

### v2 的事件格式与统一接口

2b-i 开始写 `schema_version="trace-v2"`。原根字段和模型统计口径保留，新增根 `events` 数组及 `tools`、`sources`、`checks`、`repairs` 四个汇总；模型事件仍在 `models.events`，增加关联字段。不复制历史行，也不把 v1 没有的新信息解释成零次。一个轮换文件可以包含两个版本；2b-ii 查看器逐行分版本解释，未知版本单独诊断。

[统一接口](../src/trading_companion/turn_trace.py)只提供两种业务用法：`trace_call` 包围已有调用或作装饰器，`trace_event` 包围需要跨多条语句的事件。业务模块不拼记录字典、不维护词表，也不访问收集器内部字段：

```python
@trace_call("check", "research_response")
def validate_research_response(text, *, execution, expected_request):
    ...

bars = trace_call("source", "daily_bars", source.read_daily_bars)
```

关闭追踪时 `trace_call` 直接执行原调用，不检查参数或返回值，不读诊断时钟；多语句的上下文接口只产生空句柄。接口内部隔离元数据检查、计时、词表和写盘错误；原业务异常继续传播，原调用至多执行一次。只检查已知结果类型的元数据，不调用通用 `to_dict()`、字符串化或未知对象属性来猜来源。

| 非模型事件字段 | 含义 |
| --- | --- |
| `kind` / `operation` | `tool/source/check/repair` 与固定操作；工具名限现有四个只读工具，未知提议不回显名字 |
| `event_id` / `parent_event_id` | 全类别共享的轮内整数号及父事件号；不使用用户或供应商编号 |
| `phase` | 事件开始时的原阶段，尤其区分 `execution` 和 `projection` |
| `start_ms` / `elapsed_ms` | 相对轮次开始的偏移及实际经过时间；由独立追踪时钟计算 |
| `source` / `access` | 已知类型或受信配置给出的固定来源；访问类别为 `network/local/snapshot/unknown`；非来源事件为 `null/unknown` 占位 |
| `entered` | 是否进入该语义操作；工具通过原授权和额度后才置真；跳过为假，不表示供应商收到请求 |
| `status` / `code` | 固定状态与固定结果码；未知字符串为 `other`，没有异常文本 |

状态为 `ok`、`limited`、`rejected`、`failed`、`stopped`、`skipped`、`unfinished`。`unfinished` 表示整轮收尾时该事件尚未结束；`elapsed_ms=null`，不把它算成功或零耗时。状态 `ok` 只表示此操作按原接口返回；数据是否有效由对应检查事件表达，并不证明回答的全部自由文本为真。

四个汇总都有 `seen`、`entered` 和七个同名状态计数。`seen` 为观察到的入口次数，含跳过；`entered` 为实际进入次数，跳过不计；状态计数之和等于 `seen`。规则修复的“不需要纠正”可使 `repairs.seen=1`、`skipped=1`、`entered=0`，不能说模型重试了一次。进入模型重写流程后仍可能被共享预算挡住；实际模型尝试仍只按原预算预留成功计入 `models.attempted`。

#### 工具、来源与检查的实际覆盖

- [工作流工具](../src/trading_companion/workflow_tools.py)调用[单次研究工具](../src/trading_companion/research_tool.py)完成主分析时共用一次逻辑工具事件；进入原执行分支后才标记 `entered`。提议不匹配、重复和额度拒绝仍有结果，未读取来源。知识和快照摘要是本地工具；补充指标只重用原快照。
- [日线入口](../src/trading_companion/multi_analysis.py)记录已有读取、来源校验和记录校验，覆盖技术和公司研究；已知 CSV 为 `local`，补算快照为 `snapshot`。来源抛错、空记录、无效记录分别保留原语义。
- [公司来源](../src/trading_companion/company_research.py)按章节记录，区分东方财富公司/财务/新闻/公告、新浪和巨潮；历史约束跳过资料时 `entered=false`。内置服务不再重复记录外层 `collect`；未知注入服务仅以来源未知的批次调用记录，不能凭其自报标签推断供应商。一次章节或筛选读取可能包含多次 HTTP，事件数不是 HTTP 请求数。
- [消息服务](../src/trading_companion/api_service.py)记录已有证券目录与可选市场背景加载；[公司研究](../src/trading_companion/product_research.py)记录已有可选在线背景读取、批次校验；[筛选](../src/trading_companion/screening_agent.py)记录原快照读取；[知识问答](../src/trading_companion/open_knowledge.py)记录本地检索与原格式/引用检查。注入闭包或替身的访问类别无法确认时保留 `unknown`，不按函数名或返回标签猜测。归档写入不计来源读取。
- 技术/工作流回答及指标关系检查按实际调用次数记录，包括展示阶段的重复核验，不为追踪新增、缓存或省略校验。旧式关系回答可能跳过新的会话格式检查，但仍完成子级关系检查，不能把 `no_conversational_response` 解读为全部检查失败。低层每个字段断言不建事件。

已发生的读取可在返回后被原取消检查挡住：来源事件仍表示读取已发生，父工具或整轮记录停止；不会因为记录读取成功而发布迟到结果。根 `outcome` 和控制器仍负责表达整轮是否停止。

#### 修复与父子关联

[公司回答](../src/trading_companion/product_answer.py)第一次输出被原检查判为可修复后，`rewrite_decision` 只记录 `rewrite_allowed/disabled/not_repairable/limit_reached` 等固定理由。仅第二次实际进入重写流程时创建 `model_rewrite`，作为第二次模型与检查事件的父事件；第一次拒绝保持独立。仍最多重写一次，模型错误、再次无效、取消和预算停止都留固定结果，没有第三次调用，也不记录草稿和修复提示词。

[请求理解](../src/trading_companion/research_intent.py)的有限形状检查记录为 `intent_shape`；通过所有原身份/参数门禁、真正形成可执行请求后，`intent_rule` 表示原程序是否纠正了模型不必要的澄清。普通研究为 `rule_not_needed` 并跳过，纠正为 `rule_applied`。不把这类规则纠正叫模型重写；未形成可执行请求的早期拒绝保留原检查和轮次结果，不捏造一次成功修复。

父子号允许表示嵌套和重叠；事件号按开始分配，两个数组并非全局时间排序。子事件耗时不能相加当总耗时。父事件可能因详细上限而未保留，查看器会提示缺少父事件的条数。

#### 共享上限、词表和未来并发

模型与非模型详细事件合计最多 64 条；超限后继续统计四类固定摘要及模型用量。序列化超过字节上限时按事件号从后向前丢详细项，`dropped_events` 包含数量与字节两种丢弃。摘要不按来源、操作或码值扩展字典；查看器的细码分布只覆盖保留事件，同时标明截断。最小 2 KiB 配置也验证了终态、控制器、模型和四类摘要保留，原文件容量与故障隔离规则不变。

`_CODES` 仍是整轮公开结果词表；`_EVENT_CODES` 是新增事件可记录的固定细码。原“非轮次结果”中现在作为工具、来源或检查结果的项移出排除清单，进入事件词表；它们不会因此变成整轮公开码。源码守卫支持固定 `(status, code)` 元数据返回，并另核对公司/新闻私有拒绝理由，避免 `str(error)` 包装后的真实来源原因漏登记。未知值仍不自动注册。

共享收集器的事件号、计数、保留额度、阶段及完成标志均受同一独立锁保护；业务执行、诊断类型检查及磁盘 IO 不在该锁内。每个线程池任务分别复制 `ContextVar` 上下文，保留自己的父事件；同一轮共享收集器，不同轮隔离。`finish()` 后所有更新被忽略，写出的是独立标量结构，迟到句柄不能修改已完成记录或二次写盘。未来调度器仍须先收束任务再结束轮次；追踪不等待线程、不接管取消或发布。

### 只读查看器（2b-ii）

[查看模块](../src/trading_companion/trace_cli.py)只用标准库和追踪模块的固定词表，不导入服务启动器、读取 `.env`、联网或写入输入目录。先让服务生成记录，再单独运行：

```powershell
.\.venv\Scripts\python.exe -m trading_companion.trace_cli --trace-dir .\data\traces
.\.venv\Scripts\python.exe -m trading_companion.trace_cli --trace-dir .\data\traces --since 2026-10-27T00:00:00Z --until 2026-10-28T00:00:00Z --route technical_research --code research_completed --list 10
.\.venv\Scripts\python.exe -m trading_companion.trace_cli --trace-dir .\data\traces --executed-only --format json
.\.venv\Scripts\python.exe -m trading_companion.trace_cli --file tests/fixtures/turn_trace_v1.jsonl --file .\data\traces\turns.jsonl
```

#### 筛选与分母

| 参数 | 含义 |
| --- | --- |
| `--trace-dir` / `--file` | 二选一；前者只读四个固定文件名，后者可重复，最多四个文件 |
| `--since` / `--until` | 起点包含、终点不包含；要求带 `Z` 或 `±HH:MM`，接受最多六位小数秒，转换为 UTC，拒绝倒置或相等范围 |
| `--route` | 按 `route.kind`，可重复取并集；没有路由的轮次是 `unrouted`，包括未保存路由的重放 |
| `--code` | 按整轮结果码，可重复；工具/来源细码只出现在保留事件分布，不作整轮筛选 |
| `--mode` / `--category` | 按运行模式或终态类别，可重复取并集；不同参数之间取交集 |
| `--executed-only` | 仅选 `execution_started=true`；执行失败仍计入，不要求成功或调用过模型 |
| `--list N` | 列出按 UTC 时间、运行号倒序的最近 N 轮，默认 0，最大 1000 |
| `--format table` / `json` | 默认中文对齐表格，或输出机器可读 JSON（结构化文本） |

默认包括拒绝、失败、取消、重放。首行的“样本 A/B”是筛选后轮数/筛选前有效唯一轮数；模式、版本、事件覆盖和后面的统计都对应筛选后的 A 轮。重复运行号先去重再筛选：目录从 `turns.3.jsonl` 读到 `turns.jsonl`，同号第一条有效记录生效；显式文件按参数顺序。不能用筛选把重复号的另一条记录重新纳入。

每条路径和合计均给出总耗时与执行耗时的 p50/p95，单位毫秒。采用 nearest-rank（排序后取第 `ceil(p × n)` 个样本），同时显示各自有效 `n`；`null` 耗时不补零，真实的 0 毫秒仍是有效值。总耗时含入口前置工作，执行耗时从原控制边界开始；子调用可以重叠，不能相加当总耗时。零样本时分位数为 `null`，表格显示“未记录”。

模型总计和每轮分布分别统计尝试、开始发送、有效回复，分布桶固定为 0～6、7～9、10+。用量各字段只累加已知部分，并分别给已知轮数；全部未知保持 `null`。完整性沿用记录中的“完整用量响应数等于尝试数”定义，因此零尝试轮次也满足；查看器另给零尝试数、有尝试且完整的轮数，不能把零尝试解释成拿到了完整账单。未知传输次数独列，不从来源调用次数猜模型 HTTP 次数。

v1 可以参与路由、终态、耗时与模型统计；工具/来源/检查/修复显示“未记录”，JSON 中全 v1 时 `event_summaries=null`，混合时只累加 v2 摘要并给覆盖轮数。明细覆盖的分母是已记录的模型尝试加 v2 四类 `seen`；v1 没有记录的动作不在这个分母中，显示保留数等于分母也不能证明 v1 全部动作都被观测。摘要不受详细截断影响；细码分布只代表保留事件，表格最多展示前 20 组，JSON 保留全部固定词表组合。另列截断轮数和缺失父事件的条数，检查通过不升级为全部事实已经证明。

#### 有界读取与诊断

不递归，不创建、修改、轮换或清理输入。拒绝文件和祖先中的符号链接、Windows junction（目录连接）等重解析点，以及 UNC/设备路径；打开前检查，打开后核对普通文件身份，再检查读后身份、大小及修改时间。读取只到打开前看到的文件大小，途中新增的行留待下次读取。活动写入/轮换无法提供原子快照（同一瞬间的完整副本）；尽力检测变动并报告，不承诺发现保留了全部元数据的外部改写。需要稳定对比时，停止写入或使用已复制的普通文件。

硬上限为四文件、每文件 5 MiB、合计 20 MiB、每行 64 KiB；超大文件整份跳过，超大行分块排空后继续读。另设总物理行数 100000、有效唯一运行号 50000 的资源上限，触发则停止读取并报告。耗时样本和去重集合因此有界，最近列表最多 1000 条；不会整份加载文件或保留任意用户字段。每行通过两个明确的版本解析分支，只投影固定枚举、合法随机运行号、UTC 时间和安全数值；拒绝重复键、NaN/Infinity、布尔冒充计数、负数/大于 `10^12` 的计数、过深结构、超过 64 项的数组/对象、缺失必需字段及不一致摘要。未知字段不输出，未知结果字符串变成 `other`，未知来源变成 `unknown`，异常文本和原路径不输出。

| 诊断键 | 含义 |
| --- | --- |
| `invalid_lines` / `unknown_versions` | 已支持版本的损坏行 / 不支持的版本 |
| `oversized_lines` / `incomplete_lines` | 超限行 / 最后一条未换行的残行，即使暂时能解析也不计入 |
| `duplicate_runs` / `duplicate_files` | 已计入的运行号 / 已读取的同一物理文件 |
| `read_errors` / `unsafe_files` | 无法读取 / 链接、非普通文件或打开时身份异常 |
| `oversized_files` / `changed_files` | 文件超大 / 检测到变化的文件或目录数，同一路径只计一次 |
| `input_limit_reached` | 总字节、行数或运行号资源上限阻止继续读取 |

退出码 `0` 表示读取完成（空目录或筛选后没有样本也为 0）；`1` 表示读取不完整，仍输出有效结果及上述诊断；`2` 表示参数错误，只给固定输入提示。缺失目录是读取失败，不当作空目录。JSON 的 `status` 为 `ok` 或 `partial`；首行“读取诊断”是除文件变动外的诊断计数之和，包含行级、文件级及资源限制诊断，不是丢弃行数或跳过轮数；“变动文件”单列。详细计数以 `diagnostics` 为准。

事件分布表的“来源”仅对 `source`（逻辑数据读取）事件显示白名单来源或 `unknown`（未知）。工具、检查与修复不以数据源为维度，显示 `—`（不适用）；不把实际来源未知改成不适用。此区别只影响表格显示，JSON 保留原安全投影：未提供或不在白名单内的来源仍是 `unknown`，不输出外部任意字符串。输入记录格式和计数不变。

## 终端研究入口设计

日期：2026-10-20

后续更新：2026-10-22，已有有限指标修改、结果追问/知识、`/last`及明确股票/日期/指标增删，见第8–10节。

状态：代码与离线验证已有；本步骤未执行真实模型、真实行情或目录刷新

### 1. 本步交付与边界

`agent_cli.py`把已有自然入口、股票澄清会话和安全展示接到终端，让用户可以自己输入问题，而不必修改演示脚本。它是薄交互层：不另写模型理解、指标计算、身份续接或回答检查逻辑。

用户要求直接进行下一步，本步跳过理解题。此前只收到 `complete` 场景一次真实模型成功反馈；`partial`、`natural`、`clarification`的真实报告仍待补，不因有了交互入口就视为全部通过。真实模式是显式启用的初版能力，不是完整产品质量验收。

支持完整单股票日线问题、待选股票回复、明确指标替换、股票/ISO日期修改及单个指标增删，以及有限结果追问、定义和历史查看。自由复合修改、对话内切源/最新查询、开放知识问答、新闻选股、完整聊天记忆和交易操作未加入。

### 2. 四种启动行为

| 命令参数 | 行为 | 模型 / 行情联网 |
| --- | --- | --- |
| 不带参数 | 仅显示帮助，不读取目录或凭据 | 无 / 无 |
| `--demo` | 自动运行固定的“平安→平安银行”两轮脚本，不读交互输入 | 无 / 无 |
| `--provider deepseek --data synthetic` | 真实模型、用户交互、固定人工CSV与目录 | 可能 / 无 |
| `--provider deepseek --data tencent` | 真实模型、用户交互、已校验本地目录与腾讯历史日线 | 可能 / 按研究请求 |

没有默认真实模型或默认真实行情。`--provider deepseek`必须同时明确数据模式；人工模式不接受自选文件。`--directory`只允许在腾讯模式由启动者配置本地目录路径，不能由模型或用户问题选择；默认使用项目的 `data/security_directory_live.json`。

假模型只服务固定脚本，不假装能够理解任意中文。原参数式行情CLI、单轮接口和评估命令保持兼容。

### 3. 数据流与状态归属

```text
终端输入
  → 本地命令或长度检查
  → 重读并检查本地目录 / 固定夹具
  → run_natural_research_turn(..., session=同一个会话)
  → 原身份理解、工具、研究、事实和关系检查
  → 固定状态说明 + 已校验条件/候选 + display_answer
  → 下一次输入，或退出并清除待选状态
```

一次 `run_conversation()`只创建一个 `ResearchSession`；每次启动彼此隔离。终端持有这个对象，模型不管理会话ID，也不接收完整聊天历史。会话分开保存待选条件、有限修改基准和一份可信成功结果。“那RSI呢”可走有限结果追问，但只能读原先计算过且仍有效的结果，不能自行新增RSI实例或取数。

- `/help`：本地说明；`/last`：显式查看上次成功结果；`/reset`：清除待选、条件及结果，不补调用额度；`/exit`：退出并清理。
- 空行与未知斜杠命令不发送模型；中文“取消”和“新问题：完整问题”沿用原Agent处理。
- 待选时仅接受完整名称/代码，不按候选序号猜股票；附带指标修改的短答不会被静默截断。
- EOF、Ctrl+C和次数耗尽都会清除全部三类状态，不自动重试或恢复被中断任务。

### 4. 数据与时间边界

新增 `development_fixtures.py`，将评估入口原有的固定文件SHA256预检提取成共用函数，哈希与参考日不变。评估入口和终端入口共享这条规则，产品交互不依赖评估模块的内部函数。

人工模式仅有平安银行5条日线和4项目录身份，不能当作这些股票的真实行情。研究日期锚点固定为2026-09-26，并在横幅中明确；待选状态的15分钟有效期仍使用当前真实时钟，不因为人工锚点而永不过期。除Git的CRLF/LF差异外，夹具变更会阻断使用；这不是通用沙箱，也不消除运行时外部改文件的风险。

腾讯模式启动时先校验目录，再读取模型配置；每条送交Agent的输入前重读目录（包括映射为历史查看的`/last`），按当前上海日期检查是否为非夹具且不超过7天。文件损坏、过期或未来日期会停止会话，不自动刷新，也不继续使用旧内存副本。身份续接及结果复用还会由原会话重新核实相关范围和当前有效性。

目录刷新是单独的显式操作；本步骤没有发出刷新或行情请求。此入口只开放腾讯行情模式，不改变底层东方财富适配器和证券支持白名单。

### 5. 展示、调用与失败行为

终端只消费 `display_answer`和程序状态/候选/条件，不调用包含调试草稿的 `AgentTurnResult.to_dict()`。关系被拒绝时仍只展示事实及固定回退说明；原始模型文字、完整工具消息、凭据和底层异常不输出。

真实模式横幅说明本轮问题、已校验参数和紧凑指标证据会发给DeepSeek；密钥仅用于HTTP认证，不进入提示词。应用不主动写聊天、报告或目录文件，不代表系统终端滚动记录或外部日志一定不存在；不要把密钥作为研究问题输入。

| 范围 | 当前限制 |
| --- | --- |
| 单个自然初始问题 | 最多3次模型调用、1次分析，无自动重试 |
| 有效股票选择续接 | 最多2次模型调用、1次分析；无效短答不查询 |
| 明确指标修改 | 最多2次模型调用、1次新分析；本地无效修改不查询 |
| 自然结果追问 | 最多1次模型调用、0次行情；普通问题额度照常计入 |
| 有限指标定义 | 0次模型、0次行情；普通问题额度照常计入 |
| `/last`显式历史查看 | 0次模型、0次行情，不占普通问题额度，不延长结果寿命 |
| 一次启动 | 最多5条非空、非斜杠命令问题；超长和中文取消也计入输入次数 |
| 模型转发 | 独立包装器最多转发15次；调用前扣额度，失败不退还，超限停止 |
| 分析总数 | 由5条输入及原每轮1次执行器上限得到最多5次；不是另一个独立的分析额度存储 |

本地命令和空行不占问题次数，也不会刷新额度。以上是单进程启动的限制，不是跨启动或账户级配额。后续增量另接入每轮共享运行控制，见第11节；仍没有整轮硬中断或费用保证。

每轮显示状态、条件/默认口径、候选和安全回答；结束时显示已计入输入、转发模型调用和已确认分析次数。Ctrl+C若发生在尚未返回的研究轮中，明确提示该轮可能已经取数，不能把“尚未收到计数”记成零分析。

CLI退出码：正常退出/EOF/达到输入次数上限为0，即使个别研究失败；问题失败由逐轮状态体现。目录或调用上限阻断为1，模型配置或非法启动参数为2，Ctrl+C为130。不自动重试或改行情源。

## 正常模式与 Dev Mode

日期：2026-10-25。

### 1. 要解决的问题

真实模型连接成功不代表使用了真实行情。此前 `--provider deepseek --data synthetic` 可以连到 DeepSeek，但仍只有四条人工证券目录、平安银行五条人工日线；正常输入“分析一下中际旭创”因此找不到证券。让用户改输代码无法补齐不存在的目录记录。

现在 Web 产品默认正常运行，把人工开发环境放到明确的 Dev Mode。二者复用同一套 Agent 代码，但不混用模型、目录、行情、会话或预算。

### 2. 启动契约

```powershell
.\.venv\Scripts\python.exe -m trading_companion.api_server
```

默认监听 `127.0.0.1:8765`，正常后端使用 DeepSeek、腾讯不复权历史日线和本地真实证券目录。源码项目自动按原规则加载根目录 `.env`，进程环境变量优先。显式 `--provider` / `--data` / `--port` 仍可覆盖正常后端；它们不是浏览器请求参数。

启动检查依赖、密钥格式和现有目录是否可用，不调用模型、不获取行情、不自动联网刷新目录。真实目录缺失或过期、密钥或依赖无效时明确失败，不静默降级为人工数据。目录由用户通过已有 `security_directory_refresh --live` 命令手动更新，详见[本地配置](operations.md#本地模型配置与启动)。

`--demo` 是单独的完全离线入口：固定假模型和人工夹具、不读 `.env`，网页不能借此启用正常模式。`agent_cli` 和固定评估入口的默认行为不变。

### 3. 两个固定服务，而非任意切源

```text
同一网页 / 同一 loopback 进程
  ├─ normal：/health、/v1/sessions...
  │    └─ 正常服务：启动时固定模型、真实目录、行情来源
  └─ Dev Mode：/dev-api/health、/dev-api/v1/sessions...
       └─ 独立离线服务：fake + synthetic + 固定人工目录
```

两个 `ResearchApiService` 各自拥有会话、令牌、幂等记录、模型实例及额度；一个服务的令牌不能访问另一个服务。模型建议、聊天内容和 HTTP body 仍不能设置提供方、来源、目录、CSV 路径或预算。切模式只是选定一个服务端预配入口，不能在原会话里换源。

根 health 可返回可选 `development_mode_available` 布尔值，供界面显示或禁用按钮；它是展示能力提示，不是权限或隔离边界。健康检查成功只说明本地服务能响应，不证明供应商网络、数据质量或研究结论正确。两个后端仍分别执行原有令牌、来源绑定、配额与事实校验。

### 4. 页面切换状态

页面初始为正常模式，不持久化模式选择。首次发送在当前模式懒创建会话；模式切换本身只做 health / 会话清理，不提交研究问题。

1. 只允许空闲时切换；创建中、发送中、取消尚未确认或原请求响应不确定时禁用切换。
2. 存在旧会话时，先按原后端成功结束它；清理失败保留原模式、聊天和草稿，不创建目标会话。
3. 旧会话清理成功后，立即选择目标入口、清空原聊天、草稿、health 与页面凭据。此时旧会话已结束，不能把它当作可恢复的备份；尚未创建目标会话。
4. 再检查目标 health 并核对预期提供方与数据模式。成功后允许下一次明确发送时创建目标会话；失败则保留已选目标的断连空白状态，显示错误，不恢复已删除聊天、不自动回退、更换来源或继续发问题。用户可手动重连，或空闲时明确切回另一模式，但这仍是新对话。
5. 刷新页面回正常模式，不保留开发模式令牌或聊天。刷新仍应在无在途/不确定请求时进行，避免丢失原请求的恢复凭据。

这是丢弃旧聊天后切换环境，不是保存两个可随时来回恢复的聊天窗口。原响应重试仍使用原服务、原会话与原请求编号，不能把不确定请求带到另一个后端重发。取消请求获 202 也不表示供应商已停止或不再计费。

### 5. Dev Mode 的能力边界

- 不请求真实模型或行情，页面清楚显示假模型和人工数据。
- 目录仅含平安银行、中国平安、贵州茅台、中芯国际四条人工记录；行情样例只有平安银行在 2026-09-21 至 2026-09-25 的五条人工日线。目录中有名字不等于该股票有可用行情。
- Fake 是固定演示脚本，不是可理解任意问题的通用模型。默认长周期指标在五条样例上可能不足；不会补零、伪造历史或把结果当真实走势。
- 正常模式的新闻、基本面、选股、实时行情与下单能力没有因此增加；项目仍无自主交易权限。

### 6. 验证要求

自动检查应覆盖默认启动及显式覆盖、`--demo` 不读 `.env`、启动无真实模型/行情请求、正常配置失败不降级、双服务令牌/会话/额度隔离，以及模式切换的空闲门、清理失败、目标失败、重复点击和响应不确定保护。构建检查不能代替浏览器验收；离线检查不能代替真实供应商连通和研究质量测试。

2026-10-25 本轮离线验收：`scripts/verify.py all`通过1,341项Python测试、468项前端测试、4个Agent场景、90次MVP固定场景及API演练，零跳过；TypeScript检查、生产构建、ASGI编译资源与干净wheel检查通过。补充覆盖了正常后端重启为离线服务时，既有页面切回正常或重连均不得静默接受人工模式。本轮未进行浏览器手动验收、真实模型或行情请求，未读取真实`.env`或重启现有服务。
