# 终端研究入口设计

日期：2026-10-20

后续更新：2026-10-22，已有有限指标修改、结果追问/知识、`/last`及明确股票/日期/指标增删，见第8–10节。

状态：代码与离线验证已有；本步骤未执行真实模型、真实行情或目录刷新

## 1. 本步交付与边界

`agent_cli.py`把已有自然入口、股票澄清会话和安全展示接到终端，让用户可以自己输入问题，而不必修改演示脚本。它是薄交互层：不另写模型理解、指标计算、身份续接或回答检查逻辑。

用户要求直接进行下一步，本步跳过理解题。此前只收到 `complete` 场景一次真实模型成功反馈；`partial`、`natural`、`clarification`的真实报告仍待补，不因有了交互入口就视为全部通过。真实模式是显式启用的初版能力，不是完整产品质量验收。

支持完整单股票日线问题、待选股票回复、明确指标替换、股票/ISO日期修改及单个指标增删，以及有限结果追问、定义和历史查看。自由复合修改、对话内切源/最新查询、开放知识问答、新闻选股、完整聊天记忆和交易操作未加入。

## 2. 四种启动行为

| 命令参数 | 行为 | 模型 / 行情联网 |
| --- | --- | --- |
| 不带参数 | 仅显示帮助，不读取目录或凭据 | 无 / 无 |
| `--demo` | 自动运行固定的“平安→平安银行”两轮脚本，不读交互输入 | 无 / 无 |
| `--provider deepseek --data synthetic` | 真实模型、用户交互、固定人工CSV与目录 | 可能 / 无 |
| `--provider deepseek --data tencent` | 真实模型、用户交互、已校验本地目录与腾讯历史日线 | 可能 / 按研究请求 |

没有默认真实模型或默认真实行情。`--provider deepseek`必须同时明确数据模式；人工模式不接受自选文件。`--directory`只允许在腾讯模式由启动者配置本地目录路径，不能由模型或用户问题选择；默认使用项目的 `data/security_directory_live.json`。

假模型只服务固定脚本，不假装能够理解任意中文。原参数式行情CLI、单轮接口和评估命令保持兼容。

## 3. 数据流与状态归属

```text
终端输入
  → 本地命令或长度检查
  → 重读并检查本地目录 / 固定夹具
  → run_natural_research_turn(..., session=同一个会话)
  → 原身份理解、工具、研究、事实和关系检查
  → 固定状态说明 + 已校验条件/候选 + display_answer
  → 下一次输入，或退出并清除待选状态
```

一次 `run_conversation()`只创建一个 `ResearchSession`；每次启动彼此隔离。终端持有这个对象，模型不管理会话ID，也不接收完整聊天历史。会话分开保存待选条件、有限修改基准和一份可信成功结果。“那RSI呢”可走有限结果追问，但只能读原先计算过且仍有效的结果，不能自行新增RSI实例或取数。

- `/help`：本地说明；`/last`：显式查看上次成功结果；`/reset`：清除待选、条件及结果，不补调用额度；`/exit`：退出并清理。
- 空行与未知斜杠命令不发送模型；中文“取消”和“新问题：完整问题”沿用原Agent处理。
- 待选时仅接受完整名称/代码，不按候选序号猜股票；附带指标修改的短答不会被静默截断。
- EOF、Ctrl+C和次数耗尽都会清除全部三类状态，不自动重试或恢复被中断任务。

## 4. 数据与时间边界

新增 `development_fixtures.py`，将评估入口原有的固定文件SHA256预检提取成共用函数，哈希与参考日不变。评估入口和终端入口共享这条规则，产品交互不依赖评估模块的内部函数。

人工模式仅有平安银行5条日线和4项目录身份，不能当作这些股票的真实行情。研究日期锚点固定为2026-09-26，并在横幅中明确；待选状态的15分钟有效期仍使用当前真实时钟，不因为人工锚点而永不过期。除Git的CRLF/LF差异外，夹具变更会阻断使用；这不是通用沙箱，也不消除运行时外部改文件的风险。

腾讯模式启动时先校验目录，再读取模型配置；每条送交Agent的输入前重读目录（包括映射为历史查看的`/last`），按当前上海日期检查是否为非夹具且不超过7天。文件损坏、过期或未来日期会停止会话，不自动刷新，也不继续使用旧内存副本。身份续接及结果复用还会由原会话重新核实相关范围和当前有效性。

目录刷新是单独的显式操作；本步骤没有发出刷新或行情请求。此入口只开放腾讯行情模式，不改变底层东方财富适配器和证券支持白名单。

## 5. 展示、调用与失败行为

终端只消费 `display_answer`和程序状态/候选/条件，不调用包含调试草稿的 `AgentTurnResult.to_dict()`。关系被拒绝时仍只展示事实及固定回退说明；原始模型文字、完整工具消息、凭据和底层异常不输出。

真实模式横幅说明本轮问题、已校验参数和紧凑指标证据会发给DeepSeek；密钥仅用于HTTP认证，不进入提示词。应用不主动写聊天、报告或目录文件，不代表系统终端滚动记录或外部日志一定不存在；不要把密钥作为研究问题输入。

| 范围 | 当前限制 |
| --- | --- |
| 单个自然初始问题 | 最多3次模型调用、1次分析，无自动重试 |
| 有效股票选择续接 | 最多2次模型调用、1次分析；无效短答不查询 |
| 明确指标修改 | 最多2次模型调用、1次新分析；本地无效修改不查询 |
| 自然结果追问 | 最多1次模型调用、0次行情；普通问题额度照常计入 |
| 有限指标定义 | 0次模型、0次行情；普通问题额度照常计入 |
| `/last`显式历史查看 | 0次模型、0次行情，不占普通问题额度，不延长结果寿命 |
| 一次启动 | 最多5条非空、非斜杠命令问题；超长和中文取消也计入输入次数 |
| 模型转发 | 独立包装器最多转发15次；调用前扣额度，失败不退还，超限停止 |
| 分析总数 | 由5条输入及原每轮1次执行器上限得到最多5次；不是另一个独立的分析额度存储 |

本地命令和空行不占问题次数，也不会刷新额度。以上是单进程启动的限制，不是跨启动或账户级配额。后续增量另接入每轮共享运行控制，见第11节；仍没有整轮硬中断或费用保证。

每轮显示状态、条件/默认口径、候选和安全回答；结束时显示已计入输入、转发模型调用和已确认分析次数。Ctrl+C若发生在尚未返回的研究轮中，明确提示该轮可能已经取数，不能把“尚未收到计数”记成零分析。

CLI退出码：正常退出/EOF/达到输入次数上限为0，即使个别研究失败；问题失败由逐轮状态体现。目录或调用上限阻断为1，模型配置或非法启动参数为2，Ctrl+C为130。不自动重试或改行情源。

## 6. 运行

在项目根目录：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.agent_cli --demo
```

在已配置DeepSeek的同一终端开启交互，先用人工数据：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.agent_cli --provider deepseek --data synthetic
```

看到“你>”后，可输入 `分析平安银行，2026-09-21 至 2026-09-25，只看SMA3和RSI2`，或 `看看平安最近一个月的走势，只看SMA3和RSI2`，收到候选后再回复 `平安银行`。这是真实模型交互，可能计费，不是固定评估报告。

只有自行确认要请求真实行情、且本地非夹具目录仍有效时，才改用：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.agent_cli --provider deepseek --data tencent
```

若目录失效，请另行显式刷新，不要修改快照时间戳伪装新鲜，也不要以开发夹具授权真实行情。

## 8. 后续增量：有限指标修改

2026-10-21增加[明确指标修改](indicator-edit-design.md)：取得可信事实后，15分钟内可输入“把SMA3改成5日，其他不变”。程序核对整句、唯一目标和当前身份/来源/日期；有效修改复用原流程，最多2次模型调用及1次分析，无效修改为0/0。终端问题及总模型转发额度不变。

## 9. 后续增量：保存结果、追问、知识与历史命令

同日增加[结果追问功能块](result-followup-design.md)。成功研究后可输入“这里的RSI为什么偏高”，模型只选回答类型与原文指标，程序显示保存字段、项目定义和重新核对的关系，不重新取数。多个同类实例须明确参数；新闻原因、预测、交易和未计算指标不靠模型补造。“RSI是什么”“解释一下MACD里的DIF和DEA”等有限完整定义可直接本地回答，无需先研究股票。

`/last`映射为“查看上次结果”，仍读当前本地目录并核查快照，但不计普通问题或模型额度。新查询失败后，旧成功结果只可显式历史查看；不充当本轮结果，也不恢复旧编辑基准。15分钟后失效，查看和追问不续期。重置、退出及中断现在清除待选、条件、结果三个槽，明确“新问题：”也全清。

## 10. 后续增量：明确研究条件修改

2026-10-22增加[条件修改模块](condition-update-design.md)。可信研究后的同一会话可输入“换成中国平安”“把日期改成2026-09-21至2026-09-24”“把截止日期改成2026-09-24”“添加ATR2”或“删除RSI2”。每条只改变一类条件，其他字段由程序继承；有效修改仍最多2次模型/1次新分析，歧义或无效修改0/0。普通输入额度照常计入，不增加5条/15次上限。

换股票查目录，有歧义时保留原日期/指标/来源，复用已有名称/代码续接。终端在请求就绪后显示已确认股票名称和代码，再显示日期及指标；不是修改报告标题。未计算的新指标必须经新研究计算，删除不能选错实例、删空或悄悄补默认值。仅支持明确日期，不在此入口自动刷新日期或切换数据源。

## 11. 后续增量：共享运行控制

2026-10-22补[整轮控制](turn-control-design.md)。终端每消息创建一个 `TurnControl`，贯穿理解、提议、分析、解释及会话发布：默认90秒协作截止、最多3次模型尝试/1次分析、24,000已观察token阈值。单请求timeout取原限制与剩余时间的较小值；结果显示实际耗时、观察累计及usage完整性。缺usage不伪装零费用。

同步请求不能被强制终止，超时后返回的内容不再触发后续步骤或保存为新会话结果。解释超时仍可显示此前已核验事实，明确取消不展示本轮分析。终端没有后台 `/cancel`；等待时Ctrl+C退出，继续保留130及原分析计数不确定说明。中文“取消”仍处理待选状态，不冒充正在运行请求的中止接口。

正常轮先暂存新候选/条件/结果，最后在取消锁内检查并发布；新研究开始时旧基准依然立即消费。新增43项运行控制测试，全量856项离线通过，原四场景评估和演示保持通过；没有新增真实请求。假钟五场景演示：
