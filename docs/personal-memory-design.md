# 本机个人记忆：自选股

更新：2026-11-12。记忆第 3 层的第一个模块，按线程 #589 的方案 #592、选择 #594、实施方案 #614 及批准 #615 实现。当前改动等待 Claude 审核；验证结果和提交状态以审核消息为准。本模块只做自选，持仓与偏好、按股票研判回顾、消息收件箱、重要提醒、后台定时和推送均未实现。

## 1. 开启和数据范围

代码默认关闭。正常公开数据模式下显式指定本机文件，例如：

```powershell
.\start.cmd --personal-memory-db data\personal_memory.sqlite3
```

`start.cmd` 本身不默认启用个人库。`--no-memory` 优先禁用聊天历史、轮次摘要和个人库，忽略两个记忆库参数；关闭不会删除已有文件。demo、synthetic 和网页 Dev Mode 不创建、不读取或返回真实个人库；前两种模式不支持显式开启个人库。未开启的界面提示使用 `--personal-memory-db`，不显示文件路径。

SQLite 是单个本机文件数据库。本模块建立独立个人库，不给原 `data/conversations.sqlite3` 加表，也不与证据快照库共用文件。格式为 `personal-memory-store-v1`，首版只存自选：本机用户 `local`、完整证券代码、加入时经目录核验的名称、创建和更新时间。名称是加入时的显示名，不声称自动跟随更名。

- 每用户最多 50 只，按完整代码去重。事务（一次全部成功或全部撤销的数据库操作）内检查重复和容量，再写入；满额重复加入仍返回已在自选，不改原时间和顺序。
- 新对话、重置、模型切换、服务重启和删除聊天都保留自选。“清空自选”与“清空聊天历史”是不同操作，清空前说明范围并确认。
- 文件未加密、不自动同步，不存账户、成本价、仓位比例、资金或凭据。关闭和删除当前记录都不能撤回用户另存的文件备份。
- 错误格式、陌生版本、损坏字段和容量异常拒绝读取，不覆盖或悄悄重建原库；同一文件不能配置为个人库与聊天/快照库。启动时显式配置失败则报错，运行中失败明确显示“读取失败/变更未确认”，不回显路径、SQL 或数据库正文，不阻断普通研究。写入后刷新失败或响应丢失时不能断言没有保存，需刷新核对，不自动重试。

## 2. 用户入口

侧栏“自选股 · 保存在本机”提供本地目录搜索、候选选择、加入、逐项移除、确认清空及手动刷新。公司研究结果卡对已核验证券提供加入/移除按钮；从按钮提交的旧代码也必须重新核验，不能从回答正文猜代码。页面按钮独立于研究会话，研究额度耗尽仍可管理自选；打开页面仅读本机清单，不自动请求行情或新闻。

聊天支持“把平安银行加入自选”“从自选移除平安银行”“查看自选”。每条管理消息仍占用一条会话消息，沿用会话忙碌、问题数上限与请求编号重放规则，但不调用模型、不取行情、不做分析。重复请求只重放当时结果，不重复写入；页面另外读取最新清单，不把旧响应当成当前状态。聊天“清空自选”仅引导到面板确认，不直接删除。

身份只来自服务端现有证券目录：唯一精确代码、名称或核验别名可直接解析；部分匹配即使只有一项也要用户确认。歧义候选保留管理动作，选择后发送“把 000001.SZ 加入自选”等完整命令，不发送可能被研究澄清误解的裸代码或“第一个”。新增要求目录新鲜、身份可用；移除按已保存代码/名称解析，目录过期、股票退市或更名后仍可删除。查看和清空不读目录。目录搜索不联网、不自动刷新。

## 3. 与研究分流的边界

确定性程序在意图模型之前识别明确管理动作。否定句不写入；多对象、多动作或“加入并研究”等混合管理请求只给本地说明，不部分写入或调用模型。以下研究问法仍走原研究流程，不被“加入自选”几个字截获：

- “分析自选股里的平安银行”：研究明确说出的平安银行，不自动加载整个清单。
- “平安银行值得加入自选吗”：询问研究判断，不是保存清单的命令。
- “什么是自选股”：沿用知识/问答分流，不写清单。

管理结果使用独立 `personal_memory` 公共字段。管理原话和结果不写聊天历史或轮次摘要，不进入回答模型、意图模型、Jev（新闻标题分类辅助模型）、标题采集或运行记录正文。运行记录只允许固定类型/状态码。管理操作保留原待澄清问题、研究主体、旧图和已保存结果，不把管理候选放进研究状态。

明确要求“记住我的成本价/仓位”等个人资料管理语句只在本机答复固定说明：本模块尚未实现持仓和偏好，后续选定范围也只记录是否持有、期限和风险，不记录成本/比例，不引导到不存在的表单。普通研究问题仍按原规则发送；用户主动在研究问题里输入个人数据时，不能承诺该原话不会送模型。没有个人背景授权开关和自动注入路径，将来增加这类功能须另行审核。

## 4. 本地接口与界面隔离

所有接口沿用本机同源、Host、请求体大小和固定错误保护，与历史浏览相同使用本机单用户语义，不增加账号认证。浏览器和模型不能指定文件路径。

| 接口 | 用途 |
| --- | --- |
| `GET /v1/personal/watchlist` | 读取启用状态及最多 50 条清单 |
| `POST /v1/personal/watchlist` | 仅接受一个完整 `instrument_id`；名称由服务端核验 |
| `DELETE /v1/personal/watchlist/{instrument_id}` | 移除指定代码，可重复执行 |
| `DELETE /v1/personal/watchlist` | 清空自选，可重复执行；网页先确认 |
| `GET /v1/personal/watchlist/search?q=...` | 查询已有本地目录，1–80 字符，最多 20 个候选，标明截断 |

清单结果版本为 `personal-memory-watchlist-v1`，包含 `enabled`、`limit:50` 和 `items`；关闭、已启用但为空、读取失败是三个不同状态。搜索返回有界候选和截断标志，写接口拒绝额外字段。前端严格核验版本、证券字段、时间、去重和上限，收到成功响应后才更新；不在浏览器持久存储中另存清单。

切到 Dev Mode 立即清除页面个人清单和搜索候选，返回正常模式重新读取。请求代次阻止旧模式或旧搜索的迟到响应覆盖新状态。跨标签页通过手动刷新或下次操作读取最新值，不做后台轮询，不承诺已显示静态内容能被远程擦除。

## 5. 实现和验收边界

`personal_memory.py` 管字段和公开版本，`personal_memory_store.py` 管独立库和事务，`personal_memory_commands.py` 只解析明确动作；`api_service.py` 处理本地管理并跳过聊天记忆保存；`api.py` 提供 `/v1/personal/` 接口；前端 `Watchlist.tsx`、`controller.ts` 和 `api.ts` 管理展示与状态。

规则基线登记 `personal-memory-watchlist-v1`，以 `intent-research-documents-v3` 为父版保留完整指纹。旧题库、规则历史和付费评估锁不改写；新版本只证明代码身份，不代表语言质量或真实模型验收通过。

离线验收使用临时库、固定目录、假时钟和禁止真实模型/HTTP 的替身，覆盖容量与并发、重启保留、坏库和同文件误配、目录过期仍可删、管理命令不进入历史/模型、原研究状态不变、研究反例与现有意图题库、禁用/开发隔离、界面确认和迟到响应。工程门禁为 `verify.py python`、`web`、`bundle`；本模块真实页面流程由 Claude 用临时库检查，不需要调用付费模型或行情。此处不预写测试通过数或页面验收结论。
