## 受限指标解读：结构化论断、证据核对与安全回退

日期：2026-10-20（America/Los_Angeles）

2026-10-24增量：本文关系验证器仍负责检查论断及依赖；自然入口可用 `research-response-v1` 在同次最终调用中附带三段模型正文。新正文只保证结构与引用约束，不声称语义被程序验证。原“完全不接收模型自由文字”规则现仅适用于旧关系协议与程序事实报告；新网页展示边界见[自然语言答复设计](answer-design.md#从指标报告到自然语言研究答复)。

### 1. 本步解决什么问题

此前 `safe_answer` 能安全展示程序事实，但模型解释仍只是调试草稿。仅检查“引用存在”也不够：模型可能引用真的SMA3，却把“高于”写成“低于”，或者把“高于”当成已经发生“上穿”。

本步不接收任意模型文字。模型从本轮工具结果中选择有限的指标关系，程序核对后，用固定中文模板呈现。模型负责选取要解释的关系，不负责指标计算、改写数字或生成预测。

```text
已确认请求 → 一次分析 → 当前完整事实 + 本轮短别名
                           ├─ safe_answer：独立事实摘要
                           └─ 模型提交JSON论断
                                  ↓
                    格式 / 请求 / 引用 / 依赖 / 关系核对
                           ├─ 全部通过：程序生成中文
                           └─ 任一失败：只展示事实摘要
```

这不是自由文本语义验证、行情真实性认证或收益预测能力；没有增加模型请求、行情请求或指标计算，没有自动修正、重试和换源。

### 2. 模型输出契约

```json
{
  "version": "indicator-explanation-v1",
  "request_id": "<本轮工具结果中的ID>",
  "instrument_id": "000001.SZ",
  "trade_date": "2026-09-25",
  "claims": [
    {"evidence_id": "<本轮关系事实的f编号>", "relation": "price_position", "value": "above"}
  ]
}
```

尖括号内容是说明，不是有效运行值。短编号必须来自本轮 `tables.relations`，不能硬编码，也不能用 `numeric_facts` 中的收盘价冒充关系。日期取实际最新交易日，不是请求截止日。

严格限制：全文不超过4000字符，1–8条不同引用；根对象及每条论断仅允许规定字段和字符串类型。拒绝额外文字、代码围栏、未知版本、重复JSON键、重复论断、数值/非有限数、缺字段和超限输入。不存在“先容忍格式错误再猜模型意思”的修复路径。

JSON契约说明位于第一次模型请求的system消息中；工具结果后不再插入system消息，保持已有消息配对协议。没有假定提供方支持某种新增严格输出API。

### 3. 程序检查什么

1. 先要求事实报告可用：结果必须匹配已确认请求的ID、股票、区间、来源及完整指标集合，仅允许等价重排。
2. 根对象的请求ID、股票和实际最新日须匹配；本轮别名映射须对应当前完整事实，不合并历史映射。
3. 引用必须指向真实、可用的 `RelationResult`，而非任意数字事实；关系名、值、参数、日期和关系事实必须一致。
4. 依赖须精确匹配关系类型的字段、顺序和日期；需要前值时，只能使用紧邻前一条记录，不能用更早值或当前值替代。
5. 检查依赖数值与相应行情/指标字段、单位、参数、可用状态及事实一致，再用已有原精度数值比较关系。**不重新取数，不重新计算SMA、RSI等指标。**
6. 所选论断全部通过才接受。任一错误会清空整段解读，保留独立事实报告；不会悄悄丢掉错误论断后声称整段通过。

请求ID用于关联，不是授权令牌。短别名如 `f12` 仅在当前映射中解释：若不同请求恰好都出现同一字面编号，程序无法判断模型心里想到的是哪个历史编号，只能验证它在当前请求中的含义。

本检查针对受信执行器返回的现有内部契约，不是任意Python对象的安全沙箱，也不独立重算或认证上游指标公式及行情真实性。

### 4. 支持的关系与措辞边界

| 范围 | 检查的关系 | 中文展示限制 |
| --- | --- | --- |
| SMA / EMA | 收盘价相对均线位置、均线数值变化、两点穿越 | 高于不等于上穿；不添加上涨概率 |
| MACD | DIF相对DEA位置/穿越、柱值变化 | 柱值增加或减少只指带符号数值，不笼统称动量增强/减弱 |
| RSI | 小于30、大于70或含边界的中间区间 | 精确30/70属于中间区间；阈值不是买卖信号 |
| BOLL | 相对三轨位置、等于边界、轨道重合 | 重合轨道单独处理，不漏掉相等情况 |
| ATR | 相对紧邻前记录的数值变化 | 仅波动尺度，不表示价格方向 |
| 量能 | 相对此前窗口均量倍率和1比较；当日量与此前均量比较 | 零分母倍率不可用，不妨碍有证据的成交量比较 |
| 均线对 | 左右命名均线位置及两点穿越 | 按实际执行请求的精确实例和顺序构造，不用子串猜测 |

所有比较使用原始精度；报告中的8位有效数字只作显示。极近阈值的值可能显示为30，却仍小于30，不能用显示文本反推关系。

模板中的指标名称、中文句子、限制及完整证据ID均由程序生成，不转发模型的自由文字。当前没有跨指标冲突总结、观察条件生成、新闻/基本面解释或历史状态证明。

### 5. 编排、状态与展示接口

`AgentTurnResult` 的输出职责分开：

| 字段 | 含义 |
| --- | --- |
| `safe_answer` | 独立程序事实报告；解释失败也可保留 |
| `explanation_validation` | `not_performed` / `accepted` / `rejected`，含固定检查范围、通过的论断、完整事实ID及程序中文 |
| `display_answer` | 默认展示文本：事实摘要＋通过检查的关系；失败则仅事实与固定回退说明 |
| `model_draft` | 原始模型输出，仅调试；不能默认展示或当生产脱敏日志 |
| `answer_validation` | 保持 `not_performed`，并以 `answer_validation_scope=free_text_semantics_not_performed` 明确不是任意自由文本校验 |

检查通过且全部请求字段可用时，整轮为 `completed/research_completed`；有缺项仍为 `limited/partial_research`。检查失败时为 `limited/explanation_rejected`；若同时存在缺项，主code仍为 `partial_research`，检查原因见独立字段及 `failure_code`。模型超时、拒绝、截断或再次提议工具，沿用 `limited/explanation_unavailable`，不尝试校验半段内容。

展示属性按当前请求、草稿和证据重新检查，不缓存一个可与后续替换数据混用的“已通过”结论。无研究结果时 `display_answer=None`，调用方展示原有澄清/失败消息。

预算不变：明确格式及股票选择续接最多2次模型/1次分析；自然语言初始请求最多3次模型/1次分析。通用对话、全轮token/时长预算和真实模型场景评估仍未完成。

### 公开回答与展示

2026-10-29 A4（方案 #199、批准 #200）：DeepSeek 无工具声明的结构化回答使用 4096 输出 tokens，上界配置允许到 8192；有工具声明的请求仍最多 1500。token 是模型计量文本长度的单位。无工具回答启用 JSON 对象模式，纯文本 CLI 仍用独立文本适配器。提示要求最多四条 drivers、每条一至两句，numbers 优先标注关键价位，负百分比显式写负号；数字容差、评级和价位公式不变。

供应商返回 `finish_reason=length` 时，记录 `answer_output_truncated`，不解析或恢复任何前缀；有预算时仅使用原有一次精简重写机会。两稿均截断时回到程序事实；第二稿截断时保留首稿已核验的内容。发生截断的公开 `quality` 增加 `output_truncation_version=answer-output-v1`、`output_truncations`、`initial_output_truncations`、`repair_output_truncations`；无截断的正常回答保持原有形状。诊断和 trace 始终记录带版本的计数（含零），评估从 trace 取得零计数，不以旧答案缺字段推断为零；诊断保留结束原因，普通 trace 不保存正文。

仅完整返回的草稿允许一次有界标点恢复：最多四处插入缺失的 `}`/`]` 或删除容器末尾逗号，包括内层右括号缺在外层结束符之前的情况。扫描识别字符串与转义，不补键、值、引号或词句；修复后仍严格拒绝重复键、NaN、多对象、不安全包装，并走完整结构和同股数字检查。`punctuation_structure_recoveries` 单独计数，也计入本地结构恢复；原有完整字段前缀恢复仅用于完整返回但结构受损的草稿，不能用于已知截断。

公司研究与参考研判统一返回 `product-research-answer-v3`。每股一组 `narratives`：`summary` 直接结论、`current` 带日期的当前情况、`drivers` 主要依据、`levels` 关键价位、`scenarios` 基准/变好/变坏条件、`stance` 操作倾向。评级 `decisions` 与原 ATR 条件计划独立保留，普通基本面回答不强加评级。

文字块是 `{text, evidence_ids}`；引用可省略，程序仍按本股实际发送给模型的资料核对数字。公开引用转换回完整证据 ID。价位输入只能选程序生成的 `price_levels` ID，不能让模型填入上下界；公开表格由程序填 `lower/upper/lower_label/upper_label`。计划端点也有独立引用，模型无法改公式。

前端用 React 文本节点显示，有限解析 `**粗体**`，列表与表格由组件构造。没有通用 HTML/Markdown 执行器，文本中的图片、链接和标签不会成为元素。来源链接仍由应用原有域名白名单控制。v3 的公开来源上限为480条，以容纳三股各5期财务与新增窗口事实；单条和其他结构限制继续核对。历史 v1/v2 仍保持240条来源上限，读取与展示继续支持；旧协议专项测试使用明确命名的 legacy 入口，当前业务统一走 v3 的测试。

`quality` 由程序生成：`complete/partial/fallback`、固定 `code`、最多20个原因位置、句子计数、修正次数、结构失败次数及下述数字词元计数。`narratives[].origin=application` 的价位表列名为“程序事实”；模型解释才叫“我的判断”。资料超时说明同步进入结构化显示。

整轮 `status=limited` 与回答 `quality.state=complete` 可以同时成立：前者表示请求的资料有缺项，后者表示已生成的内容通过本轮校验。此时回答顶部按 `coverage` 列出实际未取得的领域；可用、明确排除和未请求的领域不列为缺项。

### 新增证据口径

`research_price_context.py` 使用本轮已检查的同一份 `technical.bars`，不再获取行情：

| 事实 | 算法与缺失条件 |
| --- | --- |
| 最新收盘 | 最后已完成日线，不是盘中实时报价 |
| 近5/20/60日涨跌幅 | `(C_t/C_(t-N)-1)*100`，分别要求 N+1 条有效记录 |
| 20/60日高低点与日期 | 最近 N 条 high/low；并列取最近日期，样本不足不输出 |
| MA20/MA60 | 最近 N 条收盘算术平均，样本不足不补值 |

证据的 `calculation_basis` 保留版本、复权口径、样本数、日线截止、并列规则与依赖命名空间。`request|raw_daily_bar|日期|字段` 是归档中 `technical.bars` 的行/列引用，并非原指标 `facts` 的 ID；每个引用都能定位同请求的冻结原始行。高低点依赖完整窗口，收益依赖首尾收盘，均线依赖窗口收盘。

财务接口原本一次请求最多5个报告期，现在保留这次响应中合格的5期、每期5字段（上限25），不增加请求或翻页。原披露截止、更新日期和人民币口径检查继续生效。`financial_periods.py` 只对同公司、来源、币种及指标的累计数据差分：Q1直接采用，其他季度减本年上一期；同比另需去年同季所需的累计记录，分母为0则缺失。记录全部依赖和最晚披露日。依赖缺失或同一报告期有歧义修订时不推导，缺失不写0。

模型上下文按公司与领域分配额度，优先价格、计划和财务，最终再按现有模型消息预算裁剪；删掉的证据也从可用价位中删除，引用不得悬空。A2 为修正消息预留800字符；最多4项、合计700字符的反馈，原句每项最多80字，按评级、结构、其他问题排序并去重，包含证券、字段路径、失败条件及至多两个候选值。超限时先省候选细节。预算仍不足时保留完整计划证据，优先保留当前日线价格资料，再从末尾裁剪其他证据；三股场景同时受原有调用与超时控制。

### 校验与一次修正

`answer_validation.py` 按句检查，不能证明任意自然语言推理属实。硬拒绝限于收益/涨跌保证、自编概率或胜率、HTML/链接/指令注入、声称执行、跨股错配。定位到一句就删该句，硬风险文本不反馈给模型。普通数字、日期、期限、引用和结构问题为软错误，最多修正一次。

数字由模型声明来源，程序使用 Decimal（精确十进制）核对本股、本轮实际供应的来源、值与单位。普通数字的指标、窗口、日期关联及财务报告期由模型负责选择，程序不再用邻近关键词推断它们。**核对通过只能说明数值与所选来源相容，不能证明文字中的指标、时期或解释正确**；未标注数字的语义保障更弱。提示仍要求区分累计/单季、日线/周线及标题/正式财报，人工复核要检查这些含义。

价格容差仍为 `max(0.01元,0.5%)`，微小价格另受2%上限约束；粗舍入需落在显示精度的半单位内、至少2位有效数字且相对误差不超过2%。金额先换算人民币元，再按显示末位半单位舍入，无金额百分比容差。百分比和百分点、价格和金额分别有类型；`元/股`只匹配价格。无显式符号的“下降5%”可对应-5%，显式正负号与方向冲突时拒绝，“涨跌幅”保持中性。区间两端均核对，并检查顺序，没有统一放宽容差。

有效日期须在请求历史范围或本股供应记录的日期/报告期中，但不再推断它属于旁边哪个数字。`1-9月`等期间、20日均线的参数、止盈1的序号和合法证券代码不作为裸数值。`一个月/未来1个月/下个月` 期限归一及评级期限检查保留，明确两个月不改成一个月。当前不支持的中文金额数字、外币换算等表述软删除，可在修正时改成可核对形式。

#### A3 数字标注协议

每个文字块可附可选 `numbers` 数组，包括 summary、current、drivers、levels、scenarios、stance、评级理由与失效条件；标题中的数字也检查，但不另设标题标注字段。例子中的编号须替换为本轮实际编号：

```json
{"text":"若收盘跌破25.99元，应重新评估。","numbers":[{"text":"25.99元","ref":"L5","field":"reference_stop"}]}
```

2026-10-30用户授权#243，方案#246经#247批准，有意覆盖#227/#234的普通坏标注不可降级要求。`text`须在所属块逐字出现，同片段多次出现或同跨度重复标注可逐处核对，全部标注合法且匹配才通过；不同跨度重叠和结构错仍拒绝。无数据数字的标注忽略，普通不存在field可忽略，普通无效ref可在实际送模同股证据中按原容差重新匹配；不猜组合编号。已解析跨股、值矛盾、派生结构错和计划价位不降级。能够定位时只影响相应句子，定位不到影响整个块。原因码继续区分`answer_binding_invalid`与`answer_binding_value_mismatch`。

| 字段或编号 | 含义与限制 |
| --- | --- |
| `ref=E…` | 实际供应的一条证据，公开引用还原完整证据 ID |
| `ref=L…` | 实际供应的一条价位，展开为背后的 E 和确定字段 |
| `field`，可省略 | 仅选择该记录公开的字段，如 `latest_close`、`close_20d_ago`、`revenue_yoy`、`reference_stop`、`target_1`；不接受任意对象路径或自报值 |
| `derive=distance` | 唯一开放的派生计算，必须配恰好两个有序 `refs` |

同股所有实际供应证据均参与普通未标注数字兜底，不受段落`evidence_ids`缩小；裁掉的普通数字、其他股票和其他轮资料不可用。仅RSI关系允许本轮已验证最新本地值，保留参数、周期和原事实身份，不造悬空引用。精确值优先，否则多个不同值同时落入容差就拒绝；相同值、类型的来源可合并。明确周期严格，未明确周期先日后周，同一指标的读数及关系不可混周期。新闻/公告默认只用实际供应标题；显式启用[正文 A](research-data-design.md#新闻与公告正文-a来源预算和回答片段)后，也可用实际供应的有界正文片段，均不能冒充完整文档理解或正式财务字段。快照保留但未供应的候选片段不参与该次回答核对。

距离示例：

```json
{"text":"止损11.20元距收盘11.54元约2.9%。","numbers":[{"text":"11.20元","ref":"L2","field":"reference_stop"},{"text":"11.54元","ref":"E8"},{"text":"约2.9%","derive":"distance","refs":["E8","L2"]}]}
```

`refs[0]`是基准及分母，`refs[1]`是比较价，计算 `abs(second-first)/abs(first)*100%`。两端须为同股、人民币每股单位、实际供应且各自唯一的正价格；多价计划应用 L 选择单价。分母为零、端点歧义、跨股及其他派生类型均拒绝；原稿未标注的距离不猜计算关系。

明确“止损、止盈1、止盈2、入场参考、退出观察位、上下方观察位”后紧邻数字仍须对应计划字段，标成另一字段也不能绕过。计划数值取已核对的结构化 `values`，不再从“止盈112.05元”等展示串反推。levels 端点应选 L；误写 E 时只在其能唯一映射到已有同股价位时兼容，不造新价位。上下文裁剪同步移除依赖该证据的价位。

`quality.numeric_validation_version=source-bindings-v2`；`numeric_tokens`按实际数字词元计数，`bound_numbers`不因重复标注数量重复增加。另列`bound_matched/bound_rejected`、`unbound_matched/unbound_rejected/unbound_ambiguous`、标注忽略/无效引用回退成功失败、本地RSI等计数。同一句可有多个词元，计数不当删句数；格式/安全提前拒绝可能未进入词元核对。固定版本和有界计数可入普通trace，原文只进显式本地诊断。

正文和评级分别接收。评级仍核对身份、期限、评级/方向、理由及计划用途。坏数字句不抹掉有效评级，坏评级不抹掉有效正文。首版有效字段与列表位置保留，修正只补缺失位置；部分通过的文字块可追加修正后的干净句子。最终合并后再核对结论与评级方向。整体 JSON 无法解析也允许一次结构修正；取消、调用预算和超时仍直接服从控制器。

仅普通数字错误允许独立分句保留，其他错误仍按原范围拒绝。条件、否定、因果、对比依赖或仅剩连接词/数字时整句删除。保留文本再核对一次，不增加模型调用，不重复计数字；数字引用只汇总实际保留片段来源。

计数定义升级`sentence_count_version=sentence-counts-v2`：generated_sentences累计两稿实际检查句子（含标题），deleted_sentences只计整句消失，部分保留另列partially_retained_sentences，并同时记录generated/retained/deleted_clauses和分句删除率。去重计数仍单列。retained_sentences是最终模型句子，修正合并后不重复，故三个句数不要求相加相等。结构不解析由structure_failures计数。**v2整句率不能直接比较历史v1的17.5%、26.9%。**

只要有本轮已验证、同股且日期有效的结构化价格，v3要求模型形成评级；严格单指标研究降为低信心并说明范围，无ATR时plan_id为null、参考计划不可用。仅无有效价格可insufficient_evidence；有价格而模型拒绝评级走原一次修正，仍失败标decision_rating_required，不由程序编造“持有”。前端评级与计划注明仅供参考。完整边界、历史回放和117轮覆盖层见[技术核对说明](technical-analysis-design.md#技术回答数字核对与日期参数边界)。历史v1/v2协议入口的读取与专项检查保留，当前自然研究业务统一走v3。

### 问题与数据流

旧模型主要提取参数、提出工具调用、选择指标关系；研究阶段没有收到原问题。最终文字由程序拼接事实、关系模板和四维综合，展示投影不可用时又回退整份报告。因此“预测下一步方向”得到的是读数清单。

新流程：

```text
原问题 → 模型理解 → 程序核对股票、日期、指标与来源
  → 原问题 + 已确认参数 → 模型工具提议 → 严格参数比对
  → 一次行情读取与确定性计算
      ├─ 计算字段不可用：简短说明不能判断，不发最终模型请求
      └─ 可用：模型回答问题、给条件性方向与观察条件
                  → 关系、请求绑定、段落引用与格式检查
                  → 网页正文（含依据与研判）+ 默认显示的互动日线图
```

人工/未经验证的开发 CSV 不能支持真实股票判断，即使短周期指标能计算。5条人工日线配默认指标时，主回复说明真实数据和历史长度两项缺口。人工模式固定截止日来自 `development_fixtures.REFERENCE_DATE`，不代表最新行情。

### 答复契约

自然入口最终输出 `research-response-v1`，包含 `request_id`、`instrument_id`、实际最新 `trade_date`、1–8项 `claims` 及三项 `paragraphs`。

- 每项claim继续使用 `evidence_id`、`relation`、`value`，从本轮可用关系表原样复制。
- 三段固定角色为 `answer`、`outlook`、`watch_for`，每段包含 `text` 与 `evidence_ids`，先回答问题，再给有前提的方向和成立/失效条件。
- 每段1–600字符，总JSON不超过8,000字符；提示模型总计约200–350汉字。引用非空、无重复，且来自已经核对的所选关系。
- 额外字段、重复JSON键、代码围栏、错股票/日期/请求、无效引用、反向关系、不完整对象均拒绝，不自动修复或重试。
- 本版精确数字留在程序数据视图；正文不接收额外数字，只允许请求中指标的标准标签，如 `SMA(20)`。数字规则是格式约束，不能证明中文数量或推论正确。
- 明确格式入口和旧离线关系模型继续支持 `indicator-explanation-v1`，旧JSON不被冒充成自然语言答复。

### 检查范围与取舍

复用关系验证器，检查当前请求、完整事实、依赖、单位、相邻日期及原精度比较，而不是只看引用ID是否存在。段落引用转换为完整事实ID；换掉请求或结果后会重新核验。任一新协议检查失败，拒绝整段模型正文。

**引用正确不等于段落正确。** 模型仍可能错误解释事实、夸大信息、提出没有依据的倾向。当前没有通用自由文本语义验证，也没有验证预测能力。正文标为“模型解读”，范围是 `request_and_relation_claims_checked_prose_semantics_not_verified`；`answer_validation` 仍为 `not_performed`。

允许模型说“当前偏强，但只有守住某参考位置才可能延续”，不允许把研究意见当作保证、胜率、收益承诺、目标价或已执行交易。没有新闻/基本面工具时不能假装已经查询。真实语言质量和相关性需要独立人工/模型评估，不能由契约测试推断。

### 公共接口与预算

API新增 `conversation`：来源 `model/application`、请求绑定、三段以内正文及引用记录。数据不足、错误、人工模式、停止和模型不可用时返回简短的应用答复。

旧 `answer` / `display_answer` 继续保留程序报告，供诊断与旧客户端使用；`report.fields` 保留原精度和缺失状态。前端优先检查和显示 `conversation`，React文本节点不执行HTML。坏答复显示简短降级说明，不再回退成整面报告或重新请求模型。当前附加区仅直接显示互动日线图；正文内依据仍可展开，其他附件入口移除。

知识和有限保存结果追问维持旧契约；没有实现任意长对话、自由知识问答或新闻查询。终端和明确格式工具仍保留原报告/关系输出。

没有新增模型请求：自然初始请求最多3次模型/1次分析，股票澄清续接最多2次模型；计算字段全不可用时不发最终解读。取消、超时、额度和迟到输出继续遵守 `TurnControl`。

网页启动配置把单次输出上限设为1,500 tokens，以容纳正文与引用；通用 `DeepSeekConfig` 的512默认值及整轮24,000已观察tokens阈值不变。上限不是实际花费、硬计费限制或质量保证。

## 自然单股研究：历史数据与未来展望分开

日期：2026-10-25。本文记录本模块的范围与技术契约；离线测试不等于真实模型的语言质量或预测效果验收。

### 1. 要解决的问题

“分析一下中际旭创”已经包含明确的研究动作和股票名称。用户没有写指标或日期，不代表意图不明确；目录唯一匹配时，应采用已有默认条件开始研究，而不是要求用户先学会参数格式。

“预测一下中际旭创下个月的走势”问的是未来展望，不是请求未来日线。过去将两者都塞进日期区间，容易把正常研究误判成非法未来行情查询。

本模块让模型理解研究目标，程序核实身份和取数范围，再沿用已有只读工具循环与自然语言回答。没有新增预测模型、股票模式训练或产品多Agent辩论。

### 2. 两类范围，分别保存

| 概念 | 表达的问题 | 本轮约束 |
| --- | --- | --- |
| 历史数据窗口 `start_date / as_of_date` | 用哪段已发生的行情作为依据？ | 沿用历史请求校验，不放入未来日期 |
| 研究目标 `objective.kind` | 分析当前情况，还是讨论后续情景？ | `analysis` 或 `outlook` |
| 展望期限 `objective.horizon` | 用户关心多久之后？ | 从原文核验并规范化为“下周”“下个月”“未来30天”等受限表达；未指定时为 `null` |

`ResearchConditions` 中的目标示例：

```json
{"kind":"analysis","horizon":null}
```

```json
{"kind":"outlook","horizon":"下个月"}
```

`objective` 不属于行情工具参数，也不赋予额外工具权限。工作流提示词分别传递已确认的历史请求和研究目标；模型要围绕目标作答，但取数仍必须精确匹配已确认请求。

期限只做受限表达规范化，例如“下月”保存为“下个月”、“接下来30日”保存为“未来30天”，不换算成未来实际日期。“下个月”“未来30天”“未来30个交易日”不等价；当前不支持交易日期限，不能用猜测的未来交易日历替代，更不能把未来日期冒充已取得的行情。

量化期限按天/周/月/年的正整数有限表达校验；“未来半年”可规范化为“未来6个月”。以366个自然日的折算量作容量边界（月按30、年按365；这不是未来日期计算）。超界、冲突、交易日、季度或长期等未支持表达需要澄清，不能截掉不支持的后半句。短线/中线是展望标签，不承诺固定天数。

完整时间条件也必须保留：“下下周”不等于“下周”，“下周五”不等于整周，“下个月底”及“未来30天后”不能被截成已有期限。当前不支持这些修饰时明确请求澄清；即使模型只抽出合法子串，原问题中的本地时间边界检查仍会阻止执行。

### 3. 自然输入和默认条件

- “分析一下中际旭创”“看看平安银行”：按当前单股技术研究处理；名称经目录核实，不要求用户先给代码。
- “预测中际旭创下个月的走势”“看看下周可能怎么走”：明确为条件性展望，历史窗口与展望期限独立。
- 未指定历史日期：沿用上海前一自然日为截止日、含首尾365个自然日的默认窗口。实际最新交易日由数据源返回，不能声称前一天必定开市。
- 未指定指标：沿用默认八项配置：SMA(20)、SMA(60)、EMA(20)、MACD(12,26,9)、RSI(14)、BOLL(20,2)、ATR(14)、量能(20)。
- 用户显式给出的合法历史条件优先；未来历史取数、错误参数或不支持的条件不应被默认值悄悄覆盖。
- 名称确有多义、目录无有效匹配或缺少可安全继承的身份时才澄清；模型不能自己猜证券代码。

“分析”目前只覆盖已接通的历史日线与技术指标。模型不能把一个宽泛动词解释成已经读取新闻、财报、公告或完整基本面；用户明确要求未接通的数据时，应如实说明范围，而不是假装查询过。

### 4. “那下个月呢”如何续接

这类问题没有重复股票名称，可以使用会话中经过确认的条件，但不能仅凭聊天文本或模型记忆猜测。

```text
已确认单股研究
  → 用户输入“那下个月呢”
  → 检查15分钟条件有效期、当前目录、同一身份与来源
  → 保留原历史日期和指标，更新独立objective
  → 创建新的研究请求，重新执行行情与指标研究
  → 以新结果回答下个月的条件性情景
```

继承的是**已核实的研究条件**，不是把保存结果改写成新行情。新回合会取得新的研究ID和证据；即使历史日期未变、供应商返回了相同的日线，也不声称发现了新行情或获得实时价格。

条件超过15分钟、时钟异常、目录失效、身份或来源不再一致时，不能继续隐式继承；需要用户重新明确研究对象。重置、结束会话和明确新问题也不能借旧目标偷偷恢复身份。

这与“查看上次结果”“解释刚才的RSI”不同：后两者在既有受限路径中读取保存快照，不重新取数；“那下个月呢”是新的研究目标，不冒用旧快照作当前分析。若用户要更新历史截止日，应走明确的刷新/日期修改路径，而不是把改变展望期限当成刷新命令。

### 5. 回答与界面

沿用现有 `conversation-answer-v1`，不新增必须由前端理解的展望协议：

1. `answer`：直接回答当前判断，说明关键依据和冲突。
2. `outlook`：围绕用户的期限描述有前提的可能方向或情景。
3. `watch_for`：说明哪些表现会支持或使判断失效。

回答不保证涨跌，不编造未来价格、收益率或概率；现有数字正文和引用检查仍适用。精确指标与价格保留在报告数据中，正文依据和图表浮层可查看相应读数。引用核验只能证明请求绑定与被引用的指标关系，不证明文字推理或预测准确率。

前端继续正文优先；2026-10-30按用户要求将附加区精简为默认显示的互动日线图，正文段落依据、研判卡与价位计划保留，其他附加表格和完整报告入口移除，见[图表设计](web-and-api-design.md#k-线与指标可视化)。历史日期前明确标“历史数据”，避免误认成预测区间。正常首页提供无需日期/指标的研究和“下个月”展望示例；点击只填草稿，明确发送后才研究。离线首页保留固定人工日期，不把其少量样例描述成真实市场能力。回答后不新增固定快捷问题或内部诊断面板。

没有取得行情、记录不足或最终答复未通过检查时，仍提供简短的实际原因，不让模型补写缺失行情，不自动换源，也不把指标清单当成答案。

### 6. 没有改变的边界

- 当前是单股票历史日线研究，不支持多股票比较、选股、新闻/财报研究、实时行情或任意联网。
- 行情来源由服务配置固定，模型和用户输入都不能借展望切换来源。
- 继续使用已有工具白名单、次数/时间/上下文预算、取消和幂等机制；“新目标”不会扩大额度。
- 图表与引用的 `trade_date` 仍为历史证据日期；前端不能为支持“下个月”而放松日期、股票或快照绑定。
- 没有券商账户、下单、撤单或资金管理接口。情景解读不是自动交易授权。
- 继承条件不等于长期记忆，历史过滤也不等于严格point-in-time数据。

## 安全回答展示：程序事实摘要与模型草稿分离

日期：2026-10-20（America/Los_Angeles）

后续同日更新：事实报告仍独立保持本文职责；另已实现[受限指标解读](answer-design.md#受限指标解读结构化论断证据核对与安全回退)，模型提交有界JSON，程序核对关系后生成中文。默认可展示 `display_answer`（事实＋通过的关系），只需事实则继续用 `safe_answer.text`。下文539项是报告阶段历史记录；新增54项解读测试后当前全量593项通过，不等于任意自由文本已获校验。

### 1. 解决的问题与本步范围

此前研究事实与 `model_draft` 已分开，但调用方仍需自行整理事实。模型即使说错股票、编出价格或保证上涨，也只被标记为未校验，没有独立的默认展示内容。

本步增加程序生成的 `safe_answer`：只使用本轮请求和确定性研究结果，展示价格、七类指标最新字段、缺项、来源、日期和限制；失败时提供无数值的固定说明。它不读取模型草稿，也不再联网、调用模型或计算一次指标。

**这不是自由文本回答校验。** 不解析模型语义，不将已存在的引用视为结论正确，不展示模型生成的走势判断，也未实现受限修正。`answer_validation=not_performed` 仍然成立。确定性关系的中文解读、结构化模型论断检查、知识回答及完整产品入口另行开发。

### 2. 文件与数据流

| 文件 | 职责 |
| --- | --- |
| [research_report.py](../src/trading_companion/research_report.py) | 纯函数投影、请求/证据一致性检查、字段状态和固定中文摘要 |
| [agent.py](../src/trading_companion/agent.py) | 通过 `safe_answer` 属性和JSON字段暴露报告；原状态及调用次数不变 |
| [research_tool.py](../src/trading_companion/research_tool.py) | 可选可信 `request_id`，让编排、分析及证据使用同一标识 |
| `report_demo.py`（已删除） | 只打印离线事实摘要，不打印草稿的命令入口 |
| [test_research_report.py](../tests/test_research_report.py) | 报告边界、请求ID、失败回退、自然会话和运行入口测试 |

```text
已确认请求 → 受控执行器 → 本轮结构化研究结果
                               ├─ 模型解释 → model_draft（仅调试，未校验）
                               └─ 程序投影 → safe_answer（面向用户的事实摘要）
```

`build_research_report(result, expected_request=...)` 不接收模型文本。`AgentTurnResult.safe_answer` 按当前结果生成新报告；没有研究结果时为 `None`，由原来的消息说明澄清或执行前失败。即使模型解释失败，已保留的事实仍可生成报告。

### 3. 请求ID为什么需要衔接

原来解析条件与执行器创建分析请求时各生成一个ID，参数相同却不是同一个请求对象。若直接按ID严格绑定，正常执行也会被报告拒绝。

现在编排层将已确认请求的ID作为 `ResearchToolExecutor(request_id=...)` 的可信配置传入。执行器独立使用时不传该参数，仍自行生成ID；格式在执行前验证。模型工具参数仍禁止 `request_id`，不能借此挑选旧证据。

报告同时核对请求ID、股票、起止日期、来源及全部指标实例。仅允许已有契约认可的指标重排，输出仍按已确认顺序展示。ID用于关联，不是用户身份、授权令牌或幂等键。

### 4. 报告检查什么

- 结果必须属于本轮请求；来源、真实性标记与复权口径必须符合当前模式。
- 行情属于同一股票和区间，日期严格递增；最新字段与最新日线对齐。
- 每个请求指标必须存在，参数、算法版本和预期字段集合匹配；不能少报或重复实例。
- 可用数值必须有限且不是布尔值，有当前请求、股票、日期、字段、参数、单位和值一致的事实。最新收盘价及成交量也必须有对应证据。
- 缺失或重复事实ID、过往日期的替代值、错股票、旧请求，以及数值/单位不一致都会阻断整个数值报告，不展示混杂的部分。
- 不可用字段必须保持 `None` 和无引用，不能填零。历史不足显示缺少记录数；零均量倍率未定义与数值计算错误分别展示。

这是对已有服务结果的展示边界检查，不重新运行指标公式、不证明供应商数据真实，也不是接收任意Python对象的通用安全沙箱。

### 5. 展示与失败行为

报告的 `status` 为 `complete`、`limited`、`unavailable` 或 `blocked`，与Agent整轮状态不同。模型解释超时可能让Agent为 `limited`，但全部事实字段可用时，报告仍可为 `complete`；这不意味着模型解释通过检查。

- 人工CSV在首行标明“人工样例 / 非真实行情”；未验证CSV另行标注，不能冒充在线研究。
- 在线数据只称供应商历史日线，不称实时、经独立认证或完整市场覆盖。
- 显示请求区间、实际最新交易日及采集时间，三者不混同。未知采集时间不补造时间。
- 数值文本使用8位有效数字作显示；结构化字段保持原精度，不根据显示舍入后的值推导比较关系。
- 保留非严格point-in-time、未知历史风险状态、复权、量额精度、初始化及数据截止缺口等适用提醒。未知警告、异常文本和供应商自由文本不直接插入报告。
- 无数据不推断停牌、退市或证券不存在；源失败/无效数据不展示数值、不自动换源或重试。

报告导出包含 `origin=application`、`validation_scope=deterministic_report_only_not_model_prose`、逐字段原值和完整事实ID。可在同轮 `research_result.facts` 中追溯，不使用跨请求的短别名。

兼容调试的JSON仍包含 `model_draft`，并增加 `model_draft_policy=debug_only_unchecked_not_for_default_display`。调用方应默认展示 `safe_answer.text`，不能把整个调试JSON当作已经净化的产品输出。本步没有删除草稿，也没有保证任意客户端一定遵守该策略；专用演示只打印事实摘要。

## 跨指标现状综合解读

### 1. 解决的问题与边界

事实报告回答“数值是多少”，单项关系回答“两个数谁更大”。本模块进一步按趋势、动量、波动和量能整理这些关系，明确已知、分歧与缺项。它不预测未来价格，不给收益概率、目标价、止盈止损或交易指令。

核心文件：[research_synthesis.py](../src/trading_companion/research_synthesis.py)。入口：

```python
build_research_synthesis(result, *, expected_request) -> ResearchSynthesis
```

输入必须是同一请求的 `MultiIndicatorResult` 和已经确认的 `MultiIndicatorRequest`。保存的研究可直接用保存的 `result/request` 重建摘要，不取新行情、不调用模型、不延长历史结果有效期；历史查看仍需由会话入口标明保存时间与“不是最新行情”。

### 2. 数据流

```text
确认请求 + 已有计算结果
  -> 既有 build_research_report 请求/最新证据检查
  -> 检查本模块实际使用的最新、紧邻前一条数值及 fact 依赖
  -> 四维度有限关系
  -> 趋势/动量参考相容性 + 条件化观察 + 限制
```

不读取 `result.relations` 的结论标签，也不采用模型文本。即使某个旧标签被篡改为“高于”，本模块仍直接比较已核对的数值。BOLL 轨道宽度只是已算上下轨的差，ATR 变化只是两条已有记录的比较；没有重新计算任何指标或补历史。

#### 证据检查范围

每个实际使用的数值需要匹配完整股票代码、请求编号、指标参数、算法版本、字段、单位、业务日期、所需/已有记录数、可用状态及对应 `Fact`。依赖只允许实际最新日和紧邻前一条记录。公开引用使用程序生成的规范 fact ID，不能塞入任意文本。

这验证的是请求绑定和数值依赖契约，不是重新证明指标计算、数据供应商真实性或全部历史数值。同步篡改数值及其完整证据并非本模块能全面识别的情形；不承诺密码学防篡改或投资质量。

### 3. 明确且有限的规则

| 维度 | 允许描述 | 不允许推断 |
| --- | --- | --- |
| 趋势参考 | 收盘价相对各 SMA/EMA 的位置、均线相对紧邻前一条记录的变化 | 均线就是固定支撑、未来趋势或买卖信号 |
| 动量参考 | MACD 的 DIF/DEA 位置、柱值变化；RSI 相对50和30/70参考区间 | 柱值增加就会上涨、RSI超过阈值就会反转 |
| 波动尺度 | BOLL 上下轨重合与否、轨道宽度变化、ATR尺度及变化 | 波动扩大意味着上涨或下跌 |
| 量能参考 | 量比相对1；严格此前均量为零时量比未定义 | 放量独立确认上涨、零基线等于0倍或无限倍 |

RSI 的50是本项目显式选择的参考中线，不是交易胜率。RSI=30/70属于含边界的30至70区间；RSI=50为中性边界。零MACD、零ATR、零当日成交量不会因为数值为0而被当作缺失。

同族多个参数逐实例展示，使用关系的集合而非多数计票：多个短均线不能“投票压过”一条相反的长均线。等于参考值是中性，不自动算成与上侧/下侧相反。

跨维度只比较均线价格位置和 MACD/RSI 的参考位置；波动与量能不参加价格方向表决。相同上侧/下侧只表述“本次参考关系相容”，不称为走势确认。缺少 MACD 或 RSI、缺历史或其他必要数值时，相应完整性保持受限，不把未知当作支持。

### 4. 返回契约与失败隔离

`ResearchSynthesis` 是不可变 dataclass，提供 `status/code/text` 与 `.to_dict()`。DTO版本为 `research-synthesis-v1`，来源固定 `application`，验证范围固定：

```text
request_local_numeric_reference_comparisons_not_predictions
```

主要结构：

- `dimensions`：固定四维度，每项含状态、有限状态描述、观测及缺项。
- `observations[].dependencies`：支持该有限结论的原数值 fact ID，不伪造综合“投资事实”。
- `cross_dimension`：相容、冲突、不完整或中性边界，并列出实际使用的依赖。
- `conditions`：若后续参考关系改变，应如何用新记录重新核对；不是预测或自动触发器。
- `limitations/evidence_ids`：保留复权、初始化、缺值、实际最新日期及非PIT限制。

成功状态为 `complete/limited`，只表达本摘要的字段完整性，不表示预测可靠性。冲突也可以是证据完整的结果。错误分为：

| 状态/代码 | 含义 |
| --- | --- |
| `blocked / synthesis_evidence_mismatch` | 请求、数据结构或实际使用的数值证据不一致；不展示部分结论 |
| `unavailable / synthesis_data_unavailable` | 无有效行情，不推断缺失原因 |
| `unavailable / synthesis_payload_limit` | 整份UTF-8 JSON超128KiB，不截断展示 |

异常不输出原始异常、源路径或模型草稿。综合解读不可用时，调用方可以保留已经独立通过检查的事实报告，不应把事实报告也宣称为模型验证结果。

### 数据和公式

`trade_plan.py`复用原历史风险情景的同请求日线、最新收盘、ATR、单位和依赖检查。原 `risk-scenario-v1` 算法与默认两倍目标保持不变，新方法版本为 `atr_reference_plan_v1`：

- E 为最新有效历史收盘价，A 为同一天有效 ATR，默认止损距离1.5A。
- S 为 E−1.5A 按0.01元研究网格向上取整；R=E−S。
- T1 为 E+1.5R 向下取整到分；T2 为 E+2.5R 向下取整到分。
- 实际盈亏比分别为 (T1−E)/R、(T2−E)/R，向下保留六位小数。

网页表格仅对实际盈亏比格式化：四舍五入到至多两位小数并去除末尾零，例如 `2.000000` 显示为“2 倍”，`3.500000` 显示为“3.5 倍”；原数据、计算和模型证据的精度保持不变。

使用精确十进制计算，跨 JSON 边界保留字符串。要求0<S<E<T1<T2；缺失最新 ATR、零波动、无效数值、股票/日期/单位不符或舍入后重合均不可用。不改用固定百分比、短周期、旧数据或另一股票填补。支撑压力仍为观察候选，不混入价格公式。

`trade-plan-v1` 的展示精度约定：`values.atr` 在全部计算完成后按 `ROUND_HALF_UP` 四舍五入为固定四位小数；公开计划、`plan_display` 模型计划证据及网页均使用这一展示值。内部止损、目标和盈亏比继续使用未截短的原始 ATR 与收盘价，原数值事实也不改写。前端通用十进制校验允许最多18位整数、12位小数，因此固定四位 ATR 可直接解析。收盘/入场参考补齐两位小数（10.4 显示为10.40）；若来源本身有分以下精度，则保留原值，避免展示舍入改变 E 的含义。

| 用途 | 对应评级及方向 | 展示 |
| --- | --- | --- |
| conditional_entry | 买入/增持，偏多 | 入场、止损、两档止盈、实际盈亏比 |
| wait | 持有，偏多/震荡 | 上下观察价位，触及后重新评估 |
| holding_exit | 减持/卖出，震荡/偏空 | 假如已持有的收盘参考和退出观察位；空仓观望 |

不推断持仓、成本或账户盈亏，不生成做空计划。买入计划后续收盘≤S 时失效并重评；退出/等待触发位只用于重评。所有价位是按历史波动构造的条件参考，不是预测目标，不保证成交、止损或收益；未计费用、滑点、跳空和交易限制。

### 回答契约与检查

决策回答为 `product-research-answer-v2`，普通回答保留v1。原段落与证据字段外，新增逐股票的 `decisions` 及应用生成的 `trade_plans`。模型仅选择 `plan_id`，不能创建计划或改变参数。计划编号绑定请求、证券、方法和用途；引用还需属于最终发给模型的同轮上下文。

每个研判包含证券、状态、评级、方向、期限、把握、2～4条带引用的理由、带引用的失效说明及计划编号。期限照抄应用值；评级和方向需满足上表。把握仅高/中/低，展示“模型自评，未经历史校准”。公开不可用状态有固定原因，不用默认持有/震荡替代缺失意见。模型可以指出实际缺失的领域，不能把未请求的领域自动当作必需资料。

正文、理由与失效说明共享引用归属和词面数字检查，继续拒绝收益保证、HTML/链接、输出注入和自编概率。新价位标签还要与所选计划字段对应；失效阈值由程序生成。检查不证明每句因果描述、模型方向或目标触达正确。

同次调用产生正文和研判，沿用每轮及会话预算；只针对字段或已有证据关联问题最多修正一次。编价、保证收益等不触发修正。模型失败时显示研判未形成，合法程序计划仍可展开；原计划或依赖遭篡改则不显示价位。取消与预算停止继续由原控制器处理，不发布迟到答案。

上下文在原上限内优先保留完整候选计划证据和可用同比事实。模型选择表仅含编号、证券、用途、状态和原因码；完整价格及来源在优先保留的证据中，公开计划仍含完整参数、依赖及条件。这样三股九份候选不会因重复展示元信息耗尽预算。不能因截断只留下编号或半个价格表。可选快照写入时重建检查计划，旧记录不迁移、不回填；历史查看和请求重放不重新取数、不重新调用模型。

### 1. 本模块交付

### 2. 为什么不让模型重写整份请求

旧条件已经核实，明确“添加ATR2”没有必要再请模型猜股票、日期和来源。程序直接合并唯一变化，成本和待核验输出更少；进入执行后，模型提议仍必须与合并请求完全相符。

没有新增框架、模型、数据库或工具权限。改条件不是直接改报告标题，也不是复用旧计算。每个可执行更新构造新 `request_id`，沿用原研究流程，最多两次模型调用、一次分析尝试；失败不自动重试或换源。

### 3. 数据流与职责

```text
明确修改句
  → 共用检查：可信基准、15分钟期限、当前目录、来源和日期限制
  → 完整解析为不可变 ConditionUpdate
  → 仅合并指定维度，重新校验领域契约
  → 新股票需目录确认；有歧义先保存pending、等待选定
  → 新请求就绪后清旧编辑基准、将旧结果降为历史
  → 原模型提议绑定 → 工具执行 → 指标/证据 → 事实及关系检查
  → 有可信事实才保存新条件和新结果
```

- `research_update.py`：完整语句解析及纯条件合并，不调用模型、目录网络或行情。
- `ResearchSession._checked_edit_base()`：原指标替换与新修改分支共享当前有效性检查，避免两套授权规则漂移。
- `prepare_condition_update()`：核实新证券、组织澄清或生成新请求；不直接执行工具。
- `agent.py`：分流、持有会话锁、执行前消费旧基准及成功后记录；执行逻辑不复制。
- `agent_cli.py`：显示已确认名称/代码、新条件和修改口径，不负责合并业务参数。

不传同一 `session=` 或没有有效基准时返回 `no_confirmed_research`，不从旧历史结果重新激活修改条件。每会话状态继续隔离，并发输入仍由原锁拒绝。

### 4. 股票修改与身份澄清

新股票支持完整名称、已核实别名、唯一裸代码及完整代码；使用整个目标字符串查当前目录，不让模型凭记忆给代码。

- 目录唯一匹配：核对来源支持范围，再以新证券和原条件构造请求。已明确匹配为原股票时为无变化，不重复查询。
- 多候选、部分名称或未知名称：0次模型、0次行情，保存原日期/指标/来源，要求完整名称或代码。候选存在时不得选择候选以外的证券；无候选时允许用户纠正完整身份。
- 用户澄清后复用原 `resume()`：检查当前目录、候选是否更名、时效和来源，执行前消费待选请求。无效回复不延长15分钟期限。
- 等待确认时，另一条修改不能绕过选股；可回复“取消”撤掉待选，或用“新问题：”重置。
- 待选不覆盖原可信基准和结果；取消后原基准在期限内仍可用。显式历史查看及有限知识解释也不消费待选。

不把“换成RSI14”当成股票，不把“换成腾讯/今天/最新”当成新证券。对明确附带指令的名称表达也拒绝；这些有限规则不证明任意语言意图都能正确识别。

科创板、名称含ST及新上市样例不因标签被排除；目录身份不证明历史ST、上市日、停牌或可交易性。腾讯等来源的既有前缀限制仍有效，不能靠换股票扩大范围。

### 5. 日期、指标与默认值

日期只接收完整ISO日期。区间须含首尾1–366个自然日；在线研究截止日必须早于当前上海日期。不隐式补预热历史，不因改指标或换股票而重算原相对日期。明确改日期时使用本次可信日期锚点，并显示新边界；只改截止日不擅自再回看365天。

开发CSV继承原开发契约，不因它允许固定样例日期而宣称在线可查询今天或未来。样例和在线时间约束继续分开。

添加指标须明确一个实例及参数，例如 `RSI14`、`BOLL(20,2)`或`MACD(12,26,9)`；不默默给“添加RSI”补14，也不把“添加均线”扩成两条。重复、非法参数和第13个实例均拒绝。

删除可用完整实例，或唯一匹配的类别名称；原组合含SMA20和SMA60时，“删除SMA”要求重述完整删除句，不自动选第一条。不存在的目标不执行，最后一个指标不能删空，也不回填默认组合。

默认口径标记随维度修订：显式改日期后清除旧“前一自然日/365天/相对月年”标记，添加删除后清除“默认8项”。未修改维度的历史解释保留；程序始终显示具体日期和完整指标范围。

### 6. 失败和历史结果

本地无效修改、歧义或无变化不执行，原可信基准及结果不变，不延长期限。请求就绪进入执行后，先消费旧编辑基准并将旧结果设为非当前；模型超时、提议不符、无数据、错误股票数据或中断都不能恢复旧基准。

新查询未取得可信事实时，只能通过“查看上次结果”或 `/last` 显式查看旧成功结果，并标明旧股票、日期、来源和历史身份。“这里RSI多少”不能偷偷读旧结果。事实有效但模型解释失败时，可保存新事实，不保存失败解释。

人工CSV只含平安银行5条记录。换中国平安后，原CSV不是该股票的合法数据；当前校验返回 `research_data_failed`，不是成功报告，也不将错股票数据静默改名。端到端测试另用显式标记的人工证券数据验证成功换股，不冒充真实中国平安行情。

### 1. 这一轮交付什么

| 内存状态 | 保存什么 | 不代表什么 |
| --- | --- | --- |
| `pending` | 尚待选择的股票候选、已校验日期及指标 | 已确定股票或已成功研究 |
| `confirmed` | 最近可信研究的条件与身份，供明确指标替换 | 本轮新查询已经成功 |
| `_last_result` + `_result_current` | 最近成功结果的独立快照，以及是否仍可作为当前结果 | 实时行情、永久授权或完整聊天历史 |

`SavedResearch.checked()`先深复制结果，再调用原 `build_research_report()`检查请求、字段和证据，并要求有可解释事实。完整结果与部分可用结果都能保存；模型解读失败不妨碍保存可信事实。无数据、全部不可解释或完整性失败不保存。

Python的 `frozen=True` 只禁止给dataclass字段重新赋值，不会冻结内部字典。保存、读取结果和返回快照时分别隔离可变内容，避免调用方修改原结果或返回对象后污染会话。私有字段仍是进程内代码约定，不是抵御恶意Python代码的安全沙箱。

结果只保留最近一份，15分钟后失效，以研究轮传入的可信起始时刻计时；追问和查看不会续期。这是会话复用期限，不是行情实时性承诺，也不是整轮硬超时。时间倒退同样失效。

### 3. 当前结果与历史结果

```text
成功研究A → 保存A，current=true
开始执行新研究B → 清旧修改基准，保留A但current=false
  ├─ B取得可信事实 → 用B替换A，current=true
  └─ B失败 → A只能显式历史查看，不能回答“这里的RSI”
```

- “开始执行”指请求已准备好进入原研究链路；本地无效修改或尚未完成身份澄清，不冒称已启动新研究。
- B失败后，“查看上次结果”可看A，但会显示旧股票、原日期、实际最新交易日、来源、保存时刻和历史标签。
- 查看A不恢复已消费的指标修改基准，也不把A重新标成当前结果。接着隐式追问仍得到 `no_current_result`。
- `/reset`、明确“新问题：”及原重置命令清除全部状态，包括旧结果；不是保留历史的入口。
- 有待选股票时，精确知识问题和显式历史查看不消耗待选请求；其他含糊追问仍先完成股票选择。

每次复用前重新核查15分钟期限、当前目录时效、原身份是否存在或更名、来源及开发CSV配置，以及事实完整性。失败清除失效结果；不会自动刷新目录或重取行情。会话导出仅附结果范围和时间等元数据，不附完整结果、CSV路径、聊天或模型草稿；导出仍不是生产审计日志方案。

### 4. 追问的数据流

```text
用户追问 → 检查会话快照与范围
  → 最多一次模型调用：仅判断回答类型、复制指标提及
  → 程序检查调用与指标 → 从快照选字段
  → 必要时重新核对已保存关系的证据与数值依赖
  → 程序渲染答案；不调用行情工具
```

模型工具 `interpret_saved_research_question` 仅接受：

- `request_id`：必须属于程序提供的这份快照；ID用于关联，不是认证凭据。
- `action`：`facts`、`explain`、`relations`、`clarify`或`unsupported`。
- `topic_mentions`：最多12项，必须复制用户原文，不能自行替换股票、参数或证据。

模型只收到当前问题及保存请求的股票、日期、指标范围，不收到完整结果、完整聊天或旧草稿。它选择回答类型，不生成最终数值或展示文字。仅接受一个正确工具调用；多调用、错误工具、额外字段、错ID和捏造/遗漏已识别指标都会阻断，不自动修复或重试。

本地识别到其他目录股票、新日期、实时/最新要求、改来源、新闻原因、预测或交易要求时先阻断。对KDJ、OBV等明确列出的未支持指标也先阻断，避免模型只提取RSI后静默丢弃另一个要求。这些规则及原文覆盖检查有限，不能证明任意中文意图都理解正确。

字段只从原研究计算过的实例中选择。原结果同时有SMA3和SMA5时，只说“SMA”须澄清；明确两者则能显示对应的均线对关系。未计算MACD或RSI14不会补算；缺历史和未定义保持原状态，不补零。

关系复用原 `validate_indicator_explanation()`，重新检查请求、事实、单位、日期及原精度比较，不仅依赖旧的“已通过”标志。最多展示8条已核对关系，超出明确提示非穷尽。模型或用户说“RSI偏低”，而原值为79.545455时，展示实际值与高于70的参考分区，不沿用错误前提。程序不据此解释为何发生某条新闻事件或推导未来涨跌。

### 5. 指标知识与展示契约

`parse_knowledge_question()`只匹配完整的有限定义表达，例如：

- `RSI是什么`、`RSI超卖是什么意思`。
- `解释一下MACD里的DIF和DEA`。
- `SMA和EMA分别是什么`、`20日均线是怎么计算的`。

定义与项目计算口径一致：SMA初始化EMA、Wilder RSI/ATR、BOLL总体标准差、MACD柱值2×(DIF−DEA)、严格此前窗口量能倍率。含额外股票、日期或交易要求的句子不能截取前半句当作纯知识问题。

明确知识问题0次模型、0次行情；无研究结果也可回答。超出此语法不保证直接回答，仍可能进入原意图理解并说明限制。当前没有知识来源检索和自由生成的通用教学答案。

`AgentTurnResult`新增 `knowledge_answer` / `followup_answer`，`display_answer`仅显示程序答案。追问不把缓存填进本轮 `research_result`，因此不会把历史展示统计成一次新分析。`followup_answer.validation_scope`明确仅检查保存字段和有限关系；原 `answer_validation=not_performed` 保持，不能冒称任意自由文本已被验证。
