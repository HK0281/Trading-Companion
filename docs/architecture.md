### 2026-10-28：当前已实现的处理链路

当前产品是模块化单体后端、受控的单个研究 Agent 和同源 React/TypeScript 工作台。下图描述已经实现的路径；后面的日期章节保留历史状态，长期目标不能当成已实现功能。Windows 是运行和验收平台。

```mermaid
    R --> L["本地澄清或冲突答复"]
    subgraph X["领域执行器"]
        K["一般知识 / 固定指标定义"]
```

领域执行器按需使用受控模型和只读工具。实线表示处理流程，虚线表示共享控制或可选能力。领域执行器仍处理内部澄清和后续请求，选中入口不代表已经获得研究许可。固定指标知识由原技术入口执行，图中按能力列入知识；名单续接会在复核成员和有效期后进入公司或技术研究。详细边界如下：

| 职责 | 当前实现和验证边界 |
| --- | --- |
| 路由与澄清归属 | `request_routing.py` 按静态优先级选择执行入口，不调用模型、不修改会话，也不授予工具权限。路由1b明确知识、新筛选与待澄清的优先级；本地冲突答复复用原控制与发布边界。v1/v2 特征测试（冻结行为作为对照）覆盖35场景、105轮；历史事实、人工目标与审核过的差异分别保存，见[路由设计](request-understanding-design.md#请求路由明确意图优先级与澄清所有权)。 |
| 受控模型与工具 | `TurnControl` 是每轮共享的模型/分析预算、期限和取消控制器；模型提议继续经过身份、日期、参数和作用域核验。固定知识可零模型、零取数。调用协议由项目定义，适配 DeepSeek/OpenAI，不使用 Agent 编排框架，见[工具协议](agent-runtime-design.md#工具模型协议与离线-fake-往返)和[工作流](agent-runtime-design.md#有界研究工作流设计)。 |
| 有上限的采集 | 公司领域资料与腾讯筛选批次共用 `CollectionExecutor`，最多三个未完成任务，迟到线程真正结束前仍占名额。公司配额与报价请求/字节账本分别约束，腾讯全部批次成功才发布名单；公司领域可部分可用但明确缺失。东方财富分页、技术计算、模型及市场背景读取保留原执行方式，见[并发设计](research-data-design.md#有上限的资料与报价并发采集3a3b3c)。 |
| 检查、修复与发布 | 检查因路径而异，包括请求绑定、引用、数值、证券归属及计算关系，不证明任意文字推理。公司回答可在原额度内最多重写一次；失败按原规则降级，不新增无限重试。最终会话边界隔离取消和迟到结果，见[公司研究](research-data-design.md#多维公司研究流程证据与模型切换)和[整轮控制](agent-runtime-design.md#整轮运行控制共享预算取消与迟到结果)。 |
| 可选追踪与归档 | `trace-v2` 是第二版逐轮元数据格式，覆盖模型、工具、来源、检查与修复；详细事件有共享上限，查看器区分未记录、零次与截断。SQLite 是本地证据存储，归档在发布检查后受会话边界保护，不保存原问题、聊天或模型答案。两者默认关闭，失败不丢弃研究答复，见[追踪设计](agent-runtime-design.md#每轮运行记录路由模型工具来源及检查修复)与[归档边界](technical-analysis-design.md#历史回放与本地归档读取)。 |

当前离线测试、界面截图与固定延迟计时见 [README](../README.md#development)。截图使用人工数据和固定假模型；离线契约验证不是实盘质量或真实来源速度评估。没有交易接口、严格 PIT（按当时可见历史版本查询的数据库）、全市场完整筛选或订单成交回测；这些边界与后面的长期目标分开。

### 2026-10-27：顶层请求路由集中，行为保持兼容

API服务通过`request_routing.py`集中选择原一般知识、筛选修改、新筛选、名单续接、公司研究和技术研究入口。`RouteSpec`静态声明旧优先级，`RouteDecision`给出固定原因码；只读上下文不拥有会话清理、预算或发布能力。`api_service.py`继续安排知识可选目录提示/研究强制目录加载、调用原执行器并处理幂等、取消、公共输出与异常收尾。

路由与授权分离（routing ≠ authorization）：选中名单处理器不等于名单有效，身份、日期、来源、工具和发布仍由原执行器核验；内部澄清/编辑/知识流程不随本次搬移重做。原`09cd366`的35场景/105轮特征测试（characterization test / golden master，即冻结现有行为的基线）对照路由、完整公共返回、调用和会话状态，记录已有不一致，规则修正留待1b。模块边界、时钟与目录顺序、基线复核方式见[请求路由设计](request-understanding-design.md#请求路由明确意图优先级与澄清所有权)。

### 1. 文档定位

本项目采用**模块化单体后端、受控的单个研究 Agent、确定性研究工具，以及可追溯的数据与证据**。

“模块化单体”是指先在一个 Python 项目中划分清楚职责，通过进程内接口组合能力，不提前拆成独立部署的微服务。这样更适合个人项目，也方便逐步学习、测试和定位问题。

本文回答“系统如何组织、模块如何协作、现有代码如何演进”。产品范围与验收依据见 [产品 Agent PRD](prd-agent-v0.1.md)；运行方法见 [README](../README.md)；概念和面试问答见 [学习笔记](agent-learning-notes.md)。本文不扩大当前 PRD 的交付范围，也不要求立即按目标目录重构。

标记约定：

- **已有**：能够在当前源码中找到的能力。
- **本期计划**：首个单股票、多指标日线 Agent 所需能力。
- **长期目标**：基本面、新闻、选股、历史版本、风险情景及 Web 等后续能力。
- **实验候选**：需要独立验证，不能作为已实现或必需依赖描述的能力。

### 2. 产品目标与不可突破的边界

长期产品面向 A 股个人投资者，支持知识解释、技术分析、公司研究、候选股票筛选，以及有明确假设的止盈止损情景研究。后续再扩展美股。

首个产品 Agent 聚焦中文单股票、多指标、已完成日线研究；新闻、选股、数值化止盈止损和收益评估不属于本期。

长期保持以下边界：

1. 所有实际交易由人完成；不接入券商账户，不创建下单、撤单、修改订单或资金管理通道。
2. 指标、比较关系和可计算的研究结果由程序产生；模型负责理解请求、提议使用允许的工具和解释证据。
3. 不以训练股票模式预测模型为前提，也不承诺收益、胜率或走势预测准确率。
4. 支持范围内的科创板、ST 和新上市股票不因类别被主动排除；身份未知或数据不足必须明确说明。
5. 任何输入、模型回答或外部新闻，都不能扩大程序授予的权限。

当前已有本机FastAPI、最小Web、历史K线/指标及独立本地证券状态／日历背景展示。真实主数据／日历适配器尚无；默认是明确人工夹具。也尚无生产多用户部署、DuckDB持久化、Jev、新闻/基本面、筛选、完整证据台账或严格point-in-time系统。

### 4. 总体架构

下图为目标模块关系，不表示全部模块已经存在。实线表示主要调用或结果流向，虚线表示模型生成依赖；取数结果会沿服务调用返回。

```mermaid
flowchart TD
    Entry["交互层：CLI / 本机 Web / 历史图表"] --> App["应用层：请求与会话协调"]
    App --> Agent["Agent 运行层：理解、澄清、行动提议"]
    Agent <--> Models["模型接入层：DeepSeek / OpenAI / Fake"]
    Agent --> Tools["只读工具层：白名单、参数与预算校验"]
    Tools --> Research["研究服务：技术分析 / 公司研究 / 筛选 / 风险情景"]
    Research --> Data["数据访问：校验、来源、快照与版本"]
    Data --> Providers["外部适配器：行情 / 主数据 / 公告 / 新闻 / 财务"]
    Data --> Storage["后续存储：Parquet / DuckDB"]
    Research --> Facts["结构化事实与证据"]
    Facts --> Explain["Agent 回答阶段：基于证据组织解释"]
    Models -.-> Explain
    Explain --> Check["回答检查：字段、引用与关系一致性"]
    Facts --> Check
    Check --> Output["用户结果：解释 / 安全回退 / 明确失败"]
```

权限、超时、日志和测试贯穿各层。图中没有交易执行模块，也不预留可由模型激活的交易能力。

#### 4.1 依赖规则

- 领域数据结构和指标计算不依赖模型、HTTP、界面或数据库。
- 研究服务依赖统一数据源接口，不到处硬编码某个供应商请求。
- 数据与模型适配器把外部协议转换为内部契约；适配器依赖契约，而不是让业务依赖供应商格式。
- Agent 只通过已注册的工具契约提出研究请求，不能绕过工具层直接调用适配器、数据库或终端。
- CLI 和未来 HTTP 入口调用相同的应用能力，不各自实现一套研究逻辑。
- 对象构建和供应商选择集中在应用装配处；不让模型动态导入模块或生成任意调用目标。

### 5. 模块职责

#### 5.1 交互层与应用层

交互层负责接收输入和展示结果。第一版采用终端对话；现已补React/TypeScript本机工作台，展示对话、指标字段、查询条件和证据，以及[历史K线/指标](web-and-api-design.md#k-线与指标可视化)。图表直接投影本次研究数据，不重新取数，历史必须绑定已核实快照；图表失败不影响文字。页面状态机和HTTP客户端独立于React渲染，不复制Agent；前端构建后由原FastAPI同源提供，运行时不另启Node服务。TypeScript之外仍检查HTTP结果结构及请求编号，未确认响应保留原问题/编号，不自动重试或放行新研究。

应用层协调会话、每轮请求、配置和返回结果。当前已有本机FastAPI/Pydantic入口：路由负责DTO和协议，框架无关的 `ResearchApiService`负责会话、配额和幂等，复用原Agent；计算函数不依赖FastAPI，也不全面替换内部dataclass。公共响应白名单投影，不使用包含模型草稿的调试导出。

前端不直接调用模型供应商，也不接触服务端API密钥。当前用随机会话Bearer凭据隔离资源、限制Host/Origin及本机访问，不是账户体系；以后开放多用户访问前，必须先补用户身份、TLS、账户配额和共享会话等。现有同步HTTP路由在线程池运行，取消路由只发信号；不把同步模型请求放入事件循环阻塞其他请求。

#### 5.2 Agent 运行层

Agent 负责区分知识问答、行情研究、已有结果追问和超范围请求；提取参数、发起澄清、提议工具调用，并解释有效证据。

首版采用显式状态机：

```text
理解请求 → 澄清或校验 → 执行允许工具 → 整理事实 → 解释 → 检查 → 展示
```

知识问题可以跳过行情工具；已有结果追问只有在条件和证据仍匹配时才能复用。状态机限制允许的转移，模型不能自行添加无限循环或重试。

应用层管理会话生命周期；Agent 管理当前轮的理解、待澄清参数和执行阶段。已确认条件、待确认候选及上次结果分开保存。新条件查询失败后，不能把旧结果当作新结果展示。

首次实现只保留内存会话，不默认保存完整原始对话。开发协作中使用的子 Agent，不等于产品运行时需要多 Agent。

2026-10-22后续增量：[明确条件修改](answer-design.md#会话内研究条件修改)复用现有会话和执行器；局部修改由程序完整解析、合并并重查领域契约，不新增一次意图模型调用。换股票仍查目录，有歧义先选定；修改和指标替换共享 `_checked_edit_base()`，防止时效、来源和身份检查分叉。以下2026-10-21段落为上一阶段记录；自由复合修改和任意语义检查仍未完成。

实施更新（截至2026-10-21）：先实现[明确格式单轮入口](agent-runtime-design.md#单轮研究-agent受控编排的第一个版本)，缺项零模型/行情调用；随后增加[自然语言入口](request-understanding-design.md#自然语言研究入口理解意图核实名称展示默认值)，由模型提取原文候选、程序核实目录身份及条件。有歧义时零行情分析，可见默认值不覆盖用户显式要求。[真实目录刷新](research-data-design.md#真实证券目录显式刷新与安全保存) 已独立实测，离线演示仍保留人工夹具。可选[股票澄清会话](request-understanding-design.md#股票澄清续接保留条件不依赖模型记忆)保存非股票条件，短答选定身份后重查当前目录、来源及契约，沿用原具体日期；执行前消费待选状态。[程序事实摘要](answer-design.md#安全回答展示程序事实摘要与模型草稿分离)及[受限关系检查](answer-design.md#受限指标解读结构化论断证据核对与安全回退)由程序核对本轮证据和数值关系后生成中文；不合格则仅展示事实，不重试。后续增加明确指标替换、独立成功结果快照及有限追问：模型只选回答类型/指标，程序读保存字段并复查关系；知识定义走本地有限语法。通用条件修改、开放知识问答及任意自由文本语义检查未实现；各有限检查不改变 `answer_validation=not_performed` 的含义。

#### 5.3 模型接入层

业务使用统一接口，供应商适配器负责消息转换、能力差异、响应解析与错误分类。DeepSeek 为首个真实提供方，Fake 支持离线验证，OpenAI 后续接入。

原 `TextModel.complete()` 及消息校验继续只支持纯文本。M2首切口新增独立 `ToolCapableModel`、工具定义/调用/结果/状态契约及脚本Fake，见[工具模型设计](agent-runtime-design.md#工具模型协议与离线-fake-往返)；旧演示只验证固定结果消息往返。随后新增的白名单执行器已通过独立入口连接研究服务，见下节。2026-10-19新增独立 `DeepSeekToolModel`，见[工具适配设计](agent-runtime-design.md#deepseek-工具调用适配器)；与文本接口共享HTTP传输，均显式关闭thinking，避免在没有推理历史契约时启用思考工具调用。2026-10-20记录开发者一次真实 `deepseek-flash` 工具往返成功，使用人工CSV，不能外推为所有型号或完整Agent质量已验收。原文本CLI保持兼容。

兼容 OpenAI 风格接口不等于行为完全一致；切换提供方时必须验证消息、结构化输出、工具调用、截断和错误处理。用户显式选择提供方，不静默把对话发送给另一家服务。这里的 OpenAI 指模型 API，不是自动操作 ChatGPT 网页。

#### 5.4 只读工具层

工具层是模型与程序能力之间的边界。模型提出请求不等于获得执行授权。

首版只开放一个多指标日线分析工具，一次获取选定历史序列后集中计算所需指标；跨年分片仍可能产生多次 HTTP 请求，不能把一次工具执行误认为一次网络请求。

工具层负责名称白名单、结构与业务参数校验、调用预算以及统一错误返回。不接受任意函数名、Python 对象、SQL、磁盘路径、终端命令或网络 URL。CSV 仅由开发者配置固定测试样例，不能让模型选文件。

2026-10-16已实现上述日线执行切口，详见[受控工具设计](agent-runtime-design.md#受控日线指标工具执行器)：`ResearchToolExecutor`按回合实例持有一次分析额度，多调用批次整体拒绝；完整研究结果保留本地，模型接收带请求内证据别名的紧凑结果。容量与历史校验失败明确返回，不截断证据、不自动重取数。随后通过模拟HTTP和开发者真实工具固定任务记录验证了连接；执行器本身不负责自然语言路由或全轮时限。单轮runner只创建一个执行器，并额外检查提议是否仍属于本轮已识别请求。

未来按需增加公司资料、公告检索、候选筛选和风险情景工具，不为每个指标单独暴露一次取数工具。

#### 5.5 研究服务层

研究服务实现可脱离大模型运行的业务能力：

| 服务 | 职责 | 阶段 |
| --- | --- | --- |
| 技术分析 | 指标计算、日期对齐、逐字段可用性与交叉等确定性关系 | 首个 Agent 的核心；部分基础已有 |
| 公司研究 | 整理基本面、公告、新闻事件及其来源与时间 | 长期目标 |
| 股票筛选 | 对有版本的股票池执行确定性条件，返回候选、筛选理由和缺项 | 长期目标 |
| 风险情景 | 按明确方法计算参考水平，展示假设、适用条件和失效条件 | 长期目标；不执行交易 |

筛选首先保证股票池、数据时间和规则可复现，再由模型解释候选。模型不能凭记忆补齐缺失财务数字，也不能在没有方法与输入的情况下编目标价或上涨概率。

#### 5.6 数据与证据层

数据层统一外部来源、数值单位、时间、复权口径和版本。本地[证券状态／交易日历背景契约](market-and-screening-design.md#证券主数据与交易日历背景)已有，按有效区间与发布时间保留unknown，并与原bars作非破坏性冲突提示。真实master/calendar接入、完整历史ST/上市/停复牌版本及公司行动仍待实现；当前背景不进入模型或筛选，不将today快照冒充历史已知事实。

证据模块把结果整理成可定位的事实。事实卡片由程序渲染；模型引用事实标识解释，不改写事实数字。未来新闻与公告引用还需定位原文、文档版本和支持结论的具体片段。

回答检查不仅验证“引用存在”，还要检查日期、单位、数值与方向关系。引用有效但把“低于”写成“高于”同样不合格。自由文本的全部语义无法仅靠字段校验保证，仍需人工评估和限制可表达的结论。

当前已实现事实卡片的最小版本：`research_report.py` 检查本轮请求ID、股票、区间、指标、字段及其数值/单位/日期证据，生成固定中文摘要。`ResearchToolExecutor` 可接收可信应用传入的请求ID，与编排及事实关联；模型不能设置ID。报告不解读或验证自由文本，也不生成趋势关系，草稿仍保留在调试字段。详见[安全展示设计](answer-design.md#安全回答展示程序事实摘要与模型草稿分离)。

随后新增 `relation_explanation.py`：模型只能选择本轮可用关系，不能提交任意句子或目标价。程序检查引用、当前/前一记录、单位与依赖顺序，并从现有原精度数值核对关系；全段通过才渲染固定中文。`display_answer` 合并事实及通过的关系，否则回退；`safe_answer` 仍独立保留。支持七类指标与精确命名均线对，不包含跨指标冲突解释或预测质量验收，见[受限解读设计](answer-design.md#受限指标解读结构化论断证据核对与安全回退)。

### 6. 关键数据契约

下表列出各阶段契约需要表达的内容。M1b已新增 `IndicatorSpec`、`MultiIndicatorRequest`、`MultiIndicatorResult` 及字段、组件、关系和事实契约，详见[多指标设计](technical-analysis-design.md#多指标分析服务与证据契约)；最小股票澄清状态、事实报告及 `indicator-explanation-v1` 受限关系候选已独立实现。通用会话、自由文本解释和历史版本等契约仍待后续实现。

| 契约 | 必须表达的内容 |
| --- | --- |
| 研究请求 | 请求编号、股票、日期区间、指标及参数、显式数据源、已采用默认值 |
| 数据快照 | 股票、覆盖区间、来源、复权与单位口径、获取时间；后续增加版本和历史可得性依据 |
| 指标结果 | 指标实例与参数、算法版本、计算起点、初始化方式、字段值、值对应日期及可用性 |
| 结构化事实 | 事实标识、数值或关系、单位、日期、支持它的结果字段及适用限制 |
| 解释候选 | 引用的事实标识、允许的关系与解释类型，以及不确定性；不获得新的执行权限 |
| 本轮结果 | 查询条件、整体数据状态、逐项结果、解释或回退内容、警告与脱敏诊断标识 |

可用性需区分“可用、历史不足、未定义、计算错误”，不能统统变成 `null` 后不解释原因。合法的 0 和不可用值不同。

MACD 的 DIF、DEA 和柱值可以在不同记录数下就绪。部分指标可用时只解释有效部分，不静默用旧日期字段补当前缺值，也不让模型补算。

旧版 `AnalysisResult` 的状态仍表达单 SMA 结果；多指标契约需要独立演进，不能把旧接口中 `ok` 的含义悄悄改成另一种语义。现有 `analyze_daily_bars()` 与 CLI 保持回归兼容。

### 7. 一次日线分析的数据流

以“分析 000001.SZ 截至 2025-09-05 的趋势和动量”为例，目标流程如下：

1. 应用创建本轮请求，提供明确日期锚点，并读取当前会话的已确认条件。
2. Agent 识别意图和候选参数；有歧义时追问，本轮不查询行情。
3. 程序合并条件、应用允许的默认值，校验股票、日期、指标、来源和预算。
4. 工具调用研究服务，由选定适配器读取日线；校验字段、单位、顺序和日期范围。
5. 同一份日线集中计算请求的指标，产生逐字段状态、初始化信息和确定性关系。
6. 证据模块生成事实标识。给模型的是必要字段、关系和缺项说明，而不是全部历史序列。
   程序综合独立重查它实际使用的最新/紧邻前一数值，生成四维度参考比较，不采用任意模型文本；默认回答和历史概览复用它。停止不生成综合，取消不展示本轮结果。
7. Agent 组织解释；程序核对引用与允许关系，不合格时按剩余预算修正，或回退为事实摘要。
8. 展示查询条件、实际最新交易日、事实、解释和限制；保存本轮匹配的确认条件与结果。

源失败、无数据或行情无效时，不调用模型生成走势判断。行情成功而模型失败时，可以保留可信事实，但必须明确没有完成模型解释。

### 8. 历史数据、存储与 point-in-time

#### 8.1 时间不是一个字段

长期数据设计至少需要区分：

| 时间信息 | 含义 |
| --- | --- |
| `trade_date` 或业务所属期 | 行情发生日、财报所属期等，不等于公开日期 |
| `published_at` | 来源宣称的发布时间；本身仍需验证，不能证明当前版本当时已存在 |
| `retrieved_at` | 本系统实际读取时间，不代表历史用户当时可得 |
| 状态有效区间 | 某次 ST、停牌等状态从何时生效到何时结束 |
| 版本与可得性依据 | 具体内容版本、修订记录，以及什么证据支持它在截止时点已可得 |

日期过滤只限制业务日期，不能排除后续修订。财务数据、公告与风险标签需要保留历史版本；历史股票池还需包含当时存在、后来退市的股票，避免只看今天仍存续的样本。

仅在今天抓到一个标为过去发布时间的文档，不能据此声称已经还原当时内容。缺乏可验证版本时，明确标注局限，而不是倒填一个历史可得时间。

#### 8.2 存储演进

后续优先考虑 Parquet 保存经许可的快照，DuckDB 执行本地结构化研究查询；使用数据源、股票、区间、口径和版本等条件定位数据。算法与计算起点也必须参与结果缓存标识，避免错用旧结果。

DuckDB 并不是 point-in-time 正确性的保证；保证来自时间契约、版本保存、查询规则和测试。公开接口可访问，也不代表允许任意缓存、商用或再分发，接入前需核对条款。

首版仍使用现有不复权日线。公司行动会影响指标，不能把价格跳变自动解释为交易趋势；以后引入复权，也要固定算法与数据版本，不静默替换口径。

#### 8.3 模型自身的历史信息风险

即使工具数据已经按时点隔离，预训练模型仍可能记得之后发生的事件。历史研究只允许解释输入证据，并通过诱导后续信息的评估检查越界行为。

这能降低风险，但不能证明自由文本绝对没有历史信息污染。数据回放正确性、模型解释质量和交易策略表现是三类不同验证，不能相互代替。

### 9. Jev 的可选位置

Jev 是后续分类或路由任务的实验候选，不是第一版依赖。本文不重新核验其版本、许可、部署条件或承诺具体模型能力。

未来有新闻/公告后，可针对事件分类、相关性判断或进一步研究路由建立固定任务。先与简单规则、主模型比较准确性、覆盖率、延迟和成本，再决定是否接入。

接入应通过独立分类接口完成，主研究链路不依赖 Jev 专有输出。失败时执行事先定义、可见的回退；升级到付费模型也必须受用户配置、数据发送范围与预算约束。

Jev 不替代数值计算、权限校验、历史时点过滤或引用检查。不把全部输入强制先过一次 Jev，也不把所谓分类置信度当作交易胜率。

### 10. 安全、运行预算与诊断

#### 10.1 安全边界

- 只注册研究工具；不注册交易、任意 SQL、任意文件或通用代码执行能力。
- 外部资料是数据，不是指令。新闻中的“忽略限制”等文本不能影响系统权限。
- 密钥由本地环境配置提供，不进入提示词、Git、前端、日志或错误信息。环境变量不是加密保险箱。
- 启用真实模型前说明哪些问题、会话与证据会发送到哪个提供方；测试默认使用假模型，不自动产生付费调用。
- 日志默认不保存原始完整对话；不同会话的状态和结果隔离。

#### 10.2 预算与失败行为

当前产品Agent入口已接入[共享运行控制](agent-runtime-design.md#整轮运行控制共享预算取消与迟到结果)，以下区分实际同步限制与尚未实现的硬中断/费用保证。

当前明确格式runner最多两次模型调用，自然语言初始请求最多三次（多一次候选理解）；两者都最多一次分析、无自动修正。股票澄清首轮最多一次模型、零分析；成功短答续接不重复理解，最多两次模型、一次分析；无效短答、取消和过期均零调用。上述路径共用单轮计数、90秒单调协作期限及24,000已观察token阈值；不能把底层HTTPtimeout或协作检查写成硬期限。

终端层另外限制一次启动最多5条问题、15次模型转发，调用前消耗额度，重置状态不补额度；最多5次分析来自每轮执行器与输入上限的组合。启动级限制与每轮控制器独立，并不构成跨启动的账户配额或费用保证。中断时尚未返回一轮的分析次数标为未确认，不能静默记零；详见[终端设计](agent-runtime-design.md#终端研究入口设计)。

| 范围 | 实际约束 |
| --- | --- |
| 研究范围 | 每次 1 只股票、最多 12 个指标实例、含首尾最多 366 个自然日 |
| 工具 | 每轮最多执行 1 次日线分析工具 |
| 模型 | 理解、提议、解释共用最多3次；明确格式流程最多2次，没有自动修正 |
| 截止时间 | 模型连接/读取timeout默认30秒并取剩余时间较小值；每轮90秒协作检查，不是硬中断 |
| token | 已观察累计达到24,000停止，缺失/不一致usage另标记，不是完整账单或预调用保额 |

底层HTTP连接/读取timeout不等于应用层总截止时间。当前已在阶段及I/O边界检查截止/取消，迟到结果不继续调度或写入新会话状态；同步请求仍可能晚于90秒返回。新状态暂存后在取消锁内发布，旧基准消费及显式重置立即生效。供应商或SDK自动重试默认关闭；若后续启用，每次真实请求仍须计入同一预算。

| 异常 | 目标行为 |
| --- | --- |
| 参数不明确或非法 | 追问或在联网前拒绝，不擅自改条件 |
| 源失败或无效行情 | 返回明确原因，不编行情，不静默换源 |
| 数据合法但部分指标不足 | 展示有效部分及缺项；不伪装完整成功 |
| 模型超时、截断或错误引用 | 明确失败或回退到可信事实，不把残缺解释当成功 |
| 越权工具、反复调用或总预算耗尽 | 程序阻断并结束当前轮 |

#### 10.3 可观测性

记录请求编号、阶段、模型与提示词版本、数据源与快照标识、算法版本、调用次数、耗时及脱敏错误。token 用量未知时保留未知，费用仅在有对应计价规则时估算。

先采用结构化日志；确实需要跨进程追踪时再评估 OpenTelemetry 等组件，不为展示技术栈提前增加部署依赖。

### 3. 用户真正想做的产品

#### 3.1 长期需求

面向个人投资者，支持：

- 自然中文问答和交易知识解释。
- 多种技术指标、K 线与量价观察，以及条件化的后续方向分析。
- 结合基本面、新闻、公告和技术形态研究个股。
- 从股票中寻找有研究价值的候选，并说明为什么入选。
- 有计算方法、输入依据和失效条件的止盈止损参考。
- 先覆盖 A 股；科创板、ST、新上市股票需要包含，不能仅因类别主动排除。
- 使用中国可访问的模型，DeepSeek 优先；保留 OpenAI 风格工具协议和模型提供方切换。

用户不要求自行训练机器学习模型学习股票模式。预训练 LLM 负责理解和解释，程序负责可计算结果与权限。不要把“预测走势”的需求实现成保证方向、凭空目标价或虚构胜率；应回答可用证据支持的倾向、冲突、确认条件和失效条件。

#### 3.2 已经反复强调的体验

- 输入“分析平安银行接下来的走势”应可开始工作，不要求用户先填好代码、日期和全部指标。
- 模型先理解意图，程序核实名称和条件；只有确有身份或范围歧义时才澄清。
- 主回复必须回答原问题。不能用几十行指标、证据 ID、参数和执行记录代替分析。
- 第一条消息直接创建会话，像普通聊天产品一样使用，不需要手动“开始会话”。
- 不显示永远相同的推荐问题、固定追问按钮或无关免责声明。
- 参数与执行诊断不应回到普通聊天正文。来源、图表和必要资料可作为次级展示。
- 必要的数据真实性、样本覆盖和重大缺失应简明保留；去除噪声不代表隐瞒人工数据或未知事实。
- 正常模式必须是默认；Dev Mode 需要明确可操作的开关，并且与真实服务隔离。
- 密钥从根目录 `.env` 在启动时读取，不让用户每开一次终端重复粘贴。
- 只查技术指标的狭窄模板不能代表完整产品。缺失一个领域时，应继续利用其他可用证据回答。

#### 3.3 技术特色与简历背景

用户希望项目有区分度、架构可解释、面试时能讲清楚，而不是靠组合高级词和堆技术栈。历史上讨论过 Jev、DuckDB、证据台账等目标描述；不能据此声称当前已经安装或完成。

Jev 是用户主动提出的实验候选。接入前需要重新核验其官方项目、接口、许可、适用任务和实测效果。当前没有 Jev 依赖、实验验收或生产路由，不要自行补写“已经通过”。个人简历、实习和原始附件与当前工程交接无关，不复制到仓库。

#### 5.1 入口分工

- `api_server.py`：配置和启动；只监听 `127.0.0.1`，单 worker，无访问日志。
- `api.py`：HTTP 接口、严格请求/响应边界、同源/主机检查。
- `api_service.py / ResearchApiService`：会话令牌、幂等、额度、取消、任务分流和结果投影。
- `frontend/src/App.tsx`：聊天界面；`controller.ts`：会话与请求状态机；`api.ts`：HTTP 客户端。

#### 5.2 分流顺序不能随意改变

2026-11-12 自选模块和持仓与偏好已由 Claude 审核、提交并推送 `9aa98af`、`4faea64`。在下述研究分流及意图模型之前，本地处理明确个人管理命令，不调用模型或行情、不写聊天历史/摘要、不改变研究待澄清。管理消息仍计一条会话消息，面板接口独立于研究会话；“平安银行值得加入自选吗”“分析自选股里的平安银行”“我持有平安银行，分析走势”仍研究，不保存或自动加载个人资料。接口为 `/v1/personal/watchlist` 与 `/v1/personal/preferences`，详见[设计](memory-design.md#本机个人记忆自选股持仓与偏好)。

`ResearchApiService.message()` 只有在启用工作流、不是历史请求，且不属于旧版指标定义问题（`parse_knowledge_question()` 返回 `None`）时，才先判断是否为一般知识问题；目录中的证券名称可以否决这一分类，目录不可用不应阻断纯知识解释。其余路径加载目录，然后依次选择：

1. 完整数值选股请求 → `screening_agent.run_screening_turn()`；“筛选名单中第一只”等属于名单引用。
2. 没有待回答的身份/指标澄清、不是历史查看或指标知识问题时，名单引用 → `screening_followup.run_screening_followup_turn()`，在受控轮次内重查有效性和对象；无名单的明确序号直接说明缺口，不调用模型。
3. 满足公司研究、待澄清或续问条件且配置了公司数据服务 → `product_agent.run_product_research_turn()`。
4. 剩余 → `agent.run_natural_research_turn()`，保留原技术 Agent 路径。

这不是把所有问题直接发给一个无限制 LLM。新增路由必须考虑知识误吞股票问题、筛选误判普通研究、旧上下文误继承等回归风险。

#### 5.3 公司研究

`product_plan.py` 提取研究候选与范围，程序核对原文、可信目录、日期、指标和允许领域；`product_research.py` 收集领域证据，复用日线计算；`product_answer.py` 用有限证据回答原问题，再检查输出。

一般走势问题可以结合多个领域；明确“只看新闻”“不要技术指标”不能被模型计划覆盖。历史截止时间与未来展望期限分别保存；“未来一个月”不是获取未来行情的授权。

综合阶段没有工具。首遍出现允许修复的引用关联错误时最多一次无工具重写，使用原有证据和固定反馈；不重新抓数据、不复制不合格草稿、不放宽检查、不无限重试。引用/数字正确不代表全文语义或因果关系已经证明。

#### 6.1 筛选的特别约定

- 八字段：价格、涨跌幅、成交额、换手率、**动态 PE**、PB、总市值、流通市值。
- 模型一次提取条件；程序核对用户原文中的字段、阈值、单位、运算符、数量和排序，再计算名单。模型不改写名单数值。
- 腾讯默认按当前目录的沪主板、深主板、科创、创业各取最多 50 只；存在代码顺序偏差。当前目录未覆盖北交所身份，不能据此说北交所没有股票。
- 扩大样本档已在工作区实现、待Claude审核：显式`--screening-coverage expanded`，腾讯对每类完整目录按`floor(i × 目录数量/q)`下标均匀间隔抽取，`q=min(200,目录数量)`，每类抽满名额，小目录取全部，总样本最多1000、请求最多20，默认规模和25秒采集截止不变。东财扩大档仍用供应商分页顺序；覆盖审计单列目录未选中、尚未观察及供应商未读数量。没有联网验证扩大档速度、稳定性或全市场完整性。
- 聊天展示数量当前为 1–20；底层数值服务最大展示 50，不能把底层上限当成聊天支持范围。
- 支持已说明规则的明确双边区间；不支持 OR、歧义或复杂范围、行业/板块/ST 过滤、指定股票名单、静态/滚动 PE 等条件时，不能吞掉条件后继续执行。
- “帮我选几个潜力股”可给出明确标注默认口径的成交额活跃候选，不能改称潜力评分或收益预测。
- 筛选开始会处理旧研究上下文，取消/截止后不发布迟到候选。成功名单保存15分钟，仅以已展示顺序提供最多三只的序号/名称/代码选择；多条名单里的“它”不默认第一只。研究后普通“它”指当前研究对象，显式“名单中第二只”可继续选原名单，知识解释不延长有效期。
- 名单选择位于一般知识与完整筛选判断之后，有限条件续改在完整筛选之前，原身份/指标澄清优先。过期、目录身份或来源/模式变化时不沿用旧序号；完整具名新问题仍可独立核名。A/B均已审核提交，真实多轮质量验收未做。

#### 6.2 指标与时序的特别约定

- 原八项默认实例是 SMA20/60、EMA20、MACD(12,26,9)、RSI14、BOLL(20,2)、ATR14、量能20；新指标不会全部自动塞入每轮。
- EMA 用 SMA 初始化；MACD 柱值为 `2 × (DIF − DEA)`；RSI/ATR/ADX 使用项目定义的 Wilder 平滑；BOLL 是总体标准差。
- OBV 首条为 0，保留整数，依赖快照起点；不是资金金额。VWMA 零窗口成交量时未定义，不填 0。
- 背离的极值必须有右侧记录确认，不用未确认最新转折点。支撑压力是聚类候选，不是已验证目标价。
- 周线只聚合日历边界已完成的周；这不等于权威交易所日历已经证明记录完整。不缩短周指标周期来制造可用值。
- 回放使用前一条收盘信号、下一条开盘敞口，最后一条开盘结束；基准区间和费用假设相同。默认单 SMA20、每次敞口切换 5 基点，不支持的策略不能偷换成 SMA。

### 9. 数据、模型与配置

#### 9.1 数据源

| 用途 | 当前正常默认 | 显式替代与限制 |
| --- | --- | --- |
| 历史日线 | 腾讯直接 JSON，不复权 | `--data akshare_eastmoney`；人工 `synthetic` 需明确选择；不自动换源 |
| 证券身份 | 本地 `data/security_directory_live.json` | 由独立刷新命令读取沪深交易所；需要有效且足够新的目录，不在聊天或启动时自动更新 |
| 公司/财务 | 东方财富固定端点 | 当前结构化响应，不具备历史版本证明 |
| 新闻 | 新浪个股资讯列表 | 东方财富可显式配置；主要标题/摘要，公开接口会波动 |
| 公告 | 东方财富 | 巨潮可显式配置，已核实映射范围为深市；不是完整公告全文解析 |
| 筛选报价 | 腾讯分批采样 | `--screening-data eastmoney`；已观察过东方财富断连，无静默备援 |
| 当前交易所背景 | 未指定本地背景文件时，公司研究使用官方选定证券路径 | `--market-context` 是可信本地 JSON 配置；当前信息不能回填历史 |

正常腾讯日线支持的沪深前缀以适配器校验为准；已有范围包含科创、ST 和新股，但并不代表北交所、CDR、基金、指数均支持。筛选来源可能能返回某代码，也必须先有可信目录身份。

#### 9.2 模型

- 服务端配置 DeepSeek / OpenAI 工厂，共用工具消息协议；会话内提供方固定，切换建立独立会话。
- DeepSeek endpoint 固定为 `https://api.deepseek.com/chat/completions`；OpenAI 为 `https://api.openai.com/v1/chat/completions`。
- 这是 OpenAI API 的 Chat Completions/function tools 适配，不是登录或自动操作 ChatGPT 网页，也不是任意兼容地址都已支持。
- 默认提供方配置无效就拒绝启动；可选提供方无效则不展示；不静默跨提供方重试。
- 真实探测应复用 `model_registry.configured_models()` 的生产配置；DeepSeek 生产输出上限为 1,500 tokens。曾直接使用适配器 512-token 默认配置导致 JSON 截断，不应通过放宽校验掩盖。
- `deepseek-flash` 是此前实际验证过的账号模型标识，不保证任何账号都可用，也不要擅自更名。

#### 9.3 `.env` 与凭据

仅以下配置名需要交接，**不要读取、打印、复制或提交真实 `.env` 内容**：

```dotenv
DEEPSEEK_API_KEY=your_key
DEEPSEEK_MODEL=model_available_to_your_account
OPENAI_API_KEY=optional_openai_key
OPENAI_MODEL=optional_openai_model
```

根目录 `.env` 只在启动阶段加载；同名进程环境变量优先，**空值也会覆盖文件**。修改后重启服务，不是每次发送前重读。加载器不搜索父目录、不展开变量、不修改全局环境；独立 wheel 安装应显式提供进程环境。

用户曾在 Windows 粘贴密钥时混入控制字符。排错只检查“是否存在、是否含空白、是否 ASCII、是否可打印”等布尔值，不输出密钥。密钥不进入前端、`VITE_*`、日志、截图或交接文件。`.env.example` 是空模板，已有 `.env` 不覆盖。

### 10. 必须保留的工程约束

1. **模型提议不是授权。** 身份、日期、指标、筛选字段/阈值/单位/排序绑定用户原文和程序契约；模型不能任意增加研究范围。
2. 工具是只读白名单，服务端决定来源、路径和权限；模型/HTTP 客户端不能指定任意 URL、文件、SQL、shell 或 Python 函数。
3. 外部新闻、公告和网页都是数据，不是指令；不能扩大 Agent 权限。
4. 同轮指标、观察、图表与回放复用同份冻结日线。补指标不是重新抓一份行情；图表失败不应毁掉正文。
5. `null/unknown` 不等于 0、非 ST、正常可交易或条件不满足；不为缺失日期补价格，不缩短预热窗口制造结果。
6. 交易日、报告期、发布时间、采集时间、本地观察时间、规则生效日分开。日线日期过滤、哈希归档都不等于严格 PIT。
7. 证据 ID、股票、日期、单位和数值必须对齐本轮；不借另一家公司或旧快照的事实。
8. 引用与数字通过不代表任意文字语义、因果关系或投资判断已经证明。发现误拒应定位规则和证据，不直接移除核验。
9. 一个领域或可选归档失败时保持其他有效证据；不能用“严格”作为所有问题都拒答的理由。
10. 正常与 Dev Mode 的模型、行情、背景、会话、令牌与额度隔离；人工模式强制禁止混入实时筛选/背景来源。
11. 保留请求 ID 幂等、未确认响应的原编号恢复、取消竞态、截止检查和迟到结果发布隔离；不通过无脑自动重试造成重复付费或重复计算。
12. 预算由整轮共享，子模块不能新开控制器绕开上限。90 秒是协作截止、24,000 是已观察 token 阈值，不是远端硬中断或账单保证。
13. 当前技术循环最多 6 次模型 / 6 次工具 / 2 次分析；公司研究最多 6 次模型 / 3 次日线分析。上限不要求用满，旧入口有较小 profile，不能把所有路径统一扩到最大。
14. 保留单会话提供方固定、服务端凭据、严格 DTO、同源与主机约束。公网部署和生产账户属于独立里程碑。

### 11. Windows 上如何运行

在项目根目录使用 PowerShell。虚拟环境无需激活，不要为了激活而修改系统执行策略。已有 `.venv` 时直接使用其 Python；新克隆才需要 `py -3.11 -m venv .venv`。

首次准备或依赖变更：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[api,model,dev]"
pnpm.cmd --dir frontend install --frozen-lockfile
pnpm.cmd --dir frontend build
```

需要 AKShare 来源时再额外安装 `.[data]`，正常腾讯运行不必为此安装 AKShare。将 `.env.example` 复制为 `.env` 的操作只适用于本地文件不存在时；由用户填写实际密钥。

真实目录缺失或过期时，显式刷新（公开数据请求，不调用模型）：

```powershell
.\.venv\Scripts\python.exe -m trading_companion.security_directory_refresh --live --timeout 15
```

正常启动（默认开启聊天历史、个人记忆和有界事件正文阅读）：

```powershell
.\start.cmd
```

`start.cmd` 默认个人库为 `data\personal_memory.sqlite3`，首次正常启动创建。`--no-personal-memory` 只关个人库，保留聊天和研判回顾；`--no-memory` 禁用全部记忆，均不删除已有文件且优先于路径。正文可用 `--research-documents off` 关闭，用户后传参数覆盖脚本默认。demo/synthetic 自动省略脚本隐式个人库与正文默认值，显式开启仍按原规则报错；网页 Dev Mode 继续隔离真实库和来源。直接运行 `python -m trading_companion.api_server` 的正文仍默认关闭、个人库仍需显式路径；`ResearchApiService` 的构造默认值不变。

默认地址 `http://127.0.0.1:8765/`；可用 `--port 8767`。交接前最后运行的服务位于 **`http://127.0.0.1:8767/`**，这只是当时的本机状态，不保证未来仍运行。不要因端口占用随意结束不属于当前任务的进程。

其他显式入口：

```powershell
# Optional evidence archive; no chat persistence.
.\.venv\Scripts\python.exe -m trading_companion.api_server --snapshot-db .\data\research_snapshots.sqlite3

# Fully offline finite demonstration; no .env loading or live providers.
.\.venv\Scripts\python.exe -m trading_companion.api_server --demo

# Offline numeric screening without a model.
.\.venv\Scripts\python.exe -m trading_companion.screening_cli --demo
```

前端由 Vite 构建到被 Git 忽略的 `src/trading_companion/web_assets/`，然后 FastAPI 同源提供，不需要第二个前端服务器。修改 UI 后 build；修改后端或 `.env` 后重启 Python 服务。仅刷新页面不会加载新后端。未构建时 `/` 可返回 503，而 API 仍可使用。

页面刷新或服务重启会失去内存聊天/会话。Dev Mode 切换清理旧会话；未确认请求会阻止切换。显式 `deepseek + synthetic` 仍可调用付费模型，不等于 `--demo` 或网页 Dev Mode。

### 12. 可用于人工验收的问题

正常模式例子：

- `分析平安银行的走势，接下来一个月关注什么？`
- `只看新闻，分析中际旭创最近发生了什么`
- `比较平安银行、浦发银行和招商银行的营收增长、利润增长和ROE`
- `分析平安银行的量价配合，看看有没有背离和支撑压力候选`
- `比较平安银行日线和已完成周线方向`
- `分析平安银行，给出基于ATR的止盈止损参考情景`
- `筛选市盈率高于0且市盈率不超过20的股票，按成交额降序选5只`
- `帮我选几个潜力股`：应显示活跃样本默认口径，不能假称预测潜力。
- `市盈率和市净率有什么区别？`
- `平安银行是什么板块，什么时候上市？`：资料失败时不能用行业名称冒充交易所板块。
- `回测平安银行SMA20，比较同期持有收益和最大回撤，交易成本0.05%`

这些是验收例子，不是要求一次性全部发送真实模型。真实调用可能计费，应设明确的小样本和上限，并记录实际结果、失败及数据真实性。

- `中芯国际的涨跌幅限制是什么？`
- `回测平安银行SMA20，比较同期持有收益和最大回撤，交易成本0.05%`

股票名称仍由可信本地目录核实，模型不能靠记忆补代码。需要当前ST状态时，来源没有证据就回答未核实，不能把“未出现在一个列表里”解释成非ST。

路由1b在工作区修正六项冲突，待审核：例如先说`平安只看SMA3`，待澄清时插问`MACD是什么`，再回复`平安银行`，将继续原来的SMA3请求。知识插问不延长15分钟期限；`第一个`不能借旧筛选名单绕过证券名称确认。workflow关闭时一般知识给明确提示，不创建公司请求；异常多待澄清要求取消或重置。详见路由修正及逐轮证据。

筛选中的PE明确是动态市盈率。支持上述数值条件同时成立及明确双边区间，不支持行业/板块过滤、静态/滚动PE、OR、指定股票名单等条件；这些请求会先说明缺口，不删掉一部分条件后继续。上下界倒置、单位不明或未知附加句也先澄清。数量使用阿拉伯数字。泛泛选股且没有数值条件时，明确以成交额给出活跃样本，不将它命名为潜力预测。

筛选名单在同一会话有效15分钟，可按表格序号、名称或代码选最多三只研究；知识问题不消耗或延长名单。多只名单只说“它”会要求明确对象；选择并研究后，“它”指当前研究对象，“名单中第二只”仍可继续选其他成员。名单过期、身份/模式变化或清空会话后不能沿用旧序号；重新筛选取数失败或取消也不回退到旧名单。B部分已由Claude复审并提交、推送为`5b0031c`；有效续改不调用模型，重新采集整个配置样本，成功后展示全部新条件并更新序号。详见[筛选与续接规则](market-and-screening-design.md#有界-a-股报价样本筛选)。

回放默认SMA20及单次敞口切换5基点成本；明确参数时支持一个SMA，不把其他策略静默改成SMA规则。前一条收盘产生信号，下一条开盘调整敞口，最后一日开盘结束；基准使用完全相同的区间和入场/退出费用假设。数据太短就说明不足。

### 3. 数据与模型如何协作

```mermaid
flowchart TD
    Chat[用户问题] --> Session[同源API与独立会话]
    Session --> Route{任务分流}
    Route -->|知识| Retrieve[本地版本化片段检索]
    Retrieve --> Explain[模型解释与逐段引用检查]
    Route -->|筛选| Conditions[模型提取条件]
    Conditions --> Ground[程序核对原文 字段 阈值 单位 排序]
    Ground --> Quotes[批量报价样本与身份核对]
    Quotes --> Filter[程序筛选 排序 覆盖统计]
    Route -->|公司或技术研究| Plan[名称 日期 领域核对]
    Plan --> Data[财报 新闻 公告 日线 交易所背景]
    Data --> Compute[指标 信号 比较 风险情景 或固定回放]
    Compute --> Answer[有界证据供模型回答原问题]
    Answer --> Validate[引用 数字 公司归属与范围检查]
    Explain --> UI[自然主回复与折叠来源]
    Filter --> UI
    Validate --> UI
```

首次筛选只需一次模型意图提取，有限条件续改不调用模型，数值名单均由程序生成；一次批量快照读取不等于一次HTTP请求，腾讯默认200只当前需多批请求。公司研究最多三只明确候选，共用原模型/日线分析额度与协作期限。知识解释不请求行情，历史回放复用同份日线，不重新取数。所有路径都没有下单通道。

筛选默认腾讯，按各板块代码顺序取有界样本；当前目录没有北交所身份，不把0条目录记录当成市场没有股票。可以显式启动`--screening-data eastmoney`选择另一来源，失败不会自动换源。真实测试中东方财富列表出现过断连，因此没有将其设为默认。Dev Mode隔离真实筛选和交易所背景来源，不从正常模式借数据。

扩大档以整个板块的可信目录为基础，取`q=min(200,目录数量)`个均匀位置，下标为`floor(i × 目录数量/q)`，可触及代码靠后的对象；每类抽满名额，小目录取全部。它不是随机代表样本，也没有核验股票上市年代。覆盖审计把目录未选中、目录中尚未观察到可核对报价、供应商未读页和选中但缺报价分别说明，读取完配置目录或供应商列表仍不等于证明全市场完整。默认标准档不变。

### 2. 最终数据流

```text
Web / 终端
  -> 本机应用服务与会话
  -> 初始问题由模型提取候选；有限修改从已校验状态继承
  -> 程序核对证券身份、日期、指标和启动来源
  -> 模型提议工具调用；程序严格比对本轮请求
  -> 只读工具：一次分析，读取所选来源并做确定性计算
  -> 事实报告 + 结构化关系检查 + 程序四维度综合
  -> 同一结果的文字、证据、图表与已冻结的可选背景
```

`safe_answer`、`explanation_validation`、`research_synthesis` 是不同的验证结果：事实成功不等于模型解读成功；模型失败时，程序仍可展示自己独立核对的参考比较，但 Agent 保持 `limited`，不伪装模型通过。

综合模块不采用任意模型文字，也不信任现有关系标签；实际用到的最新/紧邻前一条数值及其 fact 必须重新匹配。历史概览从原请求/结果重新生成，0次模型、0次行情；只问 RSI 的追问不被扩成全套综合。停止只留此前核验的事实，取消不展示本轮结果；所有请求的计算字段都不可用时，不生成综合解读。

本轮保留模块化单体、原进程内接口和既有额度，没有增加代理数量、模型调用或数据库依赖。开发协作子 Agent 不等于产品使用多 Agent。

### 3. 会话与来源的明确取舍

- 窗口澄清绑定原请求、原证券、可信来源和目标窗口；15分钟有效，不能用短答延长原研究基准寿命。额外条件不能被静默忽略。
- “看最新的”保留股票、指标、来源及自然日跨度，创建新研究。日期相同也可按明确刷新重跑，但须说明没有发现新行情。人工模式仅重跑固定样例。
- 来源仅在启动时选择。同一服务内固定一种来源；要换源，停止并按新来源重启、创建新会话。旧结果不能改标签冒充另一个来源。
- AKShare 缺依赖时先返回 `data_dependency_missing`，不先读取模型配置；包存在不等于供应商连通或数据正确。

详细规则见 [综合解读](answer-design.md#跨指标现状综合解读)、[会话收口](architecture.md#mvp-会话收口窗口澄清相对日期与历史日线刷新) 和 [来源选择](research-data-design.md#产品入口的显式行情来源选择)。

### 4. 如何运行

真实 DeepSeek 模式现在支持源码项目根目录 `.env`：填写 `DEEPSEEK_API_KEY` 与 `DEEPSEEK_MODEL` 后启动，不再需要每次终端输入；终端环境变量仍优先。见[本地配置与启动](operations.md#本地模型配置与启动)。离线 `--demo` 不读取文件或密钥。

项目根目录中，先完成已有安装与构建，不必激活虚拟环境：

```powershell
.\.venv\Scripts\python.exe -m pip install -e '.[api,model,dev]'
pnpm.cmd --dir frontend install --frozen-lockfile
pnpm.cmd --dir frontend build
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.api_server --demo
```

打开 <http://127.0.0.1:8000/>。`--demo` 是有限的固定脚本，不是能自由理解任意输入的假模型。后端更新后需重启服务；无请求执行时再刷新页面，重启会丢失内存会话。

自由输入须显式启用真实 DeepSeek；以下命令可能计费，需用户自行配置模型凭据：


真实历史日线模式：

```powershell

```

东方财富需额外安装 `.[data]`，然后把 `--data tencent` 改为 `--data akshare_eastmoney`。两个命令都需当前可用的真实本地证券目录；目录刷新是单独的显式联网操作，不由服务自动执行。终端入口 `trading_companion.agent_cli` 接受相同数据模式。

场景涵盖七类单指标、完整组合、历史不足、默认参数、名称/代码/歧义、多股票、日期边界、知识、不支持的交易/新闻任务、澄清续接、指标修改、刷新、相对日期及保存结果。

30场景每轮计划67次模型方法调用，3次共201次；90个场景实例包含72次分析。离线的调用只是固定 `FixtureModel` 方法，不是付费请求，也不证明自然语言理解能力。重复之间重建模型与会话，失败即停止，不以重试挑选好结果。

报告逐步核对状态、完整研究范围、调用预算、模型解读状态、失败码、综合摘要和显示内容。部分成功不能掩盖模型解释被拒绝，程序综合失败也不能被顶层 `completed` 掩盖。

报告只写标准输出，不自动保存文件；含执行时间、参考日期、逐响应模型名、系统提示词与工具定义的 SHA-256、可见安全回答、已知 token 加总及步骤墙钟时间 p50/p95。不导出原始模型草稿、提示词原文或凭据。指纹不是完整上下文/模型权重版本，保存结果的动态请求编号也会影响系统提示词指纹；复核时还应记录 Git 提交和运行环境。缺失 usage 保持未知；耗时不是生产延迟基准。

原 `agent_evaluation` 四场景入口保留，适合小额度排错；新入口用于更宽的 MVP 固定行为集。两者都不评收益或预测准确率。

若用户决定做真实模型评估，可在上述完整命令增加 `--provider deepseek`，显式允许最多201次潜在付费调用。**本次开发没有执行它。** 即使真实固定场景全部通过，报告仍标记 `pending_live_repeats_and_human_review`，需要人工检查回答、失败原因和条件，而不是自动宣布产品验收。

## MVP 会话收口：窗口澄清、相对日期与历史日线刷新

本模块只扩展已有研究条件的有限修改，不是通用聊天记忆，也不授予模型下单权限。

### 1. 模糊窗口修改

已验证研究包含 SMA3、SMA4、RSI2 时，用户说“改成5日”，应用不能自行挑第一条指标：

1. `window_edit_candidates()` 检查整句并生成候选，不调用模型或行情。
2. `ResearchSession` 保存 `PendingIndicatorEdit`：原完整请求、证券身份、目标窗口、候选、创建时间、可信数据配置。
3. 返回 `indicator_edit_ambiguous`，状态为 `awaiting_indicator`，列出用户可复制的原指标标签。
4. 用户只回复“SMA3”时，`resume_indicator_edit()` 重查原基准、当前目录、来源配置及15分钟时效。
5. 校验通过后恢复原来的“改成5日”目标，消费待澄清请求，创建新 request ID 并重新分析一次。

候选唯一时直接执行；MACD 无单独 window，不猜 fast/slow/signal。泛称“均线”只列原组合中的 SMA/EMA。无待澄清请求的短指标不会启动新研究；附加股票、日期等子句不被静默忽略。用户也可重述完整、明确的一项指标修改，替代待澄清修改。

身份澄清和指标澄清互斥。有效回复、取消、清空、新问题、开始新研究、过期或基准失效都会消费或清除待澄清修改。无效短答不延长原请求时效，也不延长原研究基准15分钟的时效。

### 2. 相对日期修改

“改成最近一个月”“把日期改成最近30天”复用 `research_intent._dates()` 的现有算法，而不是让模型换算日期：

- 截止上海前一自然日，包含首尾日期。
- 一周7天、一月30天、一年365天；总区间最多366自然日。
- 股票、指标和数据来源不变，产生新请求重新计算。
- 今天、未来、交易日口径、复合条件不猜，要求用户澄清。

标记 `dates:relative_update`；月/年同时标记 `relative_unit:30_days_per_month_365_per_year`。算法口径和明确日期会进入可见消息。

### 3. 有限整句刷新

“看最新的”“更新到最新”“刷新行情”等完整命令，只把原自然日区间平移到上海前一自然日，保留股票、指标、来源及区间长度。

这不是实时行情，也不保证前一自然日是交易日。合成样例入口使用应用配置的固定参考日期，不查询真实市场。若日期没有变化，明确刷新仍允许新分析，但消息必须说明“区间未变化，重新计算，不代表发现了新行情”。

标记 `dates:refresh_latest_previous_day`；日期不变额外标记 `refresh:same_dates`。不静默换源、不重复使用旧结果。

### 4. 数据流与取消隔离

`用户整句 → 有限路由/解析 → 可信会话基准校验 → 合并一类条件 → 新请求 → 模型工具提议严格比对 → 确定性计算 → 事实检查 → 会话保存`

待澄清状态通过现有 `_fork_for_turn()` / `_publish_turn()` 暂存与发布。真正开始新研究前立即消费父会话旧基准和 pending；取消、超时或迟到模型返回不能重新发布待澄清请求或旧研究基准。

### 5. 主要接口与验证

- `research_edit.py`：整句窗口候选、显式标签和短答解析。
- `research_update.py`：相对日期、刷新命令与条件合并。
- `research_session.py`：待澄清状态、可信基准、时效和身份检查。
- `agent.py`：路由和现有执行链整合，不绕过提议检查或 TurnControl。
- `tests/test_mvp_conversation.py`：离线覆盖窗口恢复、额外子句、身份与配置变化、取消和迟到隔离、日期口径、固定样例刷新及模型/分析调用预算；测试禁止真实 HTTP 和密钥读取。
