## 候选行为

`research_intent_v2.py` 当前协议为 `research-intent-v2.5.4`，护栏版本为 `intent-v2-guards-v9`；前四轮公开运行的版本分别为 v2.5 / guards-v5、v2.5.1 / guards-v6、v2.5.2 / guards-v7、v2.5.3 / guards-v8。护栏是对模型提案的程序核验，不授予查询行情或执行交易的权限。任务、领域、日期、指标及价位依据仍须来自本句，只有有效原生期限待办可提供原已授权的目标及价位依据。格式、类型、枚举和出处检查继续执行；程序规范化在提案副本上进行，历史运行产物不改写。

- 具体 ETF、基金、期货、期权研究进入语义路径后拒绝，不绑定跟踪指数；概念可解释，产品作为公司背景不自动拒绝股票研究。保留原 V2161–V2164 的一次理解口径。模型提案只有通过结构和出处核验后，才可按产品能力边界降为拒绝。
- 已知不支持指数复用 `market_selection()` 的本地拒绝；身份未知仍澄清。历史命令和冲突待办直接复用 `route_research_request()` 的生产优先级和规范化。历史引用经现有缓存校验器核对，在会话私有副本上检查，避免校验器的清理操作改变原会话。没有有效保存结果也不调用意图模型。
- 普通继续、序号在多待办冲突时本地澄清；取消、历史优先；完整独立新任务可以绕过旧待办。公司和指数的严格整句期限回复，在 899 秒内可续接，900 秒起、时钟回拨、来源/模式/身份变化时本地澄清。失效时为空绑定、无价位授权，analysis 为中性占位，保留本句期限。带额外条件的回复进入完整理解。
- “同一只/同一只股票”先按最近完整单对象指代检查，不把“一只”当序号。多对象、无记录、未来发布、身份失效、来源/模式变化或关闭记忆均不猜对象；真实序号仍由既有选择器核验。
- v2.5.1 对“这两只、前面这两只、它们、这些”等完整整体指代先于单对象序号处理，仅绑定最近合法多对象；带数词必须与实际数量一致，单对象、失效状态或数量不符仍澄清。明确问题对象的 selection 若与某个 mention 完全重复，清掉冗余 selection 并记录纠正；不清掉其他冲突，也不补造遗漏对象。未知指数身份保持空绑定和身份澄清。
- v2.5.2 对“上一份比较里的第二只”等完整中性前缀，只在最近合法多对象研究中抽取序号，并记录 `previous_research_ordinal`。前缀由“上一份/上次/刚才/前面”、比较/研究/报告等受限词及连接词构成，不接受任意前缀；不能跨到待办或同时保存的筛选名单。数量越界、单对象、身份/来源/模式/时序失效、无有效研究时仍澄清；前缀含其他证券名、历史编号或名单时不剥前缀，保留原有作用域核验。
- 身份歧义与任务分类分开，已确定股票/指数任务时保留 task，以空绑定和 clarify_identity 表达身份问题。
- v2.5.3 对模型将未知指数研究写为 clarify 的情况，依据本句明确的指数对象及研究表达恢复 index_research，记录 clarification_task；身份仍不绑定，仍澄清，不放宽基金、混合对象或指数领域能力检查。此前任务纠正要求绑定成功，遗漏了身份未明的情况。
- 日线、周线、K线属于 technical，不能当指标；成交量是指标。指数明确的 technical 不再被清空，已移除 `index_default_domain` 纠正。公司情况、业务情况及主营业务在提示词中明确为 profile；泛称某公司情况不强加领域。
- v2.5.1 对肯定要求的指标或日线/周线/K线补齐 technical，保留原文依据并记录 `explicit_technical_cue`；否定或排除不提供依据，严格范围和冲突检查继续执行。仅走势、价位依赖或否定 ATR 不补领域。提示词区分“经营现状/近况”和公司概况；并列领域可复制同一整段原文，不拆出不存在的片段；“放下/转向”不造排除；同一对象增删条件为 update，仅重算或更新数据为 refresh。
- 否定及移除支持通用动词和领域/指标映射，保留完整原文片段、协调列表、长句尾部及同轮冲突。否定唯一限制不等于排除领域或指标；仅限定时间范围也不设 strict_scope。
- v2.5.2 对肯定领域与排除领域相交，保留排除、删除相交领域，输出 `clarify_conflict` 并记录 `domain_conflict`；指标相交同理，记录 `indicator_conflict`，保留不被排除的指标及其原文参数，严格范围不清空，也不授权默认指标。结构、出处、否定依据、严格范围证据和非冲突领域的能力检查继续执行。“原样”视图仍保留修补前的无效状态。操作类别只补充通用提示词：旧任务仅更新数据/最新情况/筛选结果为 refresh，实际改条件为 update；失效对象不因增补语气变得可续接。
- “这 N 天/周/月”仅在候选内按近 N 天/N×7 天/N×30 天适配，复用生产原有自然日计算，截止参考日前一天，输出仍保留原文。“本月”“这三个月以来”和自然季度不套该规则。生产日期解析器原样保留。
- 非法、倒置、过长或未完成日线窗口保留请求的日期原文并澄清。未来实际数据不能因提取成 horizon 而变为可执行价位情景；未来相对事实不填历史 date_expression 或未来观察期限，明确日历日期仍保留原文。方向预测和明确条件情景仍可研究。不支持指标保留原文并澄清，日线误填指标仍拒绝提案。
- v2.5.3 明确量化期限如“未来0天”解析失败时，clarify_conditions 优先于模型给出的 clarify_horizon，记录 invalid_horizon；冲突、身份/对象失效和拒绝仍优先。原期限文本保留，不继承旧期限；真正缺少期限、泛称“以后”和合法期限沿用既有规则。operation 仍只补通用提示词，不由程序改写。

本地路径为零次目标理解；普通语义路径通常一次，仅按下文批准的格式失败策略最多重问一次。模型固定为 deepseek-flash、temperature=0、thinking=disabled、1500 输出 token 上限。token 是模型文本计量单位；零温度不保证完全确定。

## v2.5.1 的 JSON 诊断和有界修复

#402 指定的公开 v2.5 开发运行中，V2033 和 V25D012 在传输层解析工具参数时失败。原报告和尝试账本的 response=null，没有保存长度、结束原因或解析位置，因此不能确定这两次的具体病因；不从别处找正文，也不重跑补证据。#404 要求本轮同时落实以下诊断与修复。

传输适配器默认不修复。只有显式开启诊断、提供安全记录通道，并声明当前 v2.5.4 意图工具时才能开启修复；其他工具、旧候选和正式聊天拒绝此修复配置。公开候选评估的独立模型构造显式开启，旧 v2.4 评估工厂和准入路径原样保留。

先严格解析完整 JSON。首次失败后，可以独立尝试下述单处裸值修复、字符串内未转义控制字符的 `strict=False` 解析，或去掉一层完整 markdown 代码块／完整对象后单纯的尾随说明。每种修复均从原文开始，只接受唯一完整的顶层对象；不搜索前缀文字中的对象，不合成结尾，不组合多种修复。多对象、重复键、截断、非对象、非有限数、过长或过深结构仍失败。模型结束原因为 length、aborted 等中断时，即使参数看似完整也不解析和修复。

v2.5.4 新增 `unquoted_scalar`，即对象键对应的文字值漏加双引号。只在首个严格解析错误正好是对象键冒号及空白之后的值起点时尝试；扫描前缀时跳过完整字符串，排除字符串中的假键和数组元素。裸值必须在下一逗号或右花括号处结束，文字长度 1–200，不含引号、方括号、花括号、冒号、反斜杠或换行，不为布尔/null/数字。只补这一处引号，然后严格解析整份对象；两处裸值或同时有其他格式错误均不修。不依据题号或答案决定是否修复。

成功修复仍须通过 ToolCall（工具调用参数及标识符核验）的标识符、重复键、大小、深度等校验和完整意图的结构、枚举、原文依据、范围、身份校验。记录 `tool_arguments_repaired` 及 control_char / code_fence / trailing_text / unquoted_scalar 类别和原始错误位置。默认失败诊断只记录调用序号、参数字符数、受控结束原因、解析位置/行列和受控类别，不保存失败正文、片段、解析器原话或任意异常。中断的解析位置保持未知。每次尝试先落盘预留计数，诊断关联同一题目与尝试，并同步落盘。v2.5.3 评估工厂的显式原文保存例外见下节。

报告单列修复总次数、类别和题号；修复后的响应明确标为 `repaired_tool_arguments`，不冒充服务商的原样提案。“原样+原标注”评分列仍按修复前格式失败计分，纠正后评分列才使用通过检查的结果。修复不重试、不增加调用次数，也不改变失败分母。

## v2.5.3 的评估原文和格式重问

#410 提出、#411 细化且 #412 批准以下策略例外。传输层 `save_failed_arguments` 默认关闭；只有显式指定 public/sealed 评估作用域、开启诊断、提供接收器、声明当前候选工具时可开启。仅最终 `tool_arguments_json_invalid` 保存失败的工具 arguments 原文，单事件最多 10000 字符，附原长度及截断标记。过大参数先按既有协议上限拒绝。只保存模型工具参数，不保存 HTTP 正文、头信息、解析器原话或异常文本。公开工厂显式开启；sealed 配置只供未来工厂复用，不提供新的封存入口。报告注明“评估工件包含失败的模型参数原文”。

仅当前候选公开评估显式开启一次格式重问，触发为 `tool_arguments_json_invalid`；其中 `incomplete_json` 诊断只在 finish_reason=tool_calls 的参数解析阶段产生。length/aborted 中断、网络、超时、HTTP JSON 错误、拒绝、工具结构错误、语义失败均不重问。第一次保留前述有限修复；v2.5.3 第二次完全关闭修复，v2.5.4 按 #417 改为第二次仅允许 unquoted_scalar，其余类别仍关闭。再次失败不再调用。消息、上下文、工具定义、模型参数完全相同，不追加提示。

每题最多 2 次，请求次数、已观察 token、取消状态及整个轮次的截止时间共用同一控制器，不因重问重置。共享 `ControlledToolModel` 增加显式关闭网络重试的选项，默认仍保持原网络/超时重试行为；候选关闭它，自行仅安排格式重问。每次请求前分别持久化预留全局预算，题内及全局序号、诊断、耗时、响应和失败类别逐次保存。总上限 dev 233、regression 85 **包含重问**，不翻倍；没有余额就保留原失败，所有未测保留完整分母。

报告单列重问总次数、第二次解析（仅允许单处裸值修复）且语义核验成功次数及题号，并与本地修复分类分别统计。第二次语义不合格不计成功。原样视图保留第一次格式失败，规范化视图才使用第二次合格结果；response_origin 明确为 format_retry。计量按每次尝试统计，解析失败的响应及用量保持未知，不按零补齐。旧成绩注明当时的调用策略。

冻结文件不改。#412 明确第三批最终封存检验须使用相同候选行为；届时 Claude 审核运行器和锁时另行登记“每题一次”文字的策略例外、总上限和每题上限。本批不运行封存预检或检验。

## v2.5.4 的价位依据与日期片段

提示词明确 plan_phrase（请求价位的原文依据）只填肯定请求，否决片段填 exclusions（排除项），wants_plan=false 时该字段必须为 JSON null；所有字符串加双引号。程序在原有结构、出处和排除依据核验后，对 wants_plan=false 的非空 plan_phrase 清空：精确等于合法 plan 排除片段时记 vetoed_plan_phrase，其他记 unused_plan_phrase。不新增矛盾拒绝，不把 wants_plan 改为 true；已有伪造出处、错误字段类型和非法排除仍按原规则拒绝。原样提案和原样视图不改。

日期片段如“这三个月的K线”仅在共享解析器实际识别到该字段的唯一日期前缀、前缀仍为本句及字段原文子串、独立解析合法且与已核验历史窗口一致时，裁为“这三个月”，记 date_expression_prefix。“这”到“近”的适配保持长度相同，输出仍用原话。完整日期不裁；多个日期、未覆盖日期条件、“以来/之前”等后缀、非法或未来窗口均不靠裁剪放行。生产共享日期解析器保持原状。

生产规则源码有独立校验值，行为等价的重构也会使旧题库的基线检查失败。因此本批直接复用现有生产路由函数，候选日期适配也留在候选文件中，没有修改生产路由或重写基线。共享调用包装器只有上述默认兼容的重试配置扩展，并单独回归测试默认行为。

旧 v2.4 锁记录的是旧源码。当前候选变化后，旧运行器应拒绝锁漂移，不能重新生成旧锁来放行。对应测试拆为真实当前仓库拒绝旧锁，以及独立快照下的运行机制测试；真实准入路径保持原状。旧运行报告、45/83 的检验失败及调用记录均原样保留。
