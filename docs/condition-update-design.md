# 会话内研究条件修改

日期：2026-10-22（America/Los_Angeles）

状态：明确修改语法及离线验证已有；未新增真实模型、行情或目录请求。

## 1. 本模块交付

在同一会话已有可信研究后，支持换股票、明确改日期、添加或删除一个指标。未修改的字段继承自程序保存的 `confirmed` 条件，而不是从聊天或旧模型草稿恢复。

| 用户输入 | 改变 | 保留 |
| --- | --- | --- |
| `换成中国平安，其他不变` | 由目录核实的新股票 | 原具体日期、指标、来源 |
| `把日期改成2026-09-21至2026-09-24` | 起止日期 | 股票、指标、来源 |
| `把截止日期改成2026-09-24` | 截止日期 | 原开始日期及其他字段 |
| `把开始日期改成2026-09-22` | 开始日期 | 原截止日期及其他字段 |
| `添加ATR2` | 增加一个明确实例 | 原指标顺序、其他条件 |
| `删除RSI2` | 删除一个已有实例 | 其他实例和研究条件 |

原“把SMA3改成5日，其他不变”继续走已有同类参数替换接口，不改变其错误码和行为。

每条只修改一个明确维度，日期区间的两个边界视为一类修改。不接受一句同时换股票和改指标，不接受一次添加/删除多项，不接受对话内换数据源、“看最新的”、相对日期更新或任意中文条件重写；不会先做能理解的半句话。初始自然研究问题仍使用原模型理解链路，本模块只是明确修改命令的程序分支。

## 2. 为什么不让模型重写整份请求

旧条件已经核实，明确“添加ATR2”没有必要再请模型猜股票、日期和来源。程序直接合并唯一变化，成本和待核验输出更少；进入执行后，模型提议仍必须与合并请求完全相符。

没有新增框架、模型、数据库或工具权限。改条件不是直接改报告标题，也不是复用旧计算。每个可执行更新构造新 `request_id`，沿用原研究流程，最多两次模型调用、一次分析尝试；失败不自动重试或换源。

## 3. 数据流与职责

```text
明确修改句
  → 共用检查：可信基准、15分钟期限、当前目录、来源和日期限制
  → 完整解析为不可变 ConditionUpdate
  → 仅合并指定维度，重新校验领域契约
  → 新股票需目录确认；有歧义先保存pending、等待选定
  → 新请求就绪后清旧编辑基准、将旧结果降为历史
  → 原模型提议绑定 → 工具执行 → 指标/证据 → 事实及关系检查
  → 有可信事实才保存新条件和新结果
```

- `research_update.py`：完整语句解析及纯条件合并，不调用模型、目录网络或行情。
- `ResearchSession._checked_edit_base()`：原指标替换与新修改分支共享当前有效性检查，避免两套授权规则漂移。
- `prepare_condition_update()`：核实新证券、组织澄清或生成新请求；不直接执行工具。
- `agent.py`：分流、持有会话锁、执行前消费旧基准及成功后记录；执行逻辑不复制。
- `agent_cli.py`：显示已确认名称/代码、新条件和修改口径，不负责合并业务参数。

不传同一 `session=` 或没有有效基准时返回 `no_confirmed_research`，不从旧历史结果重新激活修改条件。每会话状态继续隔离，并发输入仍由原锁拒绝。

## 4. 股票修改与身份澄清

新股票支持完整名称、已核实别名、唯一裸代码及完整代码；使用整个目标字符串查当前目录，不让模型凭记忆给代码。

- 目录唯一匹配：核对来源支持范围，再以新证券和原条件构造请求。已明确匹配为原股票时为无变化，不重复查询。
- 多候选、部分名称或未知名称：0次模型、0次行情，保存原日期/指标/来源，要求完整名称或代码。候选存在时不得选择候选以外的证券；无候选时允许用户纠正完整身份。
- 用户澄清后复用原 `resume()`：检查当前目录、候选是否更名、时效和来源，执行前消费待选请求。无效回复不延长15分钟期限。
- 等待确认时，另一条修改不能绕过选股；可回复“取消”撤掉待选，或用“新问题：”重置。
- 待选不覆盖原可信基准和结果；取消后原基准在期限内仍可用。显式历史查看及有限知识解释也不消费待选。

不把“换成RSI14”当成股票，不把“换成腾讯/今天/最新”当成新证券。对明确附带指令的名称表达也拒绝；这些有限规则不证明任意语言意图都能正确识别。

科创板、名称含ST及新上市样例不因标签被排除；目录身份不证明历史ST、上市日、停牌或可交易性。腾讯等来源的既有前缀限制仍有效，不能靠换股票扩大范围。

## 5. 日期、指标与默认值

日期只接收完整ISO日期。区间须含首尾1–366个自然日；在线研究截止日必须早于当前上海日期。不隐式补预热历史，不因改指标或换股票而重算原相对日期。明确改日期时使用本次可信日期锚点，并显示新边界；只改截止日不擅自再回看365天。

开发CSV继承原开发契约，不因它允许固定样例日期而宣称在线可查询今天或未来。样例和在线时间约束继续分开。

添加指标须明确一个实例及参数，例如 `RSI14`、`BOLL(20,2)`或`MACD(12,26,9)`；不默默给“添加RSI”补14，也不把“添加均线”扩成两条。重复、非法参数和第13个实例均拒绝。

删除可用完整实例，或唯一匹配的类别名称；原组合含SMA20和SMA60时，“删除SMA”要求重述完整删除句，不自动选第一条。不存在的目标不执行，最后一个指标不能删空，也不回填默认组合。

默认口径标记随维度修订：显式改日期后清除旧“前一自然日/365天/相对月年”标记，添加删除后清除“默认8项”。未修改维度的历史解释保留；程序始终显示具体日期和完整指标范围。

## 6. 失败和历史结果

本地无效修改、歧义或无变化不执行，原可信基准及结果不变，不延长期限。请求就绪进入执行后，先消费旧编辑基准并将旧结果设为非当前；模型超时、提议不符、无数据、错误股票数据或中断都不能恢复旧基准。

新查询未取得可信事实时，只能通过“查看上次结果”或 `/last` 显式查看旧成功结果，并标明旧股票、日期、来源和历史身份。“这里RSI多少”不能偷偷读旧结果。事实有效但模型解释失败时，可保存新事实，不保存失败解释。

人工CSV只含平安银行5条记录。换中国平安后，原CSV不是该股票的合法数据；当前校验返回 `research_data_failed`，不是成功报告，也不将错股票数据静默改名。端到端测试另用显式标记的人工证券数据验证成功换股，不冒充真实中国平安行情。

## 7. 无凭据演示

在项目根目录PowerShell运行：

```powershell
$env:PYTHONPATH='src'
.\.venv\Scripts\python.exe -X utf8 -B -m trading_companion.condition_update_demo
```

固定演示依次运行：研究→添加ATR2→删除RSI2→改截止日→“平安”歧义→选择中国平安→查看旧结果。包含预期的跨股票数据拒绝；整体返回0代表演示符合预期，不代表每次研究成功。

总计10次Fake模型调用、5次分析尝试，其中4次有可信研究，第5次拒绝错股票CSV。没有密钥、付费调用或网络请求，不接受自由输入；这不是交互终端，因此不改变真实CLI原来的5条问题/15次转发上限。

自己输入仍沿用显式DeepSeek终端模式；研究修改可能计费，本步没有代用户运行。当前快照15分钟期限、`/last`不占问题额度、重置不补调用额度等原规则不变。
