## 1. 这份文档解决什么问题

PRD 是产品需求文档，用来约定“给谁用、解决什么问题、做到什么程度、如何判断做完”。技术设计文档则进一步规定模块、接口、数据结构和实现方式。

这份 PRD 不要求一次性实现完整交易助手。它定义接下来可以开始开发的第一个产品 agent，以及它与长期产品规划之间的关系。

文档中的范围划分是本期建议；默认窗口、运行预算、对话界面和验收阈值均为待确认的设计值，不代表当前代码已经支持，也不代表已经测得的性能。

## 2. 产品定位与长期方向

### 2.1 长期产品

面向 A 股个人投资者的交易研究与决策辅助工具：解释交易知识，结合行情、基本面、公告和新闻分析个股，逐步支持选股、条件化走势判断和有明确方法依据的止盈止损研究。美股后续扩展。

所有实际交易由用户自行完成。产品不获得券商交易权限，不代用户下单、撤单、修改订单或管理资金。这是长期边界，不是仅对第一版的限制。

本项目不以训练股票模式预测模型作为前提。价格指标由程序计算，语言模型负责理解问题、选择允许的工具、解释证据与不确定性。使用预训练模型不等于自行训练股票预测模型。

### 2.2 本期交付

用户用中文提出一个单股票日线问题，agent 在必要时澄清参数，获取可验证的数据，结合均线、MACD、RSI、布林带、ATR和量能解释市场状态，明确展示证据、指标之间的一致或冲突、日期及限制。

一句话：**先做一个能够说明“我查了什么、算了什么、依据是什么、哪些还不知道”的研究助手。**

本期不承诺预测收益或提高胜率；技术含量来自可测试的工具调用、状态处理和证据约束，而非堆叠框架名称。

## 3. 用户与核心场景

第一位用户是项目开发者本人及少量受邀测试者。默认用户能理解股票代码，但不一定熟悉指标或数据口径。本期没有账户体系、付费、真实用户规模或生产服务承诺。

| 场景 | 用户希望完成的事 | 产品应提供的帮助 |
| --- | --- | --- |
| 日线分析 | “看看 000001.SZ 最近的走势” | 使用默认指标组合，从趋势、动量、波动和量能四个方面解释 |
| 指标问答 | “MACD和RSI的信号为什么不一样？” | 解释指标观察角度、关联性与不能推出的结论 |
| 连续追问 | “把SMA20改成5日，其他不变” | 正确继承已确认条件，仅修改指定指标参数 |
| 历史截面 | “只看截至 2025-09-05 的数据” | 严格使用截止日内行情，不讨论之后实际发生的走势 |
| 异常理解 | “为什么查不到？是不是停牌了？” | 区分查询失败、无数据和历史不足，不擅自推断原因 |

## 5. 范围：本期做什么，不做什么

### 5.1 P0：本期必须完成

1. 中文单股票日线分析，每次分析一个股票、一个日期区间和一个受限的指标组合。
2. 股票或时间含义不明确时先追问，不猜测后直接查询。
3. 日线数据取自指定数据源，所有行情数字与计算关系来自程序结果。
4. 解释本期各项指标的含义、参数、历史不足和初始化影响；综合描述指标的一致与冲突，不做简单投票式买卖判断。
5. 支持同一会话内选择指标、修改指定参数、日期、股票，以及对已有结果追问。
6. 明确处理无数据、历史不足、网络失败、无效数据和模型失败。
7. 默认真实数据源为腾讯；允许启动时显式选择现有东方财富源。同一服务/终端内固定来源，不自动切换；换源需重启并建立新会话。
8. DeepSeek 作为首个计划接入的模型提供方；具体可用模型在接入时验证。
9. 使用终端对话作为首个交互入口，保留现有参数式 CLI。

### 5.2 本期不做，但保留在后续产品规划中

- 全市场筛选、多股票比较、组合管理。
- 新闻、公告、财务指标和公司事件研究。
- KDJ、OBV、复杂K线形态、自动背离/支撑阻力识别，以及把多指标转成可执行买卖策略。
- 数值化止盈止损目标、仓位建议和具体交易策略。
- 收益率概率预测、策略回测、模拟成交和收益/回撤评价。
- 严格 point-in-time 数据库、历史修订追踪及完整证据台账。
- 自动识别 ST 身份、上市日期、停复牌及交易规则。
- 实时行情、分时线、当日尚未完成的日线。
- 原终端首版不要求UI；后续已补本机最小Web及历史K线/指标展示，不含实时图表、移动端App、用户账户、长期记忆与后台定时任务。
- Jev 接入、自行训练预测模型或多 agent 研究团队。

“暂不做”不表示取消长期需求，而是避免让首个可运行版本依赖整个产品先建设完成。

### 5.3 A 股覆盖约束

- 腾讯当前支持的代码前缀：SH `600/601/603/605/688`；SZ `000/001/002/003/300/301`。
- 支持范围内的 ST 和新股不因类别而被主动排除；数据不足时如实返回。
- 没有证券主数据与历史风险标签前，不得声称某股票“不是 ST”“已上市足够久”或“可以正常交易”。
- 腾讯暂不支持北交所、`689` CDR、基金和指数；这些请求应明确说明本期覆盖限制，不偷偷换数据源。
- 切换到另一现有源时仍须经过该源的参数校验；支持代码格式不等于数据存在或单位已全面验证。

### 5.4 本期指标清单

以下7类指标均纳入本期。用户泛问“分析走势”时使用默认组合；明确只问某项时只计算所请求的指标及其内部依赖，不强制输出全部指标。内部依赖不重复占用用户指标名额。

| 观察角度 | 指标及默认参数 | 返回内容 | 用途与解释边界 |
| --- | --- | --- | --- |
| 趋势 | SMA20、SMA60 | 两条均线、价格相对位置及有效的均线关系 | 描述不同尺度的趋势；多条均线不是独立证据 |
| 趋势 | EMA20 | 指数移动平均线、价格相对位置 | 较重视近期价格；更敏感不代表更准确 |
| 动量/趋势变化 | MACD(12,26,9) | DIF、DEA、柱值及可验证的交叉事件 | 观察动量变化；滞后指标，不保证转折 |
| 动量 | RSI14 | RSI值与30/70参考区间标签 | 描述近期涨跌强弱；低于30不等于即将反弹，高于70不等于应立即卖出 |
| 波动/价格位置 | BOLL(20,2) | 中轨、上轨、下轨及收盘价相对位置 | 描述价格相对近期分布的位置；触轨不等于反转，轨道不是预测区间 |
| 波动 | ATR14 | 平均真实波幅，单位为元/股 | 描述波动尺度，不判断涨跌方向；本期不自动换算成止损价 |
| 量能 | 成交量MA20与相对前20条均量倍率 | 当日成交量、含当日滚动均量、此前20条基准均量及倍率 | 判断成交是否活跃；量能变化不等于资金净流入或机构买入 |

默认组合包含8个用户指标实例：SMA两组，其余6类各一组。MACD的三条输出、布林带的三条轨道和量能的多个字段各属于同一指标实例。

参数建议范围：SMA/EMA周期为1–120的整数；RSI/ATR/BOLL周期为2–120的整数；MACD满足 `2 ≤ fast < slow ≤ 120`、`2 ≤ signal ≤ 60`；BOLL标准差倍数为有限正数且不超过4。每次最多12个去重后的指标实例，超限先提示用户缩小组合，不静默删减。

### 5.5 统一计算口径与最少记录数

这些约定用于避免与其他软件比较时出现“同名指标数值不同但原因不明”。技术设计和测试必须固定实现细节、版本与误差容限；不得直接依赖第三方库的隐含默认值。

| 指标 | 本项目计算口径 | 最早可用条件 |
| --- | --- | --- |
| SMA(n) | 最近n条收盘价的算术平均 | n条日线 |
| EMA(n) | 用前n条收盘价的SMA初始化；之后权重为 `2/(n+1)` 的递推 | n条日线；刚初始化不等于已不受起点影响 |
| MACD(f,s,g) | DIF=EMA(f)−EMA(s)；DEA为DIF的EMA(g)，用最初g个有效DIF均值初始化；柱值明确为 `2 × (DIF−DEA)` | DIF需s条；DEA/柱值需s+g−1条，默认分别26条、34条 |
| RSI(n) | 使用n个相邻收盘变化的平均上涨/下跌初始化，再按Wilder方式递推，权重为1/n | n+1条日线，默认15条 |
| BOLL(n,k) | 中轨=SMA(n)；上下轨=中轨±k倍收盘价总体标准差，固定 `ddof=0` | n条日线，默认20条 |
| ATR(n) | 每条TR取当日高低差、高价与前收盘差的绝对值、低价与前收盘差的绝对值三者最大；n个TR平均初始化，再按Wilder方式递推 | n+1条日线，默认15条；首条没有前收盘，不用高低差代替TR |
| 量能MA(n) | 包含当日在内的最近n条成交量均值 | n条日线 |
| 相对前n条均量倍率 | 当日成交量÷此前n条成交量均值，分母不含当日 | n+1条日线，默认21条 |

补充约定：

- “日”表示可用日线记录数，不保证等于连续交易日或自然日。不得为休市/缺失记录补零或复制收盘价。
- RSI平均上涨与下跌均为0时记为50；仅平均下跌为0且上涨大于0时为100；仅平均上涨为0且下跌大于0时为0。说明这是固定实现约定，不是模型判断。
- 量能倍率分母为0时该字段标为“未定义”，不输出无穷大、0或任意放量标签；正常有量分母下当日0成交量可以得到倍率0。
- 常量价格序列可产生ATR=0和布林带三轨重合；这是有效结果。若以后增加百分比带宽等除法指标，必须另定零分母行为。
- 不将这里的量能倍率命名为盘中“量比”：我们没有分钟级成交节奏信息。
- 收盘价处于均线上方与“刚刚上穿”是不同事实。交叉事件须有连续两条有效关系；上穿定义为前一条差值≤0且当前>0，下穿定义为前一条≥0且当前<0。仅最新点有效时不判断交叉。
- EMA、MACD、RSI、ATR依赖计算起点。每次返回实际计算起始日、可用记录数、种子方式和初始化后递推次数；递推尚不足相关最长周期3倍时，显示项目约定的“起点影响提示”。该阈值不是数学收敛或可靠性的保证。
- 指标未达到最少记录数时值为null，不能让模型补算。MACD只有DIF可用时可以展示DIF，但不能编造DEA/柱值或交叉事件。
- 这些指标均来自同一份经校验、不复权的日线。分红/送转引起的价格跳变可能同时影响多个指标，不能解释为获得了多份独立证据。

### 5.6 多指标分析原则

回答按“趋势—动量—波动—量能—冲突与限制”组织，不机械罗列全部数值。优先解释用户关心的问题，允许同一份结果同时出现趋势偏强、动量走弱和波动扩大。

SMA、EMA、MACD都高度依赖价格序列，不能简单用“3个看多、1个看空”计算上涨概率、信心分或买入评级。波动指标没有天然看多/看空方向，成交量增加也不能自动解释为买盘增加。

模型负责用证据解释分歧，程序负责计算数值及关系。本期不建立指标加权交易评分，也不将多指标一致直接升级为下单建议。

## 6. 核心交互流程

### 6.1 一次分析的完整流程

以下主流程适用于行情分析。纯知识问题直接进入受限知识解释，不要求股票代码或调用行情工具；旧结果追问仅在查询条件不变且证据相关时复用既有结果；超出范围的问题直接说明本期限制。

1. 接收中文问题，区分日线分析、已有结果追问、知识解释或超出范围的请求。
2. 提取用户明确指定的股票、日期、指标及参数和数据源，并与当前会话中的已确认参数合并。
3. 程序检查参数；有歧义则提出一个简短追问，本轮不调用行情工具。
4. 对允许采用默认值的字段应用默认值，并在结果中说明实际使用的查询条件。
5. 调用一个白名单日线分析工具，一次取数后集中计算所请求的指标；复用已有数据源、校验和SMA计算组件，扩展分析服务。
6. 先判断行情数据是否有效，再判断每个指标字段是否可用。有效数据中部分指标可用时，明确缺项并仅解释可用证据；全部指标不可用时只返回事实与不足说明。源失败、无数据或行情损坏时，不请求走势解释。
7. 检查模型解释中的证据引用与允许的结论类型，不合格时改用受控的事实摘要。
8. 向用户展示结果，保存本次已确认参数和结果供后续追问使用。

产品 agent 的职责是请求理解、澄清、工具选择和解释。股票标识校验、日期限制、指标计算、权限以及调用预算由程序执行，不能只依靠提示词约束。

### 6.2 输入与默认值（建议值，待确认）

| 字段 | 规则 |
| --- | --- |
| 股票 | 正常入口允许证券名称，不要求用户记代码；由有来源的目录映射标准标识，完整代码也可输入，不能凭模型记忆补码 |
| 名称/代码歧义 | 名称或裸代码在可信目录中唯一明确匹配可继续，并展示名称/代码；多个候选、未知或仅部分名称匹配先澄清，不查个股行情 |
| 截止日期 | 未指定时使用上海日期的前一个自然日；不是声称该日一定开市 |
| 当日/未来 | 明确说“今天”或未来日期时，解释当前限制，并询问是否改查此前日线；不静默改成昨天 |
| 指标组合 | 未指定时采用§5.4默认组合；明确只问某指标时只计算该项及内部依赖。具体参数按§5.4校验，现有CLI默认值不因此改变 |
| 起始日期 | 未指定时回看365个自然日，含截止日，为多个指标提供较长历史；不保证每个参数组合均有足够初始化历史 |
| 明确区间 | 严格尊重用户指定起止日期；不为补足指标自行读取区间之前的数据；可解释需要更多历史，请用户决定是否扩展 |
| 最大区间 | agent 工具暂限制为含首尾最多366个自然日；更长请求建议缩小范围，不悄悄截断 |
| 数据源 | 启动时显式选择腾讯或东方财富；会话继承且固定，不接受对话/HTTP任意切源；换源需重启并显示新来源 |
| “20日”含义 | “20日均线”指20条日线；区间中的自然日、交易日与记录数不能混同，有歧义则澄清 |
| 交易日表达 | 没有交易日历时不能保证“完整20个交易日”；可解释为最近20条可用记录的需求，需单独实现后再开放 |

默认回看区间只是取数策略，不保证每项指标都有足够日线或充分消除初始化影响。报告区间与计算区间本期保持一致，不隐式增加区间外预热数据。模型不得把历史不足解释为新股、停牌或接口故障中的某一种，除非另有已验证证据。

相对日期由程序根据上海日期解析或核验。模型必须收到明确的日期锚点，不能自行使用训练知识判断“今天”。

2026-10-20实现说明：自然入口已采用上海前一自然日截止、含首尾365自然日及8个默认指标，条件随结果导出；相对月/年暂按30/365自然日计算并记录策略，不等于自然月。仅部分表达可解析，其他先澄清。目录有7天新鲜度限制，离线演示保留4条夹具，另有真实沪深列表刷新；不声称全市场完整性或历史名称可得性。

### 6.3 连续对话与状态

2026-10-21实施增量：[明确指标修改](indicator-edit-design.md)已接入。获得可信事实且事实报告检查通过后，保存15分钟的条件基准；“把SMA20改成5日，其他不变”只替换目标实例并重新取数，保留原具体日期。整句有额外要求、目标不唯一、越界、重复或无变化时不执行，需重述完整修改句。有效新请求执行前消费旧基准，失败且无本轮可信事实则不恢复。此子步骤新增40项、当时全量722项离线通过。

随后同日增加[可信结果保存与追问](result-followup-design.md)：独立保存最近一份成功结果，深复制隔离；自然追问最多1次模型、0次行情，展示原字段、项目定义与重新核对的关系。明确知识问题0/0；显式“查看上次结果”或`/last`为0/0。新研究失败后旧结果只能带原条件显式查看，不冒充当前结果，不恢复旧编辑基准；查看不延长15分钟有效期。当前全量769项离线通过，未新增真实模型/行情实测。

2026-10-22再补[明确条件修改](condition-update-design.md)：换股票使用目录身份，未知/歧义先保存原条件待选；改ISO区间或单个边界，其他条件不变；添加一个明确指标或删除一个唯一实例，不补默认参数、不删空。每条只改变一类条件，有效修改最多2次模型/1次分析，未执行的无效修改0/0。新请求仍经过原范围绑定和事实检查，失败不恢复旧基准。新增44项，全量813项离线通过，未新增真实请求。

可选会话分别保存待选股票/指标条件、可信修改基准和成功结果，使用前重查当前目录、来源、时效及契约。不同会话使用独立内存对象；不传 `session=` 不能追问或改旧条件，明确指标定义仍可本地回答。2026-10-22补齐[模糊窗口短答续接、相对日期及“看最新的”](mvp-conversation-design.md)。来源按启动固定；自由复合修改、任意指代及开放问答不作为本轮MVP前置。股票选择边界见[续接设计](identity-clarification-design.md)。

- “把SMA20改成5日，其他不变”：继承最后一次已确认的股票、日期、来源和其他指标，只替换该SMA实例。仅说“把窗口改成5日”且存在多个候选指标时先追问。
- 修改指标或参数时保留原起止日期，包括此前由默认值生成的日期；只有用户改变日期或明确要求重新按默认范围查询时，才重新计算区间。
- “这个均线是什么意思”：只解释最近一次相关结果；不必重复联网。
- “换成600000.SH”：明确更新股票，其他保留的条件应在回答中显示。
- “看最新的”：保留原自然日跨度，将截止日平移至上海前一自然日，重新研究；不声称实时或该日开市。同日期刷新说明未发现新行情，人工模式只重跑样例。
- 明确的新参数覆盖旧参数；含糊指代、相互冲突的输入应追问。
- 尚未确认的候选股票单独保存为待澄清状态，不覆盖已确认的分析对象。
- 改参数后如果查询失败，不能把旧查询结果呈现为这次结果；旧结果仍可单独查看，但必须标明其条件。
- “新对话”清空会话上下文。不同会话的股票、数据、密钥与用户输入不得混用。
- 首版不将完整对话长期写入磁盘；当前优先保留结构化任务状态和一份成功结果，不保存最近6轮完整消息。若以后确需消息窗口，再单独定义长度、隐私和失效规则，不依赖模型自行恢复。

## 7. 回答应该是什么样

### 7.1 成功分析的输出结构

1. **查询条件**：股票代码、来源、起止日期、指标组合与参数、采用的默认值。
2. **事实卡片**：实际最新交易日、对应收盘价、各指标最新字段及状态、记录数、不复权/未知复权口径。字段较多时分组展示，不把全部序列塞入正文。
3. **分维度解读**：趋势、动量、波动、量能各说明关键事实，区分计算结果和一般性解释。
4. **冲突与观察条件**：明确哪些指标一致、哪些矛盾、哪些尚不可用；描述可继续观察的条件，不给多数票概率。
5. **限制**：指标初始化、非复权、数据最新性、未使用新闻/基本面、未校验ST/上市状态等适用提醒。

默认输出中文，避免每次堆砌长免责声明。重要限制不可隐藏在“展开详情”之后。详细字段和来源信息可供用户查看。

2026-10-20实施说明：当前先完成第1、2、5项的最小程序事实报告 `safe_answer`，供默认展示或模型失败时使用。它校验请求/字段/证据一致性，只展示数值与缺项，不生成模型的趋势解读、冲突分析或观察条件。调试JSON仍有未校验 `model_draft`，不可直接当作产品回答。上述完整输出结构及自由文本解释检查仍为目标，见[安全展示设计](safe-report-design.md)。

后续同日实现：第3项增加受限关系版本，模型提交 `indicator-explanation-v1` JSON选择本轮关系；程序检查后以固定中文表达，`display_answer` 合并事实与通过的解读。任一论断失败即回退，不增加调用次数。尚无第4项跨指标冲突总结、观察条件或任意自由文本检查；不能把部分关系通过称为整体走势预测通过。见[解读设计](grounded-explanation-design.md)。

### 7.2 单项请求示例（基于已实测历史数据，不是未来预测）

用户：分析 000001.SZ 在 2025-09-01 到 2025-09-05 的日线，用3日均线。

预期回答示意：

> 本次使用腾讯不复权日线，共5条记录。查询截止日期和实际最新交易日均为2025-09-05。
>
> 最新收盘价为11.72元，SMA3约为11.74元；按未四舍五入数值比较，收盘价低于该日均线。
>
> 这说明最新收盘价低于最近3条日线收盘价的平均值，但仅凭这一点不能判断之后必然下跌，也不足以给出买卖目标。可以继续观察后续收盘价与各日均线的相对位置。
>
> 本次未分析新闻、基本面或历史风险标签；不复权价格也可能受分红、送转等事件影响。

以上措辞不是固定模板要求，但其事实、范围和证据约束必须保持。

对于默认多指标请求，回答应分组组织，而不是照搬上述单SMA模板。例如，当工具实际返回“价格高于SMA20/60、MACD柱值仍为正但较前一条缩短、RSI较高、ATR上升”时，可以解释为“均线关系仍偏强，但上行动量有放缓迹象，波动尺度扩大”。负柱进一步下降则可能表示下行动量增强，不能笼统称作动量放缓。这只是条件化表达示例，不是对某只实际股票的判断；每个前提都必须确实存在于本次证据中。缺少量能数据时明确说明，不补写“成交量确认上涨”。

### 7.3 数据不足与失败

| 现有返回/异常 | 产品行为 | 禁止行为 |
| --- | --- | --- |
| `ok` | 生成事实卡片和有限解释 | 把指标关系当成确定走势或收益保证 |
| `insufficient_history` | 旧单SMA接口继续展示已有行情、窗口及缺少记录数；多指标接口按下述逐项规则处理 | 让模型自行补足价格、把空值当零，或因一个长周期不足否定其他有效指标 |
| `no_data` | 说明源为空或条件没有匹配记录，保留查询条件 | 直接认定停牌、退市、新股或股票不存在 |
| `source_error` | 说明本次取数失败，允许用户决定重试或显式换源 | 编造行情、自动换源后不告知用户 |
| `invalid_data` | 说明收到的数据未通过校验，不生成行情判断 | 把部分有效行拼成完整成功结果 |
| `InvalidRequestError` | 转成可理解的参数提示/澄清 | 当成网络失败反复请求 |
| 模型超时/不可用 | 如果已有可信事实则提供程序生成的事实卡片；否则说明暂不能处理 | 声称模型已分析、自动换到另一付费模型 |
| 模型输出不符合约束 | 一次受限修正仍不合格时回退至事实摘要 | 不受限制地重试或直接展示无依据内容 |

部分数据不足并不等于整个产品报错；产品状态需区分“完成、需澄清、结果受限、失败、超出范围”。这些状态与底层行情 `status` 是不同层次，不能混为一个枚举。

**多指标返回契约是本期新增内容，不能直接套用旧 `AnalysisResult` 的单窗口整体状态：**

- 行情数据有效后，每个指标实例返回标识、参数、算法口径、计算起点、最新值日期、所需/实际记录数及字段状态。
- 每个输出字段区分“可用、历史不足、未定义、计算错误”，附原因及适用的缺少数量；不能只给一个全局 `missing_bars`。
- 全部请求字段可用时为“完成”；只有部分字段可用时为“结果受限”，但可以解释可用部分；全都不可用时仍可以展示可信行情并说明原因，不生成综合走势判断。
- 行情本身无效或取数失败仍整体失败；若是某项指标计算异常，不标记整体完整成功，不伪装成历史不足，保留脱敏诊断并限制该指标解释。
- 各字段以实际最新交易日对齐；当天缺值不能无提示地拿更早的有效值填充。交叉等派生标签因缺少前一有效点不可用，也应单独说明。
- 30条记录请求默认组合时，SMA20、EMA20、RSI、BOLL、ATR和量能已有值；SMA60及MACD的DEA/柱值不足，DIF可单独展示。明确只请求SMA3时，不附加其他指标的历史要求。

## 8. 工具、事实和证据约束

### 8.1 本期只读工具

仅开放一个日线分析工具，输入是经验证的股票、日期、指标列表及参数和允许的数据源。工具内部集中计算多项指标，不为每个指标各发一次行情请求。外部名称与具体数据结构在技术设计中确定。

工具内部执行顺序：参数验证 → 创建数据源并取一次历史序列 → 行情校验与日期截取 → 指标计算与逐项状态 → 事实整理。复用已有源和指标组件，新增多指标分析服务；保留 `analyze_daily_bars()` 与现有单SMA CLI兼容性，不通过改坏旧接口来添加功能。不能允许模型任意传入 Python 对象、函数名、网络地址或磁盘路径。

生产对话只允许真实源。CSV 用于开发与离线测试，由开发者配置固定样例；不让模型自行指定文件。使用样例时输出必须醒目标注“人工样例/非真实行情”，且不作为市场建议。

### 8.2 数字和关系由程序提供

- 收盘价、各项指标字段、记录数和日期直接读取工具结果；所有指标使用同一股票、来源、复权口径和计算区间，不跨源拼接补齐。
- “高于/低于/等于均线”由程序比较完整精度数值，模型不能自行重新计算。
- 如果展示“均线较前一条上升/下降”，需由程序比较两条有效均线；不存在前一条时不能生成该结论。
- RSI区间标签、布林带内外位置、MACD柱值变化、量能倍率及交叉事件均由程序生成，不让模型重算。ATR单位是价格，不得称为百分比波动率。
- 本期没有计算的收益率、年化波动率、目标价或胜率，不能由模型临时编算后混入事实。
- 计算保留精度，展示时四舍五入；因显示精度造成两数看似相等时应说明，不改变实际关系。
- 源端已舍入的量额不会因单位换算恢复精度。腾讯的量额精度限制应进入适用的回答限制信息。

### 8.3 最小证据关联

每条行情事实需要能够定位到本次查询的具体字段，例如：查询编号、股票、日线日期、指标实例及其参数、字段名。SMA20与SMA60、MACD的DIF与DEA必须有不同的事实标识，不能只用一个模糊的“均线值”。旧接口的 `sma_close` 字段不直接充当整个新指标集合。

模型解释使用本次事实标识引用依据。事实卡片由程序渲染；模型不能改写其中的数字。若模型解释引入未允许的行情数字或无效事实标识，输出检查应拒绝该解释并回退。

“高于/低于/等于”“均线上升/下降”等方向性结论也必须匹配程序生成的关系标签。引用存在且数字正确、但关系表述相反，同样属于不合格解释；技术设计应选择可验证的结构化表达，不能只检查引用是否存在。

本期的证据关联是单次分析内的结构化引用，不等于已建设跨文档证据台账。不得虚构新闻链接、交易所公告或原始发布时间。

### 8.4 历史问题的限制

- `requested_as_of_date` 是用户查询截止日，`latest_trade_date` 是实际取得的最后一条日线日期，必须分别显示。
- `retrieved_at` 是本次读取时间，不是历史信息发布时间。
- 日线截取没有消除后续数据修订带来的历史偏差，不得称为严格 point-in-time 回放。
- 模型不得用其记忆中的后续走势、事件或新闻补充历史截面分析；本期只允许解释传入的行情事实。
- 测试集应主动诱导模型透露后续结果；通过有限测试并不证明模型永远不会越界。

## 9. 模型与 Jev 的位置

### 9.1 模型提供方

第一阶段计划使用 DeepSeek。模型名称、服务可达性、工具调用及结构化输出支持情况，接入时以实际文档和测试为准；不在 PRD 中假定某个型号一定具备特定能力。

业务代码依赖统一的模型提供方接口，而不是散落的供应商专用调用。兼容 OpenAI 风格的接口有助于接入，但不等于不同供应商行为完全一致。

本期必须实现一个真实提供方和一个离线假模型，以验证业务流程不被某一供应商绑定。后续添加 OpenAI 提供方时，应复跑同一套评估；切换由用户显式选择，不静默发生。

这里的“以后支持 ChatGPT”在工程上指接入适当的 OpenAI API 模型，不是操纵 ChatGPT 网页，也不意味着网页订阅自动提供 API 额度。

### 9.2 Jev

Jev 是后续实验候选，不是第一版必须依赖的组件，也不替代日线计算、参数校验或证据检查。

等有明确的事件分类、路由等任务后，再验证其实际能力、许可、部署要求和稳定性。只有相对于简单规则或当前模型，在固定数据集上获得可复现的质量、延迟或成本收益，并且失败时可回退，才考虑纳入主流程。

目前没有足够依据在本 PRD 中承诺 Jev 能解决某类错误，或宣称已经部署。

## 10. 权限、安全和运行预算

### 10.1 强制边界

- 只注册只读行情分析工具；不注册券商、交易、任意终端、SQL、文件写入或任意 URL 访问工具。
- 不向模型提供交易密钥，也不创建券商订单通道；用户要求下单时说明产品没有该能力。
- 第三方文本、模型输出和用户输入均不能扩大工具权限。后续引入新闻时，其内容仍属于数据而非指令。
- API 密钥由本地配置/环境变量提供，不进入提示词、Git、用户输出或日志。
- 首次使用应说明用户问题、必要会话内容与行情事实会发送给所选模型提供方；用户自行配置并启用服务，不在测试时擅自调用其他付费服务。
- 本期不收集券商账号、真实持仓或资金信息。日志默认不保存原始完整对话。
- 对外发布、批量缓存或再分发之前，核对行情源与模型服务的许可、使用条款和调用限制；公开可访问不等于允许任意商用或再分发。

### 10.2 每轮预算（实际默认与建议分开）

| 项目 | 建议限制 | 超限行为 |
| --- | --- | --- |
| 用户输入 | 最多2,000个字符 | 提示缩短问题，不能静默截掉关键参数 |
| 股票和指标 | 每次1只股票、最多12个指标实例；默认8个 | 超限先澄清或引导拆分，不静默删项 |
| 行情分析工具 | 最多执行1次 | 不由模型自动重复取数；用户下一轮可明确重试 |
| 模型调用 | 已实施：自然初始最多3次，明确格式默认2次；更窄路径保留原次数，无自动修正 | 回退停止前事实或明确结束；停止轮不存新结果 |
| 行情网络等待 | 每次连接/读取15秒 | 进入数据源错误处理；不是全流程总期限 |
| 单次模型请求 | 已实施：默认30秒连接/读取timeout，与剩余整轮时间取小值；不是HTTP硬期限 | 连接/读取超时处理为失败，返回后还须检查整轮期限 |
| 每轮总耗时 | 已实施：90秒单调时钟协作截止 | 检查点停止后续调度、忽略迟到结果；不承诺90秒立即返回 |
| 模型输出 | 已实施：默认512，配置最多1,500 tokens | 控制长度；截断结果不得冒充完整成功回答 |
| 已观察token | 已实施：达到24,000停止；用量缺失保持未知 | 响应后停止，允许当前请求越阈值，不是预付费/计费上限 |

一次行情工具执行可能包含跨年分片的多个HTTP请求。现有底层timeout不等于总耗时上限；腾讯现逐片检查共享截止与取消，DeepSeek/行情传入更小timeout，AKShare只约束其公开方法。同步请求不能被控制器强制中断，晚返回仍可能计费；当前只保证检查点不续调度、不发布迟到新状态。终端Ctrl+C退出，不提供后台取消命令。

2026-10-20实施说明：明确格式入口仍最多两次模型调用、无缺省参数补全；新自然入口增加一次候选理解，最多三次模型调用，并采用可见默认日期和指标。两者最多一次分析，无自动修正或重试；表中的整体耗时、token及修正机制未完整实现，不能由次数边界推断全部预算完成。

2026-10-22增量：[运行控制](turn-control-design.md)已贯穿理解/提议/分析/解释及最终会话发布，使用单次控制器和独立monotonic钟，不与15分钟TTL或固定样例日期混用。调用前扣额度，失败不退；缺失/不一致usage不当作零消耗。解释停止可显示此前事实但不保存，取消不展示本轮分析；新研究已消费的旧基准不恢复，旧成功结果只可显式历史查看。新增43项离线检查，不代表硬截止/账单上限已实现。

未来若增加格式/证据自动修正，仍须共用同一轮最多3次模型调用，不能另开额度；当前没有自动修正。用户补充澄清信息属于新一轮，不受上一轮已消耗预算影响。

模型客户端的自动重试默认关闭；若后续启用，每次实际请求均计入同一调用预算与总截止时间，不能把一次SDK方法调用误计为一次网络请求。

“修改窗口重新算”是用户的新一轮请求，不计作上一轮的自动重试。纯知识问答不消耗行情工具预算；对旧结果的解释可复用清楚标识的已有证据。

一次工具调用可完成整个指标组合，不能因增加7类指标就允许7次行情工具调用。模型接收最新字段、必要的前一有效点、派生关系和缺项说明，而非重复发送每项指标的完整历史序列；完整序列留在计算层供查看和验证。

## 11. 质量、诊断与验收

### 11.1 衡量什么

第一版看的是请求理解、证据一致性、边界遵守和错误恢复，而不是股票收益率。没有经过测试的数据不能写成产品成绩。

每轮可记录：请求编号、程序/提示词版本、所选模型与数据源、经过校验的参数、状态、工具与模型调用次数、耗时、供应商返回的 token 用量（若有）以及脱敏错误类型。

不记录 API 密钥，不默认记录原始用户对话；诊断存储如启用，应提供关闭与清除方式。成本按实际提供方计费规则估算，不能跨模型用同一个固定价格猜测。

### 11.2 两层验收

**离线自动化验收（阻断门槛）**：使用固定行情与假模型覆盖状态、参数、安全和异常。所有关键用例必须通过，同时现有基础层回归测试保持通过。

**真实模型评估（独立报告）**：准备至少30个有预期行为的中文场景，每个重复3次；记录模型、提示词版本及测试日期。建议将正确行动选择/参数理解达到90%作为初始目标；任何最终展示给用户的虚构行情数字/错误标的，或实际发生的跨权限执行，都必须修复并加入回归集后再验收。90%不是对安全错误的容忍配额。

模型原始候选中的错误如果被正确拦截且安全回退，不算最终违规，应单独记录拦截率、修正成功率与回退率。大量依赖回退仍可能意味着产品效果不合格，不能仅凭没有违规就认定问答能力达标。

真实评估需用户配置并启用模型服务后运行；离线测试不能证明真实模型效果。评估样本量和通过率必须如实报告，不外推成生产可靠性保证。

2026-10-20增量实现：[固定场景契约评估入口](agent-evaluation-design.md)已有完整、部分不足、名称输入、歧义澄清4项独立预期；默认假模型，显式真实模式也只发固定人工数据，最多8次模型调用且首错后停止。自动化验证只用模拟HTTP；随后用户回传 `complete` 一次通过，其他3项尚无报告。它是后续评估的起点，不替代上述至少30场景、每项3次及人工检查要求，不将正确的 `limited` 或澄清状态误记为场景失败。

2026-10-22已新增 `mvp_evaluation`：30个固定场景，最多3次独立重复，完整计划201次模型方法调用、72次分析，显式全局额度不足则在凭据读取前拒绝。CI只执行人工行情/假模型，90/90离线通过；真实模式必须显式选择DeepSeek且可能计费，尚未执行。每步核对模型解读、综合证据及实际显示，不只看Agent顶层状态。记录日期、模型名和系统/工具指纹，任何模式都不自动宣布真实质量通过，仍需人工复核。详见[验收清单](mvp-completion.md#5-新的30场景评估)。

字段、数字和工具权限可通过程序约束；自由文本的全部语义正确性无法仅凭字段校验保证。评估须人工检查解释是否过度推断，必要时收紧允许的解释类型，而不是宣称已彻底消除幻觉。

端到端延迟与 token 用量记录 p50/p95 和测试条件，先建立基线，不预先宣称“低延迟”或“成本下降”。总截止时间的行为必须单独通过可控测试。

| AC-23 | 显式启动选择数据源，或对话要求切源 | 启动显示固定来源；对话不能改源，提示重启；新源重新取证，失败不混入另一来源 |
| AC-24 | 调试输出和异常日志 | 无密钥、无原始敏感对话或越权路径泄露 |
| AC-25 | 各指标恰好少一条、足够、再多一条 | 分别验证初始化、null边界及递推首步；MACD的DIF和DEA分开验证 |
| AC-26 | 已知小样本与独立手算/参考实现 | 数值符合固定种子、Wilder平滑、柱值倍数、ddof口径及误差容限 |
| AC-27 | 恒定价格、单向涨跌、前20条成交量全零 | RSI按约定处理，ATR可为0，布林带可重合，量能零分母标未定义 |
| AC-28 | 30条记录请求默认组合，或只请求SMA3 | 前者逐字段部分可用并解释有效证据；后者不附加全套历史要求 |
| AC-29 | 同一计算起点，追加截止日之后的行情 | 截止日内各项指标及证据不变，无未来泄漏 |
| AC-30 | 最新点高于均线，但无前一有效点或未发生穿越 | 不能宣称金叉/上穿；实际事件满足两点关系定义 |
| AC-31 | 均线偏强、动量走弱、ATR变大且量能不一致 | 分维度解释冲突，不输出投票胜率，不给ATR涨跌方向 |
| AC-32 | 计算起点不同，或递推历史很短 | 展示起点/初始化信息及提示，不承诺与所有软件完全一致或已经收敛 |
| AC-33 | 某指标字段当日缺值、上一日有值 | 当日保持不可用，不静默前向填充或混用日期 |
| AC-34 | 不复权序列出现明显价格跳变 | 提示公司行动等可能影响，不仅凭指标确认除权事件或真实趋势 |

样本中的 ST/新股标签可由测试夹具预先给定以验证“不排除”的行为，但不能据此宣称程序已经具备实时识别标签的能力。2026-10-22增量已实现独立本地[证券状态／交易日历背景](market-context-design.md)：包含业务有效期、发布时间、采集时间、unknown、自然日年龄和非破坏性日历对照。默认仍为明确人工夹具，无真实master/calendar adapter；背景不发送模型、不进入筛选或交易规则，也不证明历史时点可得性。

## 12. 开发顺序与完成定义

2026-10-07实施说明：根据近期关于产品agent内部顺序的讨论，先独立实现模型接入层与离线测试，作为M2的前置小步骤。它不依赖行情工具，也不代表M1a/M1b已完成。正式接通本PRD的多指标agent主流程前，仍须完成下列指标与工具契约阶段。

| 阶段 | 交付物 | 阶段完成条件 |
| --- | --- | --- |
| M0：确认需求 | 本PRD确认版、关键决策记录 | MVP范围、默认值、权限和验收口径达成一致 |
| M1a：确定性指标 | EMA/MACD/RSI/BOLL/ATR/量能及多SMA、固定计算口径 | 边界、已知样本、初始化和无未来数据测试通过 |

每个阶段单独讲解和演示，不一次性生成整个系统。2026-10-21按用户要求扩大每步交付为完整功能块，不再设置互动理解题，保留关键取舍及学习笔记。代码注释使用英文，面向用户的说明与产品回答使用中文。2026-10-22最新要求：从本机API模块开始，每个模块完成验证后commit并push，不为微小改动频繁提交。

本期完成不要求网页界面、新闻、全市场选股、Jev 或严格历史回放；也不能把它称为完整交易助手已经完成。
