# 自然语言公司回答与局部校验

2026-10-29，方案 #165 经 Claude #166 批准。本文对应 A 批工作区实现；真实模型质量验收尚未进行。后续顺序为 C 批 20 题评估工具、真实评估、B 批路由调整。

## 公开回答与展示

公司研究与参考研判统一返回 `product-research-answer-v3`。每股一组 `narratives`：`summary` 直接结论、`current` 带日期的当前情况、`drivers` 主要依据、`levels` 关键价位、`scenarios` 基准/变好/变坏条件、`stance` 操作倾向。评级 `decisions` 与原 ATR 条件计划独立保留，普通基本面回答不强加评级。

文字块是 `{text, evidence_ids}`；引用可省略，程序仍按本股实际发送给模型的资料核对数字。公开引用转换回完整证据 ID。价位输入只能选程序生成的 `price_levels` ID，不能让模型填入上下界；公开表格由程序填 `lower/upper/lower_label/upper_label`。计划端点也有独立引用，模型无法改公式。

前端用 React 文本节点显示，有限解析 `**粗体**`，列表与表格由组件构造。没有通用 HTML/Markdown 执行器，文本中的图片、链接和标签不会成为元素。来源链接仍由应用原有域名白名单控制。v3 的公开来源上限为480条，以容纳三股各5期财务与新增窗口事实；单条和其他结构限制继续核对。历史 v1/v2 仍保持240条来源上限，读取与展示继续支持；旧协议专项测试使用明确命名的 legacy 入口，当前业务统一走 v3 的测试。

`quality` 由程序生成：`complete/partial/fallback`、固定 `code`、最多20个原因位置、句子计数、修正次数及结构失败次数。`narratives[].origin=application` 的价位表列名为“程序事实”；模型解释才叫“我的判断”。资料超时说明同步进入结构化显示。

整轮 `status=limited` 与回答 `quality.state=complete` 可以同时成立：前者表示请求的资料有缺项，后者表示已生成的内容通过本轮校验。此时回答顶部按 `coverage` 列出实际未取得的领域；可用、明确排除和未请求的领域不列为缺项。

## 新增证据口径

`research_price_context.py` 使用本轮已检查的同一份 `technical.bars`，不再获取行情：

| 事实 | 算法与缺失条件 |
| --- | --- |
| 最新收盘 | 最后已完成日线，不是盘中实时报价 |
| 近5/20/60日涨跌幅 | `(C_t/C_(t-N)-1)*100`，分别要求 N+1 条有效记录 |
| 20/60日高低点与日期 | 最近 N 条 high/low；并列取最近日期，样本不足不输出 |
| MA20/MA60 | 最近 N 条收盘算术平均，样本不足不补值 |

证据的 `calculation_basis` 保留版本、复权口径、样本数、日线截止、并列规则与依赖命名空间。`request|raw_daily_bar|日期|字段` 是归档中 `technical.bars` 的行/列引用，并非原指标 `facts` 的 ID；每个引用都能定位同请求的冻结原始行。高低点依赖完整窗口，收益依赖首尾收盘，均线依赖窗口收盘。

财务接口原本一次请求最多5个报告期，现在保留这次响应中合格的5期、每期5字段（上限25），不增加请求或翻页。原披露截止、更新日期和人民币口径检查继续生效。`financial_periods.py` 只对同公司、来源、币种及指标的累计数据差分：Q1直接采用，其他季度减本年上一期；同比另需去年同季所需的累计记录，分母为0则缺失。记录全部依赖和最晚披露日。依赖缺失或同一报告期有歧义修订时不推导，缺失不写0。

模型上下文按公司与领域分配额度，优先价格、计划和财务，最终再按现有模型消息的 JSON 字节预算裁剪；删掉的证据也从可用价位中删除，引用不得悬空。最多4条、每条80字的具体反馈预留预算，三股场景同时受原有调用与超时控制。

## 校验与一次修正

`answer_validation.py` 按句检查，不能证明任意自然语言推理属实。硬拒绝限于收益/涨跌保证、自编概率或胜率、HTML/链接/指令注入、声称执行、跨股错配。定位到一句就删该句，硬风险文本不反馈给模型。普通数字、日期、期限、引用和结构问题为软错误，最多修正一次。

数字使用 Decimal 十进制核对，匹配本股、指标用途、单位和事实日期。价格容差为 `max(0.01元,0.5%)`，微小价格另受2%上限约束；粗舍入需落在显示精度的半单位内、至少2位有效数字且相对误差不超过2%。金额先换算人民币元，再按显示末位半单位舍入，无金额百分比容差。涨跌幅保留符号，中性标签“涨跌幅”不代表下跌；“下降5%”可对应-5%；百分比不能当百分点、单季不能当累计、止损不能借用收盘或目标。

区间两端分别核对；数字事实绑定邻近日期；5日回报不能借20日同值。20日均线、止盈1等周期和序号不当成裸价格。`一个月/未来1个月/下个月` 语义归一，明确两个月不改成一个月；未来期限不改变日线截止。当前不支持的中文金额数字、外币换算等表述软删除，可在修正时改成可核对形式。

正文和评级分别接收。评级仍核对身份、期限、评级/方向、理由及计划用途。坏数字句不抹掉有效评级，坏评级不抹掉有效正文。首版有效字段与列表位置保留，修正只补缺失位置；部分通过的文字块可追加修正后的干净句子。最终合并后再核对结论与评级方向。整体 JSON 无法解析也允许一次结构修正；取消、调用预算和超时仍直接服从控制器。

计数定义：`generated_sentences` 累计两次草稿实际检查的句子（含小标题）；`deleted_sentences` 累计被拒绝的句子；`retained_sentences` 是最终保留的模型句子，两次草稿的相同句子不会在最终回答里重复。因为修正草稿可能重复首版，三个计数不要求相加相等。`retained_paragraphs` 为最终有模型内容的段落数。结构无法解析不虚构句子数，由 `structure_failures` 单独计数。

## 事实兜底与诊断

模型完全失败时展示程序事实、最新可用行情/财务及观察价位；已有 ATR 计划继续显示。缺资料明确说明，不补造“持有”或任何已形成评级。计划/上下文完整性检查失败不向模型或表格泄漏无效价位。没有证据不调用模型。

追踪保持 `trace-v2`，增加 `answer_validation` 事件，内含固定 `version=1` 的白名单元数据；不存问题、答案、错误原句或反馈。`product_answer` 逐次记录草稿检查，评估可区分先拒绝、修正通过与最终兜底。CLI 可按运行号查询：

```powershell
.\.venv\Scripts\python.exe -m trading_companion.trace_cli --trace-dir data\traces --run-id <32位运行号>
```

`start.cmd` 默认开启 `data\traces`，`--trace-dir PATH` 可覆盖，`--no-trace` 优先关闭；直接启动 Python 服务仍默认关闭。容量、故障隔离和旧 trace 读取维持原约定。
