# 自选股消息收件箱：有限检查与本机未读

更新：2026-11-12。第四模块按 #629 批准的方案实现，当前为未提交工作区改动，待 Claude 审核及页面验收。前三模块自选、持仓偏好、研判回顾已由 Claude 分别审核、提交并推送 `9aa98af`、`4faea64`、`f2484cf`。本文不预写本模块工程门禁或真实标题抽查结论。

## 1. 用户能做什么

“消息收件箱”打开时只查看本机已保存标题，默认未读，每页最多20条；可切全部、按完整代码筛选、手动刷新、标为已读及确认清空。点击原链接不会隐式标为已读。标题按普通文本显示，来源链接只接受固定规范形式并安全打开。

只有“检查自选消息”“检查下一批”才发起一批公开来源读取，继续需要再次点击，不自动遍历50只自选。页面固定显示“有限检查，非全量监控”：来源只取最近30天每源最多5条，可能漏掉密集发布、离线期间和列表之外的信息。“本机暂无未读消息”不能解释为没有新闻；“新发现”也不等于刚刚发表。

短时间内连续检查，来源可能限制请求，届时会显示为取不到，请稍后再查。不自动重试、换源或追加请求来补足结果，原有批次期限和请求预算不变。

沿用 `--personal-memory-db PATH` 显式开启，`start.cmd` 默认不开启。`--no-memory` 优先禁用；关闭功能不打开或迁移个人库，不删除已有文件。demo、synthetic、网页 Dev Mode 不读写真实个人库，不构造该功能的真实来源客户端。面板独立于研究会话，不消耗问题、模型、分析或付费额度。重要性判断、重要提醒、后台定时、弹窗和推送均未实现。

## 2. 个人库 v3 与严格升级

个人库格式为 `personal-memory-store-v3`，与聊天库、证据快照库分离。正常模式显式打开旧v1/v2时，在同一次事务（全部成功才保存的一组操作）中核验完整旧结构、对象和全部旧行，补齐必要偏好表，再建立消息、已见标识和逐股逐源状态，最后设v3并复核。原自选/偏好值、顺序、时间和修改标识保留；陌生版本、额外对象、坏数据拒绝，不覆盖重建。升级后旧程序不能打开此库；关闭和开发路径不触发迁移。

每次加入自选生成一个随机 `generation`，即本次加入的身份标识，放在新的来源状态表中，不改变原自选公开字段。新浪新闻、东财公告独立保存 `revision` 修改标识、是否建立基线、上次成功和尝试时间、固定状态/错误码、跳过数、未读清理累计数与时间。提交结果时在事务内重读自选、generation和来源revision，防止删除重加、清空后迟到写回或旧检查覆盖新水位。

消息只保存核验过的公共字段：完整证券、保存名称、固定来源、规范原链接/文档标识、原发表日期与精度、来源提供的时刻、首次发现时间、来源取数时间、发现途径、基线标签和已读时间。不存问题、回答、持仓、账号或原始响应正文。日期精度保持日期，不补时分，不把发现时间当发表时间。

消息身份由“证券＋来源＋规范文档标识/链接＋发表日期”确定。相同文档改标题不生成第二个未读、不重置阅读状态；相同标题的不同文档或日期分别保留。并发重复导入保留原首次发现和已读状态。

## 3. 基线、水位与有界保留

每股每源分别建立初次基线和推进完整成功水位；水位只是成功检查时间，不代表已经完整覆盖到该时刻。有效空响应可以成功；部分条目核验失败时保存其余有效标题，显示部分失败与跳过数，保留原完整成功水位。请求失败、超时、取消、未执行、容量或存储失败不推进。每次重新看固定30天快照并去重，不仅按上次水位过滤，避免漏掉同日或迟到出现的标题。

新浪个股列表中未提及该公司、不在查询日期窗口内，或链接格式正常但不在原保存白名单内的合格标题属于正常筛选，不计核验失败。仅收件箱窄读取入口先核标题格式、链接和时间戳，再将正常筛选计入 `filtered_count`。格式判断接受HTTP和HTTPS，要求有效新浪域或子域、无用户信息，路径非空且可打印，完整链接及标题各最多600字符；新浪HTTP研报、移动站/快讯站等不支持的形式计为 `news_link_form_unsupported`，仅过滤，不访问、跟随、改写协议或保存。可保存链接仍限原HTTPS白名单，前端链接校验不变。其他协议、非新浪域、坏格式、坏链接和无效时间戳仍计 `skipped_count`，使本次部分失败且不推进完整成功水位。全部条目正常筛除时可返回成功空结果并建立基线，不宣称来源没有新闻。普通研究的原链接白名单、`skipped_count`、覆盖率和返回结构不变。

`filtered_count` 为本批 `results` 每源回执的必填整数0–50，页面显示说明而不作失败；它只保留在当前回执及有界重放缓存，不进入逐源状态表或本机列表DTO，不因刷新或重启继续显示。个人库仍为原v3结构，无本次新增迁移。

- 初次手动成功导入标为“初次建立基线”；后来未见过的标题标为“自上次检查以来新发现”。普通研究旁路另标“研究中发现”，不推进手动检查基线和成功水位。
- 每股消息最多500条、最长90天，先清已读旧项；必须清理未读时保留累计数量及时间，页面可见。清理在本机操作中按需执行，没有后台清理任务。
- 已见文档指纹为独立账本，每股最多2000个，只存标识和日期，至少保留来源30天查询窗口所需标识。无法安全腾出容量时显示容量限制，不静默丢标识或推进水位，避免清理后同文档反复成为新未读。
- 移除/清空自选在同一事务删除对应消息、已见标识和两源状态；重新加入从新基线开始。确认“清空消息收件箱”保留自选、持仓偏好和聊天，删除消息/已见并重置来源状态、轮换generation；请求核对集合修改标识，跨页面变化后先刷新再确认。删除偏好或聊天各自独立。

## 4. 固定来源和实际请求预算

`watchlist_news_sources.py` 负责串行来源读取，固定新浪新闻列表 `sina_company_news` 与东方财富公告 `eastmoney_announcements`。不继承研究的可选来源；巨潮需要目录和查询两次请求，不符合每源一次预算。复用现有证券、页面、发表时间、链接及结构核验，不抓正文、PDF、行情或财务，不调用标题分类或回答模型。

| 限制 | 执行方式 |
| --- | --- |
| 每批最多5股/10次实际HTTP尝试/50条标题 | 服务端自选有序快照；每股每源最多一次，失败也消耗，不重试、不跳转、不换源、不翻页 |
| 最近30天/每源最多5条 | 固定 `ResearchDataRequest` 条件，复用原适配器核验 |
| 实际开始间隔至少1秒 | 读取器实例保留跨相邻批次的上次实际开始时间，等待期间检查取消及期限 |
| 每批20秒/每请求最多6秒 | 使用单调时钟的协作检查，单次超时受批次剩余时间约束；不能保证强制中断底层阻塞调用 |
| 每响应512000字节/全批5120000字节 | 十进制字节；声明长度与实际流读取双重检查，超限停止该源 |
| 与普通研究共用最多3个来源槽位 | `CollectionExecutor.run_inline` 在当前线程借原许可，真实同步调用及客户端清理结束后在 `finally` 释放，不套普通采集Future（可能提前返回的异步结果） |

专用传输在实际发送前重核固定GET端点、证券/来源、严格参数、每对一次及批次额度；等待请求间隔后、真正发送和计数前调用 `before_request(instrument_id, source)`，有界重核自选generation/快照身份，回调前后都检查取消。身份已失效则置取消，不计未发出的尝试或来源位置；不在每个响应块读取数据库。随后重算剩余超时，才扣实际尝试。响应和专用客户端均在真实路径关闭。普通 `collect_many` 仍最多三股，不扩大其额度。

读取方法为 `WatchlistNewsSourceReader.read_watchlist_sources(requests, *, cancel, deadline, on_source, start_source=0, before_request=None)`，同步逐源回调核验证据及状态；`start_source=1` 仅让首股从公告继续。返回实际请求/字节数、已消耗来源对数及停止原因。发出HTTP后才取消/截止仍消耗该来源对，下一批不能隐式重试；等待许可/间隔时尚未发出的来源保留待检查位置。

## 5. 检查、取消、幂等与游标

服务实例最多一个实际检查在途，无后台队列。异步HTTP处理器只等待一个同步工作器；断连、服务关闭或页面停止等待传入线程安全取消信号。槽位直到工作器真实收尾才释放，不能因为浏览器已不等而启动下一批。已提交部分保留，取消不撤销已有保存。

取消与本地提交使用同一个控制锁决定先后：取消先发生则阻止提交；先完成的来源保留。每源发送前、保存前和返回前核对取消与自选身份。同一服务处理移除/清空自选或清空收件箱时立即使在途gate失效，发送前身份回调也能发现其他页面或进程造成的变化，阻止后续来源请求。手动单源本机提交最多200毫秒协作预算并受整批剩余时间约束；SQLite忙等待、进度回调及提交前检查限制本地工作，但操作系统磁盘阻塞无法硬停止，不能声称绝对200毫秒或20秒墙钟上限。

消息列表游标与检查批次游标独立。检查游标只保存自选快照身份及下一“股票—来源”位置；已执行失败来源计入进度，未执行保留。自选集合变化使旧游标失效，提示重新开始。每批返回成功、失败、未检查和剩余进度，不把未执行伪装成功。

列表按首次发现时间倒序；相同发现时间内按发表日期、实际发表时刻、消息标识依次倒序。同一发表日期内有明确时刻的排在仅日期项之前；跨时区时刻统一UTC微秒排序，日期项不补造时分，原字段保持不变。SQL有界取最多21项，列表游标携带同一组排序字段，避免翻页重复或漏项。旧列表游标缺少新排序字段会明确失效，刷新后从首页重新取；检查批次游标不受影响。

每次检查使用独立请求编号；同编号和原游标只返回有界原结果，不重新联网。编号与不同游标组合返回409冲突，忙碌明确拒绝；服务进程保留最近32份回执及最多4096个已接纳编号，回执淘汰后旧编号返回409退役而不重复I/O，到编号上限返回429并明确需重启。这是本机单进程有界账本，重启后重新开始，不是持久任务系统。浏览器等待期限为20秒批次加收尾裕量；响应丢失或写后刷新失败显示“变更未确认，请刷新核对”，保留原编号供用户手动核对，不能换编号自动重试。

## 6. 普通研究的零新增请求旁路

`watchlist_news_sidecar.py` 在正常当前公司研究中读取本轮开始时已在自选的加入标识；资料核验完成、综合回答之前，只复用已经取得的两种固定来源原始公共标题，每股每源最多5条。不借正文、搜索摘录或分类结果补标题，不追加来源、模型或行情请求；不依赖 `--capture-news-titles`，不读临时采集文件。

旁路总共最多200毫秒协作本地预算：开始快照最多50毫秒，合批保存最多150毫秒；不是每股各150毫秒，也不是硬磁盘停止保证。保存失败在API收件箱响应的可选 `sidecar_status` 中告知，只允许 `null`、`inbox_sidecar_saved`、`inbox_sidecar_unavailable`；这是进程内固定状态，重启为null，不新增数据库字段，也不改变研究响应。纯存储 `store.list_inbox` DTO不含该字段，由API附加；页面在保存未确认时提示核对，不据此断言本轮标题已全部写入。原证据、E引用、回答及发布路径保留；旁路在事务提交前调用 `before_commit` 的研究 `checkpoint`，取消使事务回滚，之后仍按原研究取消规则停止。此处是协作检查，不声称旁路具有手动gate同锁边界或能硬中断磁盘阻塞。旁路仍核generation/revision、去重与容量，不推进手动完整成功水位。

历史研究、重放、纯解释、开发/合成路径不触发。未开启个人库时，不增加数据库访问、额外墙钟读取或研究上下文内容。自选、收件箱和持仓不自动进入模型、聊天摘要、标题调试文件或运行记录正文。标题分类排序和重要提醒没有因本模块启用。

## 7. 本机接口与页面隔离

响应版本为 `personal-memory-notifications-v1`；API收件箱DTO可额外附带上述内存 `sidecar_status`，存储层DTO不含此字段。无需研究会话令牌，沿用本机同源/Host保护；不是公网账户体系。请求拒绝任意来源、URL、代码列表、文件路径及额外字段。

| 接口 | 输入和行为 |
| --- | --- |
| `GET /v1/personal/inbox` | `unread_only` 默认true，可选完整 `instrument_id` 与列表 `cursor`；每页20条，只读本机，返回未读总数、最多100条逐源状态和清理告知 |
| `POST /v1/personal/inbox/check` | 仅请求编号 `request_id` 和可选检查 `cursor`，明确执行一批 |
| `PATCH /v1/personal/inbox/{message_id}` | 仅标为已读，严格请求体 `{read:true}`，幂等 |
| `DELETE /v1/personal/inbox` | 网页确认后以 `If-Match` 传64位集合修改标识，保留自选/偏好/聊天 |

前端 `MessageInbox.tsx` 展示、`inboxMessages.ts` 严格解析，controller分别维护列表、检查及写入状态。初始化、打开面板、本机刷新和翻页只有本机GET；切模式、禁用、清空、移除时拒绝迟到响应。跨页面刷新或下次请求核对，不加后台轮询、跨标签页通知或浏览器第二份持久消息。

本模块同时将研判回顾的收益风险比显示为十进制四舍五入后的固定两位，例如 `2.000000 → 2.00 倍`、`1.485714 → 1.49 倍`；原存储、响应、图表数值和一般研究卡保持原口径。窄屏入口可达性单独验证，不能据此宣称修复已有整体侧栏布局限制。

## 8. 规则、验证与提交边界

规则 `personal-memory-notifications-v1` 以完整 `personal-memory-review-v1` 为唯一父版，父摘要为 `8519d1a39c79fdd5657dd2507e5cb8c9d7d01070e7142993d583d93707aff5ca`；不改旧题库、历史预期、封存/付费评估锁，不登记重要提醒规则。代码身份登记不代表模型语言质量或真实来源已经验收。

Codex使用临时库、固定目录、假时钟和HTTP替身验证迁移/回滚、身份竞态、基线/部分失败、水位、日期精度、去重已读、保留/容量、两类游标、请求编号重放、实际来源上限和共享槽位、取消真实收尾、旁路零新增请求、禁用/开发隔离及页面解析。正式门禁为 `verify.py python`、`web`、`bundle`，实际结果在审核请求记录。
