# 整轮运行控制：共享预算、取消与迟到结果

日期：2026-10-22。状态：已接入两个产品Agent入口及终端，离线验证；没有新增真实模型、行情或目录请求。

## 1. 解决的问题

此前不同路径有自己的次数边界，但没有贯穿“理解 → 提议 → 行情分析 → 解释 → 保存结果”的统一停止机制。单个HTTP请求有timeout，也不代表整轮研究一定在该时间内结束。

本模块把这些阶段接到同一个 `TurnControl`。预算由可信应用代码创建，模型工具参数和用户文字不能修改预算、时钟或取消信号。没有引入Agent框架、线程池或新第三方依赖。

## 2. 默认限制及适用范围

| 维度 | 实际默认行为 |
| --- | --- |
| 整轮时长 | 从进入受控执行到会话发布前，使用单调时钟检查90秒期限 |
| 模型调用 | 自然入口共享最多3次；明确格式入口默认2次，原流程本身也不增加调用 |
| 分析 | 全轮共享最多1次，在构造数据源/读取前消费，失败不退还 |
| token | 累计观察值达到24,000立即停止，不重试；不是预付费或严格花费上限 |
| 模型输出 | 沿用DeepSeek现有每次默认512、配置最多1,500 tokens |
| 网络timeout | DeepSeek默认30秒、行情默认15秒；实际传入值进一步取剩余整轮时间的较小值 |

`TurnLimits`允许应用收紧限制，不能扩大上述产品上限。单次指标修改、身份续接最多2次模型，结果追问最多1次，明确知识和历史查看0次；原路由界限仍有效。每条新消息创建新的控制器，不能重用已开始/完成的控制器。

适用范围是 `run_research_turn()`、`run_natural_research_turn()`及经它们运行的CLI/契约评估场景。独立文本模型CLI、底层工具smoke、目录刷新等没有因此变成整轮受控任务。终端在Agent入口之前读取本地目录的时间也不计入这一轮90秒。

终端原有每启动5条普通问题、15次模型转发上限仍独立生效。若外层会话额度拒绝转发，整轮控制器记录一次模型方法尝试，不伪称已发生一次付费供应商请求；没有返回usage则用量不完整。

## 3. 数据流与代码职责

```text
产品Agent入口
  → 创建/认领单次TurnControl；占用原会话锁
  → 暂存会话状态 + ControlledToolModel包装原模型
  → 理解 / 提议：调用前扣次数，响应后记usage并检查停止
  → 工具：验证参数后扣分析额度，计算完成并返回时再次检查
  → 解释：共用同一控制器，迟到的解释不参与展示
  → finish()：在取消锁下最后检查，再发布新会话状态
```

- [turn_control.py](../src/trading_companion/turn_control.py)：不可变限制、单次生命周期、线程安全取消、预算计数、脱敏运行元数据。
- [agent.py](../src/trading_companion/agent.py)：包装两个入口，处理停止结果，协调会话暂存及提交；不改变股票/日期/指标绑定。
- [research_session.py](../src/trading_companion/research_session.py)：`_fork_for_turn()`暂存，`_publish_turn()`发布；新研究开始仍立即消费旧基准。
- [research_tool.py](../src/trading_companion/research_tool.py)：在实际分析前消费共享额度，不让通用工具异常处理吞掉停止信号。
- [deepseek_model.py](../src/trading_companion/deepseek_model.py)、[tencent_adapter.py](../src/trading_companion/tencent_adapter.py)、[akshare_adapter.py](../src/trading_companion/akshare_adapter.py)：传入剩余时间约束；腾讯每个跨年分片后检查，防止继续发下一片。
- [agent_cli.py](../src/trading_companion/agent_cli.py)：每消息新建控制器，只显示安全答案、时间和用量完整性。

使用 `ContextVar`把控制器传到嵌套的同步I/O边界，避免把预算加入模型可提议的业务参数，也不需要让会话额度包装层识别DeepSeek的具体类型。绑定在 `finally`恢复；它不是进程全局可变单例，也不承诺自动传播到新线程。本项目当前执行链不在后台线程继续研究。

`TurnStopped`独立于模型/数据源异常，不能被内部失败回退误吞。计数在调用/分析尝试前消费；实际返回的次数以控制器为准，而不是入口预先递增的旧局部计数。

## 4. 超时与取消：实际边界

这是**协作式截止控制，不是90秒必定返回的硬中断**。Python同步函数、正在等待的requests和远程模型不能被这个对象强行终止。requests的timeout主要限制连接/读取等待，不是整个HTTP下载的硬期限。

控制器在阶段之间、每次模型前后、腾讯每片请求前后及最终发布前检查；如果进行中的操作超过期限，返回后的内容被丢弃，不再启动下一阶段。未在90秒内返回的远程请求仍可能计费。AKShare只约束其公开方法传入的timeout和返回后的行为，不能控制其依赖内部不可见的请求或重试。未来真正需要即时返回时，要单独设计异步任务/进程隔离和供应商取消能力，不能把超时线程称为请求已取消。

`control.cancel()`可以由可信上层UI的另一执行上下文发出，只设停止信号、不创建线程。终端仍同步运行，没有后台 `/cancel`；等待时按Ctrl+C会退出、清理会话并返回130。中文“取消”仍是空闲时清待选请求的命令，不等同于终止正在执行的模型请求。

`finish()`最后检查与发布共用取消锁：若取消先被接收，不发布新状态；若已成功发布并完成，后来的 `cancel()`返回False，不把已完成轮重新改成取消。发布回调只做有界本地引用替换，不做网络、模型调用或再次取消。

## 5. 会话与展示政策

| 停止时机 | 默认展示 | 会话影响 |
| --- | --- | --- |
| 理解/提议停止，尚无事实 | 说明未完成 | 不增加候选或成功结果 |
| 分析迟到，或投影直到超时才返回 | 不展示迟到事实 | 不存结果，不调用解释模型 |
| 解释停止，已有及时核验事实 | 只展示本轮事实与未完成说明 | 不存本轮新结果/编辑基准 |
| 明确发出取消信号 | 不展示本轮分析 | 不存本轮新状态 |
| 合法新研究已开始，之后停止 | 不恢复旧编辑基准 | 旧成功结果只可显式历史查看 |
| 已有结果的追问停止 | 不展示迟到追问答案 | 原可信结果仍保留，TTL不续期 |

旧基准消费和显式“新问题：”重置属于立即失效操作；新候选、新条件、新快照属于暂存后发布操作。这不是数据库事务，也不将所有错误回滚到旧研究。暂存的不可变条件可共享引用；快照读取仍走原来的深复制隔离。

普通模型失败与预算停止不同：前者仍可按原规则保存可信事实；后者不提交新的会话结果。已消费的有效选股回复即使中断也不能再次续跑。原会话锁在停止/异常/中断后释放，进行中第二条消息返回 `session_busy`。

## 6. Token统计不能伪装成成本控制

每个响应将可用的prompt/completion/total分别累计；缺失字段保持未知，不凭空补0。停止计数取 `max(可用total, 可用prompt+completion)`再累加，保守使用已有数据；只在三个字段完整且相加一致时标记该响应usage完整。

没有完整usage时，累计观察值只代表已知部分或不一致报告下的保守停止值，不能视为真实总消耗。`usage_complete_for_attempts`还要求每次模型尝试都有完整一致usage；失败但未返回usage的调用不会被忽略。晚返回的有效模型响应仍统计usage，但它的工具调用和文本被丢弃；若传输/解析失败而无可用响应，则无法追补账单。

阈值在响应后检查，允许本次已经越过阈值，但不再后续调度；没有使用分词器估算输入、预留下一次最大费用、账户余额或人民币预算。默认继续允许缺usage的响应，仍受次数/时长/现有输出上限约束，不把这个策略称为严格token上限。

`AgentTurnResult.to_dict()`新增 `runtime`，包含限制、停止码、耗时、尝试数、收到响应数和usage完整性。被丢弃的响应不会加入原 `model_responses`，但可出现在 `runtime.responses_received`统计中。runtime不包含密钥、问题、模型草稿、文件路径或底层异常；整个Agent调试导出仍不是脱敏生产日志。

停止码：`turn_deadline_exceeded`、`turn_cancelled`、`model_call_budget_exhausted`、`analysis_budget_exhausted`、`token_budget_exhausted`。没有自动重试、修正、换模型或换行情源。
